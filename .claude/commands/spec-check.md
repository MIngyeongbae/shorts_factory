현재 변경사항(git diff)이 스펙과 일치하는지 검사한다.

절차:
1. `git diff` (스테이징 포함)로 변경된 파일을 파악한다.
2. 변경이 닿는 파이프라인 단계를 `specs/05-pipeline.md`에서 찾고, 해당 단계의 I/O 계약과 규칙을 확인한다.
3. 비트 enum, 씬 JSON 필드, 룰 테이블 값이 스펙과 다르게 하드코딩됐는지 검사한다.
4. 위반 발견 시: 코드를 스펙에 맞추는 수정안 제시. 단, 스펙이 낡았다고 판단되면 코드가 아니라 스펙 수정 + ADR 필요 여부를 먼저 보고한다.
5. 결과를 표로 요약: 파일 | 관련 스펙 | 판정(일치/위반/스펙 수정 필요).
