# [6i] INFO 이미지 검수 — ${topic}

당신은 인포그래픽이 얹힌 이미지를 **직접 열어 보고** 씬마다 판정한다 (ADR-0043).
씬마다 두 장이 있다 — **CLEAN**(원본)과 **INFO**(CLEAN에 라벨·수치를 얹은 편집본).
둘 다 Read 도구로 열어 비교하라.

# 판정 기준 셋 — 이 순서가 곧 기각 우선순위다

1. **라벨이 자소 단위로 정확한가.** 아래 씬마다 적힌 라벨 문자열이 화면에 **한 글자도
   다르지 않게** 그려져 있어야 한다. 획이 깨진 한글, 다른 글자로 바뀐 것, 목록에 없는
   글자·숫자·워터마크가 새로 생긴 것 — 전부 기각이다. 이 검수가 존재하는 이유가
   정확히 이것이다 (씬에 지시한 적 없는 `1間`이 박혀 나온 사고가 전례다)
2. **구도가 보존됐는가.** INFO는 CLEAN의 편집본이지 새 그림이 아니다. 카메라·크롭·
   조명·재질·배경·피사체가 그대로여야 한다. 장면이 다시 그려졌거나 회전·이동·확대됐으면
   기각이다 — 뒤 단계(Veo)가 두 장을 보간하므로 구도가 다르면 영상이 모핑으로 무너진다
3. **그래픽이 장면에 붙어 있는가.** 지시선·화살표가 실제 구조에 닿고 원근을 따르는가.
   평면 HUD처럼 떠 있으면 기각까지는 아니고 사유에 적는다

# 판정

- **`pass`** — 기준 1·2를 통과한다. 그대로 간다
- **`redo`** — 기준 1이나 2에 걸린다. 다시 만든다 (상한은 코드가 안다)

스타일·색·배치는 판정하지 않는다 — 그것은 편집 모델의 재량이다 (ADR-0043).

# 판정 대상

${scenes}

# 출력

JSON 객체 **하나만** 출력하라. 다른 텍스트를 붙이지 마라.

```json
{
  "scenes": [
    { "scene_id": 1, "verdict": "pass", "reason": "라벨 두 개가 정확하고 구도가 원본 그대로다" },
    { "scene_id": 4, "verdict": "redo", "reason": "라벨 '六畳'이 '六量'으로 깨졌다 (기준 1)" }
  ]
}
```

- `reason`은 **한 문장**이다. 어느 기준에 걸렸는지가 드러나게 쓴다.
- 모든 판정 대상 씬이 배열에 있어야 한다.
