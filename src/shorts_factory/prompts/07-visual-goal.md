너는 이미 확정된 쇼츠 대본에 **`visual_goal`** 한 필드만 채운다.

`visual_goal`은 **그 씬의 그림이 지는 설명**이다. 한국어 한 구절로 적는다.

# 왜 이 필드가 있나

글만으로 90~102초 안에 전달할 수 있는 양에는 한계가 있고 전달력도 약하다.
**그림이 설명의 일부를 지면 같은 분량 안에 더 많은 사실이 들어간다.**

그림 한 장은 **시간을 채우는 것이 아니라 설명을 대신하는 것**이다. 자막이 이미
말한 것을 한 번 더 비추는 그림은 아무 일도 하지 않는다.

# 규칙

- **자막(`text`)이 이미 말한 것을 되풀이하지 마라.** 본문이 말하지 않고 넘어가는 것,
  말로 하면 길어지는 것을 그림이 진다
- **자막을 바꿔 쓴 문장은 실패한다.** 기계적으로 겹침을 재서 거른다
- 그 씬의 `subject`(이미 정해진 피사체)가 무엇을 설명할 수 있는지 보고 적는다
- 한 구절이면 된다. 문장으로 늘이지 마라

# 예

```
자막:    1989년 3월 17일 오전 8시 55분, 탑 하나가 무너집니다.
피사체:  이탈리아 도시 광장의 오래된 벽돌 종탑
→ visual_goal: "붕괴의 순간과 규모 — 본문이 날짜만 말하고 넘어가는 것"

자막:    4명이 숨졌고 잔해는 8,000 m³였죠.
피사체:  출입 통제선이 쳐진 텅 빈 광장
→ visual_goal: "8,000 m³가 얼마만 한 양인지 — 광장을 덮은 잔해의 부피감"

자막:    가장 쉬운 방법은 한 번에 통으로 붓는 거였습니다.
피사체:  한 덩어리로 쏟아지는 콘크리트 타설 장면
→ visual_goal: "'통으로'가 실제로 어떤 규모의 작업인지 — 한 번에 흘러드는 양"
```

나쁜 예 (자막을 되풀이한다):

```
자막:    4명이 숨졌고 잔해는 8,000 m³였죠.
→ visual_goal: "4명이 숨지고 잔해가 8,000 m³였다는 것"   ← 실패
```

# 판정 대상

$scenes

# 출력 스키마

정확히 이 구조의 JSON 객체 **하나만** 출력한다.

{
  "goals": [
    {"scene_id": 1, "visual_goal": "이 그림이 지는 설명"},
    {"scene_id": 2, "visual_goal": "이 그림이 지는 설명"}
  ]
}

- **모든 씬에 대해** 출력한다. 하나라도 빠지면 실패한다
- `scene_id`와 `visual_goal` 두 키뿐이다. 대본을 고치지 않는다

# 출력 형식

JSON 객체 하나만 출력한다. 코드펜스(```), 설명, 머리말, 맺음말을 붙이지 않는다.
첫 글자는 `{`, 마지막 글자는 `}`여야 한다.
