# 05. 파이프라인 단계 정의 및 I/O 계약

각 단계는 독립 실행 가능한 모듈이며, 파일 기반 JSON으로 통신한다. 중간 산출물은 `runs/{run_id}/` 아래에 저장되어 어느 단계에서든 재시작 가능하다.

> **이 문서는 설계이지 구현 현황이 아니다.** 아래 단계 중 일부는 아직 코드가 없다
> (`[1c]`·`[2b]`·`[4]`·`[8]`·`[10]`·`[11]`, 그리고 ADR-0039 §4의 `[6]`·`[7]` 계정
> 인스턴스 대조).
> **무엇이 실제로 도는지는 `README.md`의 「구현 현황」이 정본이다** — 스펙에 상태를 적으면
> 커밋마다 스펙이 흔들리고, 그러면 스펙이 자산 역할을 잃는다 (ADR-0034 §1).

## 단계 목록

```
=== 1부: 토픽 패키지 생산 (한계비용 0, 완전 자동, 일 1~5개) ===

topics/backlog.md
  → [0a. topic]     → topics/{slug}/ 폴더 생성 (매체 적합성 판별, 스펙 06)
  → [0b. research]  → 01-research.md → 02-verify.md → 03-critique.md → 04-factsheet.json
                       (각각 독립 헤드리스 세션, ADR-0009)
  ┌ [1a. outline]   → 07-outline.json    (흥미 포인트 선정 + 서사 구조 설계 + 단별 사실·글자 배분)
  │ [1s. sceneplan] → 08-sceneplan.json  (씬 분할 + 글·그림 분담 + 연출 선택. 그림 필드가 여기 소관)
  └ [1w. write]     → 05-candidates/*.json (요지 → 자막 문장. 씬 구조를 바꾸지 않는다)
    ↑ 셋은 순서대로다. 옛 [1. script] 한 단계를 가른 것이고 1부의 출력은 그대로다 (ADR-0029)
  → [1c. critique2] → 03-critique.md 갱신 (대본 후보 공격)
  → [1b. score]     → 09-score.json + 06-script.json  (훅 스코어링: 비판 반영 채점 → 상위 1개)
  → [2. validate]   → 06-script.json     (구조·스키마·그라운딩 최종 게이트. **재생성하지 않는다** —
                       오류는 각 단계 직후 검증이 그 자리에서 잡고, 여기 실패는 보고·중단이다. ADR-0044)
  → [2b. judge]     → judgment/ai.json   (AI 심사관 판정: go/revise/no_go, 스펙 07)
                       revise 시 fix_directives 주입 → [1a]부터 재생성 → 재심사 (상한 2회).
                       심사관이 무는 것은 서사·훅이라 문장만 고쳐서는 답이 안 나온다

=== 판단 게이트 (ADR-0009 → ADR-0010 이양 경로) ===
  → 자율성 레벨에 따라: L0~L1 사람 판정(judgment/human.json, AI 판정 비공개 상태에서),
    L2 확신 구간 AI 전결 + 에스컬레이션, L3 AI 전결 + 샘플 감사. go 시에만 2부 진입

=== 2부: 영상 생산 (MJ 정액 + 인포씬만 Veo 종량, go 승인분만. ADR-0025·0043) ===
  → [3. tts+sync]   → narration.wav + timing.json + scenes.timed.json
                       (ElevenLabs with-timestamps 문자 정렬 → 문장 경계 실측, ADR-0004)
                       **2부의 실행 첫 단계다** (ADR-0043 결정 4) — 102초 초과 중단이 지출보다
                       앞서야 하고, [7]의 Veo 길이 선택(4/6/8초)이 실측 길이를 요구한다
  ┌ [4. refpack]    → refs/{scene_id}/*.jpg + refs.json  (씬별 실사 참조: 사진 + 서술, ADR-0030)
  └ [5. prompt]     → prompts.json       (씬별 이미지 프롬프트, 스펙 03 룰 적용)
    ↑ 둘은 선후가 없다. 각자 06-script.json만 읽는다 (ADR-0020).
      [5]는 refs.json이 있으면 서술을 싣고 없으면 그냥 간다
  → [6. imagegen]   → images/{scene_id}.{ext}  (확장자는 프로바이더가 정한다 — ADR-0021.
                       NB2는 JPEG, MJ는 PNG) + images/_cand/{scene_id}/q{0..3}
                       (MJ가 이미 만든 4장. 씬을 동시에 제출한다 — ADR-0031)
                       + image_source.json  (씬별 잡 id·사분면 = [7]의 영상 입력, ADR-0041)
  → [6r. imagereview] → image_review.json  (씬별 판정: pass / 사분면 교체 / redo, ADR-0031)
                       redo 씬만 [6]에 다시 넣는다 (상한 1회). image_source.json 갱신
  → [6i. info]      → info/{scene_id}.jpg + info.json  (**인포씬만.** CLEAN에 NB2 편집으로
                       라벨·수치를 얹은 INFO 이미지 + 자소 대조 검수, ADR-0043)
  → [7. motion]     → clips/{scene_id}.mp4  (전 씬 영상 — ADR-0039. **인포씬은 Veo first/last,
                       나머지는 MJ relax** — ADR-0043. 강등 시에만 Ken Burns)
  → [8. overlay]    → 대형 텍스트·파티클 합성 (레이어 B). clips/를 덮어쓰지 않는다
  → [9. assemble]   → timeline.mp4       (FFmpeg: 디졸브 + 자막 번인)
  → [10. mix]       → final.mp4          (TTS + SFX + BGM, 스펙 04)
  → [11. report]    → report.md          (실패 씬, 재시도 이력, 소요 시간/비용)
```

## 단계 간 계약 파일 (runs/{run_id}/)

토픽 패키지(`topics/{slug}/`)는 사람이 읽는 산출물이고, 단계 간 기계 계약은 run 디렉터리에 둔다 (ADR-0011).

| 파일 | 생산자 | 용도 |
|---|---|---|
| `topic.json` | [0a] | 소재명·슬러그·백로그 관측 지표. 하류 단계의 입력 |
| `state.json` | 전 단계 | 단계 상태(pending/running/done/failed/blocked). 재시작 시 완료 단계 스킵 판단 |
| `research.json` | [0b] | 팩트시트 사본 (스펙 06) |
| `logs/*.json` | LLM 어댑터 | 헤드리스 세션 응답 원본 |

### 2부 계약 파일 — 값 하나의 출처는 하나다 (ADR-0020)

| 파일 | 생산자 | 역할 | 읽는 단계 |
|---|---|---|---|
| `scenes.timed.json` | [3] | **씬의 유일한 출처.** 대본 속성(`beat`·`text`·`subject`·`subject_scale`·`subject_anchor`·`transition`·`camera`·`motion`) + 실측 시각(`start`/`end`). 이미지 지시(`visual_goal`·`framing`)는 싣지 않는다 — 그림 쪽 소비자는 `prompts.json`을 읽는다 | [7] 클립 길이·카메라·모션, [9] 전환·자막 |
| `refs.json` | [4] | **씬별 실사 참조.** `description`(사진에서 읽어 낸 형태·재질·배치)과 내려받은 파일 목록. 씬이 비어 있어도 된다 — 도해 씬에는 참조가 없다 (ADR-0030) | [5] `description`을 프롬프트에 싣는다, [6] `attachable` 파일을 첨부 |
| `prompts.json` | [5] | **씬별 이미지 지시.** 시간 정보를 담지 않는다. `style.dialect`가 어느 프로바이더 문법으로 쓰였는지 밝힌다 (ADR-0027) | [6] `prompt`·`negative_prompt`·`style`, [6r] `redo` 씬만, [8] `overlays` |
| `timing.json` | [3] | **[3]의 실행 기록.** 엔진 메타·배속·원속 길이·오디오 길이·경고. 계약이 아니라 기록이라 길이 초과로 멈출 때도 남는다 | [11] 리포트, 사람 |
| `images.json` | [6] | **[6]의 실행 기록.** 프로바이더·앵커 수·씬별 상태/재시도/폴백/후보 목록. 계약이 아니라 기록이다 | [6r] 판정 대상과 후보, [11] 리포트, 사람 |
| `image_review.json` | [6r] | **[6r]의 실행 기록.** 씬별 판정(`pass`/`pick`/`redo`)·고른 사분면·기각 사유. 계약이 아니라 기록이다 (ADR-0031) | [11] 리포트, 사람 |
| `image_source.json` | [6] → [6r] | **`[7]`의 영상 입력 계약** (ADR-0041, 정본 `specs/schema/image-source.schema.json`). 씬마다 `task_id`·`quadrant` 둘 — "지금 화면에 있는 그림이 어느 잡의 몇 번째 장인가". **영상 입력이 있는 씬만 담는다**; 폴백 씬과 잡 id 개념이 없는 프로바이더는 항목이 없다 | [7] `mj_video` 입력 |
| `info/{scene_id}.jpg` | [6i] | **인포씬의 INFO 이미지** — CLEAN(`images/{scene_id}.png`)에 계약의 `info.labels`를 얹은 편집본 (ADR-0043). `info` 필드가 있는 씬만 존재한다. Veo는 파일을 base64 인라인으로 받으므로 잡 id 사이드카가 필요 없다 | [7] Veo의 last frame |
| `info.json` | [6i] | **[6i]의 실행 기록.** 씬별 상태·검수 판정·재생성·강등. 계약이 아니라 기록이다 | [11] 리포트, 사람 |
| `clips.json` | [7] | **[7]의 실행 기록.** 씬별 모션 분기·적용 카메라·역방향 여부·재시도. 계약이 아니라 기록이다 | [11] 리포트, 사람 |
| `subtitles.ass` | [9] | 자막 파일. `ass` 필터의 입력이라 파일로 존재해야 한다 | [9] 번인 |

- 씬의 시각을 읽는 곳은 `scenes.timed.json` **하나뿐이다.** 같은 숫자를 두 파일이 들고 있으면 갈라지고, 갈라진 쪽을 읽은 단계만 싱크가 어긋난다
- `prompts.json`의 `beat`·`subject_scale`·`camera`·`motion`은 `06-script.json`에서 복사해 온 값이다. **고치는 곳은 `06-script.json` 하나다**
- `prompts.json`의 `framing_source`는 그 씬의 구도가 **계약에서 왔는지 기본값으로 떨어졌는지**만 밝힌다 (`scene` | `beat_default`). 연속한 두 씬의 `framing`이 같아도 **이미지를 재사용하라는 뜻이 아니다** — 구도만 같고 `subject`는 다르다. [6]이 캐시 힌트로 읽으면 안 된다
- `prompts.json`의 `subject`는 한국어 그대로 프롬프트에 들어간다. 번역하지 않고(ADR-0001·0014), 대신 그 한국어를 화면에 글자로 그리지 말라고 명시한다 (ADR-0002). **Midjourney도 한국어를 그대로 받는다** — 영어로 옮겨도 품질 차가 없었다 (ADR-0027 실측). `subject_anchor`도 같은 자리에 한국어 그대로 들어가며, `prompts.json`에 별도 필드로 남지 않는다 — 프롬프트 문자열 안에 있다. 고치는 곳은 여기서도 `06-script.json` 하나다
- `prompts.json`은 **방언 하나만** 담는다 (ADR-0027). `[6]`은 `style.dialect`와 자기 프로바이더가 어긋나면 호출 전에 멈춘다 — 방언이 틀린 문자열은 편당 과금을 쓴 뒤에야 실패한다
- 씬당 베이스 이미지는 1장 = 호출 1회다 (ADR-0019). `overlays`는 전부 레이어 B라 [6]이 아니라 [8] 소관이다

- 소스 카드(`knowledge/`)는 run·토픽에 종속되지 않는 **누적 자산**이라 run 디렉터리에 두지 않는다 (ADR-0012)
- `slug`: 음운 변화 미적용 로마자 표기, `[a-z0-9-]` 최대 60자 (ADR-0011)
- `run_id`: `YYYYMMDD-{slug}`
- 헤드리스 세션에는 읽기 도구만 준다. 산출물 파일은 오케스트레이터가 쓴다 (ADR-0011)

### 1부 ↔ 2부 경계 (ADR-0017)

두 부는 아래 **두 파일로만** 만난다. 2부는 그 밖의 1부 산출물에 의존하지 않는다.

| 파일 | 역할 |
|---|---|
| `topics/{slug}/06-script.json` | 씬 계약. 1부의 최종 산출물이자 2부의 **읽기 전용** 입력 |
| `topics/{slug}/judgment/human.json` | 게이트. `decision: go`일 때만 2부 진입 (스펙 07 스키마) |

- `07-outline.json`·`08-sceneplan.json`은 **1부 내부 파일이다** (ADR-0029). 2부는 읽지 않는다 — 경계 파일은 위 둘뿐이라는 이 규칙이 단계가 늘어도 그대로라는 뜻이다
- **2부는 `06-script.json`을 수정하지 않는다.** 모든 2부 산출물은 `runs/{run_id}/` 아래에 쓴다
  (`narration.wav`, `timing.json`, `scenes.timed.json`, `refs/`, `refs.json`, `prompts.json`,
  `images/`, `images/_cand/`, `images.json`, `image_source.json`, `image_review.json`,
  `info/`, `info.json`, `clips/`, `subtitles.ass`, `timeline.mp4`, `final.mp4`, `report.md`).
  `runs/*`는 `.gitignore` 대상이라 미디어가 커밋되지 않는다
- 계보는 `run_id`로 잇는다. 2부 산출물은 대본과 같은 `run_id`의 run 디렉터리에 놓인다

## 단계별 규칙

- **[0b. research]**: 스펙 06의 소스 등급(A~D)에 따라 웹 검색·수집. 1차 사료 필수 아님, 위키백과는 B등급 근거로 인정, 확정되지 않은 유력 학설은 `confidence: medium` (ADR-0016). 해외 소재는 영어 검색 병행. verdict: fail 시 백로그 반려하고 종료. 팩트시트는 사람 검수 지점 (유일한 수동 게이트).
- **[1a. outline]** (계약: `specs/schema/outline.schema.json`): 팩트시트만 읽는다. **씬도 문장도 만들지 않는다.** 훅 후보를 여러 개 내고 하나를 고른 이유(`why_chosen`)를 적는다 — 여기서 고르는 것은 문장이 아니라 **각도**다. **이 소재에 맞는 단(act) 구성을 설계한다** — 개수도 이름도 순서도 소재가 정한다 (ADR-0033 §2). 단마다 전달할 사실과 **글자 예산**을 배분하고, 예산 합계는 `specs/schema/script-rules.json`의 `limits.total_chars`다 — **분량 산수를 여기서 한 번만 한다.** 훅이 앞에 오고 마지막 단이 훅의 소재로 돌아오는 것(수미상관)이 구조에 거는 유일한 제약이다. 그라운딩(ADR-0007)은 단 단위로 먼저 건다 (`grounded_in`이 팩트시트 항목 키다).
- **[1s. sceneplan]** (계약: `specs/schema/sceneplan.schema.json`): `07-outline.json` + 팩트시트를 읽는다. **문장을 쓰지 않는다.** 씬을 `limits.line_count` 범위로 나누고 씬마다 `beat`·`says`(말할 요지)·`char_budget`, **그림 필드**(`visual_goal`·`subject`·`subject_anchor`·`subject_scale`), **연출 필드**(`framing`·`transition`·`camera`·`emphasis`)를 적는다. **`motion`은 고르지 않는다** — 전 씬 영상이라 고를 것이 없고(ADR-0039 결정 1), 값은 `beat-defaults.json`의 기본값이 정한다. `says`에 종결어미·수사 의문문·시그니처 문구가 들어오면 `[1w]`가 할 일이 없어진다. **연출은 자유 기술이 아니라 `specs/schema/vocab.json` 어휘에서의 선택이다** (ADR-0033 §3) — 어휘에 없는 값이 필요하면 어휘를 늘리는 PR이 먼저다. **그림 필드가 전부 이 단계 소관인 것이 ADR-0029의 요점이다** — 배분을 먼저 정하라는 ADR-0022가 비로소 독립 단계가 된다. `subject_scale`·`subject_anchor`가 세션 몫인 근거는 그대로다 (ADR-0018·0028: 재질과 고유명사는 팩트시트를 든 세션만 알고, `[5]`가 추론해 붙이면 판단을 변환기에 넣는 것이다). **앵커 고유명사의 언어도 여기서 정해진다** — 소재의 1차 자료 언어로 적고(ADR-0042), 그 표기는 팩트시트에 이미 있다(ADR-0037이 조사·검증을 현지어로 돌린 결과다). 한국어로 「일본 …」이라고 적으면 한옥이 나온다는 것이 실측이고, `[5]`는 번역하지 않으므로 여기서 안 정하면 아무 데서도 안 정해진다. **인포씬도 여기서 정한다** (ADR-0043) — 화면에 라벨·수치가 그려져야 설명이 서는 씬에 `info.labels`(화면에 그려질 문자열 그대로, 1~4개)를 단다. 문자열 속 수치는 팩트시트에 있어야 하고 (ADR-0007), 배치·색·지시선은 적지 않는다 — NB2 재량이다. **산출 직후 오케스트레이터가 기계 검증한다** (ADR-0044): 씬 수 범위·어휘·`visual_goal` 겹침·`says` 숫자와 `info` 수치의 그라운딩. 실패 시 같은 세션 resume으로 1회 재청하고, 그래도 실패면 중단·보고한다 — 틀린 계획을 `[1w]`로 흘려보내지 않는다.
- **[1w. write]**: `08-sceneplan.json` + `07-outline.json`을 읽고 `says` → `text` 변환만 한다. 구어체 존댓말·수사 의문문·시그니처 문구·줄당 리듬이 이 단계 몫이다. **씬 구조를 바꿀 수 없다** — 세션의 출력은 `{scene_id: text}`뿐이고, `06-script.json`은 오케스트레이터가 `08-sceneplan.json`의 필드에 그 text를 얹어 **조립한다** (ADR-0044). 세션에게 필드 복사를 시키지 않고 따라서 전수 대조도 없다 — 대조가 아니라 조립이므로 어긋날 수가 없다 (복사 필드 하나가 어긋나 파일 전체가 실패하고 편당 10분짜리 재집필이 3회 돌던 구조를 이것이 없앤다). **조립할 필드 목록을 손으로 적지 않는다** — 두 스키마의 교집합이고 `sceneplan.carried_fields()`가 계산한다 (ADR-0034 §3). 팩트시트를 직접 읽지 않는다 — 숫자는 `says`에 이미 있고 없는 숫자를 쓰면 ADR-0007 위반이다. 타임스탬프는 오케스트레이터가 계산한다 (ADR-0014·0033). `confidence: low` 사실은 프롬프트에 주입하지 않는다. **산출 직후 오케스트레이터가 씬 단위로 검증한다** (ADR-0044): 분량(`char_budget`)·문체·`says` 숫자 보존. **실패한 씬만** 같은 세션 resume으로 재청하고(상한 1회), 그래도 실패면 중단·보고한다. 전체 재집필은 없다. **후보 수는 현재 1개다** — `[1b. score]`가 구현돼(ADR-0040) 늘릴 수단은 생겼으나 늘리는 결정은 아직 없다.
- **[1b. score]** (계약: `specs/schema/score.schema.json`): 루브릭(hook_strength / info_density / standalone) 기반 LLM 채점. 축 이름·축당 만점·임계값은 **`specs/schema/script-rules.json`의 `score` 절이 정본이고 코드는 로드만 한다** (ADR-0034 §3). 입력은 **후보 대본 + `03-critique.md` + `07-outline.json`** 셋이다 — **팩트시트를 주지 않는다**. 채점은 사실 검증이 아니고 그것은 `[0b]`·`[2]` 몫이며, `07-outline.json`을 주는 이유는 `why_chosen`이 **채점 대상**이기 때문이다 (ADR-0040). `[1a]`가 각도를 고를 때 비판을 보지 않는 것은 설계이고(ADR-0009), **비판은 여기서 반영된다.** **임계값 대조는 기계가 한다** — 세션은 점수와 선발만 내고 `verdict`를 쓰지 않는다. 전 후보가 기준 미달이면 선발하지 않고 반려·리포트한다. **임계값이 아직 비어 있으면(캘리브레이션 전) 채점만 하고 반려하지 않는다** — 근거 없는 수로 반려선을 그으면 첫 편에서 임의로 갈린다. 텍스트 생성 비용은 무시 가능한 수준이므로 후보 수는 비용이 아니라 채점 신뢰도로 결정. 추후 실제 조회수 데이터로 루브릭 보정(피드백 루프)을 v2 과제로 둔다.
- **[2. validate]**: 스펙 01의 검증 항목(분량·수미상관) + 씬 계약 스키마 검증(`specs/schema/scene.schema.json`) + 그라운딩 검증(대본 숫자 전수 추출 → 팩트시트 대조, ADR-0007 — `info.labels` 속 수치 포함, ADR-0043). **구조 검증은 없다** — 단 구성이 소재마다 다르므로 기계가 볼 수 있는 것이 아니고, 서사가 성립하는지는 `[2b] judge`가 본다 (ADR-0033 §5). **재생성하지 않는다** (ADR-0044가 ADR-0029의 재진입 규칙을 대체했다). 오류는 각 단계 직후 검증이 그 자리에서 잡으므로(`[1s]`·`[1w]` 규칙) 여기는 **최종 게이트**다 — 실패하면 보고하고 중단하며, 다시 돌릴지는 사람이 정한다. 여기서 걸리는 것은 직후 검증의 구멍이라는 뜻이고, 그것은 재생성이 아니라 검증기 수리 대상이다. "문장 문제로 그림 계획까지 버리지 않는다"는 ADR-0029의 목적은 fail-fast가 더 싸게 지킨다 — 틀린 단계 밖으로 오류가 아예 안 나간다.
- **[3. tts+sync]**: **2부의 실행 첫 단계다** (ADR-0043 결정 4) — 102초 초과 중단이 이미지·영상 지출보다 앞서야 하고, `[7]`의 Veo 길이 선택(4/6/8초)과 4.6초 초과 씬의 사전 식별이 실측 길이를 요구한다. 다다미 편이 `[3]` 없이 `[5]→[6]→[6r]`로 가서 총 길이도 모른 채 24씬을 산 것이 실물 반례다. 대본 전체 단일 호출 + with-timestamps. 문자 정렬에서 씬(자막 줄) 경계 start/end 추출해 `runs/{run_id}/scenes.timed.json`을 **새로 쓴다**(ADR-0017. `06-script.json`은 건드리지 않는다) — 문장 경계를 뽑은 뒤 각 줄의 마지막 문장 끝만 취한다 (ADR-0013). 실측-추정 오차 씬당 ±1.5초 초과 시 경고. 총 길이 102초 초과 시 **대본 축약이 필요하다고 리포트하고 멈춘다** — 2부가 1부를 직접 다시 돌리지 않는다 (ADR-0017의 단방향 경계). 재생성은 사람이 1부를 다시 실행해 판단한다. atempo 1.1 적용 후 타임스탬프도 1/1.1 스케일 보정.
- **[4. refpack]** (계약: `specs/schema/refs.schema.json`): `06-script.json`의 `subject`·`subject_anchor`로 검색어를 만들어 씬별 실사 참조를 모은다 (ADR-0030). 산출은 둘이다 — **`description`**(사진에서 읽어 낸 형태·재질·색·배치를 한국어 구절로)과 **내려받은 파일 목록**. 도해 씬이나 실물이 없는 개념 씬은 **비운다**. 부재를 경고하지 않는다 (ADR-0028의 선택 필드와 같은 태도). 소비는 두 경로이고 **강등 사다리는 `첨부+서술 → 서술 → 없음`이다** — 한쪽이 죽어도 다른 쪽이 돈다. 라이선스가 `public-domain`·`cc0`·`cc-by` 계열인 사진만 `attachable: true`이고, 불명·저작권 있음은 서술 경로만 탄다. `source_url`·`license`·`credit`을 전부 기록한다. **참조 사진 자체가 최종 산출물에 들어가는 일은 없다** — 이미지 프롬프트는 입력이다. 이 단계의 세션에는 **웹검색 도구를 준다** (지금까지 읽기 도구만 준 것과 다르다, ADR-0011). 세션은 URL과 서술을 JSON으로 돌려주고 내려받기는 오케스트레이터가 한다.
- **[5. prompt]**: **판단하지 않는다.** 구도는 씬 계약의 `framing`을 그대로 옮기고, 비어 있을 때만 `specs/schema/beat-defaults.json`의 기본값으로 떨어진다 (ADR-0033 §3). **기본값으로 떨어진 씬 수를 요약에 낸다** — 그 수가 크면 연출 선택이 형식적으로 비어 있는 것이고 ADR-0033의 되돌릴 조건이 관측되는 자리다. 오버레이는 전부 레이어 B다 — 베이스 이미지는 전 씬 클린이고 2-pass 어노테이션 경로가 없다 (ADR-0019). 출력 방언은 `--dialect {mj,nb2}`로 고르고 기본값은 `mj`다 (ADR-0027). **방언은 표기 변환일 뿐이라 스타일 문자열·구도 어휘·배제 항목은 방언과 무관하게 같다.** MJ 방언에서는 스타일 앵커 없음을 경고하지 않는다 — 그 경로가 스타일 앵커를 쓰지 않기 때문이다 (ADR-0025 G3). 씬의 `subject_anchor`는 값이 있을 때 `subject` 뒤에 콤마 항목으로 싣고, **거르지 않는다** — 어느 명사가 그 씬에서 더 센지는 변환기가 알 수 있는 값이 아니다 (ADR-0028 G2). 부재도 경고하지 않되 **앵커를 채운 씬 수를 요약에 낸다** (되돌릴 조건의 관측 수단).
- **[6. imagegen]**: 시작 전에 `style.dialect`와 프로바이더가 맞는지 대조하고 어긋나면 호출 없이 멈춘다 (ADR-0027). 프록시 설정(간격·상한·모드 플래그)의 대조는 기계가 하지 않는다 — 정책 파일과 대조 게이트는 폐기됐고(ADR-0032 §1·§2 폐기), 값의 원본은 ADR-0025이며 맞추는 것은 사람이 웹 UI에서 한다. **같은 자리에서 계정 인스턴스가 실제로 작업을 받을 수 있는 상태인지도 본다** (ADR-0039 §4) — 콜드스타트에 전 씬을 던지면 프록시가 접수는 하되 디스코드로 나가지 못해 잡이 `SUBMITTED 0%`로 영구히 선다. 실패로 기록되지도 않는다. 씬당 1회 재시도. 2회 실패 시 인접 씬 이미지 재사용(카메라 워크만 변경)으로 폴백하고 리포트에 기록. 편당 베이스 호출 = 씬 수 (2-pass 없음, ADR-0019). **제출은 `POST /mj-fast/mj/submit/imagine`이다** (ADR-0039이 ADR-0025 §2의 "이미지 relax"를 뒤집었다) — 1잡이 relax 180.4초에서 **7.0초**가 되고 GPU는 0.6~0.8분뿐이라 Pro 30시간이면 월 80편이다. 영상이 relax로 빠졌기 때문에 생긴 자리다. **모드는 프롬프트 플래그가 아니라 엔드포인트 프리픽스가 정하고, 프록시의 자동 변환에 맡기지 않는다** (ADR-0039 §4) — 같은 호출이 2026-08-19 오전에는 조용히 모드가 바뀌어 성공했고 오후에는 거절됐다. **씬을 동시에 제출한다** (ADR-0031 §4). 제출한 뒤는 대부분 기다리는 시간이라 한 줄로 세울 이유가 없다 — 27씬을 순차로 돌면 잡 하나가 100초여도 45분이 된다(실측). **워커 수는 여기에 적지 않는다.** `--jobs`가 없으면 프로바이더에게 묻고(`ImageClient.concurrency()`), MJ 어댑터가 활성 계정의 `coreSize`(fast 동시 한도)를 읽는다 — 제출이 fast이므로 그 큐의 한도가 맞는 출처이고, relax 한도인 `relaxCoreSize`는 `[7]` 영상이 쓴다. 그 값은 **구독 플랜이 정하므로** 문서나 코드에 적어 두면 플랜을 바꾼 날 조용히 틀린다 (ADR-0031 G3). 못 읽으면 예외를 올리지 않고 1로 떨어진다 — 느려질 뿐 틀리지 않는 쪽이다. **대기 상한도 여기에 적지 않는다** (ADR-0035). 잡 하나를 얼마나 기다릴지는 프록시 큐가 정하고 그것을 아는 것은 프로바이더뿐이다 — 단계가 숫자를 선언하면 어댑터가 선언한 값이 죽고, 짧게 잡힌 상한은 **이미 성공한 잡을 버린 뒤 재시도로 큐를 두 배로 만든다**(실측). 사람이 정해야 하면 `--timeout`이 이긴다. `images.json` 갱신은 **직렬**이다 — 씬 하나가 끝날 때마다 쓴다는 계약(ADR-0020)의 목적이 재실행 시 다시 사지 않는 것이므로 병렬이 그것을 깨면 안 된다. 429(`ImageGenRateLimited`)가 나오면 워커를 1로 줄이고 백오프한다. **MJ가 낸 4장을 전부 `images/_cand/{scene_id}/q{0..3}.png`로 남기고** `q0`을 `images/{scene_id}.png`에 복사한다 — 하류 계약은 그대로다. 사분면을 고르는 것은 `[6r]` 몫이고, 이미 산 것이라 추가 과금이 없다. **`image_source.json`을 함께 쓴다** (ADR-0041) — 씬마다 잡 id와 사분면이고, `[7]`이 영상을 만들 때 필요한데 이미지 파일 내용에서 복원되지 않는다. **인접 씬 폴백으로 채운 씬은 항목을 내지 않는다**: 그 그림은 옆 씬의 복사본이라 잡 id가 없고, 원본의 id를 빌려 주면 같은 그림으로 영상이 두 번 나오는데 MJ 영상은 카메라를 프롬프트로만 받아 스펙 03의 역방향 워크를 걸 자리가 없다.
- **[6r. imagereview]**: 헤드리스 세션이 **이미지를 직접 보고** 씬마다 판정한다 (ADR-0031). **시각을 쓰지 않으므로 `scenes.timed.json`을 읽지 않는다** — 판정 기준이 대조하는 값은 씬 계약에 있고 `visual_goal`은 그 파일에 애초에 실리지 않는다. `[5]`와 같이 `06-script.json` 하나에서 읽고, 판정 대상과 후보 목록은 `images.json`에서, `redo` 씬을 다시 살 때만 `prompts.json`을 연다. 판정 기준 **셋**이 곧 기각 우선순위다 — ① `subject`·`subject_anchor`의 대상이 맞는가 ② `visual_goal`이 지려던 설명을 지는가 ③ 글자·워터마크·기형 사고가 없는가. **자막 자리(옛 기준 ③)는 폐기됐다** (ADR-0038, 아래 D-6) — 이미지가 하단을 비워 줄 이유가 없고, 실측에서 비워지지도 않았다. **스타일은 판정하지 않는다** — 스타일 문자열은 작동하고 있고, 판정 세션에 룩을 맡기면 어휘 밖에서 연출이 결정된다 (ADR-0033 §3). **판정 세션에 대본 문장(`text`)을 주지 않는다** (ADR-0038) — 그림이 지려던 것은 `visual_goal`이 이미 말한다. 네 장이 갈리지 않으면 손댈 곳은 `text`를 끌어오는 것이 아니라 `visual_goal`을 더 구체적으로 쓰게 하는 쪽이다 (`[1s]`). 판정은 `pass` / `pick q{n}`(사분면 교체, 재생성 없음) / `redo` 셋이다. **사분면 선택이 재생성보다 먼저다.** `redo`는 4장이 전부 기준 ①②에 걸릴 때만이고 **상한 1회**다 — 재생성 결과는 다시 판정하지 않는다 (판정↔재생성 루프에는 끝나는 조건이 없다). `[6]`의 인접 씬 폴백과는 축이 다르다: 그건 호출이 실패했을 때, 이건 결과가 틀렸을 때다. **`image_source.json`을 갱신한다** (ADR-0041) — `pick`은 그 씬의 `quadrant`를, 재생성 성공은 `task_id`를 새 잡 것으로 바꾸고 `quadrant`를 0으로 되돌린다. 재생성이 실패해 지금 이미지를 그대로 두면 항목도 그대로다.
- **[6i. info]** (ADR-0043): **인포씬만** — `06-script.json`에 `info` 필드가 있는 씬. `images/{scene_id}.png`(CLEAN — `[6r]`이 고른 그 장)와 계약의 `info.labels`를 NB2 편집 호출에 넣어 **구도를 보존한 채 라벨·수치를 얹은** `info/{scene_id}.jpg`를 만든다 (NB2는 JPEG만 낸다 — ADR-0021). 라벨 문자열은 계약 그대로 넣는다 — 고치거나 요약하지 않는다 (ADR-0020: 값 하나의 출처는 `06-script.json` 하나다). 배치·색·지시선은 지시하지 않는다 — NB2 재량이다. **검수를 포함한다**: 비전 세션이 렌더된 글자를 계약 문자열과 자소 단위로 대조하고 구도 이탈을 본다 — 다다미 씬 9의 `1間` 사고(`[6r]`이 못 거른 것)가 근거다. 검수 실패 시 재생성 1회, 그래도 실패면 그 씬을 **인포 없는 일반 영상으로 강등**하고 기록한다 (D-5: 실패는 단계 안에서 끝난다). `info.json`은 실행 기록이다 — 씬별 상태·검수 판정·강등. 인포씬이 없는 편에서는 단계 전체가 스킵된다 (D-3).
- **[7. motion]**: **전 씬을 영상으로 만든다** (ADR-0039이 ADR-0006 하이브리드를 폐기했다). **인포씬은 Veo다** (ADR-0043): `info` 필드가 있고 `info/{scene_id}.jpg`가 있으면 Veo 3.1에 first frame = `images/{scene_id}.png`(CLEAN), last frame = INFO를 **base64 인라인**으로 넣는다 — MJ처럼 "닿는 URL"을 만들 UPSCALE 왕복이 이 경로엔 없다. **길이는 8초 고정이다** — `lastFrame`을 넣으면 Veo가 8초만 받는다 (2026-08-20 실호출 실측: 4·6초는 `Your use case is currently not supported`로 400이고 화면비·해상도·티어를 바꿔도 같다). 공식 문서의 "8초 강제" 목록에 interpolation이 빠져 있어 처음엔 씬 길이에 맞춰 4·6을 골랐고 인포씬이 전부 400이었다. **8초는 호출 단위이지 클립 길이가 아니다** — 남는 꼬리는 `[9]`가 `trim`으로 자른다. 프롬프트에 순차 조립 지시(앵커 → 지시선 → 라벨·수치 순으로 나타나 INFO 상태로 수렴)와 씬 계약의 `camera`를 싣는다. ⚠ **이 지시는 아직 안전하지 않다 (ADR-0043 G2 미결).** 조립을 만드는 것은 이 지시가 맞지만(빼면 그래픽이 마지막 0.5초에 한꺼번에 뜬다), **넣으면 Veo가 끝 프레임을 복사하는 대신 글자를 직접 그려서** 표본 2/2에서 텍스트 사고가 났다 — 한 씬은 끝 0.3초에 라벨이 뭉개졌고, 다른 씬은 트림 지점에 계약에 없는 영어 라벨이 화면을 덮었다. **트림 지점이 안전하다는 보장이 없다.** 선택지는 ADR-0043 「그래서 남은 선택지」에 있고 사람 결정이 남았다. Veo가 낳는 오디오는 버린다 — 소리는 `[10]` 소관이다. 실패 시 `mj_video`로 강등하고 `demoted_from`을 채운다. `[6i]`가 강등한 씬은 INFO가 없으므로 자연히 일반 경로다. **나머지 씬은 아래 그대로다.** `motion` 필드 분기이되 기본값이 `mj_video`라 씬이 값을 비우면 영상이 된다 (`specs/schema/beat-defaults.json`, ADR-0033 §3). `mj_video` → `POST /mj-relax/mj/submit/video`. **relax라 GPU를 쓰지 않고**(실측 `30.00 → 30.00`) 그것이 전 씬 영상을 가능하게 한 유일한 조건이다 — 대신 **Pro 이상 플랜을 요구한다.** 그 아래에서는 MJ가 `Relax mode for video is limited to Pro and Mega plans`로 거절하고, 이는 씬 하나의 실패가 아니라 프로바이더 전체의 문제라 남은 씬을 시도하지 않고 전부 내려간다 — 같은 오류로 27번 실패하는 것은 결과가 아니라 소음이다. **편당 영상 씬 상한을 두지 않는다** — GPU가 0이라 셀 이유가 없다 (ADR-0006의 10씬 상한 폐기). **`batchSize: 1`을 보낸다** (ADR-0039 §3): MJ는 잡 하나에 4개를 내는데 우리는 U1 하나만 쓰고, relax에서 비용 이득은 없지만 fast로 되돌아갈 때 GPU가 3.25배 걸려 있다. `[6]`과 같이 시작 전에 **계정 인스턴스 상태를 대조한다** (ADR-0039 §4). **영상 입력은 `image_source.json`에서 읽는다** (ADR-0041) — 씬마다 잡 id와 사분면이고, 항목이 없거나 그 파일의 `provider`가 자기 영상 프로바이더와 다르면 그 씬은 내려간다. **`images.json`·`image_review.json`은 열지 않는다** (ADR-0024 §2) — 기록이지 계약이 아니다. `kenburns` → FFmpeg zoompan(camera 값 적용, 파라미터는 스펙 03의 "카메라 워크 파라미터" 표). `kling` → v2.6 Turbo급 i2v 5초 무음, 2회 실패 시 kenburns 강등. **강등 사다리는 `mj_video` → `kenburns` → `static`이고 아래로만 간다** (ADR-0025 §3). **강등을 조용히 하지 않는다** — 씬마다 `demoted_from`을 채우고 경고를 남긴다. 리포트가 강등 수를 세지 못하면 영상을 만들었다고 착각하게 된다 (ADR-0039). 클립 길이 = 씬 길이 + 디졸브 겹침 0.6초. **클립의 로컬 0초가 씬의 `start`이고 0.6초는 전부 꼬리다** (ADR-0024) — 겹침을 앞뒤로 나누지 않는다. 같은 이미지가 두 씬에 걸리면([6] 폴백) 2회차부터 스펙 03의 역방향 워크를 쓰고, **그 판정은 이미지 파일 내용으로 한다** (ADR-0024).
- **[8. overlay]**: `prompts.json`의 `overlays`(전부 레이어 B, ADR-0019)를 `[7]`의 클립 위에 합성한다. **`clips/`를 덮어쓰지 않는다** (ADR-0024) — 별도 디렉터리에 전 씬을 내고, 오버레이가 없는 씬은 그대로 통과시켜 항상 전 씬이 갖춰지게 한다. `kling` 클립은 편당 과금 산출물이라 오버레이를 고치려고 다시 살 수 없다. 디렉터리 이름은 이 단계를 구현할 때 정한다.
- **[9. assemble]**: 자막은 **scenes.timed.json** 기준 ASS 생성 후 번인 (ADR-0020 — 씬의 `text`·`start`·`end`를 읽는 곳은 이 파일 하나다). 전환은 씬 계약의 `transition`을 그대로 쓰고, 비어 있을 때만 `specs/schema/beat-defaults.json`의 기본값으로 떨어진다 (ADR-0033 §3). 길이 0.6초는 클립 기하가 정한 고정값이다 (ADR-0024). 싱크 오차 ±200ms 이내 검증.

## 실패 정책

- 단계 실패 = 해당 run 디렉토리에 상태 기록 후 종료. 같은 run_id로 재실행 시 완료된 단계는 스킵.
- 씬 단위 실패는 폴백 처리하고 파이프라인은 계속 진행 (스펙 00 성공 기준 5).
- **재생성 루프는 없다** (ADR-0044). 검증은 산출 직후 그 단계에서 하고, 재청은 실패 씬만 상한 1회(같은 세션 resume)다. 최종 게이트(`[2]`)의 실패는 보고·중단이고 다시 돌릴지는 사람이 정한다. `[2b] judge`를 구현할 때도 revise를 사슬 재실행으로 만들지 않는다.

## 확정된 결정

- 판단 게이트 = 섀도우 심사관 + 자율성 사다리 L0→L3 (ADR-0010)
- LLM 단계 실행 = Claude Code 헤드리스, 구독 플랜 (ADR-0008)
- 대본 = 팩트시트 그라운딩 (ADR-0007)
- TTS = ElevenLabs 본인 목소리 클로닝 (ADR-0004)
- 이미지 = **Midjourney 정액 구독 + 로컬 프록시** (ADR-0025). NB2 + 스타일 앵커(ADR-0005·0021)는 방언 하나로 남아 폴백 경로다
- 모션 = **전 씬 영상.** `mj_video`가 기본값이고 `kenburns`는 선택지가 아니라 **강등 결과**다
  (ADR-0039이 ADR-0006 하이브리드를 폐기했다). `kling`은 MJ 밴 대비 차선으로만 남는다 (ADR-0025 §3)
- 모드 배치 = **이미지 fast, 영상 relax** (ADR-0039이 ADR-0025 §2를 뒤집었다). 엔드포인트 프리픽스가 정하고 프록시의 자동 변환에 맡기지 않는다
- 대본 생산 = `[1a] outline` → `[1s] sceneplan` → `[1w] write` 3단계. 배분이 집필보다 먼저다 (ADR-0029)
- 이미지 참조 = `[4] refpack`이 실사진과 서술을 모으고, 강등 사다리는 `첨부+서술 → 서술 → 없음` (ADR-0030)
- 이미지 판정 = `[6r] imagereview`. 사분면 선택이 재생성보다 먼저다 (ADR-0031)
- `[7]`의 영상 입력 = **사이드카 계약 `image_source.json`** (ADR-0041). 기록(`images.json`·`image_review.json`)을 계약으로 승격하지 않는다
- 대본 구조와 연출 = **소재마다 설계한다.** 도메인 제한 없음, 고정 단 구성 폐기, 연출은 닫힌 어휘에서 `[1s]`가 고른다 (ADR-0033)
- 계약의 정본 = `specs/schema/`. 코드는 상수를 선언하지 않고 로드한다 (ADR-0034)
- 인포씬 = **MJ CLEAN + NB2 편집(INFO) + Veo first/last 영상** (ADR-0043). 지정과 라벨 문구·수치는 `[1s]`가 계약(`info` 필드)에 적고, 화면 텍스트는 자소 대조 검수를 통과한 것만 나간다 (ADR-0002의 부분 번복 — 자막·레이어 B는 여전히 합성이다)
- 대본 검증 = **단계 직후 검증 + 실패 씬만 재청(상한 1, resume) + 최종 게이트는 보고·중단** (ADR-0044가 ADR-0029 재진입 규칙을 대체). 2부 실행은 `[3] tts`가 첫 단계다 (ADR-0043)

## 단계 독립 원칙 (ADR-0034 §2)

단계 하나를 버려도 옆이 안 무너져야 파이프라인을 계속 세분화할 수 있다.

- **D-1. 단계는 파일로만 통신한다.** 함수 호출로 잇지 않는다 (ADR-0011)
- **D-2. 단계는 자기가 읽는 필드만 안다.** 모르는 필드는 읽지도 지우지도 않고 통과시킨다
- **D-3. 선택적 입력의 부재는 경고가 아니다.** 없으면 그 기능만 빠지고 단계는 돈다
- **D-4. 단계 추가는 기존 단계를 수정하지 않는다.** 새 단계는 새 파일을 쓰고, 그 파일을
  읽고 싶은 단계만 읽는다
- **D-5. 실패는 단계 안에서 끝난다.** 강등 사다리나 폴백으로 처리하고 파이프라인을 세우지
  않는다. 세우는 경우는 **돈이 나가거나 되돌릴 수 없을 때만이다** (방언 불일치, 정책
  드리프트, 길이 초과)
- **D-6. 단계는 하류의 편의를 위해 자기 산출물을 깎지 않는다** (ADR-0038). 하류가 필요한
  것은 하류가 만든다. 이미지가 자막 자리를 비우는 대신 **자막이 어디서든 읽히게** 하고,
  판정 단계가 대본 문장을 읽는 대신 **그림 목표만** 본다. 깎아 준 자리는 실측에서
  **비워지지도 않았고**(4/4 실패) 비워진 만큼은 그림이 아니라 종이였다

## 비용 기준선 — **변동비가 아니라 정액이다** (ADR-0025)

**편당 생성 비용은 0에 가깝다.** 이미지·영상이 Midjourney 정액 구독 + 로컬 프록시로
옮겨 갔기 때문이다. 종량제 시절의 "편당 ~$7"은 폐기된 값이다. **예외는 인포씬
하나다** (ADR-0043) — NB2 편집과 Veo 영상이 씬 단위 종량으로 붙는다. 전 씬이 아니라
인포씬만이라 사는 것이고, 편당 $10을 넘기면 재검토한다.

| 자원 | 성격 | 한도 |
|---|---|---|
| **MJ fast** (이미지, `[6]`) | 돈이 아니라 **GPU 시간.** 이미지 1잡 = 0.6~0.8분 · 7.0초 | Pro 월 30시간 → 편당 22분이면 **월 80편** |
| **MJ relax** (영상, `[7]`) | **GPU 0** (실측 `30.00 → 30.00`). 추가 과금도 없다 | 편수 상한 없음. **Pro 이상 플랜이 전제다** |
| **Veo** (인포씬 영상, `[7]`) + NB2 (`[6i]`) | **종량 — 유일한 변동비다** (ADR-0043). 인포씬만 붙고 편당 ~$3~7 추정, 실단가는 첫 프로브에서 확정 | 편당 $10 초과 시 인포씬 수·Veo 티어 재검토 (ADR-0043 되돌릴 조건) |
| Claude 구독 | 고정비. 1부 전 단계가 여기서 돈다 (ADR-0008) | 사용 한도 |
| ElevenLabs (`[3]`) | 플랜 문자 수 할당량 | 플랜별 |

- **씬 수가 늘어도 이미지 비용이 안 는다.** 이것이 ADR-0025의 목적이고, 편당 씬 수를
  아끼던 설계 압력이 사라진 자리다
- **편수를 묶던 것이 사라졌다.** 영상이 relax(GPU 0)로 가면서 `mj_video` 씬 수가 월
  편수를 깎지 않는다 (ADR-0039). `[1s]`가 영상 모션을 예산으로 아끼던 자리도 같이
  사라졌다 — 전 씬 영상이라 고를 것이 없다. 남은 병목은 **벽시계**다: 28씬이 편당
  약 36분(이미지 1.5 + UPSCALE 1.6 + 영상 32 + U1 추출 1.6, 동시 3 기준)
- 종량제로 돌아가는 경로(`kling`, RunPod)는 **폴백으로만 남아 있다** (ADR-0025 검토한 대안).
  그 경로를 켜면 변동비가 되살아난다
- 손익분기: 쇼츠 RPM 0.05~0.2원/조회 (docs/reference-analysis.md). 생성 변동비가 0이므로
  손익분기는 이제 **고정비(구독) ÷ 월 편수**로 계산한다. 수익 모델은 평균이 아니라
  멱법칙(소수 편의 대박) 기준으로 본다
