# 05. 파이프라인 단계 정의 및 I/O 계약

각 단계는 독립 실행 가능한 모듈이며, 파일 기반 JSON으로 통신한다. 중간 산출물은 `runs/{run_id}/` 아래에 저장되어 어느 단계에서든 재시작 가능하다.

> **이 문서는 설계이지 구현 현황이 아니다.** 아래 단계 중 일부는 아직 코드가 없다 (`[10]`).
> **무엇이 실제로 도는지는 `README.md`의 「구현 현황」이 정본이다** — 스펙에 상태를 적으면
> 커밋마다 스펙이 흔들리고, 그러면 스펙이 자산 역할을 잃는다 (ADR-0034 §1).

> **2부는 ADR-0056으로 갈아엎었다** (2026-08-22). 이미지 단계(`[6]`·`[6r]`·`[6i]`)와 MJ·NB2
> 경로는 파이프라인에서 빠졌고, 씬당 **텍스트→영상 클립 1개**(Gemini Omni Flash)를 만든다.
> 토픽 하나가 **ko·ja·en 세 대본**을 갖고 **클립 풀 하나**를 공유해 쇼츠 3편이 된다. 화면 텍스트는
> **영어(ASCII)만**이다. MJ 이미지 어댑터는 휴면 코드로 남아 있을 뿐 어느 단계도 부르지 않는다.

  그 자리에 돌아온다
- ~~`[8. overlay]`~~·~~`[11. report]`~~ — **삭제 (ADR-0054).** 후처리 합성은 자막 번인(`[9]`)만
  남는다. 실행 집계는 `state.json`과 단계별 기록 파일이 이미 한다. **비었던 `[8]` 번호는
  ADR-0055의 엔딩 실사가 받았다**
- **영상 라인** (ADR-0059): 2부는 라인 셋을 갖고 1부는 하나다. 라인 = `[7]`의 어댑터 + 그
  라인의 값 몇 개(초 범위·2샷 여부)이고, 씬 계약·클립 계약·검수·3개 국어 공유는 라인과 무관하다.
  목록·기본값·어댑터 표는 `vocab.json` `video_line`이 정본이다 — 로컬 GPU(ComfyUI + H3, 변동비 0,
  **초기 기본**), 유료 API(Omni, 전환 조건 충족 뒤), 그림 우선(MJ, ADR-0060 전까지 미구현 — `[7]`이
  멈추고 조용히 다른 라인으로 내려가지 않는다). 2샷을 만들지 않는 라인에서는 `[3s]`가 `shot2`를 뗀다
- `{lang}` ∈ `ko` · `ja` · `en` (ADR-0056). **ko는 필수이고 ja·en은 선택이다** — 대본 파일이
  없는 언어는 그 언어의 단계만 빠지고 나머지는 돈다 (D-3). 씬 계약은 언어와 무관하게 하나다

## 단계 간 계약 파일 (runs/{run_id}/)

토픽 패키지(`topics/{slug}/`)는 사람이 읽는 산출물이고, 단계 간 기계 계약은 run 디렉터리에 둔다 (ADR-0011).

| 파일 | 생산자 | 용도 |
|---|---|---|
| `topic.json` | [0a] | 소재명·슬러그·백로그 관측 지표. 하류 단계의 입력 |
| `state.json` | 전 단계 | 단계 상태(pending/running/done/failed/blocked). 재시작 시 완료 단계 스킵 판단 |
| `logs/*.json` | LLM 어댑터 | 헤드리스 세션 응답 원본 |

### 2부 계약 파일 — 값 하나의 출처는 하나다 (ADR-0020)

| 파일 | 생산자 | 역할 | 읽는 단계 |
|---|---|---|---|
| `scenes.timed.{lang}.json` | [3] | **그 언어의 씬 시각의 유일한 출처.** `script[.{lang}].md` 줄 그대로의 `text` + 실측 시각(`start`/`end`)에 **선택 필드 `title`**(그 언어 대본의 `# 제목` — ADR-0065)만 담는다 — 대본 속성(연출·그림 필드)은 `[3s]`의 `scenes.json` 소관이다. `[7]`·`[9]`는 두 파일을 메모리에서 병합해 읽는다 (ADR-0052 — 파일로 남기지 않는다, 겹치면 실측이 이긴다). **세 파일의 씬 수는 같다** — `[2l]`의 줄 1:1 정렬이 그것을 보장하고 `[3]`이 대조한다 | [7] 클립 길이(세 언어의 최장), [9] 그 언어의 자막·트림, [3s] 줄 경계(ko만) |
| `scenes.json` | [3s] | **씬 계약** (위 「핵심 계약」 절). 씬 계약을 읽는 단계는 전부 이 파일을 연다. 세션 산출(씬 연출표)의 계약은 `specs/schema/sceneplan.schema.json`, 병합본의 계약은 `scene.schema.json`이다. **언어와 무관하게 하나다** — 연출·무대·라벨은 세 쇼츠가 같다 | [4]·[5]·[7] 씬 계약 소비자, [9] 전환 |
| `refs.json` | [4] | **씬별 실사 참조.** `description`(사진에서 읽어 낸 형태·재질·배치)과 내려받은 파일 목록. 씬이 비어 있어도 된다 — 도해 씬에는 참조가 없다 (ADR-0030) | [5] `description`을 프롬프트에 싣는다, [8] 엔딩 후보 |
| `prompts.json` | [5] | **씬별 영상 지시.** 시간 정보를 담지 않는다 — 길이는 `[7]`이 실측에서 정한다. 골격(FORMAT·STYLE·STAGING·SUBJECT·CAMERA·RED·NEGATIVE)은 스펙 03 | [7] `prompt`·`negative_prompt` |
| `timing.{lang}.json` | [3] | **[3]의 실행 기록.** 엔진 메타·목소리 id·배속·원속 길이·오디오 길이·경고. 계약이 아니라 기록이라 길이 초과로 멈출 때도 남는다 | 사람 |
| `clips.json` | [7] | **[7]의 실행 기록.** 씬별 프로바이더·요청 길이·지연·재시도·강등(`demoted_from`)·인접 재사용. 계약이 아니라 기록이다 | 사람 |
| `clip_review.json` | [7] | **[7] 검수의 실행 기록.** 씬별 OCR 대조 결과·비전 판정·기각 사유·재생성 여부. 계약이 아니라 기록이다 (ADR-0056 결정 6). 판정에 쓴 실물(프로바이더 원본 mp4·정규화 후보·프레임 PNG)은 `clip_review/` 아래에 남는다 — `clips/`에는 채택된 클립만 있다 | 사람 |
| `ending.json` | [8] | **엔딩 실사 컷 계약** (ADR-0055, 정본 `specs/schema/ending.schema.json`). 화면에 나가는 순서대로의 클립 목록 + 라이선스·크레딧. `rejected`는 같은 파일에 실린 **기록**이다 — 재고로 엔딩이 안 서는지 보는 자리다. **파일이 없으면 엔딩이 없는 것이고 그것은 정상이다** (D-3) | [9] 마지막 씬 뒤에 잇는다 |
| `ending/credits.txt` | [8] | 업로드 설명란에 붙일 **사람용** 출처 목록. 화면 크레딧이 강등돼도 이 파일은 남는다 | 사람 |
| `subtitles.{lang}.ass` | [9] | 그 언어의 자막 파일. `ass` 필터의 입력이라 파일로 존재해야 한다 | [9] 번인 |

- 씬의 시각을 읽는 곳은 `scenes.timed.{lang}.json` **하나뿐이다** (언어당 하나). 같은 숫자를 두 파일이 들고 있으면 갈라지고, 갈라진 쪽을 읽은 단계만 싱크가 어긋난다
- `prompts.json`의 `beat`·`subject_scale`·`camera`·`staging`은 씬 계약에서 복사해 온 값이다. **고치는 곳은 씬 계약 하나다**
- `prompts.json`의 `framing_source`는 그 씬의 구도가 **계약에서 왔는지 기본값으로 떨어졌는지**만 밝힌다 (`scene` | `beat_default`)
- `prompts.json`의 `subject`는 한국어 그대로 프롬프트에 들어간다. 번역하지 않고(ADR-0001·0014), 대신 그 한국어를 화면에 글자로 그리지 말라고 명시한다 (ADR-0002). `subject_anchor`도 같은 자리에 원어 그대로 들어가며(ADR-0042), `prompts.json`에 별도 필드로 남지 않는다 — 프롬프트 문자열 안에 있다. 고치는 곳은 여기서도 씬 계약 하나다. **화면에 그려도 되는 문자열은 `info.labels`뿐이고 그것은 ASCII다** (ADR-0056 결정 3)
- `prompts.json`은 방언을 담지 않는다 — 프로바이더가 하나다 (ADR-0027의 방언 분기는 ADR-0056이 접었다)
- 씬당 클립은 1개 = 호출 1회다. 전 씬이 같은 골격이고 화면 그래픽은 `info`가 있는 씬의 RED 절 하나다

- 소스 카드(`knowledge/`)는 run·토픽에 종속되지 않는 **누적 자산**이라 run 디렉터리에 두지 않는다 (ADR-0012)
- `slug`: 음운 변화 미적용 로마자 표기, `[a-z0-9-]` 최대 60자 (ADR-0011)
- `run_id`: `YYYYMMDD-{slug}`
- 헤드리스 세션에는 읽기 도구만 준다. 산출물 파일은 오케스트레이터가 쓴다 (ADR-0011)

### 1부 ↔ 2부 경계 (ADR-0017 — ADR-0049 개정)

두 부는 아래 **두 파일로만** 만난다. 2부는 그 밖의 1부 산출물에 의존하지 않는다.

| 파일 | 역할 |
|---|---|
| `topics/{slug}/script.md` | 한국어 대본(정본). 1부의 최종 산출물이자 2부의 **읽기 전용** 입력. 사람이 읽는 마크다운이다 (ADR-0049 — JSON 대사 폐기) |
| `topics/{slug}/script.ja.md` · `script.en.md` | 번안 대본 (ADR-0056 결정 5). `script.md`와 **줄 1:1**. 없으면 그 언어의 쇼츠가 없을 뿐이다 (D-3) |
| `topics/{slug}/judgment/human.json` | 게이트. `decision: go`일 때만 2부 진입 (스펙 07 스키마). ko 하나로 셋을 판정한다 |

- **씬 계약(JSON)은 1부 산출물이 아니다** — 2부 내부 계약이고, `[3s. scenetable]`이 TTS
  실측 뒤에 만든다 (ADR-0049 §5). 기계 계약은 여전히 JSON이다 — 마크다운이 되는 것은
  사람이 검사하는 대본뿐이다
- `factcheck.md`는 1부 내부 파일이다. 2부는 읽지 않는다 — 단 `[3s]`가 인포 라벨 수치의
  근거를 확인할 때와 `[5]` 세션이 형태·치수·연도의 근거로 쓸 때만 예외로 읽는다 (검증된
  수치만 화면에 나간다 — ADR-0007·0056·0060)
- **2부는 대본 파일을 수정하지 않는다.** 모든 2부 산출물은 `runs/{run_id}/` 아래에 쓴다
  (`narration.{lang}.wav`, `timing.{lang}.json`, `scenes.timed.{lang}.json`, `scenes.json`,
  `refs/`, `refs.json`, `prompts.json`, `clips/`, `clips.json`, `clip_review.json`, `ending/`,
  `ending.json`, `subtitles.{lang}.ass`, `timeline.{lang}.mp4`, `final.{lang}.mp4`).
  `runs/*`는 `.gitignore` 대상이라 미디어가 커밋되지 않는다
- 계보는 `run_id`로 잇는다. 2부 산출물은 대본과 같은 `run_id`의 run 디렉터리에 놓인다
- 옛 파이프라인 경로는 코드·산출물째 폐기됐다 (ADR-0052) — 씬 계약의 소재지는
  `runs/{run_id}/scenes.json` 하나이고 갈림길이 없다

## 단계별 규칙

> 단계마다 `###` 헤딩이 붙어 있다. **자기 단계만 떠서 읽어라** — 이 절 전체는 8,700토큰이고
> `[7]` 하나는 1,900이다. 예: `sed -n '/^### \[7\./,/^### /p' specs/05-pipeline.md`

### [0. seed]

기계 단계 (LLM 0회). 백로그 항목(소재 + 시드 기사 URL)을 골라 슬러그·`topics/{slug}/`·`runs/{run_id}/`를 만든다. **반려하지 않는다** — 매체 적합성 판정은 `[1. draft]`가 한다 (ADR-0049).

### [0f. seedfetch] (ADR-0061)

기계 단계 (LLM 0회). 시드 URL을 **설치된 헤드리스 브라우저**(Chrome, 없으면 Edge)로 렌더해 `<script>`·`<style>`을 버리고 태그를 벗긴 텍스트를 `topics/{slug}/seed-body.md`에 쓴다 — 나무위키 같은 클라이언트 렌더 SPA는 WebFetch로 본문이 오지 않기 때문이다(실측: `/w/석빙고`는 내비게이션만, `/raw/`는 `Loading...`). **본문 추출을 하지 않는다** — 사이트별 셀렉터는 사이트마다 깨지므로 내비게이션째로 넘기고, 본문을 고르는 일은 글을 읽는 `[1]`이 한다. 헤더에 URL·수집 시각·글자 수를 적는다. **실패는 이 단계 안에서 끝난다** (D-5) — 브라우저가 없거나 렌더가 막히면 경고만 남기고 `seed-body.md`를 쓰지 않는다. `seed-body.md`는 **사람이 직접 써도 되는 파일이다** — 헤드리스가 막히는 사이트는 사람이 본문을 붙여넣으면 같은 경로로 흘러간다. **렌더는 시드를 확보하는 수단일 뿐 소스의 지위를 바꾸지 않는다** — 이 파일이 나무위키 본문이어도 `[2]`의 근거로는 못 쓴다 (스펙 06 소스 지위 표).

### [1. draft]

헤드리스 1회. 시드 기사(위키백과·나무위키 등)를 읽고 **통짜 내레이션**을 쓴다 → `topics/{slug}/script.md`. 정본 포맷과 서사 원칙은 스펙 01이 정의한다 — 핵심 질문·핵심 메커니즘·보이는 흐름·차별점을 먼저 정하고, 앞 1/3까지 문제·모순을 키우고, 문장마다 원인·작용·결과가 하나씩 전진한다 (ADR-0049 §3). **시드 본문의 입력 사다리는 `seed-body.md` → WebFetch → WebSearch다** (ADR-0061) — `[0f]`가 남긴 파일이 있으면 그것이 1차 입력이고, 없거나 그 안에서 본문을 못 찾으면 지금처럼 도구로 내려간다. 파일의 부재는 경고가 아니다 (D-3). 쓰기 전에 매체 적합성(그림이 이해를 보조할 수 있는가 — ADR-0047 게이트)을 판정하고, 부적합이면 대본 대신 반려 사유를 내고 멈춘다. **산출 직후 오케스트레이터가 기계 검사한다** (LLM 0회): 분량 엔벨로프·줄 규격(`script-rules.json` limits). 실패는 보고·중단이다 — 재생성 루프는 없다 (ADR-0044 원칙 유지).

### [2. factcheck]

헤드리스 1회. `script.md`가 **실제로 쓴 주장만** 검증한다 — 시드 기사 대조 + 필요시 웹 교차 확인 (스펙 06). 틀린 숫자·사실은 해당 줄을 정정해 `script.md`를 갱신하고, 통념↔사실이 어긋나면 그것을 반전 소재로 명기한다 — 어느 쪽이든 산출물이다 (ADR-0049 §1). 판정·근거 URL·정정 내역 → `factcheck.md`. **화면에 나갈 수 있는 수치(인포씬 라벨 후보)는 근거 URL 필수다** (ADR-0007·0043). 대본에 없는 주제는 검증 대상이 아니다 — 전수 조사로 돌아가지 않는다.

### [2l. localize] (ADR-0056 결정 5)

헤드리스 1회, 두 언어를 한 세션에. 입력은 `[2]`가 끝난 `script.md`와 `factcheck.md`(수치·고유명사의 표기 근거). 산출은 `topics/{slug}/script.ja.md`·`script.en.md` — 포맷은 스펙 01과 같고 **줄 수·순서가 `script.md`와 1:1**이다 (줄 = 자막 줄 = 씬, ADR-0013 — 클립 풀을 공유하는 조건). 문장은 직역이 아니라 그 언어 청자에게 자연스러운 번안이되 **줄 하나의 내용은 그 줄 안에서 끝난다** — 앞뒤 줄로 내용을 옮기면 화면(클립)과 말이 어긋난다. 숫자·단위·고유명사는 `factcheck.md`의 값을 그대로 쓴다 — 번안이 사실을 바꾸지 않는다. **산출 직후 오케스트레이터가 기계 검사한다** (LLM 0회): 줄 수 일치, 빈 줄 없음, `script-rules.json`의 `locales.{lang}.limits`가 있으면 그 엔벨로프(글자 수·줄 글자 수), 없으면 분량 검사 없이 경고만 남긴다. **초 단위 상한은 `[2l]`이 보지 않는다** — 언어별 추정 속도가 계약에 없고 ko 검사도 초를 추정하지 않으므로, 상한은 `[3] tts`가 실측으로 본다 (언어별 `total_seconds` 상한 초과 시 그 언어만 멈춘다). 하한은 어디서도 두지 않는다 (en은 ko의 ×0.78이라 하한을 깨는데 짧은 쇼츠는 손해가 아니다, ADR-0056 맥락 4). ja의 초 상한은 임시 로케일 블록이다 (ADR-0057 결정 2). 실패는 보고·중단이다. 대본 파일이 이미 있으면 다시 만들지 않는다 — 사람이 고쳤을 수 있다. 한 언어만 다시 만들려면 그 파일을 지우고 돌린다.

### [3. tts+sync]

**2부의 실행 첫 단계다** — 길이 초과 중단이 영상 지출보다 앞서야 하고, `[7]`의 클립 길이가 **세 언어의** 실측 길이를 요구한다. **언어당 1회 돈다** — `script.md`(ko, 필수)와 `script.{ja,en}.md`(있는 것만, D-3). 목소리는 언어별 환경변수(`ELEVEN_VOICE_ID` / `ELEVEN_VOICE_ID_JA` / `ELEVEN_VOICE_ID_EN`, ADR-0056 결정 7)이고 **대본 파일이 있는데 그 언어의 id가 비어 있으면 진입 전에 멈춘다** — 비싼 호출 전의 설정 오류다 (D-5의 "돈이 나가는" 경우). 대본 전체 단일 호출 + with-timestamps (모델은 `eleven_multilingual_v2` — 세 언어 공통, ADR-0004). **보내는 것은 대본 줄이 아니라 발화형이다** (ADR-0063) — 숫자·단위를 그 언어가 읽는 대로 편 텍스트이고(`specs/schema/speech-rules.json`이 정본), 사전에 없거나 문맥이 갈리는 토큰은 그대로 보내고 경고만 남긴다. 정렬 대조·경계 추출은 **보낸 텍스트** 위에서 돌고, `scenes.timed.{lang}.json`의 `text`는 **원문 그대로**다 — 두 텍스트가 갈리는 자리는 이 단계 안뿐이다 (자막·라벨 에코는 바뀌지 않는다). 문자 정렬에서 자막 줄 경계 start/end 추출해 `runs/{run_id}/scenes.timed.{lang}.json`을 **새로 쓴다**(ADR-0017. 대본 파일은 건드리지 않는다) — 문장 경계를 뽑은 뒤 각 줄의 마지막 문장 끝만 취한다 (ADR-0013). **ja·en의 씬 수가 ko와 다르면 멈춘다** — `[2l]`의 줄 정렬이 깨진 것이다. 실측-추정 오차 씬당 ±1.5초 초과 시 경고. 총 길이가 `total_seconds` 상한(102초)을 넘으면 **그 언어의 대본 축약이 필요하다고 리포트하고 멈춘다** — 2부가 1부를 직접 다시 돌리지 않는다 (ADR-0017의 단방향 경계). atempo는 스펙 04의 상한(1.2) 안에서 언어별로 건다 — ja는 ko의 ×1.13이라 대개 tempo로 흡수된다. 타임스탬프도 같은 배율로 보정. **그 언어 대본의 `# 제목`도 같이 싣는다** (선택 필드 `title`, ADR-0065) — `[9]`가 첫 씬 구간 동안 화면 상단에 굽는다. 제목이 없는 대본이면 필드를 쓰지 않고 그 언어 영상에 제목 훅이 안 붙는다 (D-3).

### [3s. scenetable] (ADR-0049 §5)

`scenes.timed.ko.json`의 실측 줄 경계 위에서 씬 계약 `scenes.json`을 만든다 — **한국어 실측 하나 위에서 1회**이고 연출은 언어와 무관하다 (ADR-0056). **헤드리스 1회.** 세션에는 도구를 주지 않는다 — 입력(대본 `script.md` 전문·실측 씬 목록·`factcheck.md`)을 전부 프롬프트에 주입하고, 산출물 파일은 오케스트레이터가 쓴다 (ADR-0011). **세션은 씬을 만들거나 합칠 수 없다** — 씬 경계는 `[3]`의 실측이다 (ADR-0013). 세션이 씬을 빠뜨리면 오류이고, 실측에 없는 씬을 지어내면 버리고 경고한다. 세션 산출(씬 연출표)의 계약은 `specs/schema/sceneplan.schema.json`이다 — 필드 정의는 `scene.schema.json`을 `$ref`하고, 어느 필드가 `scenes.json`으로 건너가는지는 두 스키마의 교집합(`sceneplan.carried_fields()`)이 계산한다 (ADR-0034). 씬마다 그림 필드(`visual_goal`·`subject`·`subject_anchor`·`subject_scale`)와 연출 필드(`framing`·`transition`·`camera`·**`staging`**·선택 **`shot2`**)를 적되 **자유 기술이 아니라 `specs/schema/vocab.json` 어휘에서 고른다** (ADR-0033 §3). `shot2`(`{framing, camera}`, ADR-0058)는 같은 피사체를 다른 구도로 한 번 더 보이는 씬 안 두 번째 샷이다 — `visual_goal`이 두 크기에서 설명될 때 고르고, 기본값은 없다. 컷 시각·자격은 `[7]`이 정하므로 여기서는 언어별 길이를 보지 않는다. **사람이 고른 영상 라인이 2샷을 만들지 않으면**(`vocab.json` `meta.video_line.{line}.shot2: false` — 로컬 H3는 컷 시각 ±0.5초라 끈다, ADR-0059 결정 5) 병합 때 `shot2`를 떼고 경고한다 — 씬은 1샷으로 돈다. 라인은 `judgment/human.json`의 `video_line`에서 읽고, 값이 어휘 밖이면 멈춘다. `staging`은 **`studio`**(중성 회색 바닥 위 기술 모델 — 구조·물건·메커니즘·수치를 보이는 씬)와 **`location`**(실제 환경 — 사건·서사·분위기 씬) 둘이고, 비우면 기본값(`beat-defaults.json`)이다. 앵커 고유명사는 소재의 1차 자료 언어로 적는다 (ADR-0042). 표기의 출처는 시드 기사·`factcheck.md`다. **인포(화면 계측 표시)도 여기서 정한다** (ADR-0056 결정 3) — `info.labels`는 **ASCII만**(숫자·SI 단위·3단어 이하 영어)이고 수치는 `factcheck.md`가 검증한 것만 쓴다 (ADR-0007 — **이것이 2부가 `factcheck.md`를 여는 유일한 예외다**, 경계 절). `info.target`에 **무엇을 재는지**를 서술하고(내용이지 연출이 아니다 — "the diameter of the hole"), `info.annotation`은 어휘(`dimension`·`arrow`·`leader`)에서 고른다. **라벨의 숫자는 그 줄이 말하는 숫자다** (`label_numbers_from_line`, ADR-0060 결정 4 — 듣는 숫자와 보는 숫자가 어긋나면 설명이 죽는다. 표기 차이 허용, 숫자 없는 라벨은 자유). 대본은 고칠 수 없으므로 조절하는 쪽은 라벨이다. `factcheck.md`가 없으면 인포 없이 돈다 (D-3). **인물은 서술로만 판정한다** (ADR-0051의 서술 경로) — 같은 인물이 2씬 이상 반복되면 최상위 `characters` 블록(외형 서술)과 씬별 `cast`를 적고, `[5]`가 그 서술을 `cast` 씬 프롬프트에 싣는다. 참조 이미지 경로는 없다 — Omni에 참조 입력이 없다 (ADR-0056 되돌릴 조건 6). **산출 직후 기계 검사한다** (LLM 0회): 연출표 스키마 → 실측 줄과의 병합 → 병합본의 씬 계약 검증 (`scene.schema.json` + `cast`↔`characters` 대조 + `visual_goal` 겹침 + 라벨 에코 + 라벨 ASCII — 임계값은 전부 `script-rules.json`에서 로드한다). 실패는 보고·중단이고 `scenes.json`을 **쓰지 않는다** — 깨진 계약 파일이 남으면 하류가 파일이 있다는 이유로 진행해 버린다. 재생성 루프는 없다 (ADR-0044). `est_start`/`est_end`에는 ko 실측값을 그대로 옮긴다 — 필드명은 씬 계약 호환이고 **시각의 정본은 여전히 `scenes.timed.{lang}.json`이다** (ADR-0020). 연출 선택의 분포(`direction_summary`)와 빈 `framing`·`transition`·`staging` 씬 수를 실행 기록에 남긴다 — ADR-0033 되돌릴 조건의 관측 수단이다.

### [4. refpack] (계약: `specs/schema/refs.schema.json`)

씬 계약의 `subject`·`subject_anchor`로 검색어를 만들어 씬별 실사 참조를 모은다 (ADR-0030). 산출은 둘이다 — **`description`**(사진에서 읽어 낸 형태·재질·색·배치를 한국어 구절로)과 **내려받은 파일 목록**. 도해 씬이나 실물이 없는 개념 씬은 **비운다**. 부재를 경고하지 않는다 (ADR-0028의 선택 필드와 같은 태도). 소비는 **서술 경로**(`[5]`가 `description`을 프롬프트에 싣는다)와 **엔딩 실사**(`[8]`)다 — 첨부 경로는 영상 프로바이더에 이미지 입력이 없어 없다 (ADR-0056). 강등 사다리는 `서술 → 없음`. 라이선스가 `public-domain`·`cc0`·`cc-by` 계열인 사진만 `attachable: true`로 표시한다 — 지금은 `[8]`의 게시 가능 판정이 그 필드를 읽는다. `source_url`·`license`·`credit`을 전부 기록한다. **참조 사진이 프롬프트 입력으로 화면에 들어가는 일은 없다** — 엔딩 실사(ADR-0055)는 다른 축이다. 이 단계의 세션에는 **웹검색 도구를 준다** (지금까지 읽기 도구만 준 것과 다르다, ADR-0011). 세션은 URL과 서술을 JSON으로 돌려주고 내려받기는 오케스트레이터가 한다.

### [5. prompt] (ADR-0060)

**헤드리스 세션 1회.** 연출은 고르지 않는다 — 씬 계약이 고른 구도·카메라·무대·라벨·인물을 **서술로 구현**한다. 세션 입력은 `script.md` 전문(머리의 핵심 질문·반전·보이는 것), `scenes.json`(씬마다 값 + 그 값의 어휘 문구), `topics/{slug}/factcheck.md`(형태·치수·연도·재질의 근거 — **`[3s]`와 함께 2부가 이 파일을 여는 두 예외**), `refs.json`의 서술(있으면), `characters`. 도구는 주지 않는다 (ADR-0011). 세션은 씬마다 `subject_prompt`(SUBJECT 단락 — 설명의 무대: 무엇이 어떻게 놓였고 무엇이 같고 다른지, 고유명사는 로마자 이름 + 형태·재질·배치, 반복 피사체는 매 씬 전체 서술 반복)·`camera_target`(워크가 닿는 곳)·`red_prompt`(info 씬 — 보조선 기하 + 라벨 따옴표째)를 **영어**로 쓴다 (`prompts/05-prompt.md`, 원카랩 참조 프롬프트가 밀도의 기준). 산출 계약은 `specs/schema/promptplan.schema.json` — **산출 직후 기계 검사한다** (LLM 0회): 영어·ASCII·길이(스키마) → 씬 id 일치·info↔`red_prompt`·라벨 포함·`shot2`↔`subject_prompt_shot2`·`camera_target`의 워크 단어 금지(`vocab.json` `camera._target_forbidden_words`). 실패는 보고·중단이고 `prompts.json`을 **쓰지 않는다**(지난 것이 있으면 지운다) — 재생성 루프는 없다 (ADR-0044). 통과하면 코드가 골격(스펙 03 「프롬프트 골격」)에 얹는다: `FORMAT`(어휘) · `STAGING`(씬 `staging` → 어휘 문구) · `SUBJECT`(세션 단락) · `CAMERA`(씬 `camera` → 어휘 문구 + 세션 착지) · `RED`(세션 기하 + 어휘 `_closing`) · `NEGATIVE`(어휘 + info 없는 씬은 글자 금지). **골격 문구는 전부 `vocab.json`에서 온다** — 코드가 영어 문장을 들고 있지 않다 (ADR-0034). **길이도 컷 시각도 쓰지 않는다** — `{seconds}`·`{cut}`은 `[7]`이 실측에서 채운다. 2샷 씬의 `prompt_shot2`(ADR-0058)는 `subject_prompt_shot2`를 같은 골격에 얹는 것이고 2샷 코드와 함께 들어온다. 구도·무대가 비어 기본값으로 떨어진 씬 수·앵커 씬 수·`info` 씬 수·참조 서술 씬 수를 요약에 낸다 — ADR-0033·0056의 되돌릴 조건을 관측하는 자리다. 출력은 `prompts.json` 하나이고 출력 계약은 ADR-0056의 것 그대로다 — `[7]`은 이 단계의 내부를 모른다. **씬마다 세션 단락 3개(`subject_prompt`·`camera_target`·`red_prompt`)를 조립한 `prompt` 옆에 그대로 싣는다** (ADR-0067) — `[7]`의 고쳐쓰기 재생성이 **부분만 고쳐 같은 골격에 다시 얹으려면** 부분이 남아 있어야 한다. 싣는 것이지 판단하는 것이 아니다.

### [6] — 비어 있다 (ADR-0056)

~~**[6. imagegen]**~~ · ~~**[6r. imagereview]**~~ · ~~**[6i. info]**~~ — **삭제 (ADR-0056).** 이미지 단계·MJ 프록시·NB2 편집·사분면 선택·INFO 이미지·`image_source.json`·`character_source.json` 전부 없다. 이 절의 실측(콜드스타트, 계정 단위 timeout, 잡 취소, `--oref` 문법)은 ADR-0025·0031·0035·0039·0045·0051에 남아 있고, MJ 이미지 어댑터는 휴면 코드다. 정지 이미지 쇼츠가 결정되면 `[6]` 번호로 돌아온다 (ADR-0056 되돌릴 조건 6).

### [7. videogen] (ADR-0056·0059)

**씬당 텍스트→영상 클립 1개**를 만든다 — 참조 프레임 없음, 9:16. **어댑터는 사람이 `judgment/human.json` `video_line`에 고른 영상 라인이 정한다** (ADR-0059 결정 2): 라인→어댑터 표는 `vocab.json` `meta.video_line.{line}.provider`이고, `--provider`를 주면 그것이 이긴다(디버깅·페이크). 어댑터가 없는 라인(`provider: null`)이면 **멈춘다** — 조용히 다른 라인으로 내려가지 않는다. 로컬 라인은 ComfyUI + MiniMax H3(같은 PC, `COMFY_URL`, 워크플로 템플릿 `config/comfy/h3-t2v.api.json`에 프롬프트·해상도·시드·길이·접두만 꽂는다, 동시 1), 유료 API 라인은 Gemini Omni Flash(`gemini-omni-flash-preview`, Google Gemini API 직접, 720p). **클립 길이 = 세 언어(`scenes.timed.{lang}.json`, 있는 것만) 중 그 씬의 최장 길이 + 0.6초(디졸브 꼬리, ADR-0024)를 정수 초로 올림, 어댑터의 초 범위로 클램프**(어댑터가 `min_seconds`·`max_seconds`로 말한다 — Omni 3~10, H3 4~10). 4/6/8 양자화가 없으므로 8초 고정보다 싸다. 10초를 넘는 씬은 10초로 만들고 `[9]`가 마지막 프레임을 정지로 늘린다 — `script-rules.json`의 줄 길이 상한(6.9초) × ja 비율(1.13) + 0.6이 10초 안이라 정상 편에선 일어나지 않고, 일어나면 경고한다. **클립의 로컬 0초가 씬의 `start`이고 꼬리는 전부 뒤다** (ADR-0024) — 언어마다 트림 지점이 다를 뿐 시작은 같다. `prompts.json`의 `prompt`에 FORMAT 초 수를 채워 보낸다. **2샷 씬**(`shot2`, ADR-0058 결정 3·4): `cut = 가장 짧은 언어의 씬 길이 × cut_ratio`(소수 첫째 자리)이고, 가장 짧은 언어의 씬 길이가 `2 × min_shot_seconds` 미만이면 **1샷 `prompt`로 산다** — `clips.json`에 `shot2_dropped: "too_short"`와 언어별 길이를 남긴다. 자격이 되면 `prompt_shot2`에 `{seconds}`·`{cut}`을 채워 보낸다. 두 값은 `beat-defaults.json` `multishot`에서 로드한다. 컷이 가장 짧은 언어 길이의 절반에 있으므로 모든 언어가 샷 1 전체와 샷 2의 절반 이상을 본다 — 언어별 트림과 충돌하지 않는다. 생성 뒤 **지정 `cut` 전후 0.2초 프레임의 차이로 컷 유무를 본다** (scene 문턱 감지가 아니다 — 프로브에서 컷 전후가 비슷한 클립은 문턱 0.25에 안 잡혔다). 컷이 없으면 **경고**이고 실패가 아니다 (`shot2_missing: true`) — 클립은 1샷으로 쓴다. 요약에 **씬 안 컷 수**를 낸다 (스펙 03 「전환」의 지표). 어댑터가 내는 오디오는 버리고(소리는 `[10]` 소관) 해상도·fps·길이는 `[7]`의 정규화가 1080×1920·30fps·정확한 길이로 맞춘다 — 로컬 라인의 0.4MP(480×864)도 여기서 2.2배 업스케일된다 (ADR-0059 결정 7 — 게시 해상도는 첫 실편을 폰에서 본 뒤 사람이 정한다). **씬을 동시에 제출한다** (ADR-0031 §4의 태도) — 워커 수 기본은 어댑터가 말하고(429가 나오면 1로 줄이고 백오프), `--jobs`가 이긴다. **검수를 포함한다** (ADR-0056 결정 6): ① **끝 프레임 OCR** — `info`가 있는 씬은 라벨 문자열이 ASCII이므로 기계가 대조한다(구현체는 코드가 고른다 — 스펙은 "라벨이 전부 읽히고 계약에 없는 숫자가 없다"는 규칙만 둔다). `info`가 없는 씬은 **글자가 없어야** 통과다 (1글자 토큰은 텍스처 노이즈로 보고 무시한다 — 실측에서 tesseract가 재질 무늬를 글자로 읽었다). OCR 구현체(tesseract)가 없으면 이 게이트만 경고와 함께 건너뛰고 비전 검수는 돈다 (D-3). ② **비전 세션 씬당 1회** — 세션 자체가 두 번 실패하면 클립을 경고와 함께 채택한다(`verdict: error`) — 검수기 고장으로 돈을 더 쓰지 않는다. 시작·중간·끝 프레임 3장(2샷 씬은 **컷 직전·직후 2장을 더해 5장**, ADR-0058 결정 4)을 보고 `[6r]`의 기준 셋(`subject`·`subject_anchor`의 대상이 맞는가 / `visual_goal`을 지는가 / 기형·워터마크 없음)에 **`info.target`을 치수선이 실제로 가리키는가**, 2샷 씬은 **컷 전후가 같은 피사체·같은 무대인가**를 더해 판정한다. 2샷 씬의 재생성 1회도 `prompt_shot2`다 — 1샷으로 강등하는 칸은 두지 않는다 (사다리가 길수록 돈이 든다). 24장을 한 세션에 넣어 5회 타임아웃한 `[6r]`의 교훈으로 **씬당 1세션, 동시 실행**이다. 스타일은 판정하지 않는다 (ADR-0033 §3). **실패 사다리**: 재생성 1회(**검수 사유를 반영해 고쳐 쓴 단락**, 새 시드 — ADR-0067) → `info` 씬이면 **RED 절을 뺀 프롬프트로 재생성**(`demoted_from: info` — 틀린 숫자보다 없는 숫자가 낫다; 내레이션·자막이 숫자를 진다) → 그래도 실패거나 일반 씬이면 **인접 씬 클립 재사용**(`demoted_from: video`, 가까운 앞 씬 우선). **강등을 조용히 하지 않는다** — `clips.json`에 씬마다 `demoted_from`, `clip_review.json`에 판정 사유. **재생성 전에 고쳐쓰기 세션을 1회 부른다** (ADR-0067, `prompts/17-clipfix.md`, 헤드리스·도구 없음): 입력은 씬 계약의 그림 필드 + `prompts.json`이 실어 둔 단락 3개(`subject_prompt`·`camera_target`·`red_prompt`) + **직전 시도의 검수 기각 사유**이고, 산출은 같은 이름의 단락 3개다. 코드가 `build_video_prompt`로 골격에 다시 얹는다 — **세션은 연출을 바꾸지 못한다**(`framing`·`camera`·`staging`은 씬 계약의 것, ADR-0033 §3). 고친 단락은 `promptplan`의 씬 단위 규칙으로 다시 재고, **어기거나 세션이 실패하면 직전 단락으로 되돌리고 경고한다** — 고쳐쓰기가 사다리를 막지 않는다 (D-5). `info` 씬의 RED 뺀 변종도 **고친 단락 위에서** 만든다. 시도마다 `clip_review.json`에 `revision`(바뀐 필드와 근거가 된 기각 사유)을 남긴다. 편당 영상 씬 상한은 없다. 실패 정책은 D-5 — 프로바이더 전체가 거절하면(키·플랜) 남은 씬을 시도하지 않고 멈춘다 (돈이 나가는 경우). 재실행 시 `clips.json`에 `done`인 씬은 다시 사지 않는다 — 갱신은 씬 하나가 끝날 때마다 직렬로 쓴다 (ADR-0020의 목적).

### [8. ending] (ADR-0055, 계약: `specs/schema/ending.schema.json`)

**엔딩 실사 컷.** AI 그림으로 설명을 끌고 온 편을 "그리고 이것이 실제 모습"으로 닫는다. **새로 수집하지 않는다** — `[4] refpack`이 출처 페이지에서 라이선스를 확인하고 내려받아 둔 사진(`refs.json`의 `file`)이 입력이고, ADR-0046이 첨부 경로를 보류한 뒤로 그 파일들의 소비자가 0이었다. 세 칸으로 돈다. **① 기계가 거른다** — 라이선스가 계약 `meta.publishable_licenses`에 있고, `meta.credit_required_licenses`인 경우 `credit`이 채워져 있는 것만. 표시 의무를 못 지킬 사진은 판정에 올리지 않는다 (판단이 아니라 대조다 — `refs.json`의 `attachable`과 같은 태도). 같은 `source_url`은 한 번만 본다. **② 비전 세션 1회가 판정한다** (`Read` + `add_dirs`, `[6r]`과 같은 메커니즘): 실사 사진인가 / 소재 실물이 식별되게 나오는가 / **식별 가능한 인물이 있으면 기각** / 워터마크·큰 글자가 없는가 / 화면을 채울 화질인가. 통과분에 표시 순서를 매긴다. **인물 기각은 라이선스와 다른 축이다** — 사진이 자유 라이선스여도 찍힌 사람의 초상권은 남는다. **③ 렌더** — `meta.max_photos`장까지, 장당 `meta.photo_seconds`초. **무수정 표시다**: 크롭도 카메라 워크도 없고 원비율을 유지한 채 남는 자리를 단색으로 채운다 (SA가 영상 전체로 번지지 않는 근거가 "개작하지 않았다"에 서 있다 — 스펙 03 「엔딩 실사」). 크레딧은 화면 하단에 굽고 `ending/credits.txt`에도 남긴다 — **강등 사다리는 `굽기+기록 → 기록`이고**, 폰트 자산이 없으면 굽기만 내려가고 기록은 그대로다. **후보가 0장이거나 전부 기각이면 `ending.json`을 쓰지 않는다** — 실물이 없는 소재(개념·도해 중심)에 엔딩이 없는 것은 정상이고 부재는 경고가 아니다 (D-3). 그 사실은 `state.json`에 남는다.

### [9. assemble]

**언어당 1회 돈다** — 입력은 같은 `clips/`와 그 언어의 `scenes.timed.{lang}.json`·`narration.{lang}.wav`, 출력은 `subtitles.{lang}.ass`·`timeline.{lang}.mp4`. 씬마다 클립을 **그 언어의 씬 길이 + 0.6초로 트림**한다 — 클립은 세 언어의 최장으로 만들어졌으므로(`[7]`) 트림은 항상 앞에서 자르고 꼬리를 버리는 방향이다. 클립이 씬보다 짧으면(10초 클램프) 마지막 프레임을 정지로 늘리고 경고한다. 자막은 `scenes.timed.{lang}.json` 기준 ASS 생성 후 번인 (ADR-0020 — 씬의 `text`·`start`·`end`를 읽는 곳은 이 파일 하나다). 자막 스타일은 `subtitle-style.json`이고 폰트는 언어별이다 (스펙 04). **`title`이 있으면 첫 씬 구간(`0` ~ 첫 씬의 `end`) 동안 화면 상단에 제목 훅을 같이 굽는다** (ADR-0065) — 자막과 같은 ASS 문서의 다른 스타일이라 필터가 늘지 않는다. **싱크 검증은 자막 큐만 센다** (제목은 `Title` 스타일이라 되읽기에서 빠진다). 제목이 줄 수 안에 안 들어가면 **제목만 빼고 경고**한다 — 제목은 마감이지 본편이 아니다 (D-5). 전환은 씬 계약의 `transition`을 그대로 쓰고, 비어 있을 때만 `specs/schema/beat-defaults.json`의 기본값으로 떨어진다 (ADR-0033 §3). 길이 0.6초는 클립 기하가 정한 고정값이다 (ADR-0024). 싱크 오차 ±200ms 이내 검증. **`ending.json`이 있으면 마지막 씬 뒤에 하드컷으로 엔딩 컷을 잇고, 컷 사이는 디졸브다** (ADR-0055) — 엔딩은 세 언어가 같은 클립을 쓰고 크레딧 번인만 언어 무관(라틴)이다. **자막과 싱크 검증(±200ms)은 씬 구간만 본다** — 엔딩에는 자막 큐가 없고 대조할 실측도 없다. 파일이 없으면 지금과 완전히 같이 돈다 (D-3·D-4).


## 실패 정책

- 단계 실패 = 해당 run 디렉토리에 상태 기록 후 종료. 같은 run_id로 재실행 시 완료된 단계는 스킵.
- 씬 단위 실패는 폴백 처리하고 파이프라인은 계속 진행 (스펙 00 성공 기준 5).
- **재생성 루프는 없다** (ADR-0044). 검증은 산출 직후 그 단계에서 하고(1부는 기계 검사 — ADR-0049), 2부 씬 단위 재청은 실패 씬만 상한 1회(같은 세션 resume)다. 검증 실패는 보고·중단이고 다시 돌릴지는 사람이 정한다.

## 확정된 결정

- 판단 게이트 = **사람이 script.md를 읽고 판정** (ADR-0009). 자율성 사다리(ADR-0010, 스펙 07)는 보류 (ADR-0049). ko의 go가 ja·en의 go다 (ADR-0056)
- LLM 단계 실행 = Claude Code 헤드리스, 구독 플랜 (ADR-0008)
- 대본 = **기사 시드 + 통짜 집필 + 후행 팩트체크** (ADR-0049가 팩트시트 선행 그라운딩을 대체). 화면에 나가는 수치는 검증분만 — ADR-0007의 정신은 그대로다. **토픽당 대본은 ko 정본 + ja·en 줄 1:1 번안** (ADR-0056 결정 5, `[2l]`)
- TTS = ElevenLabs (ADR-0004). 목소리는 **언어별** — ko는 ADR-0004의 목소리, ja·en은 `.env`의 보이스 라이브러리 id (ADR-0056 결정 7)
- 시각 = **씬당 텍스트→영상 클립 1개, Gemini Omni Flash** (ADR-0056). 이미지 단계는 없다. **화면 텍스트는 영어(ASCII)만** — 숫자·SI 단위·짧은 영어 라벨. 한국어·일본어는 자막(합성)으로만 화면에 나간다 (ADR-0002 유지). 렌더 언어는 하나(`style.base_style`), 무대는 `studio`/`location` 둘 (결정 4)
- 멀티샷은 쓰지 않는다 — 컷 위치가 언어별 문장 경계와 맞지 않는다. 클립 길이는 세 언어 중 최장 씬 기준 (ADR-0056 결정 1·2)
- 인포 = `[3s]`가 계약(`info`)에 라벨(ASCII)·대상·표시 방식을 적고, `[7]`이 RED 절로 영상 모델에 시키고 **끝 프레임 OCR + 씬당 비전 검수**로 확인한다 (결정 6). 실패 사다리는 `재생성 → 라벨 없는 재생성 → 인접 씬 재사용`
- 인물 = **서술 경로만** (ADR-0051의 `--oref` 참조 경로는 휴면 어댑터에만 있다). Omni에 참조 입력이 없어 인물 반복 소재의 일관성은 보장하지 않는다 — 그런 소재가 쌓이면 ADR-0056 되돌릴 조건 6
- MJ = **파이프라인 밖.** 이미지 어댑터(`imagegen/`)만 휴면 코드로 남고 구독은 해지 (ADR-0056 결정 1·9). 정지 이미지 쇼츠는 미정이고, 하기로 하면 새 ADR이다
- 이미지 참조 = `[4] refpack`이 실사진과 서술을 모으고, 소비는 **서술 경로**(`[5]` 프롬프트)와 **엔딩 실사**(`[8]`)다 (ADR-0030·0055). 첨부 경로는 프로바이더에 입력이 없어 없다
- **엔딩 = `[8] ending`의 실사 컷** (ADR-0055). 무수정·하드컷 진입·크레딧 표시가 조건이고, **나레이션은 `total_duration`에서 끝나고 엔딩 꼬리는 BGM이 덮는다** (`[10] mix`의 계약). 세 언어가 같은 엔딩 클립을 쓴다
- 대본 구조와 연출 = **소재마다 설계한다.** 도메인 제한 없음, 고정 단 구성 폐기, 연출은 닫힌 어휘에서 `[3s]`가 고른다 (ADR-0033). 프롬프트 문구도 어휘에서 온다 (ADR-0034)
- 계약의 정본 = `specs/schema/`. 코드는 상수를 선언하지 않고 로드한다 (ADR-0034)
- 대본 검증 = **draft 직후 기계 엔벨로프 검사 + factcheck 후행 검증 + localize 직후 줄 정렬 검사. 재생성 루프는 없다** (ADR-0044 원칙 유지, ADR-0049·0056). 2부 실행은 `[3] tts`가 첫 단계다

## 단계 독립 원칙 (ADR-0034 §2)

단계 하나를 버려도 옆이 안 무너져야 파이프라인을 계속 세분화할 수 있다.

- **D-1. 단계는 파일로만 통신한다.** 함수 호출로 잇지 않는다 (ADR-0011)
- **D-2. 단계는 자기가 읽는 필드만 안다.** 모르는 필드는 읽지도 지우지도 않고 통과시킨다
- **D-3. 선택적 입력의 부재는 경고가 아니다.** 없으면 그 기능만 빠지고 단계는 돈다
- **D-4. 단계 추가는 기존 단계를 수정하지 않는다.** 새 단계는 새 파일을 쓰고, 그 파일을
  읽고 싶은 단계만 읽는다
- **D-5. 실패는 단계 안에서 끝난다.** 강등 사다리나 폴백으로 처리하고 파이프라인을 세우지
  않는다. 세우는 경우는 **돈이 나가거나 되돌릴 수 없을 때만이다** (방언 불일치, 정책
  드리프트, 길이 초과)
- **D-6. 단계는 하류의 편의를 위해 자기 산출물을 깎지 않는다** (ADR-0038). 하류가 필요한
  것은 하류가 만든다. 이미지가 자막 자리를 비우는 대신 **자막이 어디서든 읽히게** 하고,
  판정 단계가 대본 문장을 읽는 대신 **그림 목표만** 본다. 깎아 준 자리는 실측에서
  **비워지지도 않았고**(4/4 실패) 비워진 만큼은 그림이 아니라 종이였다

## 비용 기준선 — **라인이 정한다** (ADR-0059가 ADR-0056의 "종량 하나"를 셋으로 갈랐다)

**변동비는 영상 라인의 것이다.** 초기 기본인 로컬 라인(ComfyUI + H3)은 토픽당 ≈0(전기)이고,
유료 API 라인(Omni)은 **토픽당 ≈ $8, 쇼츠 1편당 ≈ $2.7**이다 — 토픽 하나가 쇼츠 3편(ko·ja·en)이
되므로 클립 비용은 3으로 나뉜다. 유료 라인이 인포 소재의 기본이 되는 조건은 돈이다: **직전 달
광고 수익(3채널 합) > 그 달 토픽 수 × $8** (ADR-0059 결정 6). ADR-0025의 "편당 0에 가깝다"와
ADR-0043의 "인포씬만 변동비"는 폐기된 값이다.
