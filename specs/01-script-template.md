# 01. 대본 스토리 템플릿

원본 채널 3편의 SRT 실측에서 역산한 고정 템플릿. 대본 생성 LLM은 이 구조를 벗어날 수 없다.

## 7단 구조

| # | 단계 | 시점(초) | 필수 요소 |
|---|---|---|---|
| 1 | hook | 0~10 | 충격 사실 + "~가 아닙니다" 류 반전 부정문 |
| 2 | context | 10~20 | 구체적 숫자 최소 2개 (인원, 거리, 기간 등) |
| 3 | failed_solution_1 | 20~30 | "가장 쉬운 방법은 ~" 도입 → 실패 이유 |
| 4 | failed_solution_2 | 30~44 | "그럼 ~하면 되지 않냐고요?" 도입 → 실패 이유 |
| 5 | turning_point | 44~54 | **"그래서 발상을 뒤집습니다"** (문구 고정) |
| 6 | solution | 54~85 | 해결책 스텝 바이 스텝, 구체 숫자 포함 |
| 7 | ending | 85~100 | 현재와 연결 + 수미상관 (훅의 소재로 회귀) |

## 시그니처 문구 (고정)

- `failed_solution_2` 말미: **"환장할 노릇이죠."** — 매 편 필수
- `turning_point` 시작: **"그래서 발상을 뒤집습니다."** — 매 편 필수, 44~54초 구간에 위치
- `failed_solution_1` 시작: "가장 쉬운 방법은" — 권장 (매 편은 아님)

## 분량 규칙

- 총 글자 수: 545~575자 (공백·문장부호 제외)
- 문장 수: 23~28문장 (문장 1개 = 자막 1줄 = 씬 1개 후보)
- 문장당 길이: 목표 20~25자, 최대 35자 (자막 2줄 초과 금지)
- TTS 발화 속도 기준: 5.4~6.2자/초 → 총 90~100초

## 문체 규칙

- 구어체 존댓말 ("~죠", "~거든요", "~입니다" 혼용)
- 청자에게 던지는 수사 의문문 활용 ("쌓인다고요?", "~하면 되지 않냐고요?")
- 숫자는 반드시 구체적으로 (× "많은 사람" → ○ "11만 8천 명")

## 검증 (validator가 체크할 항목)

1. 7단이 순서대로 모두 존재하는가
2. 시그니처 문구 2개가 정확히 존재하는가
3. 글자 수·문장 수가 범위 내인가
4. context와 solution에 숫자가 포함되는가
5. ending이 hook의 핵심 명사를 재사용하는가 (수미상관)
