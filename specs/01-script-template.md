# 01. 대본 스토리 템플릿

원본 채널 3편의 SRT 실측에서 역산한 고정 템플릿. 대본 생성 LLM은 이 구조를 벗어날 수 없다.

## 7단 구조

| # | 단계 | 시점(초) | 필수 요소 |
|---|---|---|---|
| 1 | hook | 0~10 | 충격 사실 + "~가 아닙니다" 류 반전 부정문 |
| 2 | context | 10~20 | 문제가 성립하는 조건 (지형·인구·제약) |
| 3 | failed_solution_1 | 20~30 | "가장 쉬운 방법은 ~" 도입 → 실패 이유 |
| 4 | failed_solution_2 | 30~44 | "그럼 ~하면 되지 않냐고요?" 도입 → 실패 이유 |
| 5 | turning_point | 44~54 | **"그래서 발상을 뒤집습니다"** (문구 고정) |
| 6 | solution | 54~85 | 해결책 스텝 바이 스텝 + **구체적 숫자 2개 이상** (실측 3/5/2개) |
| 7 | ending | 85~100 | 현재와 연결 + 수미상관 (훅의 소재로 회귀) |

## 시그니처 문구

원본 3편 실측 기준. "매 편 필수"는 3편 전부에 있는 것만 해당한다.

| 문구 | 위치 | 등급 | 실측 |
|---|---|---|---|
| **"그래서 발상을 뒤집습니다."** | `turning_point` 시작, 44~54초 | **필수** | 3/3편 (44.0s / 50.0s / 44.5s) |
| "환장할 노릇" + 어미 자유 | `failed_solution_2` 말미 | 권장 | 2/3편 ("노릇입니다" / "노릇이죠") |
| "가장 쉬운 방법은" | `failed_solution_1` 시작 | 권장 | 2/3편 (21.5s / 17.4s) |

어미까지 고정된 것은 "그래서 발상을 뒤집습니다." 하나뿐이다. "환장할 노릇"은 어미가 편마다
다르고(`-입니다` / `-이죠`) 아예 없는 편도 있어 필수로 두지 않는다.

## 분량 규칙

단위는 **자막 줄(SRT 큐)**이며 씬 1개와 1:1이다 (ADR-0013). 문장이 아니다 — 한 줄에 문장이
1~3개 들어간다. 문장 수는 자유 변수이며 검증하지 않는다 (실측 29 / 29 / 35문장).

- 총 글자 수: 545~575자 (공백·문장부호 제외) — 실측 545 / 552 / 572
- 자막 줄 수: 23~28줄 — 실측 28 / 23 / 26
- 줄당 길이: 목표 19~24자, **최대 43자** — 실측 평균 19.5 / 24.0 / 22.0, 최대 31 / 43 / 41
- 줄당 시간: 평균 3.5~4.1초, 개별 0.9~6.8초 — 실측 평균 3.57 / 4.04 / 3.54
- TTS 발화 속도 기준: 5.4~6.2자/초 → 총 90~102초 — 실측 5.40 / 5.94 / 6.22자/초, 101.0 / 93.0 / 92.0초

## 문체 규칙

- 구어체 존댓말 ("~죠", "~거든요", "~입니다" 혼용)
- 청자에게 던지는 수사 의문문 활용 ("쌓인다고요?", "~하면 되지 않냐고요?")
- 숫자는 반드시 구체적으로 (× "많은 사람" → ○ "11만 8천 명")

## 검증 (validator가 체크할 항목)

1. 7단이 순서대로 모두 존재하는가
2. **"그래서 발상을 뒤집습니다."**가 44~54초 구간에 존재하는가 (필수 문구는 이것 하나다)
3. 총 글자 수·자막 줄 수가 범위 내인가
4. `solution` 구간에 구체적 숫자가 2개 이상 있는가
5. ending이 hook의 핵심 명사를 재사용하는가 (수미상관)

`context`의 숫자는 검증하지 않는다. 실측 3편 중 2편이 이 구간에 아라비아 숫자가 없다
(백악 0개 / 각자성석 3개 / 춘당지 0개). 숫자가 확실히 걸리는 구간은 `solution`이다.
