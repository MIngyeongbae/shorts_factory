# 03. 시각 연출 어휘

**연출은 닫힌 어휘에서 고른다** (ADR-0033 §3). 자유 기술이 아니고, 표가 강제하는 것도
아니다 — `[1s. sceneplan]`이 씬마다 **고르고**, 고를 수 있는 값의 전부가
`specs/schema/vocab.json`에 있다.

이 문서는 **무엇을 어떤 기준으로 고르는가**를 적는다. 값 목록은 적지 않는다 (ADR-0034 §3).
어휘에 없는 값이 필요하면 `vocab.json`을 고치는 PR을 먼저 만든다.

| 축 | 고르는 곳 | 어휘 |
|---|---|---|
| 구도 | `[1s]` → 씬 계약 `framing` | `vocab.json` `framing` (21종) |
| 오버레이 | `[1s]` → 씬 계약 `emphasis` | `vocab.json` `overlay_type` |
| 전환 | `[1s]` → 씬 계약 `transition` | `vocab.json` `transition` (길이는 고정) |
| 카메라 | `[1s]` → 씬 계약 `camera` | `vocab.json` `camera` (7종) |
| 모션 | `[1s]` → 씬 계약 `motion` | `vocab.json` `motion` |
| 스타일 | **고르지 않는다** | `vocab.json` `style` — 전 씬 공통 고정 |

`[5. prompt]`는 판단하지 않는다. 씬 계약을 방언으로 옮기는 변환기다 (ADR-0027).
씬이 연출 필드를 비웠을 때만 `specs/schema/beat-defaults.json`의 기본값으로 떨어지고,
**그 씬 수를 요약에 낸다.**

## 베이스 스타일 (전 씬 공통) — 자유화 대상이 아니다

펜선·수채 위의 극사실 렌더링 (ADR-0023). 문자열은 `vocab.json`의 `style.base_style`이고
**실호출 6회로 검증한 값이라 글자 하나를 바꾸면 재검증이 필요하다.**

**채널 룩을 실제로 지키고 있는 것이 이 문자열이다.** ADR-0033이 구도 표를 내리면서 그
사실이 드러났다 — 같은 구도 토큰으로 뽑은 4장의 구도는 제각각이었지만 룩은 4장 모두
같았다. 그래서 여기는 열지 않는다.

- 흰 종이, 작도선을 지우지 않고 남긴다, 가장자리로 갈수록 맨 종이로 사라진다
- **사실주의가 우세하다.** 재질이 곧 설명이다 — 골재, 나뭇결, 층리가 보여야 한다.
  수채 워시로 뭉개면 그 설명이 사라진다 (ADR-0022)
- 9:16 구도, 피사체는 중앙~상단 1/3에 배치. 하단 1/3은 자막 영역이다
- **읽을 수 있는 글자·손글씨 낙서를 그리지 않는다.** 정확해야 하는 한국어는 전부
  레이어 B다 (ADR-0002). 배제 목록은 `vocab.json`의 `style.negatives`
- 스타일 앵커 3장을 NB2 호출에 첨부한다 (`vocab.json`의 `style.style_anchor_dir`,
  ADR-0005·0021). **MJ 방언은 앵커를 쓰지 않는다** (ADR-0025 G3)

### 미결 둘 (실측이 필요하다)

- **D5 — `architectural`을 뺄 것인가** (ADR-0033). 도메인이 열려 건축이 아닌 소재가 온다.
  relax가 무료이므로 뺀 버전과 나란히 뽑아 정한다
- **하단 1/3이 실제로는 안 비워진다.** 2026-08-13 실측에서 `bottom third left empty`가
  4장 전부 먹지 않았다. "이 기법은 여백으로 끝나므로 하단이 저절로 비워진다"는 앞선
  기술은 **틀렸다** — 자막이 그림을 가린다. `[6r] imagereview`의 판정 기준 ③이 이것을
  사후로 잡고 있고, 프롬프트 쪽 개선은 D5와 함께 실측한다

## 참조 서술 (ADR-0030)

`[4. refpack]`이 모은 `refs.json`의 `description`은 **`subject_anchor` 바로 뒤**에 실린다.
프롬프트 항목 순서는 이렇다.

```
subject, subject_anchor…, refs.description, visual_goal, framing.shot, base_style, composition
```

- 앵커 뒤인 이유: 앵커가 **대상이 무엇인가**를 고정하고 서술이 **그것이 어떻게 생겼는가**를
  더한다. 둘은 같은 일의 두 단계라 붙어 있어야 한다. 앵커가 `subject` 바로 뒤인 것은
  실측으로 정해진 자리다 (ADR-0028 G1) — 그 앞으로 끼어들지 않는다
- **`subject`를 대체하지 않는다.** 무엇을 그릴지는 여전히 `06-script.json`이 정하고,
  겹치면 `subject`가 이긴다 (ADR-0020: 값 하나의 출처는 하나다)
- `refs.json`이 없거나 그 씬이 비어 있으면 **그냥 건너뛴다.** 참조 부재는 경고가 아니다
- 사진 파일 첨부는 `[6]` 소관이다 — 강등 사다리는 `첨부+서술 → 서술 → 없음`이다 (ADR-0030)

## 구도

축이 둘이다. **하나는 피사체 서술이고 하나는 연출이다.**

| 필드 | 무엇 | 누가 |
|---|---|---|
| `subject_scale` | `subject`를 화면에 담는 크기 | `[1s]`가 `subject`와 함께 (ADR-0018) |
| `framing` | 그 크기를 어떤 샷으로 잡는가 | `[1s]`가 어휘에서 고른다 (ADR-0033) |

`vocab.json`의 각 구도 토큰에는 `scale`이 붙어 있다. **어울리는 스케일의 표시이지
강제가 아니다** — `close` 씬에 `section_diagram`을 고를 이유가 있으면 고른다.

**고르는 기준.**

1. **`visual_goal`이 무엇을 설명해야 하는가.** 규모를 설명하면 wide 계열, 재질·접합을
   설명하면 close 계열, 보이지 않는 구조나 공정을 설명하면 diagram 계열이다
2. **앞 씬과 같은 그림이 되지 않는가.** 연속한 두 씬이 같은 토큰이면 같은 그림처럼 보인다.
   수미상관처럼 **의도적으로** 훅의 구도로 돌아오는 것은 다르다 — 그때는 같은 토큰을 고른다
3. **편 전체의 리듬.** 실측은 전환 24~26회에 하드컷 3~4회다. diagram 계열이 연속으로
   몰리면 영상이 아니라 슬라이드가 된다

**표가 보장하던 것은 프롬프트 문자열의 결정성이지 결과의 일관성이 아니었다** (ADR-0033 §2의
실측). 결과를 보는 것은 `[6r] imagereview`다.

## 오버레이와 텍스트 2계층 (ADR-0002)

- **레이어 A (이미지 생성 단계 어노테이션)**: **사용처 없음** (ADR-0019). 모든 베이스
  이미지는 클린 이미지다
- **레이어 B (후처리 합성)**: 자막, 대형 숫자, 파티클 등 **정확해야 하는 모든 한국어 텍스트**.
  FFmpeg drawtext 또는 ASS 자막으로 합성한다

씬에 붙는 오버레이는 씬 계약의 `emphasis` 하나이고 `[1s]`가 고른다. 전 씬 공통 오버레이
(우하단 파티클)는 씬 항목이 아니라 `prompts.json`의 `style` 블록에 실린다 — 소비자는
`[8. overlay]`다. 타입·레이어·배제 문구는 `vocab.json`의 `overlay`.

## 카메라 워크 파라미터 (Ken Burns)

`[7. motion]`이 `camera` 값을 화면 움직임으로 옮기는 표다 (ADR-0006의 zoompan, ADR-0024).
움직임은 **클립 전체에 걸쳐 선형**이고, 크기는 전부 하나의 상수에서 나온다.

**이동량 = 프레임의 10%.** 씬 평균 3.5~4.0초이므로 초당 2.5~3%다 — 원본 채널의
"느린 줌/틸트/팬만 사용"과 같은 대역이다 (docs/reference-analysis.md).

| camera | 줌 | 이동 |
|---|---|---|
| `slow_zoom_in` | 1.00 → 1.10 | 없음 (중앙 고정) |
| `slow_zoom_out` | 1.10 → 1.00 | 없음 (중앙 고정) |
| `pan_right` | 1.10 고정 | x: 왼쪽 끝 → 오른쪽 끝 (여백 전부) |
| `pan_left` | 1.10 고정 | x: 오른쪽 끝 → 왼쪽 끝 |
| `tilt_down` | 1.10 고정 | y: 위 끝 → 아래 끝 (여백 전부) |
| `tilt_up` | 1.10 고정 | y: 아래 끝 → 위 끝 |
| `static` | 1.00 고정 | 없음 |

- 줌 1.10은 **크롭 배율**이다. 팬·틸트의 이동 폭은 그 크롭이 화면 안에서 움직일 수 있는
  여백 전부이며, 그 여백이 곧 10%다 — 상수 하나가 줌 깊이와 이동 폭을 함께 정한다
- 복합 워크(줌 + 팬 동시)는 만들지 않는다 (스펙 02)
- 원본이 1080×1920보다 크면 업스케일 없이 크롭만으로 나온다. 현재 `[6]`의 산출물은
  1536×2752라 1.10 크롭까지 여유가 있다

### 역방향 워크 (같은 그림이 두 번 쓰일 때)

`[6]`이 폴백으로 인접 씬 이미지를 복사하면 같은 그림이 두 씬에 걸린다 (스펙 05 `[6]`
"카메라 워크만 변경"). `[7]`은 **이미지 내용이 같은 것을 보고** 2회차부터 아래 표로
바꾼다 (ADR-0024). 씬 계약의 `camera`는 고치지 않는다 — 값의 출처는 `06-script.json`
하나다 (ADR-0020).

| 계약된 camera | 2회차에 쓰는 값 |
|---|---|
| `slow_zoom_in` | `slow_zoom_out` |
| `slow_zoom_out` | `slow_zoom_in` |
| `pan_right` | `pan_left` |
| `pan_left` | `pan_right` |
| `tilt_down` | `tilt_up` |
| `tilt_up` | `tilt_down` |
| `static` | `slow_zoom_in` |

`static`만 역이 없다. 정지 화면이 두 번 지나가는 것이 가장 눈에 띄므로 움직임을 준다.
같은 그림이 **3회 이상** 나오면 카메라로 가릴 문제가 아니라 이미지 생성이 실패한
것이므로, `[7]`은 역방향을 그대로 쓰되 경고를 남긴다.

## 전환

`[1s]`가 씬마다 `transition`을 고른다 (ADR-0033 §3). 값은 둘뿐이다.

- **디졸브 길이는 0.6초 고정이다.** `[7]`의 클립 계약(클립 길이 = 씬 길이 + 겹침 0.6초)과
  맞물려 있어 이 값에서만 클립이 남김 없이 쓰인다. 0.4초로 두면 클립마다 0.2초가 버려진다
  (ADR-0024). **자유화 대상이 아니다**
- **하드컷은 서사가 끊기는 자리에 쓴다.** 실측은 편당 하드컷 3~4회 / 전환 24~26회다
  (피사 3/24, 후버댐 4/26). 나머지는 전부 디졸브다. **이 비율이 관측 지표다** —
  하드컷이 편마다 크게 흔들리면 ADR-0033을 되돌릴 신호다
- 첫 씬의 `transition`은 무시한다 (들어오는 전환이 없다)
- 씬이 값을 비우면 `beat-defaults.json`의 기본값으로 떨어진다

## 자막 스타일

- 위치: 하단 중앙, 세로 기준 화면 72~82% 지점
- 폰트: 굵은 고딕 (Pretendard Bold 계열), **검정 + 흰색 외곽선 3px**
  - 베이스가 흰 종이라 흰 글자는 외곽선만 남는다. ADR-0023에서 뒤집었다.
    굵기·크기·위치는 그대로다
- 폰트 크기 **40px 고정** (1080×1920 기준). 큐마다 크기가 달라지지 않는다
- **1줄 최대 22자, 2줄 초과 금지**
- 이 세 값은 함께 정해졌다. 40px에서 22자는 880px로 가로 안전폭 960px 안에 들어가고,
  스펙 01이 허용하는 **가장 긴 큐(43자)도 22+21로 두 줄에 들어간다.**
  즉 정상 범위의 큐는 폰트를 줄일 일이 없다 — 큐별 폰트 축소 경로를 두지 않는다
- 들어가지 않는 큐는 **스펙 01의 줄당 상한을 넘겼다는 뜻이므로 실패로 보고한다.**
  자막 쪽에서 삼키지 않는다 (1부에서 고칠 문제다)

## 부록: 비트별 기본값 — 지시가 아니라 폴백

`specs/schema/beat-defaults.json`. ADR-0001의 강제 표가 있던 자리이고, 지금은 씬이 연출
필드를 비웠을 때만 쓰인다.

**지우지 않고 남긴 이유는 되돌릴 자리이기 때문이다** (ADR-0033 "되돌릴 조건"). 편마다
룩이나 리듬이 갈리면 먼저 어휘를 좁히고, 그래도 안 되면 이 표를 다시 지시로 올린다.
관측 수단은 편당 하드컷 수·전환 수·`[6r]` 재작업률, 그리고 `[5]`가 세는 **기본값으로
떨어진 씬 수**다.
