# 06. 소재 발굴 및 리서치

## 소재 판별 — 기준은 하나다

**도메인 제한이 없다** (ADR-0033 §1이 ADR-0016의 도메인 절을 폐기했다). 옛 분야 제한은
풀렸고 국가 제한은 원래 없다.

> **그림이 설명의 일부를 질 수 있는 소재인가.**

이 채널의 정의가 "90초 안에 글과 그림으로 함께 설명한다"이므로(ADR-0022) 기준은 도메인이
아니라 **매체 적합성**이다. 그림이 아무것도 지지 못하는 소재는 이 파이프라인을 쓸 이유가
없다 — 글만 남으면 90초에 들어가는 정보량이 절반이 되고, 그림은 시간만 채운다.

판별은 씬 단위 상상으로 한다. **"이 소재로 편 하나를 채울 그림을 그리면 그중 몇 장이
본문이 말하지 않은 것을 설명하는가."** 대부분이 분위기용 삽화가 된다면 매체가 안 맞는 것이다.

- 도해로 설명되는 것(구조·단면·규모·공정·변화·비교)은 대체로 맞는다
- 실물이 없고 도해도 안 되는 것(순수 사상·감정·추상 개념)은 대체로 안 맞는다.
  **다만 도메인으로 자르지 않는다** — 같은 분야에도 그림이 지는 소재와 못 지는 소재가
  섞여 있다는 것이 ADR-0033의 요점이다

이건 관측 지표와 나란한 조건이 **아니다.** 백로그에 올라오기 전에 걸러지는 전제이므로
팩트시트 `conditions`에는 들어가지 않는다.

레퍼런스 채널("신비한 건축사전")과 겹칠 수 있는 소재는 발굴 단계에서 미리 거른다 —
`[0b]` 비판 세션까지 가서 반려되면 세션 4개가 낭비된다. **도메인이 넓어지면서 겹칠 일이
줄었으므로 이 검사를 유지할지는 미결이다** (ADR-0033 D6). `[0b]` 구현을 손댈 때 같이 본다.

## 좋은 소재의 특징 (관측 지표 — 게이트가 아니다)

아래 넷은 **없으면 반려하는 조건이 아니다.** 네 항목 전부가 폐기된 고정 구조를 채우기 위해
만들어졌기 때문이다 (ADR-0033 §1). 팩트시트의 `conditions`에 그대로 기록하되 **판정이
아니라 관측**이고, `[1b] score`의 훅 채점 입력으로 쓴다.

1. **통념 뒤집기**: 대중이 아는 대상에 대한 몰랐던 사실 ("~가 아닙니다"가 성립)
2. **실패한 대안의 기록**: "쉬운 방법이 왜 안 됐는지"의 사료
3. **구체적 숫자**: 인원·거리·기간·비용 등
4. **현재 접점**: 둘 중 하나면 충족한다
   - (a) 지금 **방문 가능한** 장소/유물과 연결
   - (b) 시청자의 **일상에서 지금도 작동하는 같은 원리**와 연결
     (예: 후버댐 냉각 → 오늘 짓는 아파트 콘크리트도 같은 수화열을 낸다)

   (a)만 있던 정의가 조사 세션을 관광 정보로 몰았다. 후버댐 팩트시트의 `present_link`가
   "파이프가 댐 속에 남아 있다 + 투어 $40"으로 끝나, 백로그가 이 소재를 고른 이유였던
   "지금 사는 아파트 콘크리트도 같은 반응을 한다"가 사실 55건 어디에도 들어오지 않았다.
   대본은 팩트시트에 없는 것을 쓸 수 없으므로(ADR-0007) 접점이 통째로 사라졌다.

   **(b)를 쓸 때도 그라운딩은 같다.** 일상 접점 역시 팩트시트에 사실로 실려야 하며,
   대본이 지어내도 되는 여지가 생기는 것이 아니다.

**넷 중 셋이 비어도 대본에 진입할 수 있다.** 그 대신 `[1b] score`에서 낮은 점수를 받고,
`[2b] judge`가 서사가 성립하는지를 본다 — 통제가 사전 게이트에서 사후 판정으로 옮겨간
것이 ADR-0033 §5다.

## [0a. topic] 소재 백로그

- `topics/backlog.md`에서 관리. 항목: 소재명, 관측 지표 체크, 출처 후보, 상태(후보/리서치중/제작완료/반려)
- 선택 항목: `slug` 컬럼. 있으면 자동 로마자 변환 대신 이 값을 폴더명으로 쓴다 (ADR-0011)
- v1 소스: 레퍼런스 채널 기존 주제 + 댓글 요청, 답사기·교양서 목차
- v2: LLM 브레인스토밍(대상 지정 → 그림이 설명을 지는 후보 N개) + 웹 검색 사실 확인
- v3(추후): 실록·국가유산포털에서 문제 서사 패턴(붕괴·홍수·화재·재건·논쟁) 자동 채굴

## 소스 등급 (ADR-0016)

1차 사료 필수 조건은 없다. 등급이 낮을수록 `confidence`를 낮게 매기면 된다.

| 등급 | 소스 | 근거 사용 |
|---|---|---|
| **A** | 기관 공식 자료(문화유산청·박물관·정부), 학술 논문(J-STAGE·CiNii·DBpia 등), 1차 사료 원문(조선왕조실록 등) | 가능 |
| **B** | 백과사전 — **위키백과(한/영)**, 브리태니커, 한국민족문화대백과사전 | 가능 |
| **C** | 언론 기사, 기관 해설글, 전시 해설 | 가능 (교차확인 권장) |
| **D** | 커뮤니티 위키(나무위키 등), 개인 블로그 | **발굴 힌트만. 근거로 쓸 수 없다** |

- 위키백과는 B등급 근거로 **인정한다.** 각주의 원출처를 따라가면 A로 올릴 수 있으나 의무는 아니다
- 해외 소재는 한국어 자료가 얕다. **영어(또는 현지어) 검색을 반드시 병행한다**
- 어느 등급이든 출처는 특정 가능한 수준까지 적는다. "위키백과"가 아니라 "영문 위키백과 Roman concrete"

## confidence 판정 (ADR-0016)

| 등급 | 기준 | 대본에서 |
|---|---|---|
| `high` | 복수의 독립 소스가 일치하거나 A등급 자료가 직접 뒷받침 | 단정해도 된다 |
| `medium` | 단일 소스이거나, **학계에서 가장 유력하지만 확정되지 않은 추론** | **추정 표현 필수** |
| `low` | 소수설·이설·출처 불명 | 사용 금지 |

`medium`이 "현재 가장 유력한 추론"을 담는 자리다. **확정되지 않았다는 이유로 버리지 않는다** —
로마 콘크리트 배합이나 피라미드 운반처럼 훅이 센 소재가 여기 몰려 있고, 논쟁 중이라는 사실
자체가 좋은 훅이다. 다만 대본에서 단정하면 채널 신뢰가 깨지므로 "~로 추정됩니다" /
"가장 유력한 설명은" / "아직 논쟁 중입니다" 같은 표현으로만 쓴다.

이 추정 표현 규칙은 **기계 검증 대상이 아니다.** 그라운딩 검증기는 숫자만 대조하고,
표현이 지켜졌는지는 `[2b. judge]`가 본다.

## 소스 카드 라이브러리 (knowledge/)

한 번 조사한 소스는 카드로 남겨 다른 토픽이 다시 찾지 않게 한다 (ADR-0012).

```
knowledge/
├── index.md                              # 카드 한 줄 요약. 자동 생성 — 수동 편집 금지
└── sources/{topic_slug}/{source_id}.md   # 소스 카드 1장
```

- `source_id`: URL 정규화 후 `{호스트}-{sha256 앞 8자}`. 같은 URL이면 항상 같은 id.
  URL이 없는 출처는 카드를 만들지 않는다 (본문에는 그대로 서술한다)
- 카드 = frontmatter(제목·url·유형·관련 유적·참조 토픽·신선도·최초조사일·최종확인일)
  + `## 핵심 발췌`(원문 인용) + `## 확인된 사실`(등급·교차확인 토픽)
- **카드에 토픽 단위 판단(verdict·conditions·twist·reject_reason)을 넣지 않는다.** 넣으면 앞
  토픽의 결론이 카드를 타고 다음 토픽 세션에 흘러들어 ADR-0009의 세션 격리가 깨진다
- **폴더는 최초 조사 토픽이고 표시 규약일 뿐이다** (ADR-0026). 소속의 진실은 frontmatter의
  `topics:`이며, 카드는 나중에 다른 토픽에 인용돼도 **이동하지 않는다.** 조회는 재귀 탐색이라
  폴더를 몰라도 된다. **경로로 소속을 판정하는 코드를 쓰지 않는다**
- `index.md`도 토픽 섹션으로 나눈다. **여러 토픽에 걸친 소스는 각 섹션에 모두 등장한다** —
  파일은 한 곳에만 있을 수 있지만 표의 줄은 그렇지 않다. 섹션 순서는 카드 수 내림차순 →
  슬러그 사전순 (ADR-0026)
- 태그·임베딩 검색은 두지 않는다. 탐색은 index.md + Read + grep
- 카드는 오케스트레이터(파이썬)만 쓴다. 세션은 Read만 한다 (ADR-0011)

### 유형별 신선도

| `type` | 예 | 신선도 |
|---|---|---|
| `primary` | 실록·승정원일기 등 1차 사료 원문 | 영구 |
| `reference` | 백과·논문·기관 해설·언론 | 365일 |
| `status` | 관람시간·보존공사·집계 등 현황 정보 | 90일 |

만료된 카드는 세션 주입 시 `⚠ 재확인 필요` 표시가 붙고 그 카드만 재fetch가 허용된다.
만료는 파이프라인을 차단하지 않는다.

## 토픽 패키지 구조 (ADR-0009)

소재당 폴더 하나. 조사→검증→비판은 각각 독립 헤드리스 세션으로 실행한다.

```
topics/{slug}/
├── 01-research.md          # 조사: 사실 수집 (넓게, 출처 필수) + 끝에 `## 참조 소스`
├── 02-verify.md            # 검증: 사실 정확성 — 숫자·연도 출처 교차 대조, confidence 판정
│                           #       + 끝에 `## 참조 소스`
├── 03-critique.md          # 비판: 콘텐츠 가치 — 그림이 설명을 지는가, 레퍼런스 채널 중복 여부,
│                           #       90초 적합성, 대본 후보의 훅 약점 지적
├── 04-factsheet.json       # 01~03 종합한 기계용 팩트시트 (아래 스키마)
├── 07-outline.json         # [1a] 서사 구조 설계 + 사실·글자 배분. 1부 내부 파일 (ADR-0029)
├── 08-sceneplan.json       # [1s] 씬 분할 + 글·그림 분담 + 연출 선택. 1부 내부 파일
├── 05-candidates/          # 대본 후보 (JSON). 번호는 생산 순서가 아니라 옛 배치 그대로다
├── 06-script.json          # 스코어링 선발본. 2부의 읽기 전용 입력 (ADR-0017)
├── judgment/human.json     # 사람 판정 (go/revise/no_go). 2부 진입 게이트 (스펙 07, ADR-0017)
└── STATUS.md               # go / no-go / 보류 + 사유 (인간 게이트, 유일한 수동 지점)
```

- 검증(02)과 비판(03)의 구분: 02는 "사실이 맞는가", 03은 "콘텐츠로서 가치 있는가"
- 비판 세션에는 01의 결론 요약이 아니라 원자료를 제공 (자기 검증 오염 방지)
- 조사(01)·검증(02) 세션에는 knowledge/index.md를 주입한다. 카드에 있는 소스는 재검색·재fetch
  금지, Read로 읽어 참조한다. 비판(03)은 라이브러리에 닿지 않는다
- 검증(02)은 카드의 핵심 발췌를 1차 근거로 쓰고, 발췌로 판정 불가한 주장만 재fetch한다
- 01·02 산출물 끝의 `## 참조 소스` JSON(재사용한 source_id 목록 + 신규 소스·발췌·사실)을
  파이썬이 파싱해 카드를 만들고 index.md를 재생성한다. 파싱 실패는 경고이며 단계를 죽이지 않는다
- 03이 대본 후보(05)까지 공격하도록 대본 생성 후 비판을 1회 더 실행 (critique 2차)
- STATUS.md가 go가 아니면 비주얼 파이프라인 진입 금지

## [0b. research] 팩트시트 산출

research.json 스키마:

```json
{
  "topic": "한양도성 각자성석",
  "verdict": "pass",
  "conditions": {"twist": true, "failed_alternative": true, "numbers": true, "present_link": true},
  "facts": [
    {
      "id": "f01",
      "claim": "1396년 태조가 한양 둘레 18.6km 성벽 공사를 시작했다",
      "numbers": ["1396년", "18.6km"],
      "source": "실록 태조 5년 1월",
      "confidence": "high"
    }
  ],
  "twist": "성돌의 이름은 낙서가 아니라 국가가 새기게 한 책임 표기다",
  "failed_alternatives": ["감독관 배치 (11만 명/18.6km 감시 불가)", "포상제 (부실이 수년 뒤에야 드러남)"],
  "present_link": "흥인지문 옆·낙산 구간에서 각자성석 실견 가능"
}
```

`conditions`의 네 값은 **관측이지 판정이 아니다** (ADR-0033 §1). `false`가 섞여 있어도
`verdict`는 `pass`일 수 있다. 이 값을 소비하는 곳은 `[1b] score`이고, 게이트가 아니다.
`twist`·`failed_alternatives`가 비는 소재가 새 도메인에서는 정상이다.

## 규칙

- `confidence: low` 사실은 대본에 사용 금지. `medium`은 사용하되 추정 표현으로만 쓴다 (ADR-0016)
- 숫자가 출처마다 다르면 가장 보수적인 값 + notes에 이견 기록
- `verdict: fail`은 **판별 기준을 못 넘길 때만이다** — 그림이 설명의 일부를 지지 못하거나,
  사실이 그라운딩을 못 버틸 때(`low`뿐이거나 출처가 없을 때)다. **관측 지표(`conditions`)가
  비어서 반려하지 않는다** (ADR-0033 §1)
- 팩트시트는 runs/{run_id}/research.json으로 보존 (사실 검증 추적성)
