# 06. 소재 발굴 및 리서치

## 소재 4조건 (모두 충족해야 대본 진입)

1. **통념 뒤집기**: 대중이 아는 대상에 대한 몰랐던 사실 ("~가 아닙니다"가 성립)
2. **실패한 대안의 기록**: 딜레마 구간(템플릿 3~4단)을 채울 "쉬운 방법이 왜 안 됐는지"의 사료
3. **구체적 숫자**: 인원·거리·기간·비용 등 최소 3개 이상
4. **현재 접점**: 지금 방문 가능한 장소/유물과 연결 (엔딩 수미상관용)

## [0a. topic] 소재 백로그

- `topics/backlog.md`에서 관리. 항목: 소재명, 4조건 체크, 출처 후보, 상태(후보/리서치중/제작완료/반려)
- v1 소스: 레퍼런스 채널 기존 주제 + 댓글 요청, 답사기·교양서 목차
- v2: LLM 브레인스토밍(대상 유적 지정 → 4조건 만족 후보 N개) + 웹 검색 사실 확인
- v3(추후): 실록·국가유산포털에서 문제 서사 패턴(붕괴·홍수·화재·재건·논쟁) 자동 채굴

## 1차 사료 소스 (우선순위순)

1. 조선왕조실록 (sillok.history.go.kr) — 전문 검색 가능
2. 국가유산청 국가유산포털 — 공공데이터 API
3. 한국민족문화대백과사전 (encykorea.aks.ac.kr)
4. 서울역사편찬원·서울역사박물관 간행물
5. 학술 논문 (건축역사학회지 등) — 숫자·도면 검증용

## 토픽 패키지 구조 (ADR-0009)

소재당 폴더 하나. 조사→검증→비판은 각각 독립 헤드리스 세션으로 실행한다.

```
topics/{slug}/
├── 01-research.md          # 조사: 사실 수집 (넓게, 출처 필수)
├── 02-verify.md            # 검증: 사실 정확성 — 숫자·연도 출처 교차 대조, confidence 판정
├── 03-critique.md          # 비판: 콘텐츠 가치 — 소재 4조건 공격, 레퍼런스 채널 중복 여부,
│                           #       90초 적합성, 대본 후보의 훅 약점 지적
├── 04-factsheet.json       # 01~03 종합한 기계용 팩트시트 (아래 스키마)
├── 05-candidates/          # 대본 후보 3~5개 (JSON)
├── 06-script.json          # 스코어링 선발본
└── STATUS.md               # go / no-go / 보류 + 사유 (인간 게이트, 유일한 수동 지점)
```

- 검증(02)과 비판(03)의 구분: 02는 "사실이 맞는가", 03은 "콘텐츠로서 가치 있는가"
- 비판 세션에는 01의 결론 요약이 아니라 원자료를 제공 (자기 검증 오염 방지)
- 03이 대본 후보(05)까지 공격하도록 대본 생성 후 비판을 1회 더 실행 (critique 2차)
- STATUS.md가 go가 아니면 비주얼 파이프라인 진입 금지

## [0b. research] 팩트시트 산출

research.json 스키마:

```json
{
  "topic": "한양도성 각자성석",
  "verdict": "pass",
  "conditions": {"twist": true, "failed_alternative": true, "numbers": true, "present_link": true},
  "facts": [
    {
      "id": "f01",
      "claim": "1396년 태조가 한양 둘레 18.6km 성벽 공사를 시작했다",
      "numbers": ["1396년", "18.6km"],
      "source": "실록 태조 5년 1월",
      "confidence": "high"
    }
  ],
  "twist": "성돌의 이름은 낙서가 아니라 국가가 새기게 한 책임 표기다",
  "failed_alternatives": ["감독관 배치 (11만 명/18.6km 감시 불가)", "포상제 (부실이 수년 뒤에야 드러남)"],
  "present_link": "흥인지문 옆·낙산 구간에서 각자성석 실견 가능"
}
```

## 규칙

- `confidence: low` 사실은 대본에 사용 금지. 숫자가 사료마다 다르면 가장 보수적인 값 + notes에 이견 기록
- 4조건 중 하나라도 불충족 시 `verdict: fail` → 백로그로 반려 (대본 생성 진입 금지)
- 팩트시트는 runs/{run_id}/research.json으로 보존 (사실 검증 추적성)
