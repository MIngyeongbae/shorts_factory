# worklog

세션을 마무리할 때 맨 위에 항목 1개를 추가한다. 역순 누적이다.
세션 시작 훅이 **맨 위 항목 1개만** 주입하므로, 다음 세션이 알아야 할 것만 그 항목에 담는다.

> ⚠ **`## `로 시작하는 줄은 항목 구분자다** (`.claude/hooks/session-start.ps1`이 그것으로
> 최신 항목을 자른다). **다른 용도로 `## `를 쓰지 말 것** — 쓰면 그게 "최신 항목"으로
> 주입되어 다음 세션이 인계를 못 받는다. 소제목은 `###`부터 쓴다.

**이 파일의 운영 규칙 (ADR-0034)**

worklog는 **인계장이지 아카이브가 아니다.** 판단과 근거는 ADR에, 지금 상태만 여기 둔다.

- **ADR에 있는 내용을 여기 다시 쓰지 않는다.** ADR 번호로 가리킨다 — 2026-08-13 (5) 항목이
  315줄까지 부푼 원인이 그 중복이었다. 훅이 맨 위 항목을 통째로 주입하므로 길이가 곧 비용이다
- 한 항목의 목표 분량은 **80줄 안팎**이다
- 항목이 **5개를 넘으면** 오래된 것을 `worklog-archive/`로 옮긴다.
  옮기기 전에 **그 항목에만 있는 판단이 없는지 보고, 있으면 ADR로 승격**한다
- 아카이브도 같은 리포에 남는다. `grep`으로 찾을 수 있으므로 유실이 아니다

## 2026-08-19 (13) — **이미지 경로가 실운영 불가였다.** ADR-0035, `mj_video` 입력 해결

**전부 `failed`로 기록됐는데 프록시에서는 같은 태스크가 전부 `SUCCESS` 100%였다.**
`MAX_ATTEMPTS=2`가 재시도로 큐에 4잡을 더 얹었다.

**`[6]`은 이제 대기 상한을 선언하지 않는다.** 워커 수와 같은 취급이다 (ADR-0031 G3).
`TIMEOUT` 상수 삭제 → `timeout=None`(=프로바이더가 정한다), CLI `--timeout` 추가,
스펙 05에 "대기 상한도 여기에 적지 않는다" 한 줄. **979개 통과**(+5), 감사 0건.
계약 테스트가 `TIMEOUT` 상수의 부활 자체를 잡는다.

## 2026-08-14 (12) — 실물 확인 2건. **동시 제출 2.53배**, **MJ 영상 호출 계약** (Fast 7.8분)

앞 항목 (11)의 구현을 실물 프록시로 확인하고, 이어서 영상 경로를 탐침했다.
판단은 전부 ADR-0025 "영상 호출 계약 실측"에 있다 — 여기 다시 적지 않는다.

### 1. `[6]` 동시 제출 실물 확인 (relax, 과금 0)

서로 다른 피사체 4씬. `concurrency() = 3`을 프록시에서 읽어 왔다.

```
씬1 t+0.0→110.7   씬2 t+0.0→120.5   씬3 t+0.0→50.9   씬4 t+50.9→151.3
```

**씬 3이 끝난 t+50.9에 씬 4가 그 슬롯을 소수점까지 정확히 이어받았다.** 총 151.3초 —
순차였으면 382.3초라 **2.53배**다. 4장 전부 `attempts=1`, 폴백·429·경고 0.
27씬 환산 `27 × 95.6 ÷ 3 ≈ 14.3분`으로 (11)의 예측이 실측으로 뒷받침됐다.

**남은 실측 하나:** 최장 잡이 **120.4초**인데 단계 기본값이 `TIMEOUT = 180`이다.
여유가 60초뿐이고 어댑터 자신의 기본값은 1800이다 (`midjourney.py`가 "짧게 잡으면 멀쩡한
잡을 죽이고 재시도해 큐를 두 배로 만든다"고 경고하는 그것). **이번엔 600으로 올려 피해
갔다. 180을 그대로 둘지 안 정했다** — ADR도 없고 시킨 사람도 없어 손대지 않았다.

### 2. MJ 영상 — **되는데, 우리 이미지로는 아직 못 한다**

메커니즘은 끝까지 돌았다(제출 → 4개 생성 → U1 추출 → mp4). 규격은 `h264 464×832 24fps
5.208초`로 **"잡당 5초 클립 4개"가 맞았다.** GPU는 7.8분으로 ADR의 8분 추정과 맞았다.

**막힌 곳은 입력이다.** `image`는 실주소만 받고 로컬 PNG를 올릴 수는 있는데 프록시가
`http://localhost:8086/...`을 돌려줘 MJ가 못 닿는다. 길 셋과 유력안(3번: MJ에 `UPSCALE`을
눌러 단일 이미지 주소를 얻는다)은 ADR-0025에 적었다.

**⚠ 계정 Remix Mode를 켠 채로 뒀다.** 영상의 전제조건이라 켰다(`mjRemixOn=true`).
되돌리려면 같은 버튼을 한 번 더 누른다 —
`POST /mj/admin/account-action/{id}?customId=MJ::Settings::RemixMode&botType=MID_JOURNEY`.
**이미지 경로에 영향이 있는지는 확인하지 않았다.** Remix는 V(variation) 버튼 동작을
바꾸는데 우리는 IMAGINE + 그리드 크롭만 쓰므로 영향이 없을 것으로 보이나, 추정이다.

## 2026-08-14 (11) — `[6]`이 동시에 제출한다. **45분 → ~16분** (ADR-0031 §4만)

발단은 "이미지 생성이 너무 느리다"였고, 27장 45분을 나눠 보니 **장당 ~100초로 relax

것이었다. 프록시를 자체 구현하는 것과는 무관한 문제다.

### 한 일 — ADR-0031 §4만. `[6r]` 판정 게이트(§1~3)는 손대지 않았다

사람이 속도만 먼저 가져가기로 정했다. 둘은 서로를 필요로 하지 않는다.

- `stages/imagegen.py` — 순차 `for` → `ThreadPoolExecutor` + `_Gate`.
  **기록 갱신은 자물쇠로 직렬**(ADR-0020의 목적이 "죽어도 다시 사지 않는다"라서),
  429면 게이트가 1로 줄고 백오프, 이어받는 씬은 워커를 안 잡는다
- `ImageClient.concurrency()` 신설 (기본 1 = 모르면 줄 세운다).
  MJ가 `POST /mj/admin/accounts`로 활성 계정 `relaxCoreSize`를 읽는다 — **코드에 3이 없다.**
  못 읽으면 예외 없이 1로 떨어진다. `--jobs`가 있으면 그것이 이긴다
- 실측: 페이크 28씬 벽시계 **8.5초 → 3.1초(2.7배)**. 실물 프록시 조회도 확인(`3`)
- 스펙 05:136에서 **"워커 기본 3"을 지웠다.** 코드에 없는 숫자였고, 워커 수를 말하는
  문장이 그 줄에 둘이었다 — 하나로 합치고 **숫자는 어디에도 안 적는다**로 바꿨다
- 974개 통과(+20), 감사 0건

### 프록시 정책 — 전역만 손봤다. 계정은 그대로다

병렬로 3개를 던지게 되면서 간격 정책의 무게가 커졌다. 그래서 실제 값을 다시 읽었고
**전역 설정이 계정보다 나빴다** — 경보가 꺼져 있어 경고 카운터가 세어지지도 않았다.

- **전역 3개를 켰다** (`POST /mj/admin/setting`, 재연결 위험 없음):
  `alertNotify.enable`·`enableAutoCollectOfficialBannedWords`·`bannedLimiting.enable`
  전부 `false` → `true`. `enableVideo`는 원래 `true`
- **일일 상한을 철회했다** (사람 결정). `dayDrawLimit`/`dayRelaxDrawLimit`을 `-1`로
  ADR-0025·정책 파일에 선언했다 — 프록시 실제 값이 처음부터 `-1`이었으므로 **바꾼 것이
  아니라 선언을 실제에 맞춘 것**이다. 잃은 것은 밴 방어가 아니라 재시도 폭주 시의 사고
  방어다 (ADR-0025 "일일 상한 철회"에 되돌릴 조건까지 적었다)
- **계정 간격은 안 건드렸다.** `interval: 1.2`, `afterIntervalMin/Max: 1.2` 그대로다.
  계정 수정 엔드포인트가 `PUT /mj/admin/account-reconnect/{id}` — **"수정하고 Discord
  재연결"**이라 실패하면 이미지 생성이 멈춘다. 사람이 웹 UI에서 하기로 했다
- **`enableRelaxToFast`는 API로 설정할 수 없다.** `DiscordAccountConfig` 스키마(48필드)에
  아예 없다. 지금 `null`이다 — 정책 파일이 선언한 값을 API가 안 받는다는 것은 ADR-0032가
  모르던 사실이고, `sf mj-policy apply`를 만들 때 걸릴 자리다
