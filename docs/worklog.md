# worklog

세션을 마무리할 때 맨 위에 항목 1개를 추가한다. 역순 누적이다.
세션 시작 훅이 **맨 위 항목 1개만** 주입하므로, 다음 세션이 알아야 할 것만 그 항목에 담는다.

> ⚠ **`## `로 시작하는 줄은 항목 구분자다** (`.claude/hooks/session-start.ps1`이 그것으로
> 최신 항목을 자른다). **다른 용도로 `## `를 쓰지 말 것** — 쓰면 그게 "최신 항목"으로
> 주입되어 다음 세션이 인계를 못 받는다. 소제목은 `###`부터 쓴다.

**이 파일의 운영 규칙 (ADR-0034)**

worklog는 **인계장이지 아카이브가 아니다.** 판단과 근거는 ADR에, 지금 상태만 여기 둔다.

- **ADR에 있는 내용을 여기 다시 쓰지 않는다.** ADR 번호로 가리킨다 — 2026-08-13 (5) 항목이
  315줄까지 부푼 원인이 그 중복이었다. 훅이 맨 위 항목을 통째로 주입하므로 길이가 곧 비용이다
- 한 항목의 목표 분량은 **80줄 안팎**이다
- 항목이 **5개를 넘으면** 오래된 것을 `worklog-archive/`로 옮긴다.
  옮기기 전에 **그 항목에만 있는 판단이 없는지 보고, 있으면 ADR로 승격**한다
- 아카이브도 같은 리포에 남는다. `grep`으로 찾을 수 있으므로 유실이 아니다

### 1. 동영상을 안 썼다 — MJ를 고른 이유의 절반이 빠졌다 (가장 큰 것)

**ADR-0025 §3이 `motion` enum에 `mj_video`를 넣고 강등 사다리를
`mj_video → kenburns → static`으로 하라고 승인했는데, 코드에도 스펙에도 없다.**

```
schemas/scenes.py:55  MOTIONS = ("kenburns", "kling")     ← mj_video 없음
grep -rn "mj_video" src/ specs/                            ← 0건
이번 편 motion 분포: Counter({'kenburns': 27})             ← 27씬 전부
```

`[1] script`의 `DEFAULT_MOTION`이 전부 `kenburns`를 박고, `[7]`은 그대로 켄번스만 돌린다.
**MJ 프록시를 세운 이유가 영상 단가였는데 영상은 한 컷도 안 만들었다.** 이미지에
켄번스만 얹을 거였으면 그 인프라가 필요 없었다. ADR-0025 §3 구현이 **다음 세션 1순위다**
(엔드포인트는 `POST /mj-fast/mj/submit/video`, 이미지와 달리 **fast라 GPU 시간을 쓴다** —
편당 몇 씬에 쓸지 규칙부터 정해야 한다).

## 2026-08-13 (2) — MJ 어댑터 완성. **막힌 것은 코드가 아니라 mjopen 라이선스다**

1. **계정 enable 토글이 아니다.** `POST /mj/admin/accounts-enable`로 켰고 제출은

### 관리 API 메모 (다음에 또 필요하다)
