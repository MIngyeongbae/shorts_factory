# worklog

세션을 마무리할 때 맨 위에 항목 1개를 추가한다. 역순 누적이다.
세션 시작 훅이 **맨 위 항목 1개만** 주입하므로, 다음 세션이 알아야 할 것만 그 항목에 담는다.

> ⚠ **`## `로 시작하는 줄은 항목 구분자다** (`.claude/hooks/session-start.ps1`이 그것으로
> 최신 항목을 자른다). **다른 용도로 `## `를 쓰지 말 것** — 쓰면 그게 "최신 항목"으로
> 주입되어 다음 세션이 인계를 못 받는다. 소제목은 `###`부터 쓴다.

**이 파일의 운영 규칙 (ADR-0034)**

worklog는 **인계장이지 아카이브가 아니다.** 판단과 근거는 ADR에, 지금 상태만 여기 둔다.

- **ADR에 있는 내용을 여기 다시 쓰지 않는다.** ADR 번호로 가리킨다 — 2026-08-13 (5) 항목이
  315줄까지 부푼 원인이 그 중복이었다. 훅이 맨 위 항목을 통째로 주입하므로 길이가 곧 비용이다
- 한 항목의 목표 분량은 **80줄 안팎**이다
- 항목이 **5개를 넘으면** 오래된 것을 `worklog-archive/`로 옮긴다.
  옮기기 전에 **그 항목에만 있는 판단이 없는지 보고, 있으면 ADR로 승격**한다
- 아카이브도 같은 리포에 남는다. `grep`으로 찾을 수 있으므로 유실이 아니다

| 파일 | 범위 |
|---|---|
| `docs/worklog.md` | 최근 5개 |

### 관측 수단이 붙었다 (되돌릴 조건을 보는 자리)

`[5]`가 요약과 run 상태에 **`구도 기본값 N씬`**을 낸다. 실물로 확인:
