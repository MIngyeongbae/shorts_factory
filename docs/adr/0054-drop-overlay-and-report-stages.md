# ADR-0054: [8] overlay·[11] report 삭제 — 화면 그래픽은 인포씬 하나, 후처리 합성은 자막 번인만 남는다

- 상태: 승인 (2026-08-22, 사람 결정 — 지시가 곧 승인이다)
- 날짜: 2026-08-22
- 관련 스펙: specs/05-pipeline.md, specs/03-visual-rules.md, specs/02-beat-schema.md,
  specs/04-audio-rules.md, specs/schema/scene.schema.json, specs/schema/sceneplan.schema.json,
  specs/schema/vocab.json, specs/schema/beat-defaults.json
- 관련 ADR: ADR-0043(인포씬 NB2 편집 — 이 결정의 전제), ADR-0002(2계층 텍스트 —
  레이어 B가 자막만 남는다, 개정), ADR-0019(레이어 A 폐기 — 레이어 B 항목이 이제
  자막뿐이다), ADR-0050(레퍼런스 정체성 탈피 — 파티클이 그 잔존이었다),
  ADR-0039·0053(강등 관측 — [11]의 존재 근거가 정지로 잠들었다)

## 맥락

### 1. 사람 결정 (2026-08-22)

> "후처리 합성을 이제 안 하잖아. NB2가 이미지에서 알아서 잘 만드는 걸 전제로 하기로
> 했는데, [8] overlay 이제 필요 없겠네. ADR도 수정해. [11] report도 그럼 제거해."

정확히 하면 후처리 합성이 전부 사라지는 것은 아니다 — **자막 번인(`[9]`)은 후처리
합성이고 그대로 남는다.** 사라지는 것은 `[8]`이 하기로 했던 나머지 합성(대형 강조
텍스트·파티클)이다.

### 2. [8]에 남아 있던 일은 둘뿐이고, 둘 다 근거가 사라졌다

ADR-0043이 화면 라벨·수치를 레이어 B 합성이 아니라 **NB2 편집(+자소 대조 검수)**으로
옮긴 뒤, [8]의 몫은 이것뿐이었다:

- **`emphasis`(big_red_text) 대형 숫자** — 인포씬과 역할이 겹친다. 화면에 세울 숫자는
  `[3s]`가 `info.labels`로 지정하고 NB2가 그린다 (검증된 수치만, ADR-0007·0043).
  같은 "화면에 숫자를 세운다"를 두 경로가 다루면 출처가 갈라진다 (ADR-0020).
  ADR-0047 이후 숫자는 화면이 지고 말이 가리키는 분담이라, 검수 있는 인포씬이 정본
  경로다 — 검수 없는 합성 대형 텍스트는 두 번째 경로일 이유가 없다
- **전 씬 우하단 반짝이 파티클(✦)** — `docs/reference-analysis.md`의 레퍼런스 채널
  실측 항목이다 ("전 프레임 우하단 반짝이 파티클"). 차임(ADR-0050 개정이 뗐다)과
  같은 부류의 **채널 시그니처 연출 잔존**이고, 유지할 근거가 없다

### 3. [11]은 소비자가 없다

집계하려던 원천 — `state.json`(단계별 상태·경고·수치), 실행 기록 파일들(`timing.json`·
`images.json`·`image_review.json`·`info.json`·`clips.json`), 단계별 요약 출력 — 이
전부 이미 남는다. 존재 근거였던 강등 관측(ADR-0039 "리포트가 강등 수를 세지 못하면
영상을 만들었다고 착각한다")과 변동비 집계(ADR-0043 인포씬 종량)는 **ADR-0053 영상
정지로 잠들었다.** 지금 만들면 읽는 사람이 없는 문서를 만드는 단계가 된다.

## 결정

1. **`[8. overlay]` 단계를 삭제한다.** `emphasis` 필드(씬 계약·연출표), `overlay`
   어휘(vocab), `prompts.json`의 `overlays`·`global_overlays`를 계약에서 걷는다.
   `[3s]`는 강조를 고르지 않는다 — **화면 그래픽 경로는 인포씬(ADR-0043) 하나다.**
2. **자막 번인은 그대로다.** ADR-0002의 레이어 B는 자막만 남는다 (해당 ADR에 개정
   노트). "정확한 한국어를 생성 모델에 기대지 않는다"는 원칙은 자막(합성)과
   인포씬(자소 대조 검수)이 지킨다 — 원칙은 살고 경로만 줄었다.
3. **`[11. report]` 단계를 삭제한다.** 기록 파일과 `state.json`이 그 역할을 이미
   한다. `report.md`는 산출물 목록에서 빠진다.
4. **`style.negatives`는 그대로 둔다** — 금지는 의존이 아니다 (vocab `negatives._role`:
   베이스 이미지에 파티클·글자가 들어오면 안 되는 것은 합성이 없어도 유효하다).
   씬별 오버레이 네거티브(`large red number text`)만 emphasis와 함께 사라진다.
5. 스펙 04의 `big_red_text` SFX 트리거 행도 함께 삭제한다 — 트리거 대상이 없다.

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| 파티클만 빼고 big_red_text는 유지 | 강조 연출의 자유도 | 화면 숫자의 경로가 인포씬과 이원화된다. 합성 텍스트에는 검수가 없다 | 인포씬이 정본이다 (ADR-0043·0047). 두 경로는 ADR-0020 위반이다 |
| `emphasis` 계약은 남기고 소비자만 없앰 | 되돌리기 쉬움 | 죽은 계약 필드 — [3s]가 고르는데 화면에 안 나온다. 관측(emphasis 수)이 거짓이 된다 | 죽은 접근자를 남기지 않는다 (ADR-0050의 청소 전례) |
| [11]을 state.json 요약으로 최소 구현 | 싸다 | 읽는 사람이 없다 — 단계 요약·기록을 사람이 이미 본다 | 필요해지는 조건(영상 재개)이 명확하니 그때 만든다 |
| [8]을 [9]의 drawtext로 흡수 | 단계 수 유지 | 흡수해도 그릴 것(emphasis)이 없다는 문제는 그대로다 | 문제는 구현 위치가 아니라 존재 이유다 |

## 결과

### 바뀌는 것

- 파이프라인: `… → [6i] → [7] → [9] → [10. mix] → final.mp4`. 남은 미구현은 `[10]`
  하나다
- specs/05(단계 목록·계약 표·[5]/[6] 규칙의 오버레이 문장·기록 파일의 "[11] 읽는 단계"),
  specs/03(오버레이 축·2계층 절 축소), specs/02(`emphasis` 필드), specs/04(big_red_text 행)
- `scene.schema.json`·`sceneplan.schema.json`의 `emphasis`, `vocab.json`의
  `overlay_type`·`overlay`, `beat-defaults.json`의 `overlay` 열 삭제
- `[5]`: `overlays`·`global_overlays` 산출 삭제, `[3s]` 프롬프트·세션 어휘 블록에서
  emphasis 삭제, 관련 요약 카운트 삭제. 구현에 묶인 테스트는 코드와 함께 간다
  (ADR-0034 §4)
- 픽스처의 `emphasis` 항목 제거 (스키마가 `additionalProperties: false`라 걷어야 통과한다)

### 되돌릴 조건

- **인포씬 검수 실패·강등이 반복되어 화면 숫자를 세울 길이 막히면** → 검수 가능한
  합성 텍스트(레이어 B)를 재도입하는 ADR로 돌아온다. 그때는 별도 단계보다 `[9]`
  drawtext 확장이 먼저다
- **영상이 재개되어(ADR-0053 되돌림) 강등·비용 관측이 다시 필요해지면** → 그때
  [11]을 실사용 요구에 맞춰 설계한다. 지금 스펙을 남겨 두지 않는 이유는 스펙이
  자산이라 틀린 스펙이 제일 비싸기 때문이다 (ADR-0034)
