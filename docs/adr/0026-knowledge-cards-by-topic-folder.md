# ADR-0026: 소스 카드와 인덱스를 토픽 축으로 정렬하되, 소속의 진실은 `topics:`에 남긴다

- 상태: 승인
- 날짜: 2026-08-12
- 관련 스펙: specs/06-topic-research.md, specs/05-pipeline.md
- 관련 ADR: **ADR-0012(평면 저장 — 본 ADR이 되돌릴 조건을 발동시킨다)**

## 맥락

ADR-0012는 `knowledge/sources/{source_id}.md` **평면 저장**을 정하고 "유적·시대별 디렉터리
트리"를 명시적으로 탈락시켰다. 사유는 두 가지였다 — **카드 0장 상태에서 분류 축을 확정하는
비용**, 그리고 **한 소스가 여러 유적에 걸친다**는 점.

같은 ADR이 되돌릴 조건을 이렇게 걸어 뒀다:

> 평면 목록에서 원하는 카드를 찾기 어려워지면 분류 체계와 선별 주입을 재설계한다.
> **그때는 축적된 카드의 `subjects`·`topics` 분포가 분류 축의 근거가 된다.**

**사람이 2026-08-12에 "폴더 구분이 없어 지저분하다"고 판단했다.** 조건이 발동했으므로
ADR-0012가 요구한 대로 실제 분포를 먼저 measure했다.

### 카드 49장의 실제 분포 (2026-08-12)

| 축 | 분포 |
|---|---|
| **`topics`** | `pisaui-satap-jiban-bogang` **27** / `hubeodaem-konkeuriteu-naenggak` **22** |
| `type` | reference 45 / status 4 |
| `subjects` | **고유값 10개.** 피사의 사탑 25 · 후버댐 22 · 나머지 8종은 1~4장 |

**27 + 22 = 49다. 모든 카드가 정확히 한 토픽에만 속한다.** ADR-0012의 존재 이유인
토픽 간 재사용은 **아직 한 번도 일어나지 않았다** — 토픽이 2개뿐이기 때문이다.

즉 `topics`는 지금 완벽한 분할이지만 **그것은 라이브러리가 어리다는 사실의 부산물이지
분류 축이 안정적이라는 증거가 아니다.** 걸치는 소스는 이미 나타났다:

```
en-wikipedia-org-85125c8c | Civic Tower (Pavia) | subjects: 파비아 시민탑, 피사의 사탑
```

파비아 시민탑(1989년 붕괴)은 피사 보강 공사의 직접적 계기다. 토픽이 늘면 이런 카드가
계속 나온다. `subjects` 축도 마찬가지다 — 고유값 10개 중 **3개가 1회만 등장**해서
1장짜리 폴더가 생긴다.

## 결정

**`knowledge/sources/{topic_slug}/{source_id}.md`. 단 폴더는 표시 규약이고, 소속의
진실은 frontmatter의 `topics:`다.**

| 항목 | 규칙 |
|---|---|
| 배치 | **최초 조사 토픽**(`topics:`의 첫 값) 폴더에 둔다 |
| **이동** | **하지 않는다.** 나중에 `topics:`가 늘어도 파일은 그 자리에 남는다 |
| 정체성 | `source_id`는 그대로다. 경로에서 파생하지 않는다 |
| 조회 | `load(source_id)`는 **재귀 탐색**으로 찾는다. 폴더를 몰라도 된다 |
| 소속 판정 | 코드는 **`topics:` frontmatter만** 읽는다. 경로를 파싱하지 않는다 |

**"이동하지 않는다"가 이 결정의 핵심이다.** 카드가 두 번째 토픽에 인용될 때마다 파일을
옮기면 git 이력이 흔들리고, 어느 폴더에 있는지가 조회 결과를 바꾸게 된다. 폴더는 사람이
훑기 위한 것이고 기계는 `topics:`를 본다 — **두 경로가 어긋나도 기계 쪽이 항상 옳다.**

이렇게 하면 ADR-0012가 탈락 사유로 든 "한 소스가 여러 유적에 걸침"이 **결정을 무너뜨리지
않는다.** 걸치는 카드는 처음 만난 토픽 폴더에 있고, `index.md`와 grep은 양쪽에서 찾는다.

### `index.md`도 같은 축으로 묶는다

폴더와 인덱스가 다른 축을 쓰면 사람이 두 체계를 외워야 한다. **인덱스도 토픽 섹션으로
나눈다.**

```
## pisaui-satap-jiban-bogang (27)
| source_id | 제목 | 유형 | 관련 유적 | 신선도 |
...
## hubeodaem-konkeuriteu-naenggak (22)
...
```

**폴더와 다른 점이 하나 있다 — 인덱스에서는 걸치는 카드가 `topics:`의 모든 섹션에
등장한다.** 파일은 한 곳에만 있을 수 있지만 표의 줄은 그렇지 않다. 이것이 폴더를 표시
규약으로 두고 `topics:`를 진실로 삼은 결정의 이득이다: **사람이 어느 토픽에서 찾아도
그 소스를 만난다.**

섹션 순서는 카드 수 내림차순, 동수면 슬러그 사전순으로 고정한다 — 재생성할 때마다
순서가 흔들리면 diff가 의미를 잃는다.

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **평면 유지 + `index.md`만 유적별로 묶기** | ADR-0012 변경 불필요, 걸치는 소스가 양쪽 섹션에 다 나옴, 코드 변경 최소 | 파일 탐색기로 볼 때는 여전히 49개 평면 | **사람이 폴더를 원한다** (2026-08-12). 인덱스만으로는 원하는 정리가 안 된다 |
| **`subjects` 첫 값으로 폴더** | 토픽보다 재사용에 가까운 축 | 고유값 10개 중 **3개가 1회만 등장** → 1장짜리 폴더가 생긴다. `subjects`는 자유 문자열이라 표기 흔들림이 곧 폴더 분열 | 슬러그 규칙이 없는 축으로 디렉터리를 만들면 오타 하나가 새 폴더가 된다 |
| **걸치는 카드를 복제** | 모든 폴더에서 보임 | 사본이 갈라진다. `교차확인` 갱신이 두 곳에 필요 | 카드는 단일 원본이어야 한다 (ADR-0012의 "두 번 다르게 요약" 방지) |
| **`topics:`가 늘 때마다 이동** | 경로가 항상 최신 | git 이력 churn, 조회가 경로에 의존 | 폴더를 계약으로 승격시키는 셈이다. 표시 규약으로 두는 것이 요점 |
| **`_shared/` 폴더에 다토픽 카드 모으기** | 걸치는 카드가 명확 | 두 번째 토픽이 붙는 순간 이동이 발생 | 위와 같은 문제 |

## 결과

**바뀌는 코드** (`src/shorts_factory/knowledge.py`)

| 대상 | 변경 |
|---|---|
| ~~`card_path(source_id)`~~ | **둘로 나눴다** — 조회와 배치는 다른 일이라 한 함수가 겸하면 "찾았느냐"와 "어디에 둘 것이냐"가 섞인다 |
| **`find_card(source_id)`** (신규) | 재귀 탐색. **없으면 `None`.** 평면 배치도 그대로 읽힌다 |
| **`placement_path(card)`** (신규) | **새** 카드를 둘 자리 = `sources/{topics[0]}/`. `topics`가 비면 `_unfiled/` |
| `save(card)` | `find_card() or placement_path()` — **기존 파일이 있으면 그 자리에 덮어쓴다**(이동 금지) |
| `load_all()` | `glob("*.md")` → `rglob("*.md")`. 정렬 키는 **파일명**이라 폴더가 줄 순서를 바꾸지 않는다 |
| `render_index()` | 평면 표 → **토픽 섹션.** 걸치는 카드는 모든 소속 섹션에 등장한다 |
| `injection()` | 표 잘라내기 기준을 첫 `\|` → 첫 `## `로 바꿨다. 안 그러면 **첫 섹션 제목이 잘려** 어느 토픽의 표인지 알 수 없다 |

**마이그레이션 (2026-08-12 완료).** 49장을 `git mv`로 옮겼다 — 피사 27 / 후버댐 22.
`source_id`가 안 바뀌므로 카드 본문은 손대지 않았고, `index.md`는 재생성했다.
**다토픽 카드는 0장이었으므로 배치에 판단이 개입한 카드가 없다.**

**추가한 테스트 6건** (`test_knowledge.py`, 801 → 807). 새로 생긴 불변식만 잠갔다:
새 카드의 배치 / **인용이 늘어도 이동하지 않음** / 평면 카드의 하위호환 / `topics` 없는
카드 / **걸치는 카드가 모든 섹션에 등장** / 섹션 정렬 순서.

**바뀌는 스펙**

```diff
-- `knowledge/sources/{source_id}.md` — 소스 1건당 카드 1장 (평면 저장)
+- `knowledge/sources/{topic_slug}/{source_id}.md` — 소스 1건당 카드 1장.
+  폴더는 **최초 조사 토픽**이고 표시 규약일 뿐이다. 소속의 진실은 frontmatter의
+  `topics:`이며, 카드는 나중에 다른 토픽에 인용돼도 **이동하지 않는다** (ADR-0026)
```

**되돌릴 조건**

- **토픽이 늘어 폴더가 수십 개가 되고 대부분이 1~2장이면** 평면으로 되돌리거나 상위
  축(유적군·시대)을 다시 검토한다. 지금은 토픽 2개에 27/22장이라 폴더가 의미 있다
- **걸치는 카드가 절반을 넘으면** 폴더가 사람에게도 거짓말을 하기 시작한다. 그때는
  ADR-0012의 평면 + 인덱스 분류로 복귀한다 (위 검토한 대안의 1번)
- `topics:`를 읽지 않고 **경로로 소속을 판정하는 코드가 생기면** 이 결정이 깨진 것이다.
  그런 코드는 리뷰에서 막는다
