# ADR-0095: **언어마다 씬의 절반을 새로 만든다** — ja는 홀수 씬, en은 짝수 씬. 클립 풀 하나를 셋이 공유하던 전제를 깬다

- 상태: **승인** (2026-09-04, 사람 — *"교체 절반으로가자. 일본은 홀수, 영어는 짝수 이렇게"*)
- 날짜: 2026-09-04
- 관련 스펙: `specs/05-pipeline.md`(`[7]`·`[9]`·`[9t]`·계약 표), `specs/03-visual-rules.md`
  (채널 룩), `specs/schema/channel-look.json`(언어별 값의 자리), `specs/schema/README.md`
- 관련 ADR: **개정** — ADR-0056 결정 5(클립 풀 공유), ADR-0059(3개 국어 공유는 라인과
  무관 — 여전히 무관하다, 공유의 범위만 준다). **잇는다** — ADR-0092(엔딩·썸네일을
  언어별로), ADR-0093(채널 그레이드). **유지** — ADR-0024(클립 기하), ADR-0072(생성·검수
  분리)

## 맥락

### 1. 같은 화면은 두 번째 채널부터 죽는다

한국어 채널의 조회수가 막힌 것을 사람이 보고 시작했다 (ADR-0092 맥락). `harrison-longitude`
실측: ko 62.90s / ja 83.00s / en 80.20s, MD5 전부 다름, 17개 씬 중 컷 시점이 같은 씬 0개 —
**그런데도 막혔다.** 순서는 항상 en 먼저 → ko 나중이라 뒤엣것이 죽었다. 이어서 엔딩 사진과
썸네일 판을 언어별로 가르고(ADR-0092) 채널마다 그레이드를 걸었는데(ADR-0093), 사람이 다시
보고했다 — *"tts 대본이 다른 동일 영상의 조회수가 0이야 … 유튜브 불펌 알고리즘에 자꾸 걸려"*
(2026-09-04). 오디오·길이·자막·엔딩·색이 다 달라도 걸린다. **남는 공통분모는 씬 클립의
픽셀이고, 그것이 원인이라는 것이 지금까지 나온 가장 강한 정황이다.** 지문 매칭은 재인코딩·
길이·오디오 교체·색·오버레이를 견디도록 만들어진 물건이라 후처리로는 못 피한다.

### 2. 값은 돈이 아니라 시간이다

`local` 라인의 `[7]`은 변동비 0이고 시드가 호출마다 랜덤이라 **다시 돌리면 다른 클립이
나온다** — 코드 변경 없이 실험이 된다. 실측(2026-09-03~04, 7편): `[7]`이 편당 60~72분,
씬당 3.3분. 언어 하나의 클립을 전부 새로 만들면 +60분, 절반이면 +30분이다.

### 3. "3개 국어가 거의 공짜"는 착시였다

지금 편당 100분에 쇼츠 3개가 나오지만 그중 2개가 조회수 0이라 **살아 있는 쇼츠 1개당
100분**이다. 언어별로 절반씩 새로 만들면 편당 ~160분에 3개가 살아 **쇼츠 1개당 53분** —
느는 게 아니라 준다. 다만 임계(몇 %까지 겹쳐도 되는가)는 아무도 모른다. 사람이 절반을
골랐고, 이 값이 되돌릴 조건 1의 관측 대상이다.

## 결정

**기본 풀 `clips/`는 그대로 두고, 그 위에 언어별 겹풀 `clips.{lang}/`을 씬의 절반만 채운다.
`[9]`는 그 언어의 겹풀에 있는 씬은 거기서, 없는 씬은 기본 풀에서 읽는다.**

1. **어느 씬이 누구 것인가는 계약값이다** — `channel-look.json` `meta.clip_scenes`:
   `ko: "all"` · `ja: "odd"` · `en: "even"`. `all`은 기본 풀(전 씬), `odd`/`even`은
   `scene_id`의 홀짝이다. 코드는 언어 이름을 손에 들지 않는다 (ADR-0034). 그 파일이 자리인
   이유는 그것이 **채널마다 화면을 가르는 값**의 파일이기 때문이다(ADR-0093의 그레이드와
   같은 지붕). 겹침은 ko–ja 50% · ko–en 50% · **ja–en 0%**다.
2. **겹풀의 클립 길이는 그 언어의 씬 길이 + 0.6초다** (정수 초 올림, 어댑터 범위로 클램프 —
   ADR-0024·0059의 산식 그대로, 입력 언어만 하나다). 기본 풀은 지금처럼 **있는 언어 전부의
   최장**이다 — 어느 언어가 그 씬을 기본 풀에서 읽을지는 씬마다 다르므로 최장이어야 한다.
   ko 겹풀은 없다(`all` = 기본 풀).
3. **`[7]`은 한 번 돌 때 기본 풀 → 겹풀 순서로 만든다.** 겹풀은 **판정에서 선택된**
   ko 아닌 언어(ADR-0094)만, 그 언어의 실측이 있을 때만. 프롬프트·검수·강등 사다리·기록
   형식은 기본 풀과 **같다** — `prompts.json`은 언어와 무관하고(ADR-0060), 겹풀 씬은 같은
   씬 계약을 새 시드로 다시 사는 것뿐이다. 기록은 `clips.{lang}.json`·`clip_review.{lang}.json`,
   검수 재료는 `clip_review.{lang}/`. 재실행 스킵은 풀마다 자기 기록으로 본다 (ADR-0020).
4. **`[9]`의 클립 조회는 "겹풀 먼저, 없으면 기본 풀"이다.** 파일 존재로 가른다 — 기록이
   아니라 파일이 정본이다(기록은 클램프 정보를 보태는 선택 입력, D-3). 겹풀이 통째로 없으면
   옛 편 그대로 돈다 (D-4).
5. **썸네일(`[9t]`)도 같은 조회를 쓴다** — ADR-0092의 판 씬 회전은 그대로이고, 그 씬의
   클립을 그 언어의 겹풀에서 먼저 찾는다.
6. **`--lang`이 주어지면 그 언어의 겹풀만 만든다** — 실험·재생성 자리다.

## 결과

### 바뀌는 것

- **`channel-look.json`** — `meta.clip_scenes` 추가, 제목·설명이 "언어별로 화면을 가르는
  값"으로 넓어진다. README 행 갱신.
- **`[7]`** — 풀 하나를 만드는 부분을 `_run_pool()`로 떼고 기본 풀 + 겹풀을 순서대로
  돈다. `VideogenResult`에 겹풀 결과가 붙는다. 요약에 풀별 씬 수·호출 수.
- **`[9]`·`[9t]`** — 클립 경로 조회 한 곳(`video/clips.py`의 `clip_for(run_dir, lang, sid)`).
- **스펙 05** `[7]`·`[9]`·`[9t]`·계약 표. **CLAUDE.md** "클립 풀 하나를 셋이 공유" →
  "기본 풀 하나 + 언어별 겹풀 절반".
- **비용** — 편당 GPU +60분(언어 둘 다 골랐을 때). 돈은 0.

### 되돌릴 조건

1. **절반으로도 두 번째 채널이 죽으면** — 임계가 50% 아래다. `clip_scenes`를 `all`로
   올린다(A안, 편당 +120분). 관측 수단은 업로드 뒤 조회수이고, **`ja`·`en` 어느 쪽이
   죽는지가 단서다**: ja–en은 0% 겹치므로 둘 다 죽으면 원인이 ko와의 50%이고, 한쪽만
   죽으면 다른 원인이다.
2. **절반이 살면 1/3을 시험한다** — 임계를 아래에서 찾는다. `clip_scenes`에 `third` 같은
   값이 필요해지면 그때 어휘를 넓힌다.
3. **겹풀 씬의 강등률이 기본 풀보다 뚜렷이 높으면** — 같은 프롬프트를 두 번 산 것이므로
   프롬프트가 아니라 검수 잣대의 흔들림이다. `clip_review.{lang}.json`이 관측 수단이다.
4. **언어가 넷이 되면** — 홀짝으로는 셋째 언어부터 겹친다. 그때 `clip_scenes`의 값을
   나머지(mod n)로 넓힌다.
