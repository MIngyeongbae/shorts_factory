# ADR-0032: 프록시 경계 — 정책 설정은 리포가 소유하고 Discord 통신만 외부에 남긴다

- 상태: 제안
- 날짜: 2026-08-13
- 관련 스펙: specs/05-pipeline.md
- 관련 ADR: ADR-0021(NB2 경로), ADR-0025(MJ 프록시), ADR-0030(참조 사진), ADR-0031(이미지 판정·병렬)

## 맥락

ADR-0025는 프로바이더를 골랐지만 **무엇이 우리 것이고 무엇이 남의 것인지는 정하지
않았다.** 그 공백이 실제 비용으로 나타났다.

### 문서에 적힌 설정은 코드가 아니다 — 드리프트 실증 (2026-08-13)

ADR-0025는 "잡 간격 30~180초, 일일 상한 200, 작업 시간대 제한 **전부 켠다**"고 적었고,
`enableRelaxToFast`는 "**반드시 OFF**(켜져 있으면 Relax 잡이 Fast로 넘어가 15시간을
태운다)"라고 못박았다. 프록시에서 실제 값을 읽었다.

| 항목 | ADR-0025 | **활성 계정** (Discord) | 비활성 계정 (공식 웹) |
|---|---|---|---|
| `interval`/`afterInterval*` | 30~180초 | **1.2초** | 30 / 180 ✓ |
| `dayDrawLimit` | 200 | **-1 (무제한)** | 200 ✓ |
| `dayRelaxDrawLimit` | 200 | **-1 (무제한)** | 200 ✓ |
| `workTime`/`fishingTime` | 켠다 | 없음 | 없음 |
| `enableRelaxToFast` | 반드시 OFF | **null (미설정)** | null |

**공식 웹 모드가 라이선스로 막혀 Discord 모드로 갈아탈 때 정책이 따라오지 않았다.**
설정은 옛 계정 오브젝트에 남았고 새 계정은 기본값으로 돌았다. 앞 세션이 27잡을 40초에
던진 것이 이것이고, 그것을 "relax 제출 40초"라는 성과로 기록했다 — **실제로는 ADR이
금지한 속도로 던진 것이다.**

아무도 몰랐던 이유는 단순하다. **그 값이 사는 곳이 컨테이너 안이고 리포에는 한 줄도
없다.** ADR 본문의 문장은 검사되지 않는다.

### 그래서 "프록시를 직접 만들자"는 물음이 나왔다

사람의 논거는 기능이 아니라 **소유권**이다 — "코드로 관리해야 수정을 할 수 있다."
맞는 원칙이다. 다만 프록시가 하는 일을 층으로 가르면 원칙을 적용할 자리가 갈린다.

| 층 | 지금 어디에 | 고칠 수 있나 |
|---|---|---|
| 요청 조립 (프롬프트·참조·모드·영상) | 우리 어댑터 | **완전히** |
| 재시도·타임아웃·동시성·큐·판정 | 우리 어댑터 | **완전히** |
| 프록시/계정 정책 (간격·상한·시간대·CAPTCHA) | 프록시 상태 | **API로 읽고 쓴다** (아래) |
| Discord Gateway 통신 (self-bot) | 프록시 내부 | 못 고친다 |
| MJ 서비스 | MJ | 못 고친다 |

3층은 REST로 완전히 열려 있다 — `GET/POST /mj/admin/setting`(211키)과
`POST /mj/admin/accounts`·`/mj/admin/account/{id}`(계정 109필드). **못 고치는 것이 아니라
아무도 관리하지 않고 있었다.**

진짜 블랙박스는 4층 하나다. 그리고 그 층은 **MJ가 커맨드를 바꿀 때마다 깨지는 층**이라
외부에 두는 것이 유일하게 이득인 층이기도 하다 (리포 마지막 커밋 2026-08-10, ⭐806).

## 결정

**경계를 3층과 4층 사이에 긋는다.** 1~3층은 리포가 소유하고 4층만 프록시에 남긴다.

### 1. 불변식은 `config/mj-proxy.policy.json`이 유일한 출처다

ADR-0025가 정한 값을 파일로 선언한다. **값을 바꾸려면 ADR-0025를 고친다** — 파일은
결정의 사본이지 결정 자체가 아니다.

- 계정 정책(간격·상한·시간대·모드 플래그)과 전역 설정(`enableVideo` 등) 중
  **우리가 의도를 가진 키만** 담는다. 나머지는 프록시 기본값에 맡긴다
- 선언하지 않은 키는 검사하지 않는다. **전부를 관리하려 들면 프록시 업그레이드마다
  깨지고, 그러면 아무도 안 본다**

### 2. `[6]`은 시작 전에 대조하고, 어긋나면 호출 없이 멈춘다

방언 대조(ADR-0027)와 같은 자리·같은 강도다. **이유도 같다** — 틀린 상태로 던진 잡은
되돌릴 수 없다. 방언은 편당 과금을 태우고, 정책 위반은 계정을 태운다.

- `--allow-policy-drift`로 명시하면 경고만 남기고 진행한다. `--allow-missing-anchors`의
  전례와 같다 (알고도 돌리는 것은 사람의 선택이다)
- 대조 결과는 `images.json`에 남긴다. 어느 편이 어떤 정책으로 만들어졌는지가 기록된다

**자동으로 고쳐 쓰지 않는다.** 프록시 상태를 조용히 바꾸는 것은 계정 하나를 공유하는
다른 작업(사람이 웹 UI에서 하는 일)을 덮어쓸 수 있다. 맞추는 것은 별도 명령
(`sf mj-policy apply`)으로 사람이 부른다.

### 3. 비밀은 리포에 들어가지 않는다

계정 오브젝트의 `userToken`·`cookie`·`botToken`·`loginPassword` 넷과 전역
`licenseKey`·`twoCaptchaKey`·스토리지 키들은 **policy 파일에 담지 않는다.** 정책 파일은
계정을 `id`로 가리키고 그 계정의 정책 필드만 말한다.

### 4. 어댑터가 프록시 기능을 다 노출한다

지금 `MidjourneyClient.submit()`은 `{"prompt": ...}` 하나만 보낸다. 프록시가 받는 것을
어댑터가 안 보내면 **그 기능은 없는 것과 같고, 없는 줄 알고 다른 결정을 하게 된다** —
ADR-0030이 "업로드 경로가 없을 수 있다"를 강등 사유로 적었던 것이 그 예다.

| 필드/경로 | 쓰임 |
|---|---|
| `base64Array` (imagine) | 참조 사진 첨부 (ADR-0030) |
| `/mj-fast/mj/submit/video` | `mj_video` (ADR-0025 §3) |
| `/mj/task/{id}/cancel` | 타임아웃 시 잡 정리 |
| `notifyHook` | 폴링 대신 콜백. 병렬 제출에서 폴링 비용을 없앤다 (ADR-0031) |
| `accountFilter` | 계정이 둘 이상일 때 대상 지정 |

### 5. 탈출 경로는 인터페이스가 이미 보장한다

`ImageClient`(`imagegen/base.py`)가 프로바이더 경계다. 자체 Discord 클라이언트가
필요해지면 **구현체 하나를 더 추가하는 일**이고 상류 단계는 바뀌지 않는다 — NB2 경로가
ADR-0025 이후에도 살아 있는 것과 같은 구조다. **이 결정은 되돌리기 싸다.**

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **프록시를 포크해 직접 빌드** | 4층까지 고칠 수 있다. 라이선스 DLL도 뗄 수 있다 | C#/.NET 빌드 체인이 들어온다 | 스택이 Python + FFmpeg다. 세 번째 언어의 빌드·배포·업스트림 머지를 지는 대가로 얻는 것이 4층인데, **그 층은 우리가 고치고 싶은 층이 아니다.** GPL-3.0이라 포크 자체는 언제든 가능하므로 문이 닫히지도 않는다 |
| **Discord 클라이언트를 자체 구현** | 완전한 소유 | 밴 회피를 다시 만들고 MJ 변경 추적을 진다 | 코드량(300~500줄)은 문제가 아니다. **잡 간격·일일 상한·시간대·CAPTCHA·계정 풀이 ADR-0025가 프록시를 고른 이유의 절반**이고, 그것을 다시 만드는 순간 이 프로젝트가 유지보수하는 대상이 된다. 위 표의 드리프트는 그 정책을 **더** 잘 관리해야 한다는 뜻이지 직접 만들라는 뜻이 아니다 |
| **현행 유지 (설정은 컨테이너에)** | 할 일 0 | 드리프트가 조용하다 | 이미 일어났다. ADR 본문에 30~180초라고 적힌 채로 1.2초로 돌았고 **성과로 기록됐다** |
| **정책을 코드로 두되 매 실행 자동 적용** | 항상 일치한다 | 사람이 웹 UI에서 한 일을 덮는다 | 계정 하나를 프록시 UI와 파이프라인이 공유한다. 조용한 덮어쓰기는 드리프트를 반대 방향으로 만드는 것일 뿐이다 |

## 결과

**새 파일**

| 파일 | 역할 |
|---|---|
| `config/mj-proxy.policy.json` | 불변식 선언. ADR-0025 결정의 사본 |
| `src/shorts_factory/imagegen/mj_policy.py` | 읽기·대조·적용 |

**바뀌는 것**

| 파일 | 변경 |
|---|---|
| `imagegen/midjourney.py` | `base64Array`·`video`·`cancel`·`notifyHook` 노출 |
| `stages/imagegen.py` | 시작 전 정책 대조 (방언 대조 옆), `--allow-policy-drift` |
| `cli.py` | `sf mj-policy show|apply` |
| `specs/05-pipeline.md` | `[6]` 규칙에 정책 대조 |

**당장 드러난 두 가지**

- **활성 계정이 ADR-0025 위반 상태였다.** 간격 1.2초 고정·상한 무제한. 이 발견으로
  **ADR-0025의 간격 정책이 정정됐다** (2026-08-13 "간격 정책 정정") — 원안의 30~180초는
  잡을 순차로 던지는 모델의 값인데 실제로는 동시 3에 완료 후 대기가 붙는 구조였다.
  채택값은 **1~10초 랜덤**이고, 문제는 간격의 길이가 아니라 `min == max`라 **규칙적이었던
  것**이다. policy 파일이 그 값을 선언한다
- **프록시 상태는 아직 어긋난 채다.** 맞추는 것은 `sf mj-policy apply` 구현 후이거나
  사람이 웹 UI에서 세 값(`afterIntervalMin`·`afterIntervalMax`·일일 상한 둘)을 고치는 것이다
- **ADR-0031 G3가 풀렸다.** `relaxCoreSize = 3`이다. 워커 기본값 3은 추정이 아니었고,
  더 나은 방법은 **하드코딩하지 않고 프록시에게 물어보는 것**이다

## 되돌릴 조건

- **policy 파일이 프록시 업그레이드마다 깨지면** 담은 키가 너무 많은 것이다. 밴에 직결되는
  넷(`afterIntervalMin`·`afterIntervalMax`·`dayDrawLimit`·`enableRelaxToFast`)만 남긴다.
  `workTime`/`fishingTime`은 ADR-0025가 "켠다"고만 하고 시간을 정하지 않아 **아직 선언하지
  않았다** — 값을 지어내지 않는다
- 대조가 상시로 걸려 `--allow-policy-drift`를 습관적으로 쓰게 되면 게이트가 죽은 것이다.
  그때는 값을 현실에 맞게 ADR-0025에서 고친다 — **문서를 현실에 맞추거나 현실을 문서에
  맞추거나 둘 중 하나여야 하고, 지금처럼 갈라진 채로 두는 것만 안 된다**
- 프록시가 죽거나 라이선스가 REST 표면까지 막으면 4층을 자체 구현한다. `ImageClient`
  구현체 추가이고 상류는 바뀌지 않는다
