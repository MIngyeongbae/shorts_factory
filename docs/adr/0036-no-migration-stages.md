# ADR-0036: 마이그레이션 단계를 두지 않는다 — `[1x]`·`[1y]` 삭제

- 상태: 승인
- 날짜: 2026-08-19
- 관련 스펙: specs/05-pipeline.md
- 관련 ADR: ADR-0012(소스 카드 — URL 정규화 중복 검사, 백필 필요를 탈락 사유로 씀), ADR-0018(`subject_scale` 신설 → `[1x]`), ADR-0022(`visual_goal` 신설 → `[1y]`), ADR-0027(마이그레이션 단계를 만들지 않는다), ADR-0028(백필 단계를 만들지 않는다), ADR-0029(`[1]` 분할), ADR-0034(자원 등급)

## 맥락

### 1. 이 프로그램은 앞만 본다 — 사람 판단 (2026-08-19)

> "이건 쇼츠를 만드는 프로그램이야. **새로운 걸 찾아 사용하는 거지 예전 것을 기용하는
> 경우는 상정하지 않았어.**"

이것이 이 ADR의 1차 근거다. 아래 실측과 인용은 전부 이 판단을 뒷받침하는 자료이지
판단을 대신하는 것이 아니다 (ADR-0034의 자원 등급 — 판단이 스펙·코드보다 위다).

**옛 산출물을 되살려 쓰는 경로는 이 파이프라인의 목적이 아니다.** 대본·프롬프트·이미지는
소재마다 새로 만든다. 계약이 바뀌면 다시 만들지, 지난 것을 고쳐 끼우지 않는다.

### 2. 뒤를 보는 장치는 딱 하나이고, 그것도 최소다

과거를 참조하는 곳이 프로젝트에 하나 있다 — **같은 내용의 쇼츠를 두 번 만들지 않기 위한
중복 검사**다. 그 범위가 ADR-0012에 이렇게 정해져 있다.

```
source_id는 URL 정규화 후 {호스트}-{sha256 앞 8자}. URL이 없으면 카드를 만들지 않는다
                                            — ADR-0012, specs/06-topic-research.md:104
```

**URL 하나로 같으냐 다르냐만 본다.** 내용 비교도, 임베딩도, 과거 산출물 로딩도 없다.
이것이 "예전 것"에 대해 이 프로그램이 하는 일의 전부이고, **이 선을 넘기지 않는다.**
마이그레이션은 이 선의 바깥이다.

### 3. 같은 규칙이 이미 세 번 쓰였는데 코드만 남아 있었다

| ADR | 날짜 | 문장 |
|---|---|---|
| ADR-0012 | 08-10 | `fact.source_ids` 강제안을 **"기존 산출물 백필 필요"를 탈락 사유로** 적어 떨어뜨렸다 |
| ADR-0027 | 08-13 | "`[5]`는 무료·결정적이므로 다시 돌리면 된다 — **마이그레이션 단계를 만들지 않는다**" |
| ADR-0028 | 08-13 | "옛 대본 3편이 그대로 계약을 만족한다. **백필 단계(`[1x]`·`[1y]` 같은)를 만들지 않는다**" |

규칙은 세 번 쓰였고 지켜졌다. **문제는 규칙이 서기 전에 만들어진 두 개가 그대로 남아
스펙과 `sf --help`에 상시 단계처럼 서 있었다는 것이다.**

### 4. 언제·왜 들어갔나

| 날짜 | 커밋 | 무엇 |
|---|---|---|
| 2026-08-11 | `d3d4e08` | `[1x] backfill-scale` — ADR-0018이 `subject_scale`을 required로 추가 |
| 2026-08-11 | `3cfbc93` | `[1y] backfill-visual-goal` — ADR-0022가 `visual_goal`을 required로 추가 |

붙인 이유는 하나였다 — **그날 이미 사람 승인이 끝난 대본 2편이 있었고 `[1]`을 다시 돌리면
대본 자체가 달라진다**(피사는 재생성 2회 만에 수렴한 것이다). 한 번 쓰고 끝나는 도구였고
실제로 여드레 만에 소진됐다. 마지막으로 코드가 움직인 날은 2026-08-13이다.

### 5. 실측 — 대상이 0건이다

리포 안의 확정 대본 전수다.

| 파일 | 씬 | `subject_scale` 있는 씬 | `visual_goal` 있는 씬 |
|---|---|---|---|
| `topics/hubeodaem-konkeuriteu-naenggak/06-script.json` | 28 | **28** | **28** |
| `topics/pisaui-satap-jiban-bogang/06-script.json` | 25 | **25** | **25** |

두 단계 다 "전 씬에 값이 있으면 세션을 부르지 않는다"가 계약이라 **지금 부르면 즉시
스킵으로 끝난다.** `docs/pipeline-status-2026-08-19.html`이 "남은 대상은 피사 편
하나뿐"이라고 적어 둔 것은 이미 틀린 서술이다.

새로 생길 일도 없다 — 두 필드는 씬 계약의 **required**이고
(`specs/schema/scene.schema.json` → `$defs.scene.required`), 새 대본은 `[1s. sceneplan]`이
직접 낸다 (ADR-0029). 안 내면 `[2. validate]`가 건다. 백필을 탈 기회 자체가 없다.

### 6. 남겨 두는 비용

| 자리 | 분량 |
|---|---|
| 스테이지 모듈 2개 | 약 430줄 |
| 전용 프롬프트 2개 | 이 두 단계 말고 읽는 곳이 없다 |
| 테스트 2파일 | **35개** (979개 중). 전부 구현에 묶여 있다 (ADR-0034 §4) |
| `cli.py` 서브커맨드 2개 | `sf --help`에 상시 노출 |
| `specs/05-pipeline.md` | 파이프라인 도식과 단계 규칙에 **상시 단계처럼** 자리를 차지한다 |

### 7. 코드 의존은 없다 — 인용만 남는다

`assert_only_scale_changed`(쓰기 전 전수 대조 가드)를 `[1w. write]`가 **개념으로** 물려받았고
스펙 05:129와 `schemas/sceneplan.py:220`이 "`[1x]`·`[1y]` 백필이 쓴 패턴이다"로 적고 있다.
다만 `[1w]`는 **자기 구현**(`sceneplan.carried_fields()`)을 갖고 있고 import가 없다.

```
$ grep -rn "backfill_scale|backfill_visual_goal|assert_only_scale_changed" --include=*.py
  → cli.py 만 나온다 (import 2줄 + 커맨드 2개 + 예외 튜플 1곳)
```

**끊어지는 것은 코드가 아니라 문장이고, 그 문장은 과거형이다.**

## 결정

**둘이다.**

**(1) 마이그레이션·백필 단계를 만들지 않는다.** 계약이 바뀌어 옛 산출물이 스키마를 어기면
**다시 만들거나 버린다.** 고쳐 끼우는 단계를 파이프라인에 두지 않는다. 과거를 보는 장치는
ADR-0012의 **URL 정규화 중복 검사 하나뿐이고 그 이상으로 키우지 않는다** — 목적이
"같은 쇼츠를 두 번 만들지 않는다"까지이지 "지난 산출물을 재사용한다"가 아니기 때문이다.
ADR-0027·0028이 개별 상황에서 내린 판단을 여기서 **상시 규칙으로 올린다.**

**(2) `[1x. backfill-scale]`과 `[1y. backfill-visual-goal]`을 삭제한다.** 스테이지 모듈 2개,
전용 프롬프트 2개, CLI 서브커맨드 2개, 구현에 묶인 테스트 2파일, `specs/05-pipeline.md`의
두 단계 항목을 없앤다.

**ADR과 worklog의 과거 언급은 손대지 않는다** — 왜 만들었고 왜 없앴는지의 기록이고,
자원 등급에서 코드보다 위다 (ADR-0034). 스펙 05:129와 `sceneplan.py:220`의 "백필이 쓴
패턴이다" 인용도 **과거형 그대로 둔다.**

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **그대로 둔다** | 손댈 것이 없다. 언젠가 required 필드가 또 늘면 쓸지도 모른다 | 대상 0건인 단계가 스펙 도식과 `sf --help`에 상시로 선다. 테스트 35개가 계속 돈다 | **"언젠가"가 이 프로그램의 상정 밖이다** (§1). ADR-0027·0028이 그 "언젠가"에 이미 **만들지 않는다**로 답했다 |
| **코드는 두고 스펙 05에서만 뺀다** | 스펙에서 상시 단계처럼 보이는 문제가 사라진다 | 스펙이 모르는 CLI 커맨드가 남는다 | **자원 등급을 거꾸로 간다** (ADR-0034). 스펙이 모르는 코드가 도는 것이 이 프로젝트가 가장 비싸게 치르는 형태다 |
| **둘을 합쳐 범용 백필 단계 하나로 만든다** (`sf backfill --field X`) | 다음에 required가 늘면 재사용한다 | 쓸 곳이 없는 것을 **더 일반화**한다. 세션에 보여줄 것이 필드마다 다르다(`[1x]`는 `subject`만, `[1y]`는 `text`까지) — 일반화하면 그 차이가 인자로 샌다 | **결정 (1)의 정면 위반이다.** 마이그레이션을 안 하기로 한 자리에서 마이그레이션 프레임워크를 만드는 셈이다 |
| **중복 검사를 내용 비교까지 넓혀 옛 산출물을 재활용한다** | 만든 것을 버리지 않는다 | 과거 산출물을 읽고 판단하는 경로가 새로 생긴다 | **목적이 다르다** (§2). 중복 검사의 목적은 같은 쇼츠를 두 번 안 만드는 것까지다. URL 한 줄로 되는 일에 내용 비교를 붙이면 뒤를 보는 코드가 파이프라인 안으로 들어온다 |

## 결과

- 삭제: `stages/backfill_scale.py`, `stages/backfill_visual_goal.py`,
  `prompts/06-subject-scale.md`, `prompts/07-visual-goal.md`,
  `tests/test_backfill_scale.py`, `tests/test_backfill_visual_goal.py`
- `cli.py` — import 2줄, `_cmd_backfill_scale`·`_cmd_backfill_visual_goal`, 파서 2개,
  예외 튜플의 `BackfillStageError`
- `specs/05-pipeline.md` — 파이프라인 도식의 두 줄, 단계 규칙의 `[1x]` 항목
- `docs/pipeline-status-2026-08-19.html` — `[1x] [1y]` 행
- 테스트 **979 → 944**. 씬 계약(required 두 필드)을 지키는 테스트는 그대로다
- **비용 변화 없음.** 두 단계 다 텍스트 세션이고 지금은 스킵으로 끝난다

### 무엇이 대신 지켜 주는가

두 필드가 비면 `[2. validate]`가 씬 계약 위반으로 건다 — 백필이 지키던 것이 아니라
**스키마가 지키던 것**이다. `[1s. sceneplan]`이 두 필드를 직접 내는 것도 그대로다.

앞으로 계약이 또 바뀌면 답은 **다시 만들거나 버린다** 하나다. `[5] prompt`가 그 전례다 —
ADR-0027이 `style.dialect`를 required로 올릴 때 옛 `prompts.json`을 마이그레이션하지 않고
**다시 돌렸다.** 비용 0이었다.

### 되돌릴 조건

**이 금지를 되돌리는 것은 실측이 아니라 사람의 판단이다.** "대본을 다시 못 만든다"가
성립하는 상황이 실제로 오면 — 그때도 기본은 버리는 쪽이고, 살리기로 정하면 그 판단을
새 ADR로 남긴 뒤 그때의 코드로 만든다. **`git log`에서 이 두 모듈을 꺼내 되살리지 않는다.**
