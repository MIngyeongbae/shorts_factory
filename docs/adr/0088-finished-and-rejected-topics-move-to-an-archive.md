# ADR-0088: 끝난 토픽은 `topics/_archive/`로 간다 — **옮기는 시점은 `[10] upload`**이고 `topic_dir`이 두 자리를 본다

- 상태: **승인** (2026-09-01, 사람 — "자리 옮기는건 구글 드라이버에 업로드하는 시점에 옮기고, 지금은 처음하는거니깐 현역빼고는 다 옮겨")
- 날짜: 2026-09-01
- 관련 스펙: `specs/06-topic-research.md`(토픽 패키지 구조), `specs/05-pipeline.md`(단계 I/O의 입력 경로)
- 관련 ADR: **유지** — ADR-0049(토픽 패키지가 산출물의 단위다), ADR-0009(2부 진입 게이트는
  `judgment/human.json`), ADR-0020(단계는 기록 파일을 남긴다), ADR-0034(값의 출처는 하나)

## 맥락

### 1. `topics/`가 45개다 — 사람이 다음에 할 일을 못 찾는다

사람 지시(2026-09-01): *"토픽이 지금 너무 많아졌어 진행했던 토픽이나 반려된 토픽은 따로 폴더
만들어서 보관하자."*

실측(2026-09-01):

| | 개수 |
|---|---|
| 토픽 폴더 전체 | **45** |
| 업로드까지 끝난 것 (`runs/*/upload.json` 존재) | **24** |
| 2부 미착수 (`clips.json` 없음) | **21** |
| 2부 착수했으나 미업로드 | **0** |

중간 상태가 0이라 **경계가 이미 이분되어 있다.** 사람이 `topics/`를 열었을 때 눈에 들어와야
하는 것은 뒤의 21개인데 24개가 그 앞을 덮는다.

### 2. 판별 축은 `STATUS.md` 머리글이 아니라 **생산 상태**다

`STATUS.md` 머리글로 나누면 틀린다. 지금 `go` 30개 중 **6개는 2026-09-01에 판정만 받은
2부 미착수분**(`goryeo-celadon`·`silla-gold-crown`·`korean-dolmen`·`hoover-dam-cooling`·
`brooklyn-bridge-wire`·`harrison-longitude`)이다. `go`를 기준으로 옮기면 **방금 승인한 편들이
보관함으로 들어간다.**

기계가 읽을 수 있는 정확한 축은 둘이다:

- **제작완료** = 그 토픽의 `runs/{run_id}/upload.json`이 있다 (ADR-0084가 만든 기록 파일)
- **반려** = `judgment/human.json`의 `decision`이 `no_go`다 (ADR-0009·스펙 07)

### 3. 옮기기만 하면 2부 재실행이 조용히 깨진다 (코드 실측)

`Paths.topic_dir(slug)`는 `topics/{slug}` 한 줄이고(`config.py:118`), 이것을 읽는 자리가
**1부만이 아니다**:

| 소비자 | 읽는 것 |
|---|---|
| `stages/draft.py`·`factcheck.py`·`localize.py` | `seed-body.md`·`script.md`·`factcheck.md` |
| **`stages/scenetable.py:335,345`** | **`script.md`·`factcheck.md`** |
| **`stages/prompt.py:524,528`** | **`script.md`·`factcheck.md`** |
| `judgment.py:46` | `judgment/human.json` |

즉 **`[3s]`와 `[5]`는 2부인데도 토픽 폴더를 읽는다.** 보관된 편을 다시 조립하거나 프롬프트를
다시 뽑으려면 그 경로가 살아 있어야 한다. 실제로 이 프로젝트는 완료된 편을 다시 건드린
전례가 있다 — 12차의 `retry-janggyeong-part2.sh`·`retry-gakgung-part2.sh`가 `runs/logs/`에 남아 있다.

### 4. `topics/`를 훑는 코드는 없다 (실측)

`glob`·`iterdir`·`listdir`·`scandir`로 `topics/`를 열거하는 자리는 **0곳**이다(`imagegen/base.py`·
`assemble.py`·`ending.py`의 `iterdir`은 앵커·폰트 디렉터리다). `[0] seed`도 폴더를 훑지 않고
`topics/backlog.md`를 파싱한다. **그러므로 `topics/` 아래에 하위 폴더를 하나 더 만들어도
깨지는 소비자가 없다.**

### 5. 옮길 때 알고 가야 하는 예외 하나

`zipper-late-adoption`은 `upload.json`이 있지만 **`timeline.en.mp4`가 없어 ko·ja 2편만**
올라갔다(다른 23개는 3편씩). 제작완료 기준(`upload.json` 존재)에는 걸리지만 실제로는 en이
빠진 편이다. 이 ADR은 **기준을 예외로 흐리지 않는다** — 보관하되 사람이 아는 상태로 둔다.

## 결정

**제작완료·반려 토픽을 `topics/_archive/{slug}/`로 옮기고, `Paths.topic_dir`이 `topics/{slug}`를
먼저 보고 없으면 `topics/_archive/{slug}`를 본다.**

1. **자리는 `topics/_archive/`다.** 새 최상위 디렉터리를 만들지 않는다 — 토픽의 정본 목록인
   `topics/backlog.md`와 같은 지붕 아래 있어야 짝이 맞는다. `_` 접두는 슬러그가 될 수 없는
   문자라(`[a-z0-9-]`, ADR-0011) 토픽 이름과 절대 충돌하지 않는다.
2. **옮기는 기준은 생산 상태다.** ① `runs/{run_id}/upload.json`이 있다(제작완료) **또는**
   ② `judgment/human.json`의 `decision`이 `no_go`다(반려). `STATUS.md` 머리글은 기준이 아니다
   (맥락 2).
3. **`topic_dir`은 두 자리를 본다.** `topics/{slug}`가 있으면 그것, 없고 `topics/_archive/{slug}`가
   있으면 그것. **둘 다 없으면 `topics/{slug}`를 돌려준다** — 새로 만드는 쪽은 언제나 현역
   자리이고, 보관함에 새 토픽이 생기는 일은 없다.
4. **옮기는 시점은 `[10] upload`다** (사람 결정 2026-09-01). 사람이 따로 정리하는 작업이
   아니라, 드라이브 업로드가 끝나면 그 단계가 이어서 옮긴다. **모든 언어가 성공했을 때만**
   옮긴다 — 실패한 언어가 있으면 아직 손이 갈 편이라 현역에 남는다.
   **옮기기는 업로드의 조건이 아니라 뒷정리다**: 실패해도 경고만 남기고 단계는 성공이다.
   파일은 이미 드라이브에 올라간 뒤라, 여기서 예외를 올리면 올라간 편이 실패로 기록된다.
5. **이동은 `git mv`다.** 파일 이력이 끊기면 "이 대본이 왜 이렇게 고쳐졌나"를 잃는다.
   미추적 폴더는 일반 이동이다.
6. **되돌리는 것도 이동이다.** 보관된 편을 다시 만들려면 `topics/_archive/{slug}`를
   `topics/{slug}`로 옮긴다. 코드가 두 자리를 보므로 옮기지 않아도 돌지만, 현역 목록에
   보이는 것이 사람에게 맞다.

`topics/backlog.md`는 **옮기지 않는다.** 보관 여부와 무관하게 소재 목록의 정본은 하나다
(ADR-0034) — 발굴이 중복 제안을 피하려고 읽는 표가 둘로 갈리면 그 목적이 깨진다.

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **A. 완료 토픽을 지운다** | 가장 단순하다 | `script.md`·`factcheck.md`는 LLM 세션 3회를 들여 만든 자산이고 근거 URL이 붙어 있다. 재발굴 시 중복 판정의 근거이기도 하다 | **자산 파괴.** 사람도 "보관하자"라고 했지 지우자고 하지 않았다 |
| **B. 최상위 `archive/topics/{slug}`** | `topics/`가 현역만 남아 가장 깨끗하다 | 최상위 디렉터리가 하나 는다. 소재의 정본 표(`topics/backlog.md`)와 패키지가 다른 지붕 아래로 갈린다 | 이득이 `_archive`와 같은데 구조만 흩어진다 |
| **C. 옮기지 않고 `STATUS.md`로만 구분한다 (현행)** | 코드 변경 0 | 지금 상태다. 45개가 한 화면에 안 들어온다는 것이 문제 제기의 출발점이다 | **문제를 해결하지 않는다** |
| **D. 옮기되 `topic_dir`은 그대로 둔다** | 코드 변경 0 | `[3s]`·`[5]`가 `script.md`를 못 찾아 **보관된 편의 2부 재실행이 깨진다.** 실패가 "파일 없음"으로 뜨므로 원인 추적도 사람 몫이 된다 | 맥락 3의 실측이 탈락시킨다 |
| **E. 심볼릭 링크를 남긴다** | 경로가 둘 다 산다 | Windows에서 심링크 생성은 관리자 권한 또는 개발자 모드가 필요하다. git이 링크를 다루는 방식도 플랫폼마다 다르다 | 이 PC가 Windows다 (환경 실측) |
| **F. 슬러그에 접두를 붙여 정렬로 민다 (`z-cochineal-red`)** | 폴더가 안 늘어난다 | 슬러그는 run_id(`{날짜}-{slug}`)의 일부라 이름을 바꾸면 **`runs/`와의 연결이 끊긴다** | 백로그 머리말이 "이미 폴더가 만들어진 항목은 바꾸지 않는다 (run 연결이 슬러그에 걸려 있다)"고 못박아 둔 자리다 |

## 결과

### 바뀌는 것

- **코드** — `config.py`의 `Paths`에 `topics_archive` 프로퍼티 추가, `topic_dir`이 두 자리를
  보도록 3줄. **다른 단계는 손대지 않는다** — 전부 `topic_dir`을 통해 들어온다.
- **파일 이동** — 25개(`upload.json` 있는 24 + `no_go` 1 = `jongmyo-jeongjeon`).
  `topics/` 현역은 **45 → 20**이 된다.
- **스펙** — `specs/06-topic-research.md`의 토픽 패키지 구조 절에 보관 자리를 적는다 (아래 diff).
- **비용** — 0. 디스크 이동뿐이고 `runs/`는 건드리지 않는다.

### 되돌릴 조건

1. **보관된 편의 2부 재실행이 실패하면** — `topic_dir` 폴백이 안 먹는 경로가 남아 있다는
   뜻이다. 그 경로를 찾아 고치거나, 못 고치면 이동을 되돌린다. 관측 수단은 재실행 로그다.
2. **`_archive`가 다시 20개를 넘어 사람이 못 찾게 되면** — 그때는 평면 보관이 한계다.
   연도·회차별 하위 폴더(`_archive/2026-08/`)로 한 겹 더 나눈다.
3. **`topics/`를 훑는 코드가 새로 생기면** — 지금은 0곳이라 안전하지만, 누군가
   `topics/*/`를 열거하면 `_archive`가 토픽으로 잡힌다. 그때는 그 코드가 `_`로 시작하는
   디렉터리를 거르게 한다.
