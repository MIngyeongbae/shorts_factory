# ADR-0053: 영상 경로 일시 정지 — 만족할 때까지 파이프라인 기본은 정지 이미지 클립

- 상태: 승인 (2026-08-22, 사람 결정 — 지시가 곧 승인이다)
- 날짜: 2026-08-22
- 관련 스펙: specs/05-pipeline.md, specs/03-visual-rules.md, specs/02-beat-schema.md,
  specs/schema/beat-defaults.json, specs/schema/vocab.json
- 관련 ADR: ADR-0039(전 씬 영상 — 본 ADR이 **정지**시킨다, 폐기가 아니다),
  ADR-0043(인포씬 Veo — 함께 정지, G2 미결이 근거), ADR-0041(영상 입력 계약 — 유지),
  ADR-0006(kenburns zoompan의 출처), ADR-0025 §3(강등 사다리)

## 맥락

### 1. 사람 결정 (2026-08-22)

> "이미지를 영상으로 만드는 파이프라인은 지금은 안되게해줘. 계속 테스트해서
> 만족스러운 정도의 결과물이 나오면 영상을 만들어서 붙이게, 지금은 정지이미지가
> 나오게 파이프라인을 수정해."

**정지이지 폐기가 아니다.** 만족 판정이 나면 되살린다 — 그때까지 영상 경로는
명시 플래그로만 도는 테스트 전용 차선이다.

### 2. 실측 — 영상 품질은 아직 만족 판정을 받은 적이 없다

- **인포씬 Veo는 미결 사고가 열려 있다** (ADR-0043 G2). 순차 조립 지시를 넣으면
  표본 2/2에서 텍스트 사고 — 라벨 뭉개짐, 계약에 없는 영어 라벨. 트림 지점이
  안전하다는 보장이 없고 선택지는 사람 결정 대기다
- **MJ 영상에는 결과 검수 게이트가 없다.** 이미지는 `[6r]`이 보지만 영상 클립은
  아무도 판정하지 않는다 — 지금까지의 산출물로 사람 만족을 얻지 못했다
- **벽시계의 대부분이 영상이다** (specs/05 비용 기준선): 28씬 편당 약 36분 중
  영상이 32분이다 (relax 1잡 206초). 정지 이미지 클립(kenburns)은 27씬 2분이다
- **Veo·NB2는 유일한 변동비다** (ADR-0043). 영상을 정지시키면 Veo 지출이 기본 0이
  된다 — NB2 편집(`[6i]`)은 이미지 편집이라 영상 정지와 무관하게 남는다

### 3. 강등으로 기록하면 안 되는 이유

`[7]`의 강등(`demoted_from`)은 **요청했는데 못 만든 것**의 기록이다 (ADR-0039
"강등을 조용히 하지 않는다"). CLI 기본만 끄고 `motion` 기본값을 `mj_video`로 두면
전 씬이 매 실행 강등으로 기록·경고되어, 리포트의 강등 수가 "실패"와 "정지 정책"을
구분하지 못하게 된다 — 관측 수단이 죽는다.

## 결정

1. **파이프라인 기본 산출은 정지 이미지 클립이다.** `beat-defaults.json`의
   `fallback.motion`을 `mj_video` → `kenburns`로 바꾼다. `[3s]`는 여전히 `motion`을
   고르지 않으므로(ADR-0039의 그 규칙은 유지) 씬이 비우면 정지 이미지가 된다.
   카메라 워크는 씬 계약의 `camera`를 그대로 zoompan에 건다 — 계약이 `static`이면
   완전 정지다. 정지 기본의 화면 리듬은 레퍼런스 실측(느린 줌·틸트·팬)과 같은 대역이다
2. **`[7] motion`의 CLI 기본을 끈다.** `--video` 기본 `midjourney` → `none`,
   `--info-video` 기본 `veo` → `none`. **영상 테스트는 명시 플래그로 계속한다**
   (`--video midjourney`, `--info-video veo`) — "계속 테스트해서 만족되면"의 자리가
   이 플래그다
3. **인포씬은 INFO 정지(`info_still`)로 돈다** (ADR-0043 개정의 `--info-video none`
   칸 그대로). 라벨은 화면에 남고 `demoted_from: veo` 기록도 ADR-0043 계약대로
   남는다 — 인포씬의 영상 설계는 살아 있고 실행만 정지라서, 이 기록은 거짓이 아니다
4. **영상 계약·어댑터·코드는 지우지 않는다.** `image_source.json`(ADR-0041)·
   `videogen/`·`[7]`의 `mj_video`·`veo` 분기·`batchSize: 1`(ADR-0039 §3) 전부 유지 —
   되살릴 실물이고 테스트 차선이 지금도 쓴다. `[6]`의 fast 제출(ADR-0039)도 유지 —
   GPU 예산(월 80편)이 그대로 성립한다
5. **아무 씬도 영상을 요구하지 않는 실행에서는 "영상 프로바이더가 없다" 경고를 내지
   않는다.** 정지가 기본인 세계에서 그 경고는 거짓 강등 보고다 (맥락 3). 씬 계약이
   명시적으로 `motion: mj_video`를 든 씬이 있을 때만 지금처럼 경고·강등한다

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| 영상 경로 코드·계약 삭제 | 파이프라인 단순 | 되살릴 때 전부 재구현. ADR-0039·0041·0043의 실측이 코드와 함께 죽는다 | 사람 결정이 "계속 테스트해서 만족되면 붙인다"다 — 정지이지 폐기가 아니다 |
| CLI 기본만 `none` (`motion` 기본값은 `mj_video` 유지) | 변경이 두 줄 | 전 씬이 매 실행 `demoted_from=mj_video`로 기록·경고 — 강등 관측이 죽는다 (맥락 3) | 정책 정지를 실패 기록으로 남기면 안 된다 |
| `motion` 기본을 `static`으로 | 문자 그대로 정지 화면 | `[3s]`가 이미 고른 `camera` 계약값이 전부 사장된다. 레퍼런스 실측의 느린 워크도 버린다 | `kenburns`가 `camera: static`을 포함한다 — 더 넓은 값이 계약을 살린다 |
| `[7]` 단계 자체를 스킵하고 `[9]`가 이미지를 직접 받게 | 단계 하나 절약 | `[9]`의 입력 계약(클립)이 바뀐다 — 단계 독립 D-4 위반. 되살릴 때 또 바꿔야 한다 | 계약 변경 두 번짜리 우회다. 클립은 그대로 두고 내용만 정지로 |

## 결과

### 바뀌는 것

- `specs/schema/beat-defaults.json`: `fallback.motion` = `kenburns`, description 갱신
- `specs/schema/vocab.json`: `motion._role`·`kenburns`·`mj_video` gloss 갱신
  (기본/강등 결과 서술이 뒤집힌다 — 어휘 enum 자체는 그대로)
- `cli.py`: `--video`·`--info-video` 기본 `none`, 도움말 갱신
- `stages/motion.py`: 결정 5의 경고 게이트, 문서화 갱신
- specs/05(`[7]`·확정된 결정·비용 기준선), specs/03(모션 행·인포씬 절),
  specs/02(`motion` 필드), CLAUDE.md, README
- 테스트: "기본값이 영상" 계약 테스트를 "기본값이 정지"로 갱신 (ADR-0034 §4 —
  구현에 묶인 단언은 코드와 함께 간다)

### 바뀌지 않는 것

- 클립 기하(씬 길이 + 0.6초 꼬리, ADR-0024), `[9]`의 입력 계약, 강등 사다리의 모양
  (`veo → info_still → mj_video → kenburns → static`), `image_source.json` 생산,
  `[6i]` NB2 편집, `[6]` fast 제출, `kling` 어휘(MJ 밴 대비 차선 — ADR-0025 §3)

### 되돌릴 조건

- **사람이 영상 테스트 결과에 만족한다고 판정하면** → `fallback.motion`을
  `mj_video`로, CLI 기본을 `midjourney`/`veo`로 되돌리는 개정 ADR. 결정 4가 코드를
  살려 두었으므로 되돌림은 그 두 기본값이 전부다
- 인포씬 Veo는 **ADR-0043 G2(순차 조립 지시의 텍스트 사고)가 함께 풀려야** 돌아온다
- 정지 이미지 편의 시청 지표가 영상 편 대비 유의하게 나쁘면 → 만족 기준을 낮춰서라도
  영상을 앞당길지 사람이 재검토한다
