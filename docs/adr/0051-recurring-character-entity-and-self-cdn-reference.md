# ADR-0051: 인물 소재 확장 — 씬 계약에 선택적 인물 엔티티, 캐릭터 시트 선행 생성 + MJ 자기 CDN 참조 주입

- 상태: 승인 (2026-08-21)
- 날짜: 2026-08-21
- 관련 스펙: specs/02-beat-schema.md, specs/03-visual-rules.md, specs/05-pipeline.md,
  specs/schema/scene.schema.json, specs/schema/vocab.json
- 관련 ADR: ADR-0028(텍스트 앵커의 상한), ADR-0030(실물 참조 — 이 결정의 실물판),
  ADR-0041(사이드카 계약 패턴), ADR-0042(앵커 언어), ADR-0046(로컬 미노출 — 이 결정이
  피해 가는 벽), ADR-0033 §3(닫힌 어휘), ADR-0019(씬당 1장=1호출의 예외 1건),
  ADR-0047(매체 적합성 게이트 — 도메인은 이미 열려 있다)

## 맥락

### 1. 도메인은 열려 있는데 인물 일관성 장치가 없다

소재 도메인에 제한이 없고(ADR-0033) 게이트는 "그림이 이해를 보조할 수 있는가"
하나다(ADR-0047). 괴담·설화·역사처럼 **사람이 서사를 지는 소재**가 이 게이트를 통과하는
경우가 있다 — 예: 원효대사 해골물(어두운 동굴 → 달게 마신 물 → 아침의 해골, 시각 서사가
설명을 직접 진다). 그런데 파이프라인에는 "같은 인물이 여러 씬에서 같은 사람으로 보이게
하는" 장치가 없다. `vocab.json`의 framing은 전부 구조물·부지용이고, specs/03에 인물
규칙은 0건이다.

### 2. 텍스트만으로는 안 된다 — 실측이 이미 있다

고유명사 앵커는 **모델이 이미 아는 대상**에만 통한다(후버댐 4/4 — ADR-0028·0030).
원효대사를 MJ가 모르면 "스님"은 씬마다 다른 스님으로 나온다. 건축물은 `[4] refpack`의
실사진으로 풀었지만, **역사·설화 인물은 실사진 자체가 없다.** 참조를 우리가 만들어야 한다.

### 3. 첨부는 막혔지만 생성 참조는 막히지 않았다 (ADR-0046 실측, 2026-08-21)

| 실측 | 결과 |
|---|---|
| `base64Array` 첨부 | `Invalid URL format` |
| 프록시 업로드 반환 주소 | `localhost` — Discord 도달 불가 |
| 위키미디어 공개 URL | **MJ가 실제로 가지러 나갔다가** 403 |

세 번째가 이 결정의 근거다: **이미지 프롬프트 메커니즘은 살아 있고, 주소가 인터넷에서
서빙되기만 하면 된다.** MJ가 생성한 이미지는 `cdn.midjourney.com/<uuid>/*.png` 주소를
이미 갖고 있다(`imageUrls` 실측 — `imagegen/midjourney.py`). 자기 CDN이라 로컬 서빙이
필요 없고, 참조 문법(`--cref`/`--oref`)은 **프롬프트 문자열의 일부**라 ADR-0046의 결과
조항("submit은 `{"prompt"}`만 보낸다")과도 충돌하지 않는다. `[7]`이 이미지 파일 대신
`task_id`+`quadrant`로 MJ 잡을 가리키는 것(ADR-0041)과 같은 축이다 — **MJ 안의 것은
MJ 핸들로 참조한다.**

### 4. 인물이 필요 없는 소재가 다수다 (사람 결정, 2026-08-21)

건축·단순 설명 소재에서 캐릭터를 만들 이유가 없다 — *"인물이 필요하지 않다면 굳이 인물
캐릭터를 만들 이유가 없잖아. 장면 나눌 때 참고를 해줘, 없다면 안 돌게."* 인물 경로는
씬 분할이 판정하는 **선택 경로**여야 하고, 없으면 호출 0회로 스킵돼야 한다.

## 결정

1. **씬 계약에 선택적 인물 엔티티를 둔다.** `scenes.json` 최상위에 선택 블록
   `characters`(캐릭터 정의: `id`·`name`·`anchor`·`appearance` 외형 서술), 씬에 선택
   필드 `cast`(등장 캐릭터 id 배열). **생산자는 `[3s. scenetable]`이다** — 씬을 나눌 때
   "같은 인물이 2씬 이상 반복 등장하고 그 인물이 서사를 지는가"를 판정해 필요할 때만
   적는다. **블록이 없으면 인물 경로 전체가 스킵된다** (D-3 — 인포씬 없는 편에서 `[6i]`가
   통째로 스킵되는 것과 같은 패턴). `appearance`는 한국어 그대로 프롬프트에 들어가고
   (ADR-0027 실측 — 품질 무손실), `anchor` 고유명사는 1차 자료 언어로 적는다 (ADR-0042).
2. **`[5] prompt`가 캐릭터 시트 프롬프트를 기계 변환한다.** `characters` 블록이 있으면
   `prompts.json`에 캐릭터 항목(BASE_STYLE + `appearance` + 시트용 구도)을 추가하고,
   씬 항목에 `cast`를 복사한다. 판단하지 않는다는 원칙은 그대로다.
3. **`[6] imagegen`이 시트를 선행 생성하고 씬 제출에 참조를 잇는다.** 캐릭터당 시트
   1잡(fast) → **U1 업스케일 1잡**(fast — 단일 이미지의 Discord CDN 서명 URL을 얻는
   왕복, `[7]` 영상 경로와 동일 패턴) → 그 URL과 시트·업스케일 잡 id를
   **`character_source.json`**(사이드카 — ADR-0041 패턴)에 기록 → `cast`가 있는 씬의
   프롬프트 끝에 **`--oref <url> --v 7`**(G3 실측)을 이어 제출한다. **다운로드·첨부
   없음.** 서명 URL은 run 안에서만 유효하고, 완료된 업스케일이 있으면 재사용한다
   (G1·G3 실측). 시트·업스케일 잡도 `images.json`에 기록한다(잡의 기록이므로).
4. **인물용 framing 어휘를 추가한다** (닫힌 어휘 — ADR-0033 §3): `figure_wide`(풍경 속
   인물), `figure_medium`(인물 중경), `figure_back`(뒷모습), `figure_silhouette`(실루엣).
   **얼굴 클로즈업 토큰은 두지 않는다** — AI 얼굴 왜곡과 `[7]` 영상 왜곡 리스크는 카메라를
   느린 워크로 묶은 것과 같은 근거다. 필요해지면 어휘 추가 PR로 다시 온다.
5. **실패 사다리**: 시트 잡 실패(재시도 1회 포함) → 캐릭터 참조 없이 `cast` 씬을
   `appearance` 서술만으로 제출하고 강등을 기록한다 (D-5). 참조가 붙은 씬 자체의
   실패·재시도·폴백은 기존 `[6]` 규칙 그대로다. `[6r]`의 판정 기준은 손대지 않는다 (D-4).

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| `appearance` 서술만 (참조 없음) | 코드 변경 0 | 씬마다 다른 인물 | ADR-0028 상한의 재현 — 서술도 결국 텍스트다. 모델이 모르는 대상에서 실패한 실측이 이미 있다. 단 **강등 사다리의 칸으로 남긴다** |
| `[4] refpack` 확장 (실사진·초상화) | 기존 단계 재사용 | 설화 인물은 실사진이 없다 | 있어도(초상화) ADR-0046이 로컬 파일 첨부를 막았다. refpack은 실물 대상 전용으로 남는다 |
| 시트를 내려받아 `base64Array` 첨부 | URL 의존 없음 | — | ADR-0046 실측에서 `Invalid URL format`으로 죽은 바로 그 경로다 |
| `--sref`로 캐릭터 고정 | 문법 단순 | 축이 다르다 | sref는 룩이지 정체가 아니고, `BASE_STYLE`을 이겨 마감을 망가뜨린 전례가 있다 (ADR-0025 G3) |
| 씬마다 직전 씬 이미지를 vary/blend로 체인 | 인접 일관성 | 중간 1회 실패가 하류 전체 오염 | 동시 제출(ADR-0031 §4)이 불가능해져 벽시계가 순차로 되돌아간다 (27씬 45분 실측의 재현) |
| 새 단계 `[5c. charsheet]` 신설 | 단계 독립 | `prompts.json`을 다시 쓰게 된다 | 값 출처 하나 원칙(ADR-0020) 위반. URL은 실행 시점 데이터라 계약 파일이 아니라 **사이드카**가 맞다 — ADR-0041과 동일한 판단 |

## 확인 사항 (게이트 — ADR-0030 패턴, 전부 정액이라 탐침 비용 0)

| # | 확인할 것 | 실측 (2026-08-21) | 실패 시 |
|---|---|---|---|
| **G1** | MJ가 참조 URL을 실제로 가져오는가 | **통과 — 단 주소가 바뀌었다.** `cdn.midjourney.com/<jobId>/0_q.png`는 익명 GET에 **403**이라 못 쓴다. 닿는 주소는 태스크 `url`의 **Discord CDN 서명 URL**(`cdn.discordapp.com/...?ex=...&hm=...`)이고, 단일 이미지는 **U1 업스케일 왕복**으로 얻는다 — `[7]` 영상 경로가 이미 쓰는 그 왕복이다. oref·이미지 프롬프트 둘 다 이 주소를 정상 fetch했다 | 참조 주입을 버리고 대안 1(서술만)로 강등 |
| **G2** | 참조가 `BASE_STYLE`을 이기지 않는가 | **잠정 통과 (표본 1).** `--oref` 4칸 전부 펜선+수채 혼합 실사가 생존. 단 **v8.2 이미지 프롬프트(`--iw 2`)는 시트의 서 있는 구도를 복제**해 씬 동작을 잃었다 — 그 변형은 기각 | 가중을 낮춰 재탐침, 그래도 밀리면 참조 포기 |
| **G3** | 참조 문법 확정 | **`--oref <url> --v 7`.** 계정 기본이 **v8.2**이고 `--oref`·`--cref` 둘 다 `not compatible with --version 8.2`로 FAILURE — v8은 cref 폐기, oref는 **v7 실행 전용**이다. `--v 7`을 명시하면 돈다. **cast 씬만 v7로 강등**되는 트레이드오프가 남는다 (비-cast 씬은 v8.2) — 편 안에서 룩이 갈라지는지는 G4에서 본다 | 문법이 또 바뀌면 재탐침 — 코드에 상수로 적지 않는다 |
| **G4** | `cast` 씬들이 실제로 **같은 인물로 보이는가** + v7/v8.2 혼용 룩 | 미확인 — 첫 인물 편에서 `[6r]` 재작업률과 사람 판독으로 잰다 | 이 ADR을 되돌린다 |

**G1·G3 실측이 결정 3의 기계를 바꾼다**: "자기 CDN URL"은 **"U1 업스케일의 Discord CDN
서명 URL"**로 읽는다. 서명 URL은 만료가 있으므로(관측상 수 시간~하루) `character_source.json`의
URL은 **run 안에서만 유효**하고, 재실행 시 시트 태스크에서 다시 읽는다. 같은 업스케일을
짧은 간격에 재요청하면 MJ가 `Slow Down!`으로 거절한다(실측) — 완료된 업스케일 태스크가
있으면 재사용한다.

## 개정 (2026-08-22) — G4 첫 관통 + G2 재탐침: 문법에 `--ow 25`를 더한다

사람 지시("인물을 만들면 이미지에 첨부가 되는지 테스트하라")로 합성 프로브
(`runs/20260822-character-probe/` — 석공 1명, cast 2씬: `figure_wide` 채석 /
`figure_back` 암벽)를 `[5]`→`[6]` 실경로로 관통시켰다. fast 6잡.

### 실측

- **배관은 전 구간 작동한다.** 시트 1잡 → U1 업스케일 → Discord CDN 서명 URL →
  `character_source.json` → cast 씬 프롬프트 끝 참조 — MJ가 접수했고 finalPrompt에
  `--oref <https://s.mj.run/…> --v 7.0`으로 남았다 (MJ가 우리 URL을 자기 참조
  주소로 축약해 수용). 코드 수정 0으로 통과했다
- **정체 전달은 성공.** 시트·씬 1·씬 2·가중 변형 전부에서 같은 노인(흰 수염,
  청회색 배자, 흰 바지)이 나왔다. `figure_back`의 뒷모습 지시도 살았다 —
  참조가 자세 지시까지 죽이지는 않는다
- **기본 가중(`--ow` 생략 = 100)은 구도·배경까지 복제한다.** 씬 1의 4칸 전부가
  시트의 흰 배경 전신 스터디를 복사했다 — 채석장도 정과 망치도 없다. G2 잠정
  통과 때 `--iw 2`에서 본 실패가 `--oref` 기본 가중에서도 난다
- **`--ow`를 낮추면 씬이 돌아온다.** `--ow 50`: 도구·바위는 복귀, 배경은 여전히
  스터디. **`--ow 25`: 동작(바위를 다듬고·지게로 나르고)·화강암 블록이 복귀**하고
  정체는 유지됐다. 각 1그리드(4칸) 표본이다

### 결정 (개정)

**참조 문법을 `--oref <url> --ow 25 --v 7`로 개정한다** (G3 갱신). 25는 표본 1의
값이다 — 실물 편에서 정체가 무너지면 올리고, 구도가 또 밀리면 내린다. 문법 상수는
여전히 어댑터 한 자리다.

### 남은 것 (G4는 아직 닫히지 않았다)

- **흰 배경이 끌려온다** — 시트의 `plain neutral background`가 참조를 타고 씬에
  들어와 "배경을 화면 끝까지"(ADR-0038)를 어긴다. `--ow 25`에서도 완전히 사라지지
  않았다. 다음 손잡이는 시트 구도(배경 있는 시트)나 가중 추가 하향이다
- **낙관·서명 낙서** — `--no`에 글자 배제가 있는데도 일부 칸에 붙었다 (아트
  스터디 룩의 부속). `[6r]` 기준 ③이 거를 자리다
- `figure_wide`의 "풍경 속 작은 인물"은 안 지켜졌다 (인물이 화면을 채운다)
- **실물 편 관통(G4 본판)은 그대로 남는다** — `[3s]`가 `characters`를 낸 첫 인물
  편에서 `[6r]` 재작업률과 사람 판독으로 잰다
