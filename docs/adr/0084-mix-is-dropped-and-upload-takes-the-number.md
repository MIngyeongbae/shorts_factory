# ADR-0084: `[10] mix`를 폐기하고 그 번호를 `[10] upload`가 받는다 — 조립된 타임라인 3개가 구글 드라이브로 간다

- 상태: **승인** (2026-08-31, 사람 — "승인할게")
- 날짜: 2026-08-31
- 관련 스펙: specs/05-pipeline.md, specs/04-audio-rules.md
- 관련 ADR: **유지** — ADR-0021·0043(SDK를 쓰지 않는다, HTTP는 `transport.py` urllib 하나),
  ADR-0077(스토리지 경계는 stdlib로 직접 만든다), ADR-0020(단계는 기록 파일을 남긴다),
  ADR-0034(자원 등급 — 값의 출처는 하나). **개정** — 스펙 04의 SFX·BGM·믹싱 절을 폐기한다

## 맥락

### 1. `[10] mix`는 설계만 있고 코드가 없다 — 폐기해도 잃는 것이 없다

`specs/05-pipeline.md` 5행이 스스로 밝힌다: *"이 문서는 설계이지 구현 현황이 아니다. 아래
단계 중 일부는 아직 코드가 없다 (`[10]`)."* `src/shorts_factory/stages/`에 `mix.py`가 없고
`final.{lang}.mp4`를 만든 코드도 없다.

그런데도 **쇼츠 36편(토픽 12개)이 이미 나왔다** — 전부 `[9]`의 `timeline.{lang}.mp4`이고
소리는 나레이션뿐이다. 사람이 그 파일로 게시 판단을 해 왔다. 즉 이 폐기는 **쓰던 기능을
빼는 것이 아니라 한 번도 구현된 적 없는 설계를 스펙에서 지우는 것**이다.

스펙 04가 `[10]`에 걸어 둔 규칙은 SFX 3줄(전환 whoosh · 하드컷 thump · 물소리 앰비언트),
BGM 3줄(저작권 프리 필수 · -18dB 이하 · `turning_point` 뒤 톤 전환), 믹싱 2줄(-16dB LUFS ·
-1dBFS 리미터)이다. **여덟 줄 전부 구현체가 없다.** 사람이 2026-08-31에 "그건 필요없고"라고
정했다.

한 줄만 다른 단계로 넘어간다: 스펙 05가 *"나레이션은 `total_duration`에서 끝나고 엔딩 꼬리는
BGM이 덮는다 (`[10] mix`의 계약)"*라고 적어 둔 자리다. BGM이 없어지면 **엔딩 꼬리는 그냥
무음**이고, 그것은 이미 36편에서 나온 결과다 — 새로 정할 것이 없다.

### 2. 지금 파이프라인의 마지막은 `[9]`이고 산출물은 run 디렉터리에 갇혀 있다

게시하려면 사람이 `runs/{run_id}/timeline.{lang}.mp4`를 탐색기로 찾아 옮긴다. 토픽 12개 ×
3개 국어 = **36파일, 4.4GB**(실측 `du`)이고 파일명이 전부 `timeline.ko.mp4`라 폴더 밖으로
꺼내는 순간 어느 편인지 알 수 없다. 자동화가 붙을 자리가 명확하다.

### 3. 파일이 100MB급이라 업로드 방식이 정해진다 (실측)

| | 크기 |
|---|---|
| 코치닐 `timeline.ko.mp4` | 88.6 MB |
| 코치닐 `timeline.ja.mp4` | 118.7 MB |
| 코치닐 `timeline.en.mp4` | 115.4 MB |

구글이 `uploadType=media`·`multipart`를 권하는 범위는 **5MB 이하**다. 100MB짜리를 한 요청에
담으면 ① 파일 전체를 바이트로 메모리에 올려야 하고(`Transport`의 본문 타입이 `bytes | None`
이다) ② 중간에 끊기면 처음부터다. **resumable 세션 + 청크**가 맞다 — 세션 URI는 응답
`Location` 헤더로 오고 이어받을 지점은 `Range` 헤더로 오므로, 이미 있는
`HeaderTransport`(응답 헤더까지 돌려주는 시그니처, ElevenLabs가 쓴다)로 **transport를 고치지
않고** 된다.

### 4. 의존성과 인증 — stdlib로 되는 길은 하나뿐이다

이 프로젝트의 의존성은 `jsonschema`·`referencing` **둘**이고 HTTP는 `transport.py`에서 urllib로
직접 친다 (ADR-0021·0043). ADR-0077이 R2 업로더에서 같은 문제를 만나 **botocore ~50MB 대신
SigV4 서명을 stdlib로 직접 만들었다.** 그 전례가 그대로 적용된다.

인증에서 stdlib로 되는 것은 **OAuth 리프레시 토큰 교환** 하나다 — `POST
https://oauth2.googleapis.com/token`에 폼 인코딩 네 필드(`client_id`·`client_secret`·
`refresh_token`·`grant_type=refresh_token`)를 보내면 액세스 토큰이 JSON으로 온다. 서비스 계정은
**JWT를 RS256으로 서명해야 하는데 stdlib에 RSA가 없다** — 게다가 서비스 계정은 개인 드라이브에
용량이 없어 공유 드라이브가 전제가 된다.

### 5. 제목은 이미 run 디렉터리에 있다 — `topics/`를 열 필요가 없다

`[3]`이 그 언어 대본의 `# 제목`을 `scenes.timed.{lang}.json`의 **선택 필드 `title`**에 이미
옮겨 둔다 (ADR-0065, 스펙 05 계약 표). 실측 확인:

```
ko  코치닐 — 은 다음으로 비쌌던 빨강, 정체는 벌레였다
ja  コチニール — 銀の次に高かった赤、その正体は虫だった
en  Cochineal — the red that cost almost as much as silver was an insect
```

**그래서 `[10]`은 `topics/`를 열지 않는다.** 스펙 05가 *"이것이 2부가 `factcheck.md`를 여는
유일한 예외다"*라고 못 박아 둔 경계이고, 제목을 `script.md`에서 다시 읽으면 그 규칙을 깨는
데다 같은 값의 출처가 둘이 된다 (ADR-0034). 새 필드도 만들지 않는다.

## 결정

**`[10] mix`를 폐기하고 그 번호를 `[10] upload`가 받는다.** 이 프로젝트의 전례다 — 비었던
`[6]`을 `frames`가, `[8]`을 `ending`이 받았다 (스펙 05). 스펙 04의 SFX·BGM·믹싱 절은 폐기
표시한다.

`[10] upload`는 **`[9]`가 만든 `timeline.{lang}.mp4`(있는 것만)를 구글 드라이브에 올린다.**

0. **제목의 출처는 `scenes.timed.{lang}.json`의 `title` 하나다** (ADR-0065). `topics/`를
   열지 않는다. `title`이 없는 언어는 그 언어만 건너뛰고 사유를 남긴다 (D-3·D-5).
1. **폴더** — 부모 아래에 `{올리는 날 YYYY-MM-DD} {한국어 제목}` 폴더 하나를 만든다.
   부모는 `.env`의 `GDRIVE_PARENT_FOLDER_ID`이고, 없으면 내 드라이브 루트다.
   같은 이름의 폴더가 이미 있으면 **만들지 않고 그것을 쓴다.**
2. **파일명** — 그 언어 대본의 제목 + `.mp4`. `코치닐 — 은 다음으로 비쌌던 빨강, 정체는
   벌레였다.mp4` · `コチニール — ….mp4` · `Cochineal — ….mp4`. 제목은 그대로 쓰고 제어문자만
   턴다 — 줄이거나 로마자로 바꾸지 않는다.
3. **전송** — resumable 세션 + 8MB 청크. 인증은 OAuth 리프레시 토큰이고 스코프는
   `drive.file`(앱이 만든 파일만)이다.
4. **기록** — `runs/{run_id}/upload.json`에 언어별 Drive 파일 id·크기·주소·업로드 시각.
   재실행하면 **같은 id를 갱신하고 새 파일을 만들지 않는다** (ADR-0020의 목적).

경계는 `storage/gdrive.py` 하나다 — 로컬 파일 하나를 올려 파일 id를 돌려준다. `storage/r2.py`
옆자리이고 같은 모양이다 (ADR-0077).

**단계 독립 6원칙** (스펙 05): D-1 파일로만 통신한다(`timeline.{lang}.mp4` → `upload.json`).
D-3 ja·en 실측이 없어 타임라인이 ko뿐이면 ko만 올리고 그것이 정상이다. D-4 기존 단계를
수정하지 않는다 — 새 파일만 쓴다. D-5 한 언어의 실패는 그 언어에서 끝나고 나머지는 올라간다.

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **A. `[10] mix`를 스펙에 남기고 `[11] upload`를 새로 단다** | 나중에 BGM을 되살릴 번호가 남는다 | 구현된 적 없는 단계가 번호를 계속 물고 있고, 사람은 그 자리를 원하지 않는다고 정했다 | 사람 결정 (2026-08-31). 폐기 번호 재사용은 이 프로젝트의 전례다 (`[6]` frames, `[8]` ending) |
| **B. `google-api-python-client`를 쓴다** | 재개·청크·토큰 갱신을 다 해 준다 | 의존성 트리가 수십 MB. "의존성은 둘"을 깬다 | ADR-0021·0043 위반. ADR-0077이 **같은 이유로 botocore를 탈락시킨** 자리다 |
| **C. 서비스 계정으로 인증한다** | 사람 개입 없이 토큰이 갱신된다 | JWT RS256 서명이 필요한데 stdlib에 RSA가 없다. 개인 드라이브에 소유권·용량이 없어 공유 드라이브가 전제가 된다 | **stdlib로 불가능하다** — B를 부르는 길이다 |
| **D. rclone 같은 외부 CLI에 맡긴다** | 우리가 쓸 코드가 거의 없다 | 이 PC에 설치돼 있지 않다(확인함). 설정이 파이프라인 밖에서 계약이 되고, 테스트에 페이크를 꽂을 자리가 없어진다 | 경계가 코드 밖으로 나간다 (ADR-0021의 이유와 같다) |
| **E. `[9] assemble`이 조립하면서 바로 올린다** | 단계가 늘지 않는다 | 새 기능이 기존 단계를 고친다. 업로드 실패가 조립까지 되돌린다 | **D-4 위반** (단계 추가는 기존 단계를 수정하지 않는다) |
| **F. R2에 올린다 (이미 있는 경로)** | 코드가 이미 있다 (ADR-0077) | 사람이 보는 자리가 아니다 — R2는 MJ에 주소를 물리려고 둔 것이고 브라우저로 열어 고르는 곳이 아니다 | 사람이 구글 드라이브를 지정했다 |

## 결과

### 바뀌는 것

- **코드 (새 파일만)** — `src/shorts_factory/storage/gdrive.py`(경계: 로컬 파일 → Drive 파일
  id), `src/shorts_factory/stages/upload.py`, `cli.py`에 `upload` 서브커맨드. **기존 단계는
  손대지 않는다.**
- **스펙** — 아래 diff.
- **`.env`** — `GOOGLE_CLIENT_ID`·`GOOGLE_CLIENT_SECRET`·`GOOGLE_REFRESH_TOKEN`(필수),
  `GDRIVE_PARENT_FOLDER_ID`(선택). 셋이 없으면 `[10]`은 **설정 없음으로 멈춘다** — 조용히
  건너뛰지 않는다 (게시물이 안 올라간 것을 나중에 알면 늦다).
- **비용** — API 호출은 무료다. 드는 것은 드라이브 용량뿐이고 **편당 ≈320MB**다. 지금 36편이
  4.4GB이므로 무료 15GB 계정이면 **≈50편에서 찬다.**

### 되돌릴 조건

1. **사람이 BGM을 다시 원하면** — `[11] mix`로 새로 단다. `[10]`은 돌려주지 않는다.
2. **드라이브 용량이 차면** — **저장 위치를 옮기지 않고 요금제를 올린다** (사람 결정
   2026-08-31, *"용량은 괜찮아. 필요하면 요금제를 올릴꺼야"*). 즉 이 조건은 설계를 되돌리는
   방아쇠가 **아니고**, 사람이 결제로 푸는 운영 항목이다. 관측 수단은 `upload.json`의 누적
   바이트이고, 목적지를 다시 정하는 것은 요금제로도 안 되는 규모가 됐을 때다.
3. ~~**`drive.file` 스코프가 사람이 만든 부모 폴더를 거절하면**~~ — **발동했다. 아래
   「실행 뒤 확인」이 결론이다.**
4. **업로드가 게시 흐름과 안 맞으면** — 편집·썸네일 작업이 드라이브 밖에서 돈다면 이 단계는
   중간 보관소일 뿐이고, 그때는 목적지가 바뀐다.

## 실행 뒤 확인 (2026-08-31, 코치닐 첫 실계정 관통)

**돌았다.** ko 88.6 · ja 118.7 · en 115.4MB = **322.7MB를 50초에** 올렸고, 재실행은 0바이트다
(기록의 파일 id로 갱신 판정 → 세 언어 다 "그대로"). 이름 규칙도 그대로 나왔다:
`2026-08-31 코치닐 — 은 다음으로 비쌌던 빨강, 정체는 벌레였다/` 밑에
`코치닐 — ….mp4` · `コチニール — ….mp4` · `Cochineal — ….mp4`.

### 되돌릴 조건 3이 첫 실행에서 발동했다 — 그리고 스코프를 안 올리기로 했다

사람이 브라우저에서 만들어 둔 폴더를 부모로 지정하자 API가 **`404 File not found`**로 답했다.
`drive.file`은 **앱이 만들거나 연 것만** 보므로 예견된 결과다.

사람이 고른 답(2026-08-31)은 **최소 권한 유지**다 — 스코프를 `drive`(전체 읽기·쓰기)로 올리는
대신 **상위 폴더도 앱이 만든다.** `runs/logs/gdrive_parent_folder.py`가 그 자리이고, 만든 뒤
id를 `.env`의 `GDRIVE_PARENT_FOLDER_ID`에 넣는다. 같은 스크립트의 `--adopt`가 이미 올라간 편
폴더를 **재업로드 없이** 그 밑으로 옮긴다(부모만 갈아 끼운다 — 그 폴더들도 앱이 만든 것이라
`drive.file`로 보인다). 사람이 브라우저에서 이름을 바꿔도 된다 — 계약은 이름이 아니라 id다.

그래서 **결정은 그대로 서고, 스코프는 `drive.file`에 머문다.** 이 조건은 닫힌다.

### 용량 — 무료 15GiB로는 막히지만 요금제 한 칸이면 목표를 덮는다 (실측 2026-08-31)

20토픽·쇼츠 59편의 `timeline.*.mp4` 4.40GiB를 잰 값이다.

| | 크기 |
|---|---|
| 쇼츠 1편 | **76 MiB** |
| 토픽 1개 (ko·ja·en) | **0.224 GiB** |

계정은 개인 Gmail(무료 15GiB)이라 **약 45토픽에서 찬다** — 지금 20토픽이니 배치 두 번이면
닿는다. 사람이 **요금제 상향**으로 풀기로 했다(되돌릴 조건 2). 사람이 말한 목표는
**500토픽 = 쇼츠 1,500편**이고 그것은 **약 112 GiB**다:

| 요금제 | 들어가는 양 |
|---|---|
| 100GB | 토픽 416개 (쇼츠 1,249편) |
| **200GB** | **토픽 833개 (쇼츠 2,499편)** — 목표를 넘는다 |
| 2TB | 쇼츠 24,999편 |
| 5TB | 쇼츠 62,498편 |

**이 수치를 흔드는 변수는 게시 해상도 하나다** — 지금은 1080×1920·30fps 인코드 기준이고,
ADR-0059 결정 7이 "게시 해상도는 첫 실편을 폰에서 본 뒤 사람이 정한다"로 미뤄 둔 자리다.
4배가 돼도 500토픽이 450GiB라 2TB 안이다. 관측 수단은 `upload.json`의 누적 바이트다.

## 제안하는 스펙 수정

### `specs/05-pipeline.md` — 파이프라인 도식

```diff
   → [9. assemble]   → timeline.{lang}.mp4  (언어당 1회 — 같은 clips/, 언어별 실측으로 트림,
                        디졸브 + 언어별 자막 번인 + 엔딩 하드컷)
-  → [10. mix]       → final.{lang}.mp4    (SFX + BGM — 나레이션은 [9]가 이미 얹었다, 스펙 04)
+  → [10. upload]    → upload.json          (조립된 타임라인을 구글 드라이브로. 폴더는
+                       `{올리는 날} {한국어 제목}`, 파일명은 그 언어 대본의 제목. ADR-0084)
 ```
```

같은 파일 5행의 *"아래 단계 중 일부는 아직 코드가 없다 (`[10]`)"*는 구현 뒤 지운다.

폐기 목록에 한 줄 더한다:
