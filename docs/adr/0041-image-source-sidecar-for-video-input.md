# ADR-0041: `[7]`의 영상 입력은 사이드카 계약으로 받는다 — 기록을 계약으로 승격하지 않는다

- 상태: 승인
- 날짜: 2026-08-19
- 관련 스펙: specs/05-pipeline.md, specs/schema/image-source.schema.json
- 관련 ADR: **ADR-0024 §2(`[7]`은 `images.json`을 열지 않는다 — 본 ADR이 지킨다)**, ADR-0020(값 하나의 출처는 하나다), ADR-0031 §2(사분면 보존·선택), ADR-0039(전 씬 영상), ADR-0025(MJ 영상 사슬)

## 맥락

### 1. ADR-0039가 `[7]`을 구현 가능하게 만들면서 계약 공백 하나를 드러냈다

MJ 영상은 이미지가 입력이고, **MJ는 자기가 만든 잡을 잡 id로 가리킬 때만 그것을 받는다**
(ADR-0025 실측: 로컬 PNG를 올리면 프록시가 `localhost:8086` 주소를 돌려주고 MJ가 못 닿는다).
`videogen/base.py`의 `VideoRequest`가 요구하는 값이 그래서 둘이다.

| 값 | 지금 어디 있나 |
|---|---|
| `source_task_id` | `images.json`의 `scenes[].engine.request_id` |
| `quadrant` | `image_review.json`의 `scenes[].pick` (`verdict: pick`인 씬만) |

**둘 다 파일 내용에서 얻을 수 없다.** `[7]`이 여는 `images/{scene_id}.png`는 바이트일 뿐
어느 MJ 잡의 몇 번째 장인지를 모른다. 해시로도, 파일명으로도 복원되지 않는다.

### 2. 그런데 ADR-0024 §2가 `[7]`의 `images.json` 독해를 명시로 막았다

> `images.json`은 `[11]`과 사람이 읽는 **기록**으로 남고, `[7]`은 그 파일을 열지 않는다
> — ADR-0020의 "값 하나의 출처는 하나다"가 유지된다.

같은 ADR의 대안 표가 탈락 사유까지 적어 뒀다 — *"그 순간 `images.json`이 기록이 아니라
계약이 된다. ADR-0020의 되돌릴 조건에 걸려 스키마·대체 ADR이 따라온다."*

**ADR-0039은 이 충돌을 다루지 않았다.** `[7]`을 구현하라고만 했고, 구현하면 저 금지에
정면으로 걸린다. 코드가 먼저 나가면 스펙이 코드를 따라오게 되는데, 그것이 이 프로젝트가
가장 비싸다고 정한 실수다 (ADR-0034 §5).

### 3. 기록 두 개가 이미 갈라져 있다 — 합치는 일을 `[7]`에 지울 수 없다

한 씬의 "지금 화면에 쓰는 그림이 어느 잡의 몇 번째 장인가"는 **두 파일에 나뉘어 있고
분기가 넷이다** (코드 대조, 2026-08-19).

| `[6]`·`[6r]`을 거친 결과 | `task_id` | `quadrant` |
|---|---|---|
| `[6]` 성공, `[6r]` `pass` | `images.json`의 `engine.request_id` | 0 (`[6]`이 `q0`을 복사) |
| `[6r]` `pick q{n}` | 위와 같음 | `image_review.json`의 `pick` |
| `[6r]` `redo` 성공 (재생성) | **`image_review.json`의 `engine.request_id`** (새 잡) | 0 |
| `[6]` 인접 씬 폴백 | **없다** — 폴백 씬의 `engine`은 `null`이다 | 없다 |

`[7]`이 이 합성을 하려면 두 기록의 내부 구조와 `[6r]`의 판정 어휘(`pass`/`pick`/`redo`)와
결과 어휘(`picked`/`regenerated`/`redo_failed`/`redo_skipped`)를 전부 알아야 한다.
**단계 독립 D-2("단계는 자기가 읽는 필드만 안다")가 무너지는 모양이다** — `[7]`이
`[6r]`의 내부 상태 기계를 아는 단계가 된다.

### 4. 사람 결정 (2026-08-19)

세 갈래를 제시했고 사람이 골랐다 — **`[6]`·`[6r]`이 사이드카 계약을 남기고 `[7]`은
그것만 읽는다.** ADR-0024 §2가 무손상으로 남는 쪽이다.

## 결정

**`runs/{run_id}/image_source.json`을 신설한다. `[6]`이 쓰고 `[6r]`이 갱신하며 `[7]`만 읽는다.**

이 파일이 답하는 질문은 하나다 — **"씬 N의 화면에 지금 있는 그림은 어느 잡의 몇 번째
장인가."** 그 밖의 것을 담지 않는다.

### 1. 정본은 `specs/schema/image-source.schema.json`이다

```json
{
  "run_id": "20260819-hooverdam",
  "provider": "midjourney",
  "scenes": [
    { "scene_id": 1, "task_id": "1758…", "quadrant": 0, "set_by": "6-imagegen" },
    { "scene_id": 2, "task_id": "1759…", "quadrant": 2, "set_by": "6r-imagereview" }
  ]
}
```

- **`provider`** — 이 잡 id가 누구의 id인가. `[7]`은 자기 영상 프로바이더와 어긋나면
  호출 없이 전 씬을 강등한다. NB2 경로에는 잡 id라는 것이 없고, MJ 잡 id를 Kling에
  넣으면 27번 실패한다
- **`quadrant`** — 0부터다. `[6r]`이 사분면을 바꿔 끼웠으면 그 번호다 (ADR-0031 §2).
  **영상은 화면에 실제로 쓰는 그 장에서 나와야 한다** — q0 고정으로 두면 판정이 고른
  그림과 영상이 다른 그림이 된다
- **`set_by`** — 그 값을 마지막으로 정한 단계. 사람이 어긋남을 추적하는 자리이고
  `[7]`은 읽지 않는다

### 2. 영상 입력이 없는 씬은 **항목을 내지 않는다**

`scenes` 배열은 **입력이 있는 씬만** 담는다. 널 필드를 두지 않는다 — `[7]`의 규칙이
"항목이 없으면 강등"이라는 한 줄이 되고, 널 검사가 분기로 새지 않는다.

항목이 없는 경우는 둘이다.

- **`[6]` 인접 씬 폴백 씬.** 그 씬의 그림은 옆 씬의 복사본이고 잡 id가 없다.
  **원본 씬의 id를 빌려 주지 않는다** — 그러면 같은 그림으로 영상이 두 번 나오는데,
  MJ 영상은 카메라를 프롬프트로만 받아 **스펙 03의 역방향 워크를 걸 자리가 없다.**
  Ken Burns로 내려가는 쪽이 역방향 워크를 지킨다
- **잡 id 개념이 없는 프로바이더** (`fake`, NB2). 파일이 통째로 없을 수도 있다

### 3. `[7]`은 항목이 없으면 **기록을 남기고** 내려간다

`mj_video` → `kenburns` → `static`. `demoted_from`을 채우고 경고를 남긴다.
**조용한 강등을 만들지 않는 것이 ADR-0039이 이 자리에서 닫기로 한 것이다**
(worklog 2026-08-19 (13) 0번).

파일이 통째로 없으면 전 씬이 이 경로를 탄다 — **단계는 돌고 기능만 빠진다** (D-3).

### 4. `images.json`·`image_review.json`은 기록으로 남는다

`[7]`은 둘 다 열지 않는다. **ADR-0024 §2가 손상 없이 유지된다.** 중복 이미지 판정도
지금처럼 바이트 해시로 한다 — 그 결정의 근거("`[7]`은 어차피 이미지를 연다")는 그대로다.

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **`[7]`이 `images.json`+`image_review.json`을 직독한다** | 파일이 안 는다. `videogen/base.py`가 이미 이 전제로 쓰였다. 코드가 제일 짧다 | 기록 둘이 계약이 된다. `[7]`이 `[6r]`의 판정·결과 어휘를 알게 되어 **D-2가 무너진다.** `[6r]`의 결과 어휘를 늘릴 때마다 `[7]`을 같이 고쳐야 한다 | **사람이 고르지 않았다.** ADR-0024 §2가 이 대안을 이미 한 번 탈락시켰고 그 사유("기록이 계약이 된다")가 그대로 살아 있다 |
| **씬 계약(`06-script.json`)에 필드를 추가한다** | 계약이 늘지 않는다. `scenes.timed.json`을 타고 `[7]`까지 이미 내려간다 | **2부가 1부 산출물을 수정하게 된다** (ADR-0017 단방향 경계 위반). 잡 id는 대본의 속성이 아니라 실행의 부산물이다 | 경계를 깬다. 같은 대본을 다시 돌리면 값이 달라지는 것을 씬 계약에 넣을 수 없다 |
| **`[6]`이 파일명에 잡 id를 싣는다** (`images/{id}.{task}.q{n}.png`) | 새 파일이 없다. `[7]`이 이미 여는 디렉터리에서 읽는다 | `find_image`의 "씬 하나에 그림 하나" 불변식이 깨지고 확장자 규칙(ADR-0021)과 충돌한다. `[8]`·`[9]`가 파일명을 파싱하게 된다 | 계약을 파일명에 인코딩하는 것은 스키마가 아니다 (ADR-0034 §4) |
| **`mj_video`를 명시적 강등으로만 처리하고 미룬다** | 오늘 조용한 강등이 사라진다. 어댑터는 이미 있다 | 전 씬 영상이 안 돈다 — ADR-0039의 결정 자체가 미구현으로 남는다 | 계약 하나를 정하면 오늘 끝나는 일을 다음 세션으로 미룬다 |
| **`motion` 필드를 없앤다** (ADR-0039 대안 재검토) | 전 씬 영상이면 씬마다 고를 것이 없어 이 문제가 구조적으로 사라진다 | 입력 계약 문제는 그대로다 — 전 씬 영상이어도 `[7]`은 여전히 잡 id를 알아야 한다 | **이 문제를 풀지 못한다.** ADR-0039이 이미 다른 사유로 탈락시켰다 |

## 결과

### 바뀌는 것

| 자리 | 변경 |
|---|---|
| `specs/schema/image-source.schema.json` | **신설** — 계약의 정본 |
| `specs/05-pipeline.md` | 2부 계약 파일 표에 행 1개, `[6]`·`[6r]`·`[7]` 규칙, 산출물 목록 |
| `stages/imagegen.py` | `image_source.json` 쓰기. `images.json`은 그대로 |
| `stages/imagereview.py` | `pick`·재생성 결과를 `image_source.json`에 반영 |
| `stages/motion.py` | `mj_video` 분기가 이 파일만 읽는다 |
| 비용 | **0.** 파일 하나가 늘 뿐 호출이 늘지 않는다 |

### 단계 독립 원칙과의 관계

- **D-1(파일로만 통신) 유지** — 오히려 강화된다. `[7]`이 `[6r]`의 어휘가 아니라 값 둘을 본다
- **D-2(자기가 읽는 필드만 안다) 유지** — `[7]`이 아는 필드는 `task_id`·`quadrant` 둘이다
- **D-3(부재는 경고가 아니다) 유지** — 파일이 없으면 전 씬 Ken Burns로 돌고, 씬마다
  강등을 **기록**한다. 기록은 경고와 다르다 — 강등 수를 세는 것이 ADR-0039의 요구다
- **D-4(단계 추가는 기존 단계를 수정하지 않는다) — 이 결정은 적용 대상이 아니다.**
  `[7]`은 새 단계가 아니라 ADR-0039이 기능을 추가한 기존 단계다. 다만 `[6]`·`[6r]`을
  실제로 고치므로 **적용 대상이 아니라는 사실을 적어 둔다** — 다음에 새 단계를 만들 때
  이 ADR을 선례로 인용하면 안 된다

### 되돌릴 조건

1. **`[7]` 말고 이 파일을 읽고 싶은 단계가 생기면** 계약의 범위를 다시 본다. 지금 답하는
   질문("어느 잡의 몇 번째 장인가")은 영상 입력 전용이고, `[11]` 리포트가 필요로 하는
   것은 기록 둘에 이미 있다
2. **프로바이더가 잡 id 없이 이미지를 입력으로 받게 되면** 이 파일의 존재 이유가 사라진다.
   MJ가 로컬 업로드를 열거나(ADR-0025의 막힌 길), Kling으로 갈아타면(ADR-0025 밴 대비)
   `[7]`은 파일 경로만으로 충분해진다. 그때는 이 계약을 지운다
3. **폴백 씬에도 영상이 필요하다고 판단되면** 결정 2를 다시 본다. 그때 같이 정해야 하는
   것은 "같은 그림의 두 영상을 어떻게 다르게 만드는가"이고, 그것은 `motion_prompt`를
   씬마다 흔드는 문제라 `vocab.json`의 `video_prompt` 어휘가 먼저 움직인다
