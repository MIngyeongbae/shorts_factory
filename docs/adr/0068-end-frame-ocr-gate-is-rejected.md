# ADR-0068: 끝 프레임 OCR 게이트를 **기각한다** — 잡음이 진짜 라벨보다 신뢰도가 높다

- 상태: **승인** (2026-08-25, 사람 — "잡음 문턱 튜닝까지 해줘. **OCR이 못 잡으면 OCR은 기각**")
- 날짜: 2026-08-25
- 관련 스펙: specs/05-pipeline.md `[7]`, specs/03-visual-rules.md, specs/schema/script-rules.json
- 관련 ADR: **일부 개정** — ADR-0056 결정 6(`[7]`의 검수 ①이 이 게이트다. ②비전 검수는 유지).
  **유지** — ADR-0002(정확해야 하는 글자는 후처리 합성이 진다), ADR-0034(값은 schema에서),
  ADR-0044(재생성 루프 없음). **되살릴 자리** — ADR-0067 뒤에 논의된 `art` 라인
  (MJ 밑그림 + NB2 인포 + H3 fl2v)에서 `last_frame`이 결정적이 되면 조건이 달라진다

## 맥락

### 1. 게이트가 한 번도 돈 적이 없었다

ADR-0056 결정 6이 `[7]`의 검수 ①로 "끝 프레임 OCR"을 뒀지만, tesseract가 PATH에 없어
**석빙고 때부터 계속 건너뛰어졌다**(D-3의 강등). 2026-08-25에 사람이 설치했고
(`winget install UB-Mannheim.TesseractOCR`, v5.4.0.20240606) 그제서야 처음으로 잴 수 있었다.

### 2. 실측 — 표본 130장, 통과 4.6%

완성 편들의 `clip_review.json` 시도별 끝 프레임 130장(라벨 있어야 하는 것 46 · 없어야 하는 것 84).
**시도 단위라 인접 재사용에 오염되지 않는다** — 그 프레임은 그 씬을 위해 생성된 것이다.

| | 통과 | 반려 |
|---|---|---|
| `info` 씬 (라벨이 전부 읽혀야) | 5 | **41** |
| `info` 없는 씬 (글자가 없어야) | 1 | **83** |

**게이트를 켰다면 130장 중 6장만 통과한다.** 나머지는 전부 재생성 사다리를 타고 내려간다 —
토큰을 아끼려고 켠 게이트가 재시도를 폭증시킨다.

### 3. 문턱으로 갈리지 않는다 — 잡음과 진짜가 **역전**돼 있다

`ocr.py`는 "한 글자 토큰은 질감 잡음으로 보고 무시한다"로 만들어져 있었다. 실제 tesseract 5.4는
세미 스타일라이즈드 3D 렌더의 질감·모서리에서 **여러 글자를 높은 신뢰도로** 뱉는다.

| | 예시 | conf |
|---|---|---|
| 잡음 (글자가 없는 화면) | `67665` `WE` `998` `5300` `9239` `2155` `3398` | **92~96** |
| 진짜 라벨 | `High` `Mid` `Low` `Capacity` | **0** |
| 진짜 라벨 (읽힌 경우) | `Pay to remove` `1016` | 95~97 |

- **신뢰도 문턱**: 96으로 올리면 진짜가 죽고, 0으로 내리면 잡음이 산다. 겹치는 정도가 아니라
  순서가 뒤집혀 있어 **분리하는 값이 존재하지 않는다**
- **길이 문턱**: 잡음 1~15자(2자가 802개로 최다), 진짜 라벨 3~13자. 완전히 포개진다
- **라벨 재현율 36%** (69개 중 25개). 게이트는 라벨이 **전부** 읽혀야 통과이므로 라벨 2개짜리
  씬은 사실상 통과 불가다
- 잡음에 `67665`·`5300` 같은 **여러 자리 숫자**가 높은 신뢰도로 섞여 `info` 씬의
  "계약에 없는 숫자" 조항을 매번 때린다

## 결정

**끝 프레임 OCR 게이트를 끈다.** `script-rules.json` `checks.end_frame_ocr: false`.

1. **스위치로 끈다. 코드를 지우지 않는다.** `video/ocr.py`와 `[7]`의 배선은 남는다 —
   ADR-0034의 자원 등급대로 판단(이 ADR)이 위이고 코드는 아래이며, **되살릴 조건이 실재한다**
   (아래). 지운 뒤 되살리는 비용이 스위치 하나보다 비싸다.
2. **비전 검수(ADR-0056 결정 6 ②)는 그대로 둔다.** 이 ADR은 검수 ①만 기각한다. 화면 글자의
   정확성은 당분간 **비전 세션과 사람 판독**이 진다.
3. **tesseract 부재 시의 강등(D-3)은 그대로 둔다.** 스위치가 꺼져 있으므로 설치 여부와
   무관하게 게이트가 안 돌지만, 배선은 남아 있어야 되살릴 때 그대로 쓴다.
4. **`ocr.py`의 "한 글자 무시" 규칙은 손대지 않는다.** 그 값을 고쳐서 살릴 수 있는 문제가
   아니라는 것이 이 ADR의 실측이다. 문턱을 바꾸는 PR이 다시 오면 이 표를 먼저 읽어라.

## 결과

- **좋은 것** — 켰다면 130장 중 124장이 헛되이 재생성 사다리를 탔을 것이다. 그 재시도가
  전부 GPU 3~7분 + 비전 세션 1회씩이었다
- **나쁜 것** — 화면 글자를 기계가 대조하는 수단이 **0개가 된다.** `info` 라벨이 틀리게
  나와도 비전 세션이 놓치면 그대로 나간다. ADR-0056 결정 6이 게이트 둘을 둔 이유가
  이것이고, 지금은 하나로 돈다
- **모르는 것** — 비전 세션이 라벨 오탈자를 얼마나 잡는지. 오늘 실측에서 비전은 좌우 반전·
  파장 오류 같은 **의미** 오류를 잘 잡았지만 **철자**를 재는 축은 아니다

## 되살릴 조건

- **`art` 라인이 서면 다시 잰다.** MJ 밑그림 + NB2 인포 + H3 `fl2v` 구조에서는 `last_frame`이
  **우리가 만든 인포 이미지**다. OCR이 보는 대상이 "H3가 상상해서 그린 질감 화면"에서
  "글자를 의도적으로 얹은 깨끗한 이미지"로 바뀌므로 위 실측이 그대로 적용되지 않는다.
  그때 이 스위치를 켜고 같은 표본 검사를 다시 돌린다
- 화면 텍스트가 **후처리 합성**으로 옮겨지면(ADR-0002의 태도를 인포까지 확장) OCR 게이트는
  필요 없어진다 — 합성한 글자는 틀릴 수가 없다. 그때는 되살리는 것이 아니라 삭제다
