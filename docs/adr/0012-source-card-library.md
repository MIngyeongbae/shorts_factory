# ADR-0012: 조사한 소스를 평면 카드로 누적하고, 인덱스 통주입으로 재조사만 막는다

- 상태: 승인
- 날짜: 2026-08-07
- 관련 스펙: specs/06-topic-research.md, specs/05-pipeline.md
- 관계: ADR-0009(세션 독립성)·ADR-0011(세션 읽기 전용)의 격리 계약 위에 얹는다

## 맥락

`[0b]`의 조사·검증 세션은 매번 웹을 처음부터 검색한다. 각자성석 1편에서 고유 URL 15건을
조사했지만 그 결과는 `topics/{slug}/`의 마크다운 산문에 갇혀 있어, 같은 유적을 다루는 다음
토픽이 같은 페이지를 다시 찾고 다시 fetch한다. 검색 자체는 구독으로 한계비용 0(ADR-0008)이지만
세션 시간(서브스텝당 900초 상한)과 외부 사이트 부하는 0이 아니고, 같은 소스를 두 번 읽으면
두 번 다르게 요약될 수 있다.

동시에 지금 카드는 0장이다. 분류 체계·태그·임베딩 검색을 지금 정하면, 데이터 없이 정한 구조를
나중에 데이터가 부정하게 된다.

## 결정

**`knowledge/sources/{source_id}.md` 평면 저장 + `knowledge/index.md` 통주입.**

- `source_id`는 URL 정규화 후 `{호스트}-{sha256 앞 8자}`. URL이 없으면 카드를 만들지 않는다
- 카드는 `키: 값` frontmatter + `## 핵심 발췌` + `## 확인된 사실`. YAML 파서를 쓰지 않는다
- 조사(01)·검증(02) 세션에 인덱스를 주입하고 `--add-dir`로 `knowledge/`를 열어 Read하게 한다.
  카드에 있는 소스는 재검색·재fetch 금지. 비판(03)은 라이브러리에 닿지 않는다
- 세션은 산출물 끝에 `## 참조 소스` JSON을 낸다. 카드 쓰기는 오케스트레이터만 한다 (ADR-0011 유지)
- 유형 3종이 신선도 3종에 1:1로 대응한다. 만료는 주입 시 표시일 뿐 차단하지 않는다
- 디렉터리 분류·태그·임베딩 검색을 도입하지 않는다. 저장은 평면, 탐색은 인덱스 + Read + grep
- **팩트시트 스키마는 건드리지 않는다.** 이 기능의 목적은 중복 조사 방지이지 사실 추적 강화가 아니다

교차 확인은 계약에 필드를 더 두지 않고 얻는다. 다른 토픽의 세션이 같은 소스에서 같은 문장을
뽑아내면 새 줄로 쌓지 않고 그 사실의 `교차확인`에 슬러그를 더한다.

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| 유적·시대별 디렉터리 트리 | 사람이 훑기 쉬움 | 카드 0장 상태에서 분류 축을 확정해야 함. 한 소스가 여러 유적에 걸침 | 데이터가 부정할 구조를 미리 굳히는 비용이 탐색 이득보다 크다 |
| 임베딩 벡터 검색 | 의미 기반 탐색 | 인덱싱 인프라·모델 의존성, 결과가 모델 버전에 따라 흔들림 | 수십~수백 장 규모에서는 인덱스 통주입이 더 정확하고 결정적이며 비용 0 |
| 태그 시스템 | 다축 분류 | 태그 어휘 관리가 또 하나의 스펙이 됨 | `subjects` 한 축으로 충분. 데이터 축적 전 스키마 확대 금지 |
| 카드 없이 팩트시트만 누적·검색 | 새 저장소 불필요 | 팩트시트는 토픽 종속이고 원문 발췌가 없어 재사용 불가 | 재조사 방지라는 목적 자체를 이루지 못한다 |
| 세션이 카드를 직접 Write | 파싱 코드 불필요 | 세션이 임의 경로에 쓸 수 있음 | ADR-0011 정면 위반 |
| `fact.source_ids`로 팩트시트에 카드 참조 강제 | 오류 전파를 fact 단위로 역추적 | 모든 fact에 매핑을 강제, 기존 산출물 백필 필요 | 목적(재조사 방지) 대비 과한 계약. 카드의 `topics:`로 얻는 거친 역추적으로 충분하다 |
| frontmatter를 PyYAML로 파싱 | 표준 파서 | 런타임 의존성 추가 (현재 jsonschema 하나뿐) | 스키마가 평면 9줄뿐이고 읽고 쓰는 곳이 한 파일이라 `split(":", 1)`로 족하다 |
| 카드를 세션 임시 디렉터리에 복사 | 파일 접근 경계 불변 | 복사·정리 로직 필요, 라이브러리가 커지면 세션마다 비용 | `--add-dir` 한 줄로 같은 목적을 달성한다. 중립 cwd와 읽기 전용 도구는 그대로다 |
| 기존 각자성석 패키지를 카드로 소급 변환 | 첫 카드를 즉시 확보 | 01-research.md에 URL 0건이라 LLM 매핑이 필요하고 결과 검수도 필요 | 재조사 방지는 다음 조사부터 효과를 낸다. 변환 비용 대비 이득이 없다 |

## 결과

- 같은 소스를 두 번 찾고 두 번 다르게 요약하는 경로가 닫힌다. 조사 결과가 토픽 산문에서
  분리돼 재사용 가능한 자산이 된다
- 반려된 토픽(verdict: fail)의 조사도 자산으로 남는다
- 새 의존성 없음. 팩트시트 스키마·`[0b]`의 03·04 경로 변경 없음. 카드가 0장인 동안은
  주입문이 빈 문자열이라 파이프라인이 종전과 동일하게 돈다
- 카드의 `topics:`로 "이 소스를 어떤 토픽이 참조했는가"까지는 알 수 있다. fact 단위 역추적은
  하지 않는다 (필요해지면 그때 `fact.source_ids`를 재검토한다)
- 세션 프롬프트가 인덱스 표만큼 길어진다
- **되돌릴 조건**: 소스 수가 늘어 `index.md` 통주입이 프롬프트에서 부담스러운 비중을 차지하거나,
  평면 목록에서 원하는 카드를 찾기 어려워지면 **분류 체계와 선별 주입(질의 기반 부분 주입)을
  재설계한다.** 그때는 축적된 카드의 `subjects`·`topics` 분포가 분류 축의 근거가 된다

## 반영한 스펙 수정 (승인 시 적용 완료)

`specs/06-topic-research.md`에 `## 소스 카드 라이브러리 (knowledge/)` 절을 신설하고,
토픽 패키지 구조와 그 아래 규칙에 조사·검증 세션의 주입·수확 규칙을 추가했다.
`specs/05-pipeline.md`의 계약 파일 절에 한 줄을 추가했다.

```diff
+- 소스 카드(`knowledge/`)는 run·토픽에 종속되지 않는 **누적 자산**이라 run 디렉터리에 두지 않는다 (ADR-0012)
 - `slug`: 음운 변화 미적용 로마자 표기, `[a-z0-9-]` 최대 60자 (ADR-0011)
```
