# ADR-0052: 옛 파이프라인 경로를 코드에서 전부 삭제한다 — 새 경로 단일화

- 상태: 승인 (2026-08-21, 사람 결정)
- 날짜: 2026-08-21
- 관련 스펙: specs/05-pipeline.md, specs/02-beat-schema.md, specs/03-visual-rules.md
- 관련 ADR: **ADR-0036 폐기** (이행 단계를 두지 않되 옛 편은 옛 경로로 돈다는 조항 —
  옛 편 자체를 버리므로 지킬 경로가 없다), ADR-0049(새 1부), ADR-0017(경계)

## 맥락

ADR-0036은 "옛 편(`06-script.json` 보유분)은 기존 경로 그대로 돈다"로 두 경로를
공존시켰다. 2026-08-21 사람 결정: **"예전 것은 실패한 것이라 다 지운다. 새 파이프라인으로만
간다."** 옛 편은 산출물째 폐기 대상이므로 옛 경로를 코드에 남길 이유가 없고, 남기면
모든 소비자 단계가 갈림길을 하나씩 들게 된다.

## 결정

1. **씬 계약은 `runs/{run_id}/scenes.json` 하나다** (`[3s]` 산출). `topics/{slug}/06-script.json`
   읽기 경로를 전 단계에서 삭제한다.
2. **`[3] tts`의 입력은 `topics/{slug}/script.md` 하나다** (ADR-0049). `06-script.json`
   입력 경로를 삭제한다. `scenes.timed.json`은 `text`+실측 시각만 담는다.
3. **`[7]`·`[9]`는 시각을 `scenes.timed.json`에서, 연출·대본 속성을 `scenes.json`에서
   메모리 병합으로 읽는다** (ADR-0020 — 파일로 남기지 않는다). `scenes.json` 부재는
   실패다 — 폴백 경로가 없다.
4. slug→run 해석은 `runs/*/topic.json` (`find_run_for_slug`) 하나다.
5. 옛 경로 전용 코드·스키마 파생·테스트 픽스처는 코드와 함께 지운다 (ADR-0034 §4).
   옛 topics/ 산출물 파일의 삭제는 사람이 한다.

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| 두 경로 공존 (ADR-0036 유지) | 옛 편 재활용 가능 | 6개 단계가 같은 갈림길을 복사해 든다 | **사람이 기각** — 옛 편은 실패작이라 다시 돌릴 일이 없다. 지킬 대상이 없는 호환성이다 |
| 옛 편을 새 계약으로 변환하는 이행 스크립트 | 산출물 보존 | 이행 단계 신설 | ADR-0036이 금지했던 바로 그것이고, 보존할 가치가 없다는 것이 이번 결정이다 |

## 결과

- 코드: `[3]` tts 단일 입력화, `[5]`·`[6]`·`[6r]`·`[6i]`·`[7]`·`[9]`의 계약 소재지를
  `runs/{run_id}/scenes.json`으로 단일화(`stages/contract.py`), 옛 파생 빌더·글롭 폴백 삭제
- 스펙: 05의 "옛 편은 …" 주석·이행기 절 삭제, 02·03의 옛 소유자 병기 삭제
- 테스트: 픽스처를 리포 `topics/`가 아니라 `tests/fixtures/`의 동결 사본에서 읽는다 —
  옛 topics 폴더가 지워져도 테스트가 산다
- 되돌릴 조건: 없음 — 옛 산출물이 지워지는 순간 되돌릴 대상도 없다
