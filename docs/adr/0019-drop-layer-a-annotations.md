# ADR-0019: 레이어 A 어노테이션(빨간 표시)을 전부 폐기한다

- 상태: 승인
- 날짜: 2026-08-11
- 관련 스펙: specs/03-visual-rules.md, specs/02-beat-schema.md
- 영향받는 ADR: ADR-0002(부분 무효), ADR-0005(2-pass 조항 무효), ADR-0006(클린 입력 조항 무의미)

## 맥락

스펙 03의 오버레이 열에는 빨간 표시가 6종 들어 있다.

| 종류 | 붙는 비트 | 성격 |
|---|---|---|
| 빨간 크레용 X | `hook_twist`, `failure_reason`, `turning_point` | 부정 |
| 빨간 X 대형 | `dilemma_peak` | 부정 |
| 빨간 측정선/영역 표시 | `context` | 설명 |
| 빨간 라벨 박스 (지도핀) | `failed_solution` | 설명 |
| 빨간 치수선/화살표 | `solution_step` | 설명 |
| 장소명 라벨 / 라벨 박스 | `hook_fact`, `present_link` | 설명 |

출처는 원본 채널 3편의 프레임 분석이다(ADR-0002 맥락 — "치수선 옆 깨진 한국어"). 즉
이 6종은 우리가 필요해서 정한 연출이 아니라 **"신비한 건축사전"이 쓰던 것을 분석하며
그대로 옮겨 적은 것**이다. 사람이 이번 세션에 그 채널의 룩을 따라갈 이유가 없다고
판단했다.

세 가지가 동시에 걸려 있다.

**1. 비용.** 레이어 A 어노테이션이 붙는 씬은 클린 베이스를 만든 뒤 편집 2-pass를
한 번 더 돌린다(ADR-0005). 이미지 호출이 씬당 2회다.

| 토픽 | 총 씬 | 레이어 A 씬 | 이미지 호출 (현행 → 폐기 후) |
|---|---|---|---|
| 후버댐 콘크리트 냉각 | 27 | 14 (52%) | 41 → 27 |
| 피사의 사탑 지반 보강 | 25 | 12 (48%) | 37 → 25 |

ADR-0005의 "편당 ~50호출(재시도·2-pass 포함) ≈ $2~2.5"에서 2-pass 몫이 통째로 빠진다.

**2. 스펙 오류가 하나 섞여 있다.** `turning_point`의 "빨간 크레용 X **→ 사라짐**"은
시간에 따른 변화라 정지 이미지 한 장에 담을 수 없다. `[5. prompt]`가 임시로 레이어 B에
올려 두고 `rule_gaps: turning_point_overlay_temporal`로 기록해 뒀다.

**3. 문구 출처가 계약에 없다.** '빨간 라벨 박스'와 '장소명 라벨'에 무엇을 쓸지 정하는
필드가 `06-script.json`에 없다. `[5]`가 `value: null`로 내보내고 있어
`[8. overlay]`가 채울 것이 없다 — 후버댐 2건, 피사 3건.

폐기하면 2와 3이 함께 사라진다.

## 결정

레이어 A를 쓰지 않는다. 스펙 03의 오버레이 열에서 빨간 표시 6종을 전부 뺀다. 장소명
라벨도 뺀다 — 문구 출처가 계약에 없고, 나레이션이 장소를 말하며 자막이 이미 하단에
깔린다.

남는 오버레이는 레이어 B 두 개뿐이다.

| 오버레이 | 적용 | 레이어 |
|---|---|---|
| `big_red_text` (대형 빨간 숫자) | `context_number`, `solution_number` | B (후처리 합성) |
| `sparkle_particles` (우하단 반짝이) | 전 씬 공통 | B (후처리 합성) |

ADR-0002의 2계층 구분 자체는 **폐기하지 않는다.** "정확해야 하는 텍스트는 합성한다"는
결정은 그대로 유효하고, 레이어 A는 정의만 남고 사용처가 비는 상태가 된다. 되살릴 때
근거를 다시 만들지 않아도 되게 두는 편이 싸다.

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| 부정 표시(X 계열 4행)만 뺀다 | 단면·도해 씬의 "어디를 보라"는 시각 안내가 남는다 | 라벨·측정선의 문구 출처 공백이 그대로 남고, 2-pass도 절반은 남는다(후버댐 14 → 5씬) | 사람이 전면 폐기를 선택 |
| 전부 유지 | 레퍼런스 채널 룩에 가장 가깝다 | 편당 이미지 호출이 2배, `turning_point` 스펙 오류·라벨 문구 출처 공백 미해결 | 따라갈 이유가 없다고 판단했다 |
| 빨간 표시를 전부 레이어 B로 이관 | 텍스트 정확도 확보, 2-pass 불필요 | `[8. overlay]`에 도형 합성 기능이 새로 필요하고, 씬마다 어디에 그릴지 정할 좌표 근거가 계약에 없다 | 얻는 것 대비 새로 만들 것이 많다 |

## 결과

**스펙**

- `specs/03-visual-rules.md` — 오버레이 열 재작성, "모션별 어노테이션 규칙" 절 삭제,
  **오버레이 타입 enum 표 신설**(스펙 02가 참조하는데 여태 없던 표다)
- `specs/02-beat-schema.md` — `emphasis.type`이 참조하는 enum이 실체를 갖는다
  (값은 `big_red_text` 하나)

**ADR**

- ADR-0002: 레이어 A의 사용처가 비었다는 사실을 결과 절에 추가. 결정 자체는 유효
- ADR-0005: "어노테이션(레이어 A): 클린 베이스 생성 → 편집 2-pass" 무효.
  편당 호출·비용 재산정 필요
- ADR-0006: "Kling 씬은 어노테이션 없는 클린 이미지를 입력" 조항이 무의미해진다 —
  전 씬이 클린이다. `kling`/`kenburns` 분기 자체는 유지

**코드**

- `schemas/visual_rules.py` — `OVERLAYS`에서 레이어 A 6종 + 장소명 라벨 2종 삭제,
  `build_annotation` 삭제, `BEAT_RULES`의 오버레이 열 정리
- `stages/prompt.py` — `annotation_prompt` 필드 삭제(항상 null이 된다),
  `rule_gaps` 4건 제거(`hook_fact_overlay_choice`, `turning_point_overlay_temporal`,
  `failed_solution_label_text`, `present_link_place_label_text`)
- `schemas/scenes.py` — `emphasis.type`을 `OVERLAY_TYPES` enum으로 조인다
  (지금은 임의 문자열이다)

**비용**

- 편당 이미지 호출: 후버댐 41 → 27, 피사 37 → 25 (약 34% 감소)
- 재시도를 포함한 ADR-0005의 편당 ~$2~2.5 산정은 하향 재산정 대상

**되돌릴 조건**

- 완성 영상에서 단면·도해 씬이 "어디를 보라"는 안내 없이 읽히지 않는다고 판단되면
  재도입을 검토한다. 단 **레이어 A로 되돌리지 않고** 레이어 B 도형 오버레이로 만든다 —
  2-pass 비용과 생성 불확실성을 다시 사지 않기 위해서다
