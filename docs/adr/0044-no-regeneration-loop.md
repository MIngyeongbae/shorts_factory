# ADR-0044: 대본 재생성 루프를 없앤다 — 단계 직후 검증 + 씬 단위 재청 + 최종 게이트는 보고·중단

- 상태: 승인 (2026-08-20, 사람 결정 — 아래 맥락 1)
- 날짜: 2026-08-20
- 관련 스펙: specs/05-pipeline.md
- 관련 ADR: **ADR-0029(재진입 규칙 — 본 ADR이 대체한다)**, ADR-0011(세션 격리 —
  산출물은 오케스트레이터가 쓴다), ADR-0034(자원 등급)

## 맥락

### 1. 사람 결정 (2026-08-20)

> "대본 만드는데 마지막 단계가 3번을 돌아서인지 만드는 시간이 너무 길어. 이러면
> 테스트조차 못 하겠어." … "3회 시도 저거 루프 구조를 없애는 게 좋을 것 같아."
> (소재 캐시는 쓰지 않는다 — 신선 소재 기준이 실효 기준이다.)

### 2. 실측 — 1부 80분 중 60분이 같은 24줄을 여섯 번 쓴 시간이다

다다미 편 `state.json` + `logs/` 파일명 (2026-08-19):

| 단계 | 벽시계 | 증거 |
|---|---|---|
| `[1a]` | 1.3분 | 정상 |
| `[1s]` | 6.2분 | 정상 |
| **`[1w]`** | **33.0분** | `1w-write.attempt3.json` — **3회 시도**, 회당 ~10분, 최종 status=failed |
| `[1b]` | 1.2분 | 정상 |
| **`[2]`** | **38.4분** | `2-validate.regen1.1a` · `regen1.1s` · `regen1.1w.attempt3` — 재생성 1회가 **`[1a]→[1s]→[1w]×3` 사슬 전체를 재실행** |

bobe 편도 `[1w] failed` — **write는 매 편 실패하고 있다.** 신선 소재는 여기에
리서치 31~38분이 얹혀 1부가 ~110분이다.

### 3. 시간을 만드는 구조가 셋이다

1. **전체 실패 단위.** `[1w]` 세션이 씬 전체 JSON을 내고 오케스트레이터가
   `carry_errors()`로 전수 대조한다 — **복사 필드 하나만 어긋나도 파일 전체가 실패**하고
   10분짜리 재시도가 돈다. 스펙 05는 애초에 "세션은 `text`만 출력한다"인데 구현이
   전체를 받아 대조하고 있다. 복사를 시키니 복사 실패가 생기는 것이다.
2. **재시도 = 새 세션.** 재시도마다 새 헤드리스 세션이 팩트시트·아웃라인·씬플랜을
   처음부터 다시 읽는다. 그 재독이 회당 ~10분의 대부분이다.
3. **재진입 = 사슬 재실행.** `[2]`의 재진입 규칙(ADR-0029: 그라운딩·훅은 `[1a]`부터)이
   실패 1건에 정상 산출물까지 다시 만들게 한다 — regen 1회 = 38분.

## 결정

재생성 루프를 없애고 **검증을 실패가 난 자리로 옮긴다.** 원칙은 하나다 —
**틀린 것을 하류로 흘려보낸 뒤 사슬을 되감지 않고, 만든 직후에 그 자리에서 잡는다.**

1. **`[1w]` 세션은 `{scene_id: text}`만 출력한다.** `06-script.json`은 오케스트레이터가
   `08-sceneplan.json` + text로 **조립**한다. `carry_errors()` 전수 대조는 폐지한다 —
   대조가 아니라 조립이므로 어긋날 수가 없다. 실패 계급 하나가 구조적으로 사라진다.
2. **단계 직후 기계 검증 (fail-fast).** `[1s]` 산출 즉시: 씬 수 범위·어휘·`visual_goal`
   겹침·`says` 숫자의 팩트시트 그라운딩. `[1w]` 산출 즉시: 씬 단위 분량(`char_budget`)·
   문체. 그라운딩 위반이 `[1w]`까지 흘러가서 사슬을 되감던 자리가 없어진다.
3. **재청은 실패 씬만, 상한 1회, 새 세션이 아니라 resume.** 24씬 중 3씬이 틀렸으면
   3씬만 다시 청한다. 같은 세션을 오류 목록만 들고 이어가므로 컨텍스트 재독이 없다.
4. **`[2. validate]`는 재생성하지 않는다.** 최종 게이트로만 남는다 — 스키마·분량
   엔벨로프·수미상관·그라운딩 전수 재확인. 실패하면 **보고하고 중단한다.** 다시 돌릴지는
   사람이 정한다. (2번의 fail-fast가 제대로 돌면 여기서 걸리는 것은 검증기 자체의
   구멍이라는 뜻이고, 그것은 재생성이 아니라 수리 대상이다.)
5. **`[2b] judge`를 구현할 때 같은 원칙을 적용한다.** revise 지시를 사슬 재실행으로
   만들지 않는다 — 스펙 07의 revise 상한 2회는 유지하되, 재실행 범위 설계는 구현
   시점에 이 ADR을 전제로 한다.

ADR-0029의 재진입 규칙(실패 종류 → `[1w]`/`[1s]`/`[1a]`)은 **대체된다.** 그 규칙이
지키려던 것 — "문장 문제로 그림 계획까지 버리지 않는다" — 은 fail-fast가 더 싸게
지킨다: 틀린 단계 밖으로 오류가 아예 안 나간다. ADR-0029의 3분할 자체(outline →
sceneplan → write)는 그대로다.

### 예상 효과

| | 현재 | 목표 |
|---|---|---|
| `[1w]` | 33분 (3회 전체 재집필) | ~8분 (1회) + 실패 씬 재청 1~2분 |
| `[2]` | 38분 (사슬 재실행) | ~0분 (기계 검증만) |
| **1부 (신선 소재)** | **~110분** | **~50분** (리서치 31~38분은 그대로) |

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| 재생성 상한만 축소 (3→1) | 변경 최소 | 구조가 그대로다 — regen 1회도 사슬 재실행 38분이고, `[1w]` 매 편 실패의 원인(전체 대조)이 남는다 | 상한이 아니라 단위가 문제다 |
| `[1a]`+`[1s]`+`[1w]` 병합 | 세션 기동 2회 절약 | ADR-0029 역행. 절약이 ~5분뿐 — 60분짜리 문제에 5분짜리 답 | 시간이 새는 곳이 단계 수가 아니다 (맥락 3) |
| resume만 도입 (구조 유지) | 재시도 회당 10분 → 1~2분 | 전체 실패 단위와 사슬 재실행이 남는다 — 6회 집필이 6회 재청이 될 뿐 | 원인 1·3이 그대로다 |
| 검증기를 세션 안에 도구로 준다 | 세션이 자가 수정 | 헤드리스 세션에 쓰기 권한을 주는 것 — 산출물은 오케스트레이터가 쓴다는 ADR-0011 위반 | 경계를 무너뜨리는 값이 아니다 |

## 결과

- **스펙**: specs/05 — `[1w]`(text만 출력·조립·씬 단위 재청), `[2]`(재생성 폐지·보고
  중단), `[1s]`(직후 검증), 실패 정책 절
- **코드**: `stages/write.py`(조립로 재작성, `carry_errors` 호출 제거),
  `stages/validate.py`(재생성 루프 제거), `stages/sceneplan.py`(직후 검증 추가),
  세션 러너에 resume 재청 경로
- **schemas**: `sceneplan.carried_fields()`는 남는다 — 대조용이 아니라 **조립할 필드
  목록**으로 용도가 바뀐다
- **되돌릴 조건**: 씬 단위 재청 상한 1회로 통과율이 실무에서 부족하면(중단이 편당
  1회 이상 상시 발생) 상한을 올리되, **전체 재집필과 사슬 재실행으로는 돌아가지
  않는다.** fail-fast 검증이 세션 산출을 과하게 반려하면(오탐) 검증기를 고친다 —
  재생성을 늘리는 쪽이 아니라
