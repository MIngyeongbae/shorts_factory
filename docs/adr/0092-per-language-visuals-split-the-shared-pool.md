# ADR-0092: **엔딩 사진과 썸네일 판을 언어별로 갈라 쓴다** — 채널 간 겹치는 화면을 줄인다

- 상태: **승인** (2026-09-03, 사람 — *"승인할게"*, 썸네일은 *"하는김에 썸네일도 다른씬을
  선택하게하자"*)
- 날짜: 2026-09-03
- 관련 스펙: `specs/03-visual-rules.md`(「엔딩 실사」·「썸네일」), `specs/05-pipeline.md`
  (`[8] ending` · `[9] assemble` · `[9t] thumbnail`), `specs/schema/ending.schema.json`
- 관련 ADR: **유지** — ADR-0055(엔딩 실사 컷·무수정 표시), ADR-0056(토픽 하나가 클립 풀
  하나를 공유해 쇼츠 3편), ADR-0091(썸네일은 씬 1 위에 막 + 제목 훅), ADR-0034(계약값은
  로드한다), ADR-0020(단계 입력)
- **폐기하지 않는다** — ADR-0056의 「클립 풀 하나」는 그대로다. 이 결정이 가르는 것은
  **클립 풀이 아니라 엔딩 사진과 썸네일 판**이고, 둘 다 변동비가 0인 자리다

## 맥락

### 1. 같은 토픽이 세 채널에 붙어 올라가고 뒤엣것이 죽는다 (사람 관측)

사람이 관측한 순서는 일정하다 — **영어 편을 먼저 올리고 한국어 편을 나중에 올리면
한국어 쪽 조회수가 멎는다.** 브루클린 다리 편과 마시멜로 편 둘 다 같은 모양이었고,
`upload.json` 기록을 보면 **지금까지 올린 15개 토픽이 전부 en·ja·ko 셋 다** 올라갔다.
평소 15분에 200~400이 찍히던 채널에서 24가 나왔다.

### 2. 세 렌더는 파일로는 이미 다르다 — 그것으로 부족했다 (실측)

`20260901-harrison-longitude`를 실측했다.

| | 길이 | 바이트 | MD5 |
|---|---|---|---|
| ko | 62.90s | 49,960,779 | `29805dc2…` |
| ja | 83.00s | 64,470,795 | `e423c39e…` |
| en | 80.20s | 63,956,798 | `fa99c125…` |

`[9]`가 **언어별 TTS 실측으로 클립을 트림**하기 때문에 **17개 씬 중 컷 시점이 같은 씬이
0개**다. 총 길이는 17초 차이 난다. 그런데도 막혔다.

**그래서 「파일이 다르다」는 반박은 이 자리에서 힘을 잃는다.** 영상 지문 매칭은
재인코딩·길이 변화·오디오 교체를 견디도록 만들어진 물건이라, 위 표의 차이를 전부
통과한다. 남는 공통분모는 **화면 픽셀** 하나다 — 세 편이 같은 `clips/`를 쓴다.

### 3. 화면을 가를 수 있는 자리가 두 군데 있다 — 둘 다 변동비 0

- **엔딩 실사** (`[8]`): 지금은 **세 언어가 같은 엔딩 클립을 쓴다**
  (`stages/assemble.py` 「엔딩은 붙이되 검증하지 않는다」). 최대 3장 × 2.4초 = **7.2초**다.
  재료는 `[4]`가 이미 내려받아 둔 사진 풀이고, `[8]`은 상한 3장을 넘긴 몫을
  **「상한을 넘어 잘렸다」로 버리고 있었다** (`stages/ending.py` `select`) — 쓸 수 있는
  재고가 이미 남아 있었다는 뜻이다
- **썸네일 판** (`[9t]`): `PLATE_SCENE_ID = 1`로 **세 언어가 같은 판**을 쓴다
  (ADR-0091 맥락 3). 바뀌는 것은 제목 글자뿐이다

**클립 자체를 언어별로 다시 뽑는 길은 택하지 않는다** — 로컬 GPU 1.5시간이 4.5시간이 된다.
그건 앞의 둘로 안 될 때 볼 카드다.

### 4. 이 결정은 가설 위에 서 있다 (정직하게 남긴다)

**중복 판정이 원인이라는 것은 확인되지 않았다.** 사람이 관측한 것은 상관이지 인과가
아니고, 유튜브가 공개한 메커니즘도 아니다. 그래서 이 ADR과 **별개로 변수 하나짜리
테스트**가 돈다 — 다음 토픽 하나를 **ko 채널에만** 올리고 2주간 en·ja를 올리지 않는다.

여기서 하는 일은 그 테스트와 무관하게 **값이 남는 쪽**만 골랐다: 엔딩이 언어마다 다른
사진으로 닫히고 썸네일 판이 언어마다 다른 것은, 중복 문제가 없었더라도 세 채널을 따로
키우는 데 손해가 아니다.

## 결정

### 1. `[8]`은 상한을 **풀 크기**로 올리고, 배분은 `[9]`가 한다

`[8]`이 렌더하는 사진 수의 상한을 `max_photos`에서 **`max_photos × len(LANGUAGES)`**로
올린다. `ending.json`의 `photos`는 이제 **화면 순서가 아니라 큐레이션 순서의 풀**이다.

**`[8]`은 언어를 모른 채로 남는다** — 언어 파일을 읽지 않고 `LANGUAGES`(3)만 곱한다.
어느 사진이 어느 언어로 가는지는 **이미 언어별로 도는 `[9]`가 정한다** (단계 독립).

### 2. 배분은 회전이고, **보폭이 풀 깊이에 따라 갈린다**

풀 크기 `N`, 언어 위치 `i`, 장수 `m = max_photos`, 언어 수 `L`일 때

```
보폭 = m if N >= m*L else 1
[(i * 보폭 + k) mod N  for k in 0..m-1]
```

**보폭을 늘 `m`으로 두는 초안은 구현 뒤 실데이터가 죽였다** (아래 부록). 요약하면 `N`이
`m`의 배수일 때 `i*m mod N`이 자리를 되돌려 세 언어가 똑같아진다.

- `N ≥ m×L`이면 보폭 `m`이라 세 언어가 **겹치는 사진이 하나도 없다**
- 얕으면 보폭 1이라 사진은 겹치되 **구성과 순서가 언어마다 다르다** — 같은 사진이 다른
  시점에 다른 이웃과 뜬다
- **`N = 1`이면 세 언어가 같다.** 이건 못 고치는 자리라 경고로 남기고 실패로 만들지 않는다
  (D-3의 태도 — 재고가 없는 것은 오류가 아니다). `N = 2`에 언어가 셋이면 두 언어가
  같아지는 것도 같다 — 2원소 순환의 서로 다른 회전이 둘뿐이다

### 3. 엔딩 클립은 **전부 꼬리를 달고** 렌더한다

지금은 마지막 장만 디졸브 꼬리가 없다 (`clip_lengths`). 언어마다 마지막 장이 달라지므로
그 불변식이 깨진다. **모든 풀 클립에 꼬리를 달고 `[9]`의 `trim`이 남는 꼬리를 자른다** —
스키마가 이미 허용하는 모양이다 (`photo.seconds`: *"클립 파일은 여기에 디졸브 꼬리가 더
붙어 있을 수 있고, 남는 꼬리는 `[9]`가 trim으로 자른다"*).

### 4. 썸네일 판은 **계측 표시가 없는 씬** 중에서 언어별로 고른다

`PLATE_SCENE_ID = 1` 고정을 푼다. 후보는 **씬 계약에 `info`가 없는 씬**이다 — `info` 씬은
빨간 계측 표시가 화면에 구워져 있어 제목 글자와 겹친다. 후보가 없으면 전 씬으로 넓히고,
그때도 없으면 씬 1이다.

언어 위치 `i`, 후보 수 `C`일 때 고르는 자리는 `i * C // len(LANGUAGES)`다 — 영상 전체에
고르게 퍼진다. **ko는 항상 가장 이른 후보**를 받아 ADR-0091이 실측한 자리에 제일 가깝게
남는다.

**ADR-0091의 실측은 씬 1에 대한 것이었다** (위쪽 1/3이 빈다). 다른 씬은 그 실측이 없다 —
막이 그라데이션이라 무너지지는 않지만 **제목 가독성은 편마다 사람이 봐야 한다.** 고른
씬 id를 `state.json`에 남겨 되짚을 수 있게 한다.

## 결과

- **변동비 0.** LLM 세션도 GPU도 늘지 않는다. `[8]`이 FFmpeg로 정지 사진 클립을 최대 9장
  렌더하고(기존 3장), `[9t]`가 프레임을 언어별로 뽑는다
- **엔딩 7.2초 + 썸네일 1장이 언어마다 달라진다.** 본편 씬은 그대로 겹친다 — 이 결정은
  겹침을 줄이지 없애지 않는다
- `[7] videogen`·`[3] tts`·`[5] prompt`는 한 줄도 안 바뀐다
- **옛 `ending.json`은 그대로 읽힌다** — `[9]`는 배분 정보가 없으면 지금처럼 `photos`를
  순서대로 쓴다 (재실행 없이 섞여 돌 수 있다)

## 부록 — 구현이 초안의 보폭을 뒤집었다 (실측)

초안은 보폭을 늘 `m`으로 뒀다. 구현 뒤 **기존 run 28편의 `ending.json`에 돌려 보니
21편이 세 언어 똑같이 나왔다.** 원인은 산술이다 — 지금까지 상한이 `max_photos`(3)라
**풀이 정확히 3장인 편이 19편**인데, `i*3 mod 3 = 0`이라 세 언어의 시작점이 전부 0으로
겹쳤다.

보폭을 깊이에 따라 가르니 이렇게 바뀐다.

| 풀 | ko / ja / en |
|---|---|
| 1장 | `[1]` / `[1]` / `[1]` — 못 고친다 |
| 2장 | `[1,2]` / `[2,1]` / `[1,2]` — ko·en이 같다, 못 고친다 |
| 3장 | `[1,2,3]` / `[2,3,1]` / `[3,1,2]` — **셋 다 다르다** |
| 9장 | `[1,2,3]` / `[4,5,6]` / `[7,8,9]` — **겹치는 사진 0** |

기존 28편 기준으로 **세 언어가 다 갈리는 편이 7 → 19편**이 됐다 (2편은 풀 1장, 7편은
2장이라 산술적으로 못 고친다). 새로 뽑는 편은 풀 상한이 9장이라 대부분 완전 분리로 간다.

**이 표가 되돌릴 조건 4의 관측 자리다** — 풀 1~2장인 편이 잦으면 `[8]`의 재고가 문제이지
배분이 문제가 아니다.

## 되돌릴 조건

1. **ko 단독 업로드 테스트가 정상 조회수를 내는데 채널을 섞으면 다시 죽는다** — 그러면
   원인이 화면 중복으로 굳고, 이 결정으로 **부족하다**는 뜻이다. 그때 클립 언어별 재생성
   (GPU 3배)이나 업로드 오프셋으로 간다
2. **ko 단독 업로드도 24뷰에 머문다** — 원인이 중복이 아니다. 이 결정은 값이 없지는
   않으므로(채널마다 다른 마감·썸네일) 남기되, 조회수 문제는 다른 축에서 다시 판다
3. **썸네일 제목이 안 읽히는 편이 잦다** — `[9t]`의 판 선택을 씬 1 고정으로 되돌린다
   (ADR-0091의 실측 자리)
4. **엔딩이 `N = 1`인 편이 잦다** — 언어별로 가를 재고가 없다는 뜻이라, ADR-0055의
   되돌릴 조건(전용 수집 세션)이 먼저다
