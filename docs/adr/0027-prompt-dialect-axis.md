# ADR-0027: `prompts.json`에 방언 축을 둔다 — `[5]`가 하나만 내고 `[6]`이 대조한다

- 상태: 승인
- 날짜: 2026-08-12
- 관련 스펙: specs/05-pipeline.md, specs/03-visual-rules.md

## 맥락

ADR-0025가 이미지 경로를 Midjourney로 옮기면서 **계약 공백 #3**을 남겼다. `prompts.json`의
`prompt`는 Nano Banana용 **여러 줄 자연어**(`Subject:`/`Shot:`/`Style:`/`Framing:` 블록)인데
MJ는 **한 줄 + `--ar` + `--no`** 문법이다. G1에서는 사람이 손으로 옮겨 붙여 검증했고,
`[5] prompt`가 방언을 내야 한다는 것만 적어 둔 채로 끝났다.

방언을 짜기 전에 **갈림길이 하나 미검증으로 남아 있었다.** G3·단면 탐침의 성공 프롬프트는
전부 **사람이 쓴 영어**였는데, `[5]`가 내는 것은 ADR-0001·0014에 따라 **한국어 `subject`
그대로**다. 한국어가 막히면 `[5]`에 번역이 들어와야 하고, 그것은 "연출은 룰 테이블에서만
나온다"(ADR-0001)와 `[5]`의 "외부 의존 없음"을 동시에 깬다.

그래서 relax 6잡(**과금 0원**, `runs/20260812-mj-lang-probe/`)으로 쟀다. 같은 씬을 언어만
바꿔 굽고, 1차에서 대조군 설계가 틀린 것을 발견해 2잡을 더 걸었다.

| 잡 | 프롬프트의 대상 부분 | 결과 |
|---|---|---|
| `s06-KO` | `협곡을 가득 메운 거대한 콘크리트 댐 덩어리` | **성공.** 협곡을 메운 댐, 조감 |
| `s06-EN` | 같은 내용 영어 | 성공. 품질 차 없음 |
| `s17-KO` | `홈이 파인 블록 접합면 클로즈업` | **실패.** 4장 중 2장이 **나무 짜맞춤** |
| `s17-EN` | `...between two **concrete** blocks` | 성공 |
| `s17-KO2` | `홈이 파인 **콘크리트** 블록 접합면` | **성공.** 4장 모두 콘크리트 |
| `s17-EN2` | 영어에서 `concrete` 제거 | **실패.** 브루탈리즘 건물 3장 + 나무 1장 |

1차의 `s17` 쌍은 언어 실험이 아니었다 — 영어 대조군을 만들며 한국어에 없던 `concrete`를
**옮기는 사람이 끼워 넣었다.** `KO2`/`EN2`가 그 교란을 걷어낸다.

**세 가지가 확정됐다.**

1. **MJ는 한국어 `subject`를 그대로 받는다.** 영어와 품질 차가 없다 (`s06`, `s17-KO2`)
2. **실패의 원인은 언어가 아니라 재질 명사의 부재다.** 영어도 재질을 빼면 같은 자리에서
   무너진다(`s17-EN2`). 이는 단면 탐침에서 "구조물 절단면 → 브루탈리즘 건물"로 나온 것과
   **같은 실패 모드**다 — 재질·맥락이 없으면 MJ의 기본 프라이어가 건물이나 목공으로 간다.
   고칠 자리는 `[5]`가 아니라 **`[1]`의 `subject` 작성 규칙**(specs/02)이며 이 ADR의 범위가
   아니다
3. **기계 변환이 사람 손번역과 갈리는 지점이 하나 있다.** `COMPOSITION`을 그대로 옮기면
   양성 프롬프트에 `bottom third left empty **for subtitles**`가 들어가는데 `--no`에는
   `burned-in subtitles`가 있다. **같은 낱말을 그리라고 하면서 그리지 말라고 한다.**
   G3 탐침에서는 사람이 옮기며 뗐고, 기계는 안 뗀다

1이 번역 경로를 닫았으므로 남은 문제는 하나다 — **같은 씬이 프로바이더마다 다른 문자열이
된다.** NB2 복귀 경로는 ADR-0021·0025에서 살아 있으므로 방언은 둘이고, 앞으로도 둘이다.

## 결정

`[5. prompt]`에 **방언 축**을 둔다. `--dialect {nb2,mj}`(기본값 `mj` — ADR-0025의 실물 경로)로
실행하고, **한 번 실행은 방언 하나만 낸다.**

- `prompt`·`negative_prompt`는 고른 방언으로 쓴다. **필드 이름과 개수는 그대로다**
- `style.dialect`에 무엇으로 썼는지 적는다 (신규 필수 필드)
- `[6. imagegen]`은 자기 프로바이더와 `style.dialect`가 어긋나면 **호출 전에 멈춘다**.
  조용히 진행하면 MJ 문법 문자열이 NB2에 그대로 들어가고, 그 실패는 **편당 과금 뒤에** 온다

MJ 방언 규칙은 위 6잡 + G3 20잡 + 단면 7잡의 실측 산출물로 확정한다.

| NB2 (현행) | MJ |
|---|---|
| `Subject:`/`Shot:`/`Style:`/`Framing:` 여러 줄 | **한 줄 콤마 나열** (`:`·`;`·줄바꿈 → `, `) |
| `style.aspect_ratio: "9:16"` | `--ar 9:16` |
| `negative_prompt` = `"Do not include: a; b."` 문장 | `--no a, b` — **문장이 아니라 항목 나열** |
| `bottom third left empty **for subtitles**` | `bottom third left empty` — **`for subtitles`를 뗀다** |
| 스타일 앵커 3장 첨부 | **없음** (ADR-0025 G3) |
| 한국어 `subject` 그대로 | **그대로** (변경 없음) |

`--relax`는 프롬프트에 넣지 않는다. 모드는 엔드포인트 프리픽스가 정한다 (ADR-0025).
`style.resolution: "2K"`도 넘기지 않는다 — MJ v8.2의 9:16은 816×1456 고정이고 대응
파라미터가 없다 (ADR-0005 수정 대상, 별건).

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **씬마다 `mj_prompt` 필드를 더한다** (두 방언을 함께 싣는다) | `[5]`를 다시 돌릴 일이 없다. `[6]`은 자기 필드만 읽는다 | 같은 값이 두 표기로 중복된다 | ADR-0020 "값 하나의 출처는 하나". 안 쓰는 방언이 항상 파일에 남고, **둘이 갈라져도 아무도 모른다.** `[5]`는 무료·결정적이라 재실행 비용이 0이므로 중복을 살 이유가 없다 |
| **`[6]`의 MJ 어댑터가 변환한다** | 계약 무변경. 이 ADR 자체가 불필요 | 프롬프트 조립이 `[5]`에서 `[6]`으로 샌다 | ADR-0001. 어댑터가 프롬프트 문자열을 만지기 시작하면 `[6]`이 연출 판단을 갖는다. ADR-0025도 이 일을 `[5]` 소관으로 적었다. 그리고 **어댑터는 `--no`에 무엇을 넣을지 모른다** — 오버레이별 네거티브는 룰 테이블에 있다 |
| **`subject`를 영어로 번역해 낸다** | MJ 프라이어에 유리할 것으로 봤다 | `[5]`에 LLM·네트워크가 들어온다 (ADR-0001·0008 충돌) | **실측으로 탈락.** 한국어가 영어와 같은 품질을 냈고(`s06`·`s17-KO2`), 실패 지점도 언어가 아니었다(`s17-EN2`가 같이 실패) |
| **방언 없이 NB2 문자열을 그대로 MJ에 넣는다** | 아무 일도 안 한다 | `Subject:`·`Style:` 라벨과 줄바꿈이 그대로 프롬프트가 된다 | MJ는 `:`·줄바꿈을 구분자로 읽지 않아 라벨이 화면 지시로 섞인다. `--ar`가 없으면 9:16도 안 나온다 |

## 결과

**바뀌는 코드**

| 파일 | 변경 |
|---|---|
| `schemas/visual_rules.py` | `build_mj_prompt()`·`MJ_NEGATIVES`·`DIALECTS` 신규. **`BASE_STYLE`·`COMPOSITION`은 안 바뀐다** — 방언은 같은 룰의 표기 변환이지 다른 룰이 아니다 |
| `stages/prompt.py` | `dialect` 인자를 받아 조립기를 고른다 |
| `cli.py` | `prompt --dialect {nb2,mj}` |
| `PROMPTS_SCHEMA` | `style.dialect` **필수** 추가 |
| `stages/imagegen.py` | `style.dialect` ↔ `--provider` 대조. 어긋나면 호출 전에 실패 |
| `specs/05-pipeline.md` | 계약 표·단계별 규칙에 방언 축 반영 (아래 diff) |

**옛 `prompts.json`은 스키마 위반이 된다.** `style.dialect`가 없기 때문이다. `[5]`는 무료·
결정적이므로 다시 돌리면 된다 — 마이그레이션 단계를 만들지 않는다 (ADR-0018의 `[1x]`는
**대본**이라 다시 만들 수 없어 백필이 필요했다. 프롬프트는 대본에서 언제든 재생성된다).

**비용: 0.** `[5]`는 순수 룰 변환이고 네트워크를 쓰지 않는다.

**되돌릴 조건**

- **MJ의 한국어 처리가 편 단위에서 흔들리면** — 이번 근거는 씬 4개다. **첫 실제 편 27씬에서
  `subject`가 그대로 그려진 비율을 센다.** 흔들리면 번역 경로를 다시 여는데, 그때는
  ADR-0001 개정이 선행한다
- **방언이 셋 이상이 되면** (예: 이미지 프로바이더 추가) 필드 하나로 감당되는지 다시 본다.
  둘일 때는 `--dialect`가 가장 작은 장치다
- **`[6]`의 대조가 실전에서 자주 걸리면** 그것은 방언 선택이 사람 손에 있다는 뜻이므로,
  `[6]`이 필요한 방언을 스스로 요구해 `[5]`를 다시 부르는 쪽으로 옮긴다

`specs/05-pipeline.md` — 2부 계약 파일 표:

```diff
-| `prompts.json` | [5] | **씬별 이미지 지시.** 시간 정보를 담지 않는다 | [6] `prompt`·`negative_prompt`·`style`, [8] `overlays` |
+| `prompts.json` | [5] | **씬별 이미지 지시.** 시간 정보를 담지 않는다. `style.dialect`가 어느 프로바이더 문법으로 쓰였는지 밝힌다 (ADR-0027) | [6] `prompt`·`negative_prompt`·`style`, [8] `overlays` |
```

같은 절의 항목 목록에 한 줄 추가:

```diff
 - `prompts.json`의 `subject`는 한국어 그대로 프롬프트에 들어간다. 번역하지 않고(ADR-0001·0014), 대신 그 한국어를 화면에 글자로 그리지 말라고 명시한다 (ADR-0002)
+- `prompts.json`은 **방언 하나만** 담는다 (ADR-0027). `[6]`은 `style.dialect`와 자기 프로바이더가 어긋나면 호출 전에 멈춘다 — 방언이 틀린 문자열은 편당 과금을 쓴 뒤에야 실패한다
```

단계별 규칙 `[5. prompt]`:

```diff
-- **[5. prompt]**: 구도는 `(beat × subject_scale)` 표에서만 나온다 (스펙 03, ADR-0018). …
+- **[5. prompt]**: 구도는 `(beat × subject_scale)` 표에서만 나온다 (스펙 03, ADR-0018). … 출력 방언은 `--dialect {nb2,mj}`로 고르고 기본값은 `mj`다 (ADR-0027). 방언은 표기 변환일 뿐이라 `BASE_STYLE`·구도 표는 방언과 무관하게 같다.
```

`[6. imagegen]`:

```diff
-- **[6. imagegen]**: 씬당 1회 재시도. …
+- **[6. imagegen]**: 씬당 1회 재시도. … 시작 전에 `style.dialect`와 프로바이더가 맞는지 대조하고 어긋나면 호출 없이 멈춘다 (ADR-0027).
```
