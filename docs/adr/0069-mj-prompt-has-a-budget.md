# ADR-0069: MJ 프롬프트는 예산이 있다 — 소재 먼저, 본문 75~85단어

- 상태: 승인
- 날짜: 2026-08-25
- 관련 스펙: specs/03-visual-rules.md, specs/schema/vocab.json

## 맥락

`art` 라인(ADR-0060 예약, worklog (45) 사람 결정)이 MJ로 정지 이미지를 그린다. ADR-0027이
MJ 방언을 **「한 줄 콤마 나열」**로 정했지만 **길이 규칙이 없다.** 그 공백에서 이번 세션이
연속으로 실패했고, 실패가 세 종류로 갈렸다.

**실측 (japan-5060hz 씬 4 · 씬 1, MJ v8.2, 2026-08-25, fast 24잡)**

| 본문 길이 | 결과 |
|---|---|
| ~200단어 (1413자) | **MJ가 프롬프트를 다시 쓴다.** 프록시가 완료 메시지를 프롬프트 텍스트로 태스크에 묶는데, 재작성되면 못 묶어 3분 타임아웃으로 죽는다 |
| ~120단어 (811자) | 묶이긴 한다. 그러나 **스타일 절이 꼬리에서 무시된다** — 계약의 그림체 대신 콘크리트 실사가 나왔다 |
| **49~79단어 (424~642자)** | **소재·스타일이 둘 다 산다** |
| 27단어 (271자) | 그림체만 남고 **소재를 잃는다** (MJ 기본 프라이어로 간다) |

재작성은 내용을 버리지 않는다 — 문장 구조와 구두점을 정규화할 뿐이고 스타일 절·`--ar`·`--no`·
`--seed`가 전부 살아 돌아온다. **잃는 것은 프록시의 매칭 능력 하나다.** 즉 상한은 품질 한계가
아니라 도구의 한계이고, 그래서 되돌릴 수 있는 종류의 값이다.

**어순이 곧 가중치다.** 같은 49단어를 스타일 먼저로 배치하면 그림체는 살고 소재가 죽는다
(건축 볼트가 나왔다). 소재 먼저가 유일하게 둘 다 살렸다. 옛 성공작(panama 25장)도 소재 먼저다.

**`::` 멀티프롬프트는 쓸 수 없다.** 조각마다 74토큰을 따로 받는다는 커뮤니티 기법을 시험했는데
MJ가 거절한다 — `Multiple text prompts aren't supported for --version 8.2`.

## 결정

**MJ 프롬프트는 `{소재 키워드 나열}, {스타일 키워드 나열} --ar {ar} --no {항목 나열}` 순서로
쓰고, 본문(플래그 앞)을 75~85단어로 묶는다.** 코드가 제출 **전에** 검사해서 어기면 멈춘다 —
MJ가 조용히 다시 쓰고 3분 뒤에 실패하는 것보다 낫다.

- 상한값은 `vocab.json`에 둔다. **코드가 상수를 선언하지 않고 로드한다** (ADR-0034)
- 스타일 문자열과 네거티브 목록은 **줄이지 않는다.** 이번 실패의 직접 원인이 그 축약이었다 —
  `realism dominant…`·`edge to edge…` 두 절과 네거티브의 종이 항목(ADR-0038이 넣은 것)을
  빼자마자 백지 위 제도 스케치가 나왔다
- 서술 문장을 쓰지 않는다. 콤마를 두른 산문은 나열이 아니다

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **프록시를 포크해 `--seed` 매칭을 넣는다** | 길이 상한이 사라진다. 재작성돼도 묶인다 — 완료 메시지에 `--seed`(프록시가 붙인 값)와 job id가 살아 돌아온다 | 7개 프로젝트짜리 .NET 솔루션 포크 + 커스텀 이미지 + `:latest` 자동 업데이트 포기 + 상류 릴리스마다 재적용 | **지금 값어치가 약하다.** `art` 라인의 CLEAN은 정지 이미지 한 장이라 영상 프롬프트의 FORMAT·CAMERA·RED 절이 필요 없고, 옛 성공작이 ~700자였다. **800자 안에 못 쓰는 씬이 실제로 나오면 그때 다시 본다** — 오늘 찾은 재료(`GetRunningTaskByNonce`가 이미 있고 seed가 재작성을 통과한다)가 그대로 쓰인다 |
| **길이를 안 재고 그때그때 줄인다** | 계약을 안 늘린다 | 실패가 **3분 뒤에** 오고 사유가 "타임아웃"이라 원인이 안 보인다. 이번 세션이 그래서 프록시·모드·컨테이너를 차례로 의심했다 | 계약 값을 코드가 모르면 같은 진단을 매번 다시 한다 (ADR-0034) |
| **`::`로 예산을 늘린다** | 소재·스타일이 서로를 안 밀어낸다 | — | **실측으로 탈락.** v8.2가 거절한다 |
| **`--v 7`로 낮춰 `::`를 쓴다** | 멀티프롬프트가 열린다 | 모델 세대가 바뀌어 그림체 실측을 전부 다시 해야 한다 | 예산 문제를 풀려고 룩을 갈아엎는 교환이라 손해다 |

## 결과

**바뀌는 것**

| 자리 | 변경 |
|---|---|
| `specs/schema/vocab.json` | MJ 방언의 본문 단어 상한·하한 신설 (`art` 라인이 소비) |
| `specs/03-visual-rules.md` | 「MJ 방언」에 어순(소재→스타일)과 예산을 적는다 |
| 코드 | `build_mj_prompt()` 부활 시 제출 전 검사. ADR-0056이 이미지 단계를 지우며 `visual_rules.py`에서 사라졌다 |

**비용**: 없다. 오히려 3분짜리 실패가 즉시 실패로 바뀐다.

**되돌릴 조건**

1. **80단어 안에 못 담는 씬이 나온다** — 그러면 위 표의 프록시 포크(seed 매칭)를 다시 본다
2. **MJ가 모델을 올려 재작성 임계가 바뀐다** — 상한은 실측값이라 v8.2에 묶여 있다. 버전이
   바뀌면 이 표를 다시 잰다
3. **프록시가 매칭 전략을 고친다** — 상류가 seed/job-id 매칭을 넣으면 이 ADR의 근거가 사라진다
