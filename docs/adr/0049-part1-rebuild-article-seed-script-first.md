# ADR-0049: 1부를 갈아엎는다 — 기사 시드, 통짜 대본, 후행 팩트체크

- 상태: 승인 (2026-08-21, 사람 결정)
- 날짜: 2026-08-21
- 관련 스펙: specs/00-overview.md, specs/01-script-template.md, specs/05-pipeline.md,
  specs/06-topic-research.md, specs/07-judgment-autonomy.md, specs/schema/script-rules.json
- 관련 ADR: **대체** — ADR-0029(스크립트 3분할), ADR-0040(스코어링 캘리브레이션),
  ADR-0047(채점 축 교체 — 축 자체가 사라진다), ADR-0048(후보 K개·1부 체인).
  **개정** — ADR-0017(1부↔2부 경계 파일), ADR-0044(재생성 없음 원칙은 유지, 검증 사다리는
  단계와 함께 소멸), ADR-0012(소스 카드 갱신 중단 — 자산은 보존).
  **유지** — ADR-0009(사람 게이트), ADR-0013(자막 1줄≈1씬), ADR-0007(정신 유지 — 검증이
  선행 팩트시트에서 후행 팩트체크로 이동), ADR-0043(2부 [3] 첫 단계 — 입력만 바뀜),
  ADR-0036(옛 산출물 이행 없음).

## 맥락

### 1. 사람 결정 (2026-08-21)

> "1부를 전체를 그냥 갈아엎어. 안 되는 거 계속 수정해봤자 이미 목표와 안 맞는 파이프라인에
> 계속 수정하는 꼴이야. … 지금처럼 쭉 해당 키워드를 다 찾아서 보고서를 만드니깐 오래 걸린다고.
> … 위키백과나 나무위키를 많이 참조하라고 했었어. 거기에 글들이 사람들이 흥미롭게 쓰는
> 글들이 많으니깐, 해당 글이 흥미롭다 싶으면 그 글을 기준으로 맞는지 간단히 팩트만 조사하고
> 대본을 만드는 거야. 실제라면 실제대로 아니라면 아닌 대로 — 사람들의 통념이 맞다 아니다를
> 알 수 있지. … 기존의 JSON 방식의 대사도 다 집어치워, 검사하기도 힘들어. 핵심은 시간이
> 획기적으로 줄어들어야 해, 목표한 대본 수준은 넘어야 해."

목표 수준의 정의도 사람이 정했다: `공학용쇼츠제작/CODEX_ENGINEERING_SHORTS_WORKFLOW_KR.md`의
제작자가 **시연용으로 간단히 만든 대본 수준을 넘지 못하면 파이프라인 전체가 의미 없다.**

### 2. 실측 — 지금 1부가 느리고 나쁜 이유

**속도.** 편당 헤드리스 세션 수 (specs/05 현행 기준):
`[0b]` 조사 체인 4 + `[1a]` 1 + `[1s]` 1 + `[1w]` K=3 + `[1c]` 1 + `[1b]` 1 + `[2b]` 1
= **12세션**, `[2b]` revise 루프(상한 2회, `[1a]`부터 재생성) 발동 시 **최대 ~26세션**.

**조사 낭비.** 호르무즈 편 실측: 조사 산출물 89,052자
(01-research 33,017 + 02-verify 26,002 + 03-critique 5,245 + 04-factsheet 24,788)로
대본 **790자**를 만들었다. **113:1.** 대본에 실제로 들어간 주장만 검증했다면 조사의
대부분은 필요가 없었다.

**품질 — 채점기가 병을 보고도 통과시킨다.** 같은 편의 자체 채점(09-score.json)이
"10~17줄은 숫자 나열이 말로만 이어짐", "고유명사를 지운 탓에 누가 누구를 침공했는지
문맥이 뜸"이라고 정확히 적고도 `verdict: pass`를 냈다 (후보 1개, 총점 10).

**구조 원인 — 쓰기 단계가 글쓰기가 아니다.** 10-write.md의 첫 계약이 "씬 구조를 바꿀 수
없다. 그림도 연출도 이미 정해져 있다"이다. 씬 수·순서·사실 배분·글자 예산(±3자)이 전부
얼어붙은 뒤에야 문장이 만들어진다 — 서사의 흐름·인과·리듬이 개입할 자리가 없다.
목표물 문서는 정반대 순서다: **대본을 통짜로 먼저 쓰고**("문장마다 원인·작용·결과가
하나씩 전진"), TTS 실측 길이가 나온 뒤에 장면표를 자른다.

ADR-0047이 채점 축(밀도→전달)을 고쳤지만 쓰는 순서는 그대로 뒀다 — 병의 절반만 잡았다.
점진 수정으로는 세션 수(12+)와 조사 방향(전수→대본)이 안 바뀐다.

## 결정

1부를 아래 셋으로 다시 만든다. **편당 LLM 세션 2회.**

```
topics/backlog.md (소재 한 줄 + 시드 기사 URL)
  → [0. seed]      기계 단계, LLM 0회 — 슬러그·토픽 폴더·run 생성 (기존 [0a] 간소화)
  → [1. draft]     헤드리스 1회 — 시드 기사(위키백과·나무위키 등)를 읽고 통짜 내레이션 작성
                    → topics/{slug}/script.md  (+ 대본이 의존한 주장 목록)
                    직후 기계 검사(LLM 0회): 분량 엔벨로프·줄 규격 (script-rules.json limits)
  → [2. factcheck] 헤드리스 1회 — script.md가 실제로 쓴 주장만 검증(기사 대조 + 필요시 웹).
                    틀린 숫자·사실은 해당 줄을 정정, 통념↔사실 어긋남은 소재로 명기
                    → topics/{slug}/factcheck.md + script.md 갱신
  → 사람 게이트    script.md를 읽고 go/no-go (judgment/human.json, ADR-0009 유지)
```

1. **조사의 방향을 뒤집는다.** 전수 조사 → 대본이 아니라, **흥미로운 기사를 시드로 대본을
   먼저 쓰고, 대본이 쓴 주장만 후행 검증한다.** 통념이 사실이면 사실대로, 틀렸으면 반전
   소재로 — 어느 쪽이든 산출물이다 (사람 결정). ADR-0007의 정신(화면에 나가는 숫자는
   검증된 것만)은 그대로 산다 — 검증 시점이 대본 앞에서 대본 뒤로 옮겨질 뿐이다.
2. **대본은 사람이 읽는 마크다운 한 장이다.** JSON 대사 폐기 (사람 결정). 한 줄 = 자막
   한 줄 ≈ 씬 하나 (ADR-0013 유지). 정본 포맷은 specs/01이 정의한다. 결과 제약
   (분량 엔벨로프, 훅이 앞, 수미상관, 시그니처 — script-rules.json `limits`/`signatures`)은
   그대로 살고, 검사는 LLM 세션이 아니라 **코드가 한다** (draft 직후, 초 단위).
3. **서사 원칙을 목표물 문서에서 가져온다.** 핵심 질문·핵심 메커니즘·보이는 흐름·차별점을
   먼저 정하고, 앞 1/3까지 문제·모순을 키우고, 문장마다 원인·작용·결과가 하나씩 전진한다.
   specs/01에 명문화한다. 매체 적합성 판별(그림이 이해를 보조하는가)은 [1. draft]가
   대본을 쓰기 전에 한 줄로 판정하고, 부적합이면 대본 대신 반려 사유를 낸다 — 세션을
   따로 쓰지 않는다.
4. **죽는 것.** `[0b]` 조사 체인 4세션, `[1a]` outline, `[1s]` sceneplan, `[1w]` write
   (후보 K개 포함), `[1c]` critique2, `[1b]` score, `[2]` validate(LLM 구조 검증 —
   기계 엔벨로프 검사로 대체), `[2b]` judge와 revise 루프, 자율성 사다리(specs/07 보류 —
   판정은 사람이 대본을 읽고 한다), script-rules.json의 `score` 블록, 소스 카드 갱신
   (ADR-0012 자산은 보존, 새 flow는 쓰지 않는다).
5. **1부↔2부 경계 개정 (ADR-0017).** 경계 파일은 `topics/{slug}/script.md` +
   `judgment/human.json` 둘이다. 씬 계약 JSON은 2부 내부로 이동한다: `[3. tts]`가
   script.md의 줄로 실측 타이밍을 만들고, **신설 `[3s. scenetable]`**이 TTS 실측 뒤에
   씬 분할·연출 어휘 선택·인포씬 지정을 한다 — 목표물 문서의 "실제 TTS 길이 기준 장면표"
   순서이고, ADR-0043 결정 4(2부는 [3]이 첫 단계)와 정합한다. **기계 계약 JSON은 2부에
   남는다** — 마크다운이 되는 것은 사람이 검사하는 대본뿐이다. `[3s]`의 구현은 별도
   세션(part2-dev 소관)이고 본 ADR은 경계 계약만 정의한다.
6. **옛 산출물 이행 없음 (ADR-0036).** 기존 topics/*의 06-script.json 등은 그대로 둔다.
   새 편부터 새 경로다.

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| 점진 수정 — ADR-0047 재캘리브레이션 + ADR-0048 K=3 완주 후 판정 | 매몰 비용 회수, 변경 폭 최소 | 쓰는 순서(빈칸 채우기)와 조사 방향(전수→대본)이 그대로다. 세션 12+, 113:1 낭비 불변 | 사람이 명시 기각 — "목표와 안 맞는 파이프라인에 계속 수정하는 꼴" |
| 쓰기 순서만 뒤집고 조사 체인(4세션)은 유지 | 그라운딩 최강 | 조사 낭비 113:1과 속도 문제가 그대로. 팩트시트가 먼저 있으면 대본이 다시 팩트시트에 끌려간다 | 속도 목표("획기적으로") 미달 |
| draft 1세션만 — 팩트체크도 생략 | 최속(편당 1세션) | 검증 없는 숫자가 화면 라벨로 박힌다(ADR-0043 인포씬). `1間` 사고 전례 — 생성 텍스트 무검수 금지는 ADR-0043이 재확인한 원칙 | 틀린 숫자는 채널 신뢰 훼손 — 비용 비대칭 (ADR-0010과 같은 논리) |
| LLM 검증 게이트(score/judge)를 새 flow에도 유지 | 자동 품질 문턱 | 호르무즈 실측 — 채점기는 병을 정확히 보고도 pass를 냈다. 세션 +2 | 판정은 사람이 대본을 읽고 한다 (사람 결정). 자동 판정은 실측으로 반증됐다 |

## 결과

### 바뀌는 것

- **속도**: 편당 LLM 세션 12~26 → **2**. 조사 산출물 ~89,000자 → 시드 기사 링크 +
  factcheck.md 한 장
- **스펙**: specs/05 1부 절·경계 절 재작성, specs/06 전면 재작성(기사 시드·주장 단위
  후행 검증), specs/01에 통짜 작성 원칙·script.md 정본 포맷 추가, specs/07 보류 선언,
  script-rules.json `score` 블록 삭제 (`limits`/`checks`/`signatures`는 유지 —
  `checks`의 씬 단위 항목은 `[3s]` 소관으로 남는다)
- **코드**: stages/research·outline·sceneplan·write·score·validate 삭제
  (session은 헤드리스 공용 배선이라 남는다 — refpack·draft·factcheck가 쓴다),
  stages/draft·factcheck 신설, topic 간소화([0. seed]), cli 재배선, status 체크리스트 갱신,
  prompts/01~04·08~10·12 삭제, prompts/draft·factcheck 신설
- **테스트**: 죽은 단계의 구현 묶인 테스트 삭제 (ADR-0034 §4), draft/factcheck 계약
  테스트 신설 (픽스처 md → 엔벨로프 검사 통과가 최소 기준)
- **백로그**: 항목에 시드 기사 URL 필드 추가
- **2부**: `[3. tts]` 입력이 06-script.json → script.md 줄. `[3s. scenetable]` 신설
  (다음 세션). 그 전까지 새 편은 대본 생산·승인까지만 돌 수 있다

### 되돌릴 조건

- **팩트체크가 새는가**: 다음 3편에서 화면에 나간 라벨·숫자 오류가 발생하면 검증을
  강화한다 — 단 전수 조사로 회귀가 아니라 주장 단위 검증의 강화다 (교차 소스 수 상향 등)
- **대본이 목표 미달인가**: script.md가 목표물(공학용쇼츠제작 시연 대본) 수준을 못 넘으면
  draft 프롬프트와 specs/01의 서사 원칙을 고친다 — 단계를 다시 늘리는 쪽으로 가지 않는다
- **시드 기사가 빈약한 소재**: 기사 한 장으로 90초를 못 채우는 소재가 반복되면 [1. draft]에
  보조 소스 1~2개 허용을 검토한다 — 전수 조사 부활이 아니라 시드 보강이다
