# ADR-0055: 엔딩 실사 컷 — `[4]`가 검증·수집한 실사진을 영상 끝에 붙인다

- 상태: 승인 (2026-08-22 — 사람이 "이대로 구현"으로 승인. cc-by-sa 포함·3장×2.4초·재고 재사용 그대로)
- 날짜: 2026-08-22
- 관련 스펙: specs/03-visual-rules.md, specs/05-pipeline.md, specs/schema/refs.schema.json, specs/schema/ending.schema.json(신설)
- 관련 ADR: ADR-0030(**부분 번복** — "참조 사진은 최종 산출물에 들어가지 않는다"),
  ADR-0046(첨부 보류 — 내려받은 사진의 소비자가 0이 된 배경), ADR-0024(클립 기하 —
  하드컷 진입의 근거), ADR-0031(비전 판정 세션 전례), ADR-0054(빈 `[8]` 번호),
  ADR-0002(화면 텍스트는 후처리 합성), ADR-0009(판단 게이트는 사람 하나)

## 맥락

사람 지시 (2026-08-22): **"실제 사진이 존재하는 쇼츠는 사진을 수집해 마지막에 넣었으면
좋겠어. 쇼츠에 넣는데 문제가 없다면. 인물은 제외하고."**

지식 쇼츠에서 AI 그림으로 설명을 끌고 온 뒤 **"그리고 이것이 실제 모습"**으로 끝나는
엔딩은 소재가 실물일 때만 가능한 마감이고, 설명(그림은 이해를 보조한다 — ADR-0047)과
신뢰(방금 본 것이 실재한다)를 동시에 닫는다.

### 재료는 이미 있다 — 소비자가 없을 뿐이다

`[4] refpack`이 씬별 실사진을 모으면서 **라이선스를 출처 페이지에서 확인하고**(WebFetch,
ADR-0030 구현 노트), 허용 라이선스인 사진만 내려받아 `runs/{run_id}/refs/`에 두고,
`source_url`·`license`·`credit`을 전부 `refs.json`에 남긴다. 그런데 ADR-0046이 MJ 첨부
경로를 보류하면서 **내려받은 파일을 읽는 단계가 지금 0개다** — 서술(`description`)만
소비되고 파일은 디스크에만 있다.

즉 "사진을 수집해"는 새 수집이 필요한 일이 아니라 **이미 검증까지 끝난 재고를
큐레이션하는 일**이다.

### ADR-0030과의 관계 — 부분 번복

ADR-0030: "최종 산출물에 참조 사진 자체가 들어가는 일은 없다. 이미지 프롬프트는
**입력**이다." 이 문장은 **프롬프트 참조라는 용도**에 대한 것이었다. 이번 결정은 같은
사진의 **다른 용도**(화면 게시)를 열되, 용도가 다르므로 판정 축도 분리한다 —
첨부 가능(`attachable`)과 게시 가능은 다른 질문이고, 게시 축은 새 계약
(`ending.schema.json`)이 진다.

### 저작권 — "쇼츠에 넣는데 문제가 없다면"의 답

수익화 채널에 붙는 축이라 라이선스별로 정리한다. `[4]`의 라이선스 어휘 기준이다.

| 라이선스 | 게시 | 조건 |
|---|---|---|
| `public-domain` · `cc0` | 가능 | 없음 (크레딧은 관행으로 남긴다) |
| `cc-by` | 가능 | **저작자 표시 필수** |
| `cc-by-sa` | 가능 | 저작자 표시 + **무수정 표시일 때만** (아래) |
| `copyrighted` · `unknown` | **불가** | — 애초에 `[4]`가 내려받지 않아 후보에 없다 |

**SA(동일조건변경허락)는 개작(adaptation)에만 전파된다.** CC 라이선스 원문에서 영상
동기화로 개작이 항상 성립하는 것은 **음악 저작물뿐**이고, 정지 사진을 무수정으로 더 큰
저작물에 싣는 것은 수집물(collection) 편입이라 SA가 영상 전체로 번지지 않는다. 크기
조정·포맷 변환은 개작이 아니다. 단, 이 논리는 **사진을 건드리지 않을 때만** 선다.
그래서 엔딩 실사의 표시 규칙은 라이선스 축이 정한다:

- **크롭 금지, 카메라 워크 금지** — 켄번스는 `crop`+`zoompan`이라 개작 축을 건드린다.
  실사는 증거라 정지가 연출로도 맞다
- **원비율 유지 + 단색 배경 패딩** — 블러 배경은 사진에서 파생한 그림이라 같은 이유로
  쓰지 않는다
- **크레딧 표시** — 프레임 하단에 굽고(자막 폰트 자산 사용, ADR-0002의 후처리 합성
  경로. 폰트가 없으면 굽기만 강등하고 기록은 남는다), `ending.json`과
  `ending/credits.txt`(업로드 설명란에 붙일 사람용)에 항상 남긴다

**인물 제외는 라이선스와 별개 축이다.** 사진이 자유 라이선스여도 찍힌 사람의 초상권은
남는다. 사람 지시이기도 하고 법 축으로도 맞다 — 식별 가능한 인물이 있는 사진은
기각한다. 이 판정은 파일을 봐야 하므로 기계 대조가 아니라 비전 세션 몫이다
(`[6r]`이 이미 같은 방식으로 이미지를 판정한다 — ADR-0031).

### 기하 — 엔딩 진입은 하드컷이어야 한다

`[7]`은 `build_timeline`의 `clip_length`대로 렌더하고, **마지막 씬의 segment는
`transition_out`이 없어 꼬리 0.6초가 렌더되지 않는다** (`video/timeline.py`의 불변식
"마지막 클립은 꼬리를 쓰지 않는다"). 엔딩을 디졸브로 진입시키면 xfade가 소진할 앞
클립 프레임이 없다. 꼬리를 만들려면 `[7]`을 고쳐야 하는데 그것은 D-4(단계 추가는 기존
단계를 수정하지 않는다) 위반이다.

**하드컷 진입은 기하가 강제하고 연출도 맞다** — "하드컷은 서사가 끊기는 자리"(specs/00)
이고, AI 그림 → 실사 전환이 정확히 그 자리다. 엔딩 사진 사이는 `[8]`이 자기 클립에
꼬리를 렌더하므로 디졸브로 잇는다.

### `[10] mix`와의 관계

타임라인 총 길이 = `total_duration` = 나레이션 길이라는 불변식이 엔딩 꼬리만큼 깨진다.
`[10]`은 미구현이라 지금 계약을 정한다: **나레이션은 `total_duration`에서 끝나고 BGM이
엔딩 꼬리를 덮는다.** 자막도 나레이션 구간에만 있다 — 엔딩에는 자막 큐가 없다.

## 결정

**`[8. ending]`을 신설한다** (ADR-0054가 비운 번호). `[6r]`·`[6i]`와 `[9]` 사이,
선후 제약은 "`[4]` 뒤·`[9]` 앞"뿐이다.

1. **후보는 기계가 거른다** — `refs.json`에서 `file`이 있는 사진(= `[4]`가 라이선스를
   확인하고 내려받은 것) 중 라이선스가 `ending.schema.json` meta의 게시 목록에 있는 것,
   `source_url` 중복 제거. 목록은 오늘 `attachable_licenses`와 같은 4종이지만 **축이
   달라 별도로 둔다** — 한쪽이 넓어져도 다른 쪽이 따라가지 않는다 (ADR-0034: 코드는
   로드한다)
2. **비전 세션 1회가 판정한다** (`Read` + `add_dirs`, ADR-0031 전례): ① 실사 사진인가
   (도해·렌더·그림 기각) ② 소재 실물이 식별되게 나오는가 ③ **식별 가능한 인물이 있으면
   기각** ④ 워터마크·큰 글자 기각 ⑤ 화면을 채울 화질인가. 통과분에 표시 순서를 매긴다
   (전경이 먼저). 상한은 meta의 `max_photos`
3. **렌더**: 원비율 유지 스케일 + 단색 배경 패딩(1080×1920), 카메라 없음, 크레딧
   drawtext(강등 사다리: `굽기+기록 → 기록`), 사진당 표시 `photo_seconds` + 꼬리 0.6초
   (ADR-0024 기하 그대로) → `ending/{nn}.mp4` + `ending.json` + `ending/credits.txt`
4. **`[9]`는 `ending.json`이 있으면** 마지막 씬 뒤에 하드컷으로 진입해 사진 클립들을
   디졸브로 잇는다. 자막·싱크 검증(±200ms)은 씬 구간만 본다 — 엔딩에는 검증할 큐가
   없다. 파일이 없으면 지금과 완전히 같다 (D-3·D-4: 새 단계는 새 파일을 쓰고, 읽고
   싶은 단계만 읽는다)
5. **후보 0장·전부 기각이면 `ending.json`을 쓰지 않는다.** 실물 없는 소재(개념·도해
   중심)에는 엔딩이 없는 것이 정상이고 부재는 경고가 아니다 (D-3). 그 사실은
   `state.json`에 남는다

값은 코드가 아니라 `ending.schema.json` meta에 둔다 (ADR-0034): `max_photos: 3`,
`photo_seconds: 2.4`(레퍼런스 전환 실측 2.3~2.9초 안 — docs/reference-analysis.md),
게시 라이선스 목록. 엔딩 꼬리는 최대 3장 × 2.4초 ≈ 7.2초로, 나레이션 상한 102초에
붙어도 쇼츠 3분 경계와 무관하다.

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **`[8]`이 웹에서 새로 수집한다** (`[4]`식 검색 세션) | 엔딩 전용 대표 사진을 노린다 | 세션 2회(수집+비전), 다운로드·라이선스 검증 배관 중복 | `[4]`가 검증까지 끝낸 재고가 소비자 없이 남아 있다 (ADR-0046). 재고로 안 되는 편이 관측되면 그때 넓힌다 — 되돌릴 조건에 걸어 둔다 |
| **`[7]`이 엔딩 클립도 만든다** | 단계가 안 는다 | `[7]`의 입력은 씬 계약인데 엔딩은 씬이 아니다 | 가짜 씬을 계약에 넣으면 씬 경계 = `[3]` 실측(ADR-0013)이 깨진다. 새 일은 새 단계가 새 파일로 한다 (D-4) |
| **사람이 고른다** (수동 큐레이션) | 판정 품질 | 2부 한가운데 수동 게이트가 생긴다 | 판단 게이트는 1부 끝 하나다 (ADR-0009). 인물·워터마크 판정은 `[6r]`이 이미 비전 세션으로 하는 종류의 일이다 |
| **켄번스 모션을 준다** | 본편과 톤이 같다 | `crop`+`zoompan`은 사진을 건드린다 | SA 전파 논리가 무수정 표시 위에 서 있다 (맥락 절). 실사는 증거라 정지가 연출로도 맞다 |
| **디졸브로 진입한다** | 부드럽다 | 마지막 씬 클립에 꼬리가 없다 | `[7]` 기하가 강제한다 (맥락 절). 꼬리를 만들려면 `[7]` 수정 = D-4 위반. 하드컷이 기하도 연출도 맞다 |
| **cc-by-sa를 뺀다** | SA 논쟁 자체를 회피 | 문화유산 사진의 큰 몫이 위키미디어 자체 촬영 = cc-by-sa | 후보 풀이 반토막 나 "실사가 존재하는데 엔딩이 없는" 편이 늘어난다. 무수정 표시 + 표시 의무 이행으로 리스크를 좁히고, 판단이 바뀌면 meta 목록에서 빼기만 하면 된다 (코드는 로드한다) |

**비용**: 비전 세션 1회(구독, 한계비용 0) + FFmpeg 몇 초. 과금 0 — 새 다운로드도 없다.

**되돌릴 조건**

- **엔딩이 시청을 깎으면 끈다.** 쇼츠는 마지막 이탈이 루프 지표를 깎는 매체다 — 엔딩
  붙은 편의 끝 5초 이탈이 안 붙은 편보다 눈에 띄게 나쁘면 이 단계는 마감이 아니라
  꼬리표다
- **재고 기각률이 높으면 수집을 넓힌다.** 비전 세션 기각 사유를 `ending.json`에 남기고,
  "쓸 사진이 없어 엔딩이 빠진" 편이 잦으면 대안 1(전용 수집 세션)로 넓힌다
- **cc-by-sa 판단이 바뀌면** meta 목록에서 빼는 것으로 끝난다 — 코드 수정 없음
