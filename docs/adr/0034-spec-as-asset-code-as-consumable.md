# ADR-0034: 스펙이 자산이고 코드는 소모품이다 — 단계 독립과 기계 판독 계약

- 상태: **승인** (2026-08-13 `specs/schema/` 신설, `schemas/*.py`가 로드로 전환)
- 날짜: 2026-08-13
- 관련 스펙: specs/05-pipeline.md, 전 스펙의 운영 방식
- 관련 ADR: ADR-0011(단계 계약·세션 격리), ADR-0017(1부↔2부 경계), ADR-0020(값의 출처),
  ADR-0033(구조·연출 자유화)

## 맥락

### 자원의 값이 뒤집혔다

**예전에는 코드가 비싼 자원이었다.** 사람이 손으로 쓰고, 고치는 데 시간이 들고, 그래서
설계는 코드를 보존하는 방향으로 기울었다. 스펙은 코드를 만들기 위한 임시 문서였다.

**지금은 코드가 싸다.** 스펙이 정확하면 구현은 다시 만들면 된다. 비싼 것은 **왜 그렇게
정했는지의 판단**이고, 그것이 사는 곳이 스펙과 ADR이다. 실측 한 번(relax 9잡, 이미지
$0.101, TTS 두 콜)에서 나온 결론은 코드를 아무리 다시 짜도 복원되지 않는다.

그러면 설계 판단의 기준이 바뀐다. **"이 코드를 살릴 수 있는가"가 아니라 "이 판단을
잃지 않는가"** 다.

### 이 프로젝트는 이미 절반쯤 그렇게 하고 있었다 — 그런데 새는 데가 있다

파일 기반 계약(ADR-0011), 1부↔2부 경계 2파일(ADR-0017), 값의 출처는 하나(ADR-0020),
선택 필드의 부재를 경고하지 않기(ADR-0028), 강등 사다리(ADR-0030) — 전부 같은 방향이다.
**원칙으로 적혀 있지 않아서 지켜지지 않은 자리가 있다.**

| 사고 | 무엇이 샜나 |
|---|---|
| **`mj_video` 누락** | ADR-0025 §3이 `motion` enum에 넣으라고 승인했는데 **스펙에도 코드에도 없었다.** 스펙 02의 enum과 `schemas/scenes.py`의 `MOTIONS`가 **손 동기화**다 |
| **ADR-0033 ↔ 스펙 불일치** | ADR이 스펙보다 앞서 나가 `CLAUDE.md`에 ⚠를 달아야 했다. 절대 원칙 1("스펙이 코드보다 우선")의 예외를 만든 셈이다 |
| **`[1] script` 과부하** | 한 단계가 아홉 가지 판단을 져서 뒤에 오는 것이 형식적으로 채워졌다 (ADR-0029) |

앞의 둘은 같은 병이다. **판단이 사는 곳(ADR)과 기계가 읽는 곳(코드) 사이에 사람 손이
끼어 있다.**

## 결정

### 1. 자원 등급을 명시한다

| 등급 | 무엇 | 바뀔 때 |
|---|---|---|
| **가장 비싸다** | ADR — 판단과 그 근거, 실측, 되돌릴 조건 | 새 ADR로 대체. **지우지 않는다** |
| 비싸다 | 스펙 — 무엇을 만족해야 하는가 | ADR을 근거로 재작성 |
| **싸다** | 코드 — 어떻게 만족시키는가 | **주저 없이 갈아엎는다** |
| 싸다 | 테스트 중 구현에 묶인 것 | 코드와 함께 버린다 |

**"코드를 살리려고 스펙을 비트는 것"이 이 프로젝트에서 가장 비싼 실수다.** 반대 방향은
싸다 — 스펙이 맞으면 코드는 다시 만들면 된다.

### 2. 단계 독립 원칙 다섯

파이프라인을 계속 세분화하고 갈아엎으려면 **단계 하나를 버려도 옆이 안 무너져야 한다.**

- **D-1. 단계는 파일로만 통신한다.** 함수 호출로 잇지 않는다 (ADR-0011 유지)
- **D-2. 단계는 자기가 읽는 필드만 안다.** 모르는 필드는 **읽지도 지우지도 않고 통과시킨다.**
  상류가 필드를 추가해도 하류가 안 깨진다
- **D-3. 선택적 입력의 부재는 경고가 아니다.** 없으면 그 기능만 빠지고 단계는 돈다
  (전례: 스타일 앵커, `subject_anchor`, `refs.json`)
- **D-4. 단계 추가는 기존 단계를 수정하지 않는다.** 새 단계는 새 파일을 쓰고, 그 파일을
  읽고 싶은 단계만 읽는다. **`[4] refpack`·`[6r] imagereview`가 그렇게 설계됐다**
- **D-5. 실패는 단계 안에서 끝난다.** 강등 사다리나 폴백으로 처리하고 파이프라인을
  세우지 않는다. 세우는 경우는 **돈이 나가거나 되돌릴 수 없을 때만이다**
  (방언 불일치, 정책 드리프트, 길이 초과)

### 3. 기계가 읽는 계약을 스펙 옆에 둔다

**스펙 문서에서 enum·스키마·어휘를 코드로 손 복사하는 것을 그만둔다.**

```
specs/01-script-template.md      ← 왜 그런가. 사람이 읽는다
specs/schema/scene.schema.json   ← 무엇인가. 코드가 로드한다
specs/schema/vocab.json          ← 구도 토큰·오버레이 타입·camera·motion 어휘
```

- 스펙 문서는 그 파일을 **참조**하고 값을 다시 적지 않는다
- 코드는 상수를 선언하지 않고 **로드한다.** `MOTIONS = (...)` 같은 손 복사가 사라진다
- ADR-0033이 룰 테이블을 **어휘 목록**으로 바꾸므로 이 형식이 마침 잘 맞는다 —
  표에서 목록이 되면 그건 데이터다

이것이 `mj_video` 사고의 재발 방지책이다. **한 곳만 고치면 스펙과 코드가 함께 움직인다.**

### 4. 테스트는 계약을 검사하지 구현을 검사하지 않는다

코드가 소모품이면 **구현에 묶인 테스트도 소모품**이다. 900개를 매번 다시 쓸 수는 없다.

- **살릴 테스트**: 픽스처 JSON을 넣고 산출 JSON이 스키마·불변식을 만족하는지 본다.
  구현이 바뀌어도 산다
- **버릴 테스트**: 내부 함수 시그니처·호출 순서·중간 자료구조를 검사하는 것. 코드와
  함께 버린다
- 새 단계의 최소 기준은 그대로다 — **픽스처 입력 → 스키마 검증 통과** (`CLAUDE.md`)

### 5. 갈아엎을 때의 순서

```
실측/판단  →  ADR  →  스펙(+ schema/)  →  코드  →  계약 테스트
```

- **역방향으로 가지 않는다.** 코드를 먼저 고치고 스펙을 맞추면 판단이 어디에도 안 남는다
- ADR이 스펙보다 앞선 기간이 생기면 **그 사실을 `CLAUDE.md`에 명시하고 기한을 둔다**
  (ADR-0033에서 실제로 그렇게 했다). 상시화되면 스펙이 자산 역할을 잃는다
- `/spec-check`가 이 불일치를 잡는 자리다

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **코드를 진실로 두고 스펙을 생성** | 동기화 문제가 원천 소멸 | 판단이 코드 주석에 갇힌다 | **자원 등급이 거꾸로다.** 실측 근거와 되돌릴 조건은 코드에서 복원되지 않는다 |
| 지금처럼 손 동기화 + 주의 | 할 일 0 | 이미 두 번 샜다 | `mj_video`는 **ADR이 승인한 것이 두 문서에서 동시에 누락**된 사고다. 주의로 막히지 않는다 |
| 스펙 마크다운 표를 파싱해 코드가 읽는다 | 파일이 안 는다 | 표 서식이 계약이 된다 | 문서 한 줄 고치면 파서가 깨진다. 산문과 데이터를 한 파일에 섞지 않는다 |
| 단계를 더 잘게 쪼개지 않고 유지 | 변경 최소 | 한 단계가 여러 판단을 진다 | ADR-0029가 그 실패를 정리했다. 세분화는 이 ADR의 전제다 |

## 결과

**바뀌는 것**

| 대상 | 변경 |
|---|---|
| `CLAUDE.md` 작업 규칙 | 자원 등급, 단계 독립 5원칙, 갈아엎기 순서 |
| `specs/schema/` | 신설. `scene.schema.json`·`vocab.json`부터 |
| `schemas/*.py` | 상수 선언 → 로드. ADR-0033 스펙 재작성과 **같이 한다** |
| `tests/` | 계약 테스트와 구현 테스트를 가른다 |

**당장 하지 않는 것**: 기존 900개 테스트를 지금 분류하지 않는다. **코드를 갈아엎을 때
그 단계 것만 정리한다** — 안 그러면 이 ADR 자체가 큰 일괄 작업이 되어 취지에 어긋난다.

**비용**: `specs/schema/` 도입은 ADR-0033의 스펙 재작성에 얹으면 추가 비용이 거의 없다.
어차피 표를 어휘 목록으로 바꾸는 중이다.

## 되돌릴 조건

- **스키마 파일이 스펙 문서와 또 갈라지면** 두 곳을 만든 것이 문제다. 그때는 스펙 문서에서
  해당 표를 아예 지우고 **스키마 파일 하나만 남긴다** (문서는 링크만 건다)
- 단계 독립을 지키느라 파일이 지나치게 늘어 사람이 흐름을 못 읽으면 D-4를 완화한다.
  관측 수단은 `runs/{run_id}/`의 파일 수다
- **ADR이 스펙보다 앞선 상태가 상시화되면** 이 ADR의 5번이 지켜지지 않는 것이다.
  그때는 ADR을 쓰는 세션이 스펙 반영까지 끝내도록 범위를 넓힌다
