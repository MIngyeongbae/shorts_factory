# ADR-0046: 로컬 프록시를 인터넷에 노출하지 않는다 — 참조 사진 첨부는 클라우드 이전까지 보류

- 상태: 승인 (2026-08-21, 사람 결정)
- 날짜: 2026-08-21
- 관련 스펙: specs/05-pipeline.md
- 관련 ADR: **ADR-0030(첨부 경로 판정 — G2를 여기서 닫는다. 서술 경로는 그대로 산다)**,
  **ADR-0025(§"인프라가 필요 없다" 전제 유지)**, ADR-0032(프록시 경계 — 비밀이 응답에 섞인다),
  ADR-0042(앵커 언어 — 이 결정이 대안으로 남긴 축)

## 맥락

### 1. 사람이 산출물을 보고 참조를 요구했다

첫 실운영 편(호르무즈, 26씬)을 보고 사람이 적었다 — *"지금은 너무 이미지가 현실적인 게
없어, 즉 AI 생성물인 게 너무 심해."* 요구는 **씬에 들어갈 실사를 내려받아 MJ에 참조로
넣는 것**이었고, 그것은 ADR-0030이 이미 설계해 둔 **첨부 경로**다.

### 2. 첨부는 기술적으로 가능하다 — 막힌 것은 도달이다 (2026-08-21 실측)

`refs/10/01.jpg`(1949 Aramco 타프라인 용접, PD, `attachable: true`)로 잰 결과다.

| 시도 | 결과 |
|---|---|
| `imagine`에 `base64Array` (data URI / raw b64) | 제출 `code=1` → **`FAILURE: Invalid link, Invalid URL format`** |
| `upload-discord-images` | `HTTP 200` → 반환 주소가 **`http://localhost:8086/attachments/…`** |
| 프롬프트 머리에 **위키미디어 공개 URL** (`--iw 1` / `--iw 0.5`) | **`FAILURE: Could not fetch image. Received status code 403`** |

세 번째가 중요하다. **MJ는 프롬프트의 URL을 실제로 가지러 나간다** — 앞의 둘이 "형식
오류"였던 것과 달리 이번엔 "가져오지 못했다"다. 즉 **이미지 프롬프트 메커니즘은 살아 있고,
주소가 인터넷에서 서빙되기만 하면 된다.** 위키미디어는 MJ를 403으로 거절한다(우리 `[4]`가
429로 막히는 것과 같은 벽)이라 원본 URL을 그대로 넘길 수는 없다.

원인은 설정 한 줄이다.

```
ImageStorageType = 1
LocalStorage.CustomCdn = "http://localhost:8086"
```

프록시는 파일을 받아 저장까지 하지만 **돌려주는 주소가 로컬이라 Discord 서버가 못 닿는다.**
ADR-0025:201이 *"경로는 있고 반환 주소가 막혀 있다"*로 적어 둔 상태가 그대로 확인됐다.
**도커 볼륨으로는 풀리지 않는다** — 저장이 아니라 공개 도달의 문제이기 때문이다.

### 3. 뚫는 길 둘은 각각 이 프로젝트의 전제를 깬다

| 길 | 깨는 것 |
|---|---|
| `CustomCdn`을 공개 주소로 (터널·포트 개방) | **보안.** 8086에는 관리 API가 같이 있고 토큰이 `admin`이며, `POST /mj/admin/accounts` 응답에 **Discord `userToken`이 평문으로** 들어 있다 (ADR-0032 §3이 로그에 싣지 말라고 한 그 값이다). 경로 제한 ingress로 좁힐 수는 있으나 노출면이 0에서 0이 아니게 된다 |
| 오브젝트 스토리지 (R2·S3·OSS) | **비용.** ADR-0025가 "변동비 0 / 인프라 필요 없음"을 채택 근거로 삼았다 |

### 4. 그리고 같은 날, 더 싼 원인이 잡혔다

같은 탐침의 언어 축에서 **프롬프트를 전면 영어로 바꾼 것만으로** 산출물이 1950년대
아카이브 사진 쪽으로 크게 이동했다 (스타일 문자열·네거티브·`--ar` 동일, 씬 10, 변형당
4칸). 한국어본은 4칸 중 2칸에 사우디 북부에 없는 **산맥**이 들어왔고, 영어본은 4칸 모두
평평한 사막에 지평선까지 뻗은 관이었다 — **참조 사진을 붙이지 않고도 `refs.json`의 실사
서술과 거의 일치했다.**

즉 "AI 생성물 같다"의 큰 몫이 **참조 부재가 아니라 프롬프트 언어**일 수 있다. 인프라 0,
비용 0인 축이 아직 다 소진되지 않았다.

## 결정

**로컬 프록시를 인터넷에 노출하지 않는다. 오브젝트 스토리지도 지금은 도입하지 않는다.**
따라서 **참조 사진 첨부 경로를 보류하고, ADR-0030의 강등 사다리에서 `서술` 칸만 쓴다.**
`[4] refpack`은 그대로 돌려 `refs.json`을 계속 만든다 — 생산을 멈추면 나중에 재개할 때
소재별로 다시 모아야 하고, 서술 경로의 입력이기도 하다.

**재개 조건은 장소의 이동이다.** 파이프라인 전체가 완성된 뒤에도 실사 참조가 필요하다고
판단되면, 그때 **프로젝트를 클라우드 서버에 세팅하고 오브젝트 스토리지를 함께 쓴다.**
로컬 PC에 구멍을 내는 방식으로는 하지 않는다.

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **Cloudflare Tunnel로 `CustomCdn` 공개** | 포트 개방 없음, 무료, 설정 한 줄 | 8086에 관리 API가 같이 있다. 경로 제한을 걸어도 노출면이 생기고, 터널이 떠 있어야 파이프라인이 돈다 | **사람이 보안 위험을 이유로 기각.** 노출되는 값이 Discord 계정 토큰이라 사고 시 복구가 계정 재발급이다 |
| **R2/S3/OSS로 전환** | 관리 API는 로컬에 남는다. 프록시가 이미 지원 | 계정·버킷·요금이 붙는다 | **사람이 비용을 이유로 기각.** ADR-0025의 "인프라 필요 없음"을 상시 비용으로 바꾸는 값어치가 아직 증명되지 않았다 — §4의 언어 축이 공짜로 남아 있다 |
| **도커 볼륨을 만든다** (사람의 첫 안) | 로컬에서 완결 | 저장 위치를 바꿀 뿐 주소는 여전히 로컬이다 | **문제를 안 푼다.** 막힌 것은 저장이 아니라 **공개 도달**이고, Discord 서버가 인터넷을 통해 가져가야 한다 |
| **위키미디어 원본 URL을 그대로 넘긴다** | 호스팅 0 | **403.** MJ가 가지러 갔다가 거절당한다 | 실측으로 탈락 (§2). 우리가 서빙하지 않는 한 안 된다 |

## 결과

### 바뀌는 것

- **코드 변경 없음.** 첨부 경로는 원래 미구현이었다 — 이 결정은 그것을 **의도적 보류로
  확정**한다. `[6] imagegen`의 `submit`은 계속 `{"prompt": …}`만 보낸다
- `ADR-0030` **G2를 닫는다** — "이미지 프롬프트를 붙여도 `BASE_STYLE`이 살아남는가"는
  **측정 불가로 종결**한다(붙일 수가 없어서 스타일 다툼까지 가지 못했다). 강등 사다리는
  `~~첨부+서술~~ → 서술 → 없음`이 된다
- `[4] refpack`은 유지. 다만 **소비자는 `[5]`의 서술 경로 하나뿐**이고 그것도 아직 미구현이라,
  현재 `refs.json`은 여전히 읽는 곳이 없다 (ADR-0030 「구현 상태」 그대로)
- **비용·보안 변화 없음** — 그것이 이 결정의 목적이다

### 되돌릴 조건

1. **파이프라인이 완성되고, 언어 축을 소진한 뒤에도 실사 참조가 필요하다고 판단되면.**
   그때는 로컬을 여는 것이 아니라 **클라우드 이전 + 오브젝트 스토리지**로 간다 (사람 결정)
2. **프록시가 Discord CDN 주소를 직접 돌려주는 경로가 확인되면.** `upload-discord-images`가
   이름과 달리 로컬 저장으로 귀결됐는데, 설정으로 Discord 업로드가 되는 모드가 있다면
   호스팅 없이 풀린다 — 확인 안 된 자리다
3. **§4의 언어 축이 재현에 실패하면.** 참조 없이 해결된다는 전제가 무너지므로 인프라
   값어치를 다시 계산해야 한다
