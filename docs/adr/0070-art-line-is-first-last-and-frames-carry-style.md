# ADR-0070: `art` 라인은 first/last 구조이고, 스타일은 프롬프트가 아니라 프레임이 진다

- 상태: 승인
- 날짜: 2026-08-25
- 관련 스펙: specs/03-visual-rules.md, specs/05-pipeline.md, specs/schema/vocab.json

## 맥락

worklog (45)에서 사람이 `art` 라인의 방향을 정했다 — **MJ가 그린 밑그림을 영상 모델이
움직인다**(ADR-0043의 구조 부활), 그리고 **"나중에 H3를 유료로 바꿀 수 있다는 것만 남겨
달라"**. 그때 남은 미지수를 "ADR 전에 프로브로 답할 것"으로 적어 뒀다.

이번 세션이 그 프로브를 돌렸다. **미지수가 전부 닫혔고, 예정에 없던 규칙이 하나 나왔다.**

**프로브 1 — 영상 모델이 `last_frame`을 지키는가** (japan-5060hz 씬 4, 로컬 H3, 150초)

| 대조 | PSNR |
|---|---|
| 출력 끝 프레임 vs 입력 `last_frame` | **31.4 dB** |
| 출력 첫 프레임 vs 입력 `first_frame` | 36.9 dB |
| 출력 중간 프레임 vs `last_frame` | 14.5 dB (= 진짜 보간, 크로스페이드 아님) |
| (기준선) `first` vs `last` | 13.1 dB |

끝 프레임의 빨간 라벨 상자(`50 Hz`·`60 Hz`·`1 s`)가 위치까지 재현됐고, **중간 프레임에서도
치수선이 기둥을 따라 움직이며 글자가 읽힌다.**

**프로브 2 — 영상 모델이 MJ 그림(분포 밖)을 움직이는가** (씬 1, MJ 이미지 → 로컬 H3)

끝 프레임 vs `last_frame` **22.6 dB** (기준선 12.8). H3 자신의 렌더(31.4)보다 낮은 것은 MJ의
조밀한 디테일이 VAE 왕복에서 더 손실되기 때문이고 화면 크기에서는 문제되지 않는다.

**여기서 예정에 없던 것이 나왔다.** 첫 시도의 **중간 프레임이 무너졌다** — 종이 위 옅은 수채
스케치로 흘러가고 가장자리에 여백까지 생겼다. 바꾼 것은 하나뿐이다:

| 영상 프롬프트 | 중간 프레임 |
|---|---|
| 내용 + 카메라 + **스타일 낱말** | **무너진다** (중간 vs last 9.5 dB) |
| 내용 + 카메라 **만** | **유지된다** (13.6 dB, 정상 보간 궤적) |

스타일을 말로 시키면 영상 모델이 **자기 프라이어로 그것을 해석해 프레임과 싸운다.**

**프로브 3 — MJ가 계측 기하를 정확히 그리는가.** 씬 4에서 위 파형은 성기고 아래는 촘촘하게
그렸다. **로컬 H3 t2v가 두 번 연속 죽은 바로 그 지점이다** (worklog (45): "50Hz·60Hz 사인파를
같은 파장으로 그린다"). 정확성을 정지 이미지가 지면 그 실패가 사라진다.

**프로브 4 — MJ 영상이 우리 INFO 이미지를 끝 프레임으로 받는가. 받는다.**
MJ CLEAN(U4) → 코드가 빨간 계측 표시를 얹은 INFO → `POST /mj-fast/mj/submit/video`의
`endImage`. **60초에 성공했고 끝 프레임에 `River 340 m`·`1.1 km` 라벨 상자·치수선·화살촉이
글자까지 그대로 나왔다.** 중간 프레임은 표시 없이 깨끗하다 — 표시가 끝으로 가며 조립된다.

**엔진이 둘이고 둘 다 선다** (2026-08-25 실측)

| 엔진 | 1클립 | 변동비 | 우리 이미지 전달 | 스타일 보존 |
|---|---|---|---|---|
| 로컬 H3 fl2v | 160~180초 | **0** | 로컬이라 문제없음 | 프롬프트에서 STYLE 절을 빼야 유지된다 |
| MJ `endImage` (fast) | **60초** | fast GPU 1.8분 (Pro 잔량 27.3h ≈ 900클립 ≈ 53편/월) | **R2로 해결** | 그대로 유지 |
| MJ `endImage` (relax) | 208초 | **0** (동시 3 → 편당 ≈ 25분, **편수 무제한**) | 〃 | 〃 |
| MJ turbo | — | — | — | 거절 (`Turbo mode isn't supported for video jobs`) |

**MJ 엔진의 전제는 공개 이미지 호스팅이었고, 같은 날 섰다.** MJ는 자기가 닿는 URL만 받는다.
프록시가 `imageStorageType = LOCAL`일 때는 `http://localhost:8086/...`을 돌려주고 MJ가
`Invalid link, Invalid URL format`으로 거절한다 (ADR-0025 실측의 재현). `NONE` 저장은 업로드
자체가 실패하고(code 9), `endImage`에 base64를 직접 넣어도 같은 거절이다.

**해결: 프록시 `imageStorageType = R2` (Cloudflare R2, 사람이 계정·버킷·토큰 생성).**
업로드가 `https://pub-<해시>.r2.dev/attachments/...png`를 돌려주고(HTTP 200 · `image/png`),
그 주소로 `endImage` 영상이 **54초에 성공**했다. 끝 프레임에 우리가 얹은 `River 340 m`·
`1.1 km`가 글자까지 재현된다. **아웃바운드 전용이라 이 PC가 열리지 않는다** — 중간에 쓴 임시
터널(trycloudflare)은 관리 API까지 함께 열어 상시 구성이 못 됐고, R2가 그것을 대체했다.
무료 티어(저장 10 GB · Class A 100만 · Class B 1000만/월)에 우리 사용량(편당 34 MB · 17회
업로드)은 자릿수가 다르다.

## 결정

**`art` 라인은 「정지 이미지가 계측을 지고, 영상 모델은 잇기만 한다」 구조로 간다.**

    CLEAN 이미지  →  first_frame
        ↓ 우리가 계측 표시를 얹는다 (숫자·라벨의 정확성은 여기서 끝난다)
    INFO 이미지   →  last_frame
        ↓ 영상 모델 fl2v
    표시가 조립되며 완성되는 클립

그 위에 규칙 셋을 계약으로 박는다.

1. **`art` 라인의 영상 프롬프트는 STYLE 절을 싣지 않는다.** 내용과 카메라만 쓴다 —
   스타일은 프레임이 진다. 지금 `[5]`의 `build_video_prompt`는 STYLE 절을 항상 싣는데
   `art`에서는 빼야 한다
2. **영상 엔진은 라인에 묶이지 않는다.** `art`의 `provider`를 갈아 끼울 수 있게 두고
   **엔진마다 프로브 1을 다시 돌린다** (비교값 31.4 dB / 기준선 13.1 dB)
3. **엔진 기본값은 MJ `endImage`(fast)로 둔다.** R2가 서면서 전달 문제가 사라졌고,
   로컬 H3 대비 3배 빠르며(60초 vs 170초) 스타일 보존이 낫다. **로컬 H3는 대체 엔진으로
   살려 둔다** — 변동비 0이고 MJ 잔량·장애 때 그대로 쓴다

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **로컬 H3를 기본으로 두고 MJ는 예비로** | 변동비가 0이고 외부 의존이 없다 | 3배 느리고, 스타일이 프롬프트와 싸워 규칙 1이 필요하다 | R2가 서면서 MJ의 유일한 걸림돌(전달)이 사라졌다. 속도·스타일 보존이 둘 다 MJ 우위라 기본을 뒤집을 근거가 없다. **다만 버리지 않는다** — 변동비 0이라 MJ 잔량 소진·장애 때의 대체 엔진이다 |
| **로컬 H3에 고정** | 전달 문제·변동비가 영영 없다 | 3배 느리고 스타일이 프롬프트와 싸운다 | 사람이 worklog (45)에서 **"H3를 나중에 유료로 바꿀 수 있게 남겨 달라"**고 명시했다. 고정은 그 지시를 어긴다 |
| **계측 표시도 영상 모델이 그리게 한다** (지금 `local` 라인) | 단계가 줄고 이미지 왕복이 없다 | worklog (45) 실측: 재사용률 korean-id 9/16 · edo 9/17. 파장이 같은 사인파, 좌우 반전 지시선 | **모델 능력의 벽이다.** ADR-0067의 고쳐쓰기가 8회 중 6회를 회복시켰지만(us-penny 2/18) 근본은 "정확한 계측 기하를 상상해서 그리기"이고 이 ADR이 그 일을 안 시킨다 |
| **스타일을 영상 프롬프트에도 실어 보강한다** | 프레임이 흐릴 때 보험이 된다 | — | **실측으로 탈락.** 중간 프레임이 무너진다 (9.5 dB) |

## 결과

**바뀌는 것**

| 자리 | 변경 |
|---|---|
| `specs/schema/vocab.json` | `video_line.art`의 `provider`를 채운다(기본 `mj-endimage`, 대체 `comfy-h3-fl2v`). `art`는 STYLE 절을 안 싣는다는 표시 |
| `specs/05-pipeline.md` | `art` 라인의 `[7]` 입력이 **씬당 이미지 2장**(CLEAN·INFO)이라는 계약. 이미지를 만드는 자리가 생긴다 |
| `specs/03-visual-rules.md` | 「스타일을 지는 것은 프레임이다」 — `art`의 영상 프롬프트 구성 |
| 코드 | MJ 영상 어댑터 부활 (`2f1b6bf^`에 온전하다) + `endImage` 인자 추가. `build_mj_prompt()` 부활 (ADR-0069). 대체 엔진용으로 `config/comfy/h3-t2v.api.json`에 `first_frame`/`last_frame` 배선 |

**비용**: MJ Pro 정액 안에서 끝난다. fast는 클립당 GPU 1.8분(잔량 27.3h ≈ 53편/월),
relax는 GPU 0에 **편수 무제한**이고 편당 ≈ 25분이다 — 배치는 relax, 단발 확인은 fast.
R2는 무료 한도 안이다. 검수 대상이 CLEAN·INFO·클립 셋으로 늘어 세션 수는 는다. 반대로
ADR-0068이 기각한 끝 프레임 OCR 게이트의 **되살릴 조건이 여기서 닿는다** — `last_frame`이
우리가 만든 이미지가 되면 OCR이 보는 대상이 바뀐다.

**되돌릴 조건**

1. **R2 무료 한도를 넘거나 r2.dev가 레이트리밋에 걸리면** 커스텀 도메인으로 옮기거나
   로컬 H3로 되돌린다. Cloudflare는 r2.dev를 「개발용, rate-limited」로 명시한다 —
   편수를 크게 올리면 이 줄이 먼저 걸린다
2. **MJ 클립은 5.2초 고정**이다. 씬 길이는 TTS 실측이 정하므로(씬 4는 3.19초) 자르거나
   extend해야 한다. 이 손실이 크면 엔진 선택이 다시 열린다
3. **`staging: studio` 도해가 아직 안 풀렸다** — `base_style`의 "배경을 끝까지"가 스튜디오
   공백과 싸워 도해가 건축물이 된다. staging별 스타일이 필요하고 별건 ADR이다
4. **영상 모델이 `last_frame` 충실도를 잃으면** 구조 전체가 무너진다. 엔진 교체마다 프로브 1
