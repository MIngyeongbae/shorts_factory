# ADR-0097: 대본을 쓰는 두 단계는 codex(ChatGPT 플랜)가 돈다 — 엔진은 단계가 정한다

- 상태: 승인
- 날짜: 2026-09-05
- 관련 스펙: specs/05-pipeline.md (「확정된 결정」·「자원과 비용」), CLAUDE.md 기술 스택

## 맥락

**ADR-0008의 되돌릴 조건이 실제로 걸렸다.** 그 ADR은 *"생산량 증가로 플랜 한도가 병목이
되거나 무인 배치의 안정성 요구가 커지면"* 호출 레이어를 갈아 끼우라고 써 뒀고, 2026-09-04
1부 8편 병렬이 `You've hit your session limit · resets 12am (Asia/Seoul)`로 죽었다
(`llm/claude_code.py`의 `session limit` 재시도 패턴이 그 실측으로 들어온 것이다). 한도는
가설이 아니라 관측된 병목이다.

ADR-0008이 그때 지목한 출구는 **Anthropic API 종량제** 하나였다. 그 사이에 출구가 하나 더
생겼다 — **ChatGPT 플랜에도 헤드리스 CLI가 있고**(`codex exec`), 인증이 플랜이면 한계비용이
같은 0이다. 두 구독은 **서로 다른 한도 풀**이다.

### 실측 1 — 요금 경로 (2026-09-05)

`codex login`(브라우저, ChatGPT 계정) 뒤 `~/.codex/auth.json`이 `auth_mode=chatgpt`이고 API 키
자리는 비어 있다. `codex login status`는 `Logged in using ChatGPT`. 종량제 경로(`codex login
--with-api-key`)는 쓰지 않았다. **한계비용 0**이다.

### 실측 2 — `[1] draft` 전편 대조 9편 (2026-09-05)

`[1]`이 실제로 보내는 프롬프트를 코드에서 그대로 빌드해(손으로 짜지 않았다) `topics/` 현역
9편 전부를 두 엔진에 물렸다. 격리는 같은 계약. 산출은 `reports/codex-ab/`.

| | codex `gpt-5.6-sol` | claude |
|---|---|---|
| 기계 검사 통과 | **8/9** (`tokyo-tower-tanks` 398자 — 상한 390 초과 8자) | 9/9 |
| 세션 시간 평균 | **44초** (33~58) | 401초 (`high-heels-cavalry` 실측) |
| 줄 수 평균 | 16.3 | 15.0 |
| 총 글자 평균 | 359 (계약 310~390) | 375 |
| 줄당 글자 중앙값 평균 | **22.0** (목표 19~24) | 25.2 (목표 위, 상한 43 아래) |
| 재청 | 0회 | — |

**사람이 9편을 다 읽고 판정했다: 대본은 codex가 낫다.** 그 판정이 이 ADR의 결정 근거이고,
아래 관찰은 결정을 뒤집지 않되 관측 항목으로 남긴다.

- **claude 쪽에는 핸디캡이 붙어 있었다** — 디스크의 claude 판은 `[2] factcheck`가 이미 줄을
  정정한 뒤이고 codex 판은 `[1]` 생출력이다. 그 조건에서 사람이 codex를 골랐다
- **줄 = 씬 = 클립이다.** codex가 편당 1.3줄을 더 쓰므로 클립이 그만큼 는다 — 로컬 라인은
  클립당 165~255초 GPU, 유료 라인은 편당 $0.4~0.65다. 공짜로 얻은 「엔벨로프 중앙」이 아니다
- **기계가 못 보는 자리가 있다.** `seokguram-humidity`의 codex 판은 마지막 줄이 질문으로
  끝나 수미상관(스펙 01의 결과 제약)이 닫히지 않는데 기계 검사는 통과했다

### 실측 3 — 격리·계약이 붙는가 (`codex exec --help`, v0.153.2)

ADR-0009·0011이 요구하는 것이 전부 플래그로 있다: `-C <디렉터리>`(중립 작업 디렉터리)
`-s read-only`(세션은 쓰지 못한다) `--ignore-user-config` `--ignore-rules`(프로젝트·사용자
지침 유입 차단 — 클로드 어댑터가 임시 디렉터리로 우회하던 것을 명시적으로 건다)
`--skip-git-repo-check`. 산출 회수는 `-o <파일>`, 이벤트는 `--json`(JSONL). 기록을 안 남기는
`--ephemeral`과 이어 붙이는 `codex exec resume <SESSION_ID> -`은 **서로 배타**다.

## 결정

**`LLMClient` 어댑터를 하나 더 둔다**(`llm/codex_cli.py`의 `CodexClient`) — `codex exec`를 같은
인터페이스로 감싼다. **엔진은 단계가 정한다**: 대본을 쓰는 **`[1] draft`(한국어 정본)와
`[2l] localize`(ja·en 번안)는 codex**, 나머지 전부는 claude다. `[2] factcheck`는 대본을 고치는
단계이지만 **웹 검증이 본체**라 claude에 남긴다 — codex에는 도구 이름 단위 제어가 없고 웹
on/off뿐이라 `WebSearch`·`WebFetch` 사다리(ADR-0061)가 다르게 돈다. 공통 플래그
`--engine {claude,codex}`가 단계 기본값을 이긴다. 격리 계약(ADR-0009·0011)·재청 상한
(ADR-0044)·재생성 루프 없음(ADR-0044)은 엔진과 무관하게 그대로다. **요금 경로는 플랜
인증뿐이다** — `.env`에 `OPENAI_API_KEY`를 두지 않는다(`cli.py`의 `load_dotenv`가 프로세스
환경에 올리고 자식 `codex`가 물려받아 종량제로 샌다).

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **Anthropic API 종량제로 전환** (ADR-0008이 지목한 출구) | 한도 없음, SLA 명확, 어댑터 1개 유지 | 편당 토큰 비용. 1부 전 단계 + `[3s]`·`[5]`·`[7]` 검수가 전부 종량이 된다 | **한계비용 0을 버리는 값이 너무 크다.** 같은 병목을 한계비용 0으로 푸는 길(다른 구독)이 생겼다 |
| **기본은 claude로 두고 `--engine`으로만 codex** | 되돌리기가 가장 싸다 | 사람이 9편을 읽고 이미 판정했는데 그 판정이 기본값에 반영되지 않는다. 매번 플래그를 적어야 하고 잊으면 조용히 claude로 돈다 | **판정이 기본값을 정한다** (ADR-0034 자원 등급 — 사람 판단이 코드 위다) |
| **1부 LLM 전부를 codex로** (`[2] factcheck` 포함) | 클로드 한도가 가장 많이 갈린다 | `[2]`는 웹 교차 확인이 본체인데 codex는 웹 on/off뿐이라 근거 URL 품질이 달라질 수 있다. 그 단계의 실측은 0편이다 | **실측 없는 자리는 옮기지 않는다** — 되돌릴 조건 2로 남긴다 |
| **손으로 codex를 돌려 결과를 붙여넣는다** | 코드 0줄 | run 디렉터리에 세션 기록이 안 남고(`logs/*.json` 계약), 배치가 안 돌고, 재현이 안 된다 | **파이프라인 밖의 산출물은 계약이 없다** (ADR-0011 D-1) |
| **엔진을 `.env`/설정 파일로 고정** | 플래그를 안 적어도 된다 | 어느 편이 어느 엔진으로 나왔는지 실행 기록만 봐서는 모른다 | 단계가 정하고 실행 인자가 덮는 편이 기록에 남는다 |

## 결과

**코드**

- `llm/codex_cli.py` 신설 — `CodexClient(LLMClient)`. 격리 플래그를 항상 걸고,
  `allowed_tools`가 비지 않으면 `-c tools.web_search=true`를 더한다. 산출은 `-o`로 받고
  `--json` 이벤트를 `logs/{label}.codex.attempt{n}.json`에 남긴다. `session_id`는
  `thread.started` 이벤트에서 읽어 `LLMResult`에 싣되 **기록용이다** — 아래 `--ephemeral`
  때문에 그 id로 이어 붙일 수는 없다
- **`--ephemeral`을 항상 켠다** — 이 엔진이 맡은 두 단계는 한 세션에 한 번에 끝나고,
  코드베이스에 `resume=`을 넘기는 자리가 **0곳**이다(재청은 2부 씬 단위의 것이다). 남길
  대화 기록이 없으므로 디스크에 흔적을 두지 않는다. 대신 **재청 요청은 프로세스를 띄우기
  전에 거절한다** — 기록이 없는데 이어 붙이는 척하면 새 세션이 열려 입력 전부를 다시 읽는다.
  ADR-0044가 없애려던 비용이 바로 그 재독이라, 조용한 재실행보다 소리 나는 거절이 싸다
- `system_append`는 프롬프트 앞에 붙인다(이 엔진에 `--append-system-prompt`가 없다).
  `add_dirs`는 무시하고 기록만 남긴다 — codex의 `--add-dir`은 **쓰기** 경로라 ADR-0012의
  읽기 경로와 뜻이 다르고, 읽기 전용 샌드박스는 이미 읽을 수 있다
- `cli.py`: `STAGE_ENGINES = {1-draft: codex, 2l-localize: codex}`(단계 상수를 import해서
  쓴다 — 손으로 옮겨 적지 않는다, ADR-0034), `_engine_for()`, `_make_client(..., stage)`,
  공통 플래그 `--engine`·`--codex-bin`. `part1`은 단계마다 클라이언트를 새로 만든다
- 한도·과부하 재시도 패턴은 **엔진마다 자기 것**이다. codex 쪽 실측 문구가 없어 공통
  신호(`429`/`503`/`rate limit`/`quota`/`too many requests`)로 시작한다
- **단계 코드는 한 줄도 바뀌지 않았다** — `LLMClient`만 보기 때문이다 (ADR-0008 어댑터 패턴)
- 계약 테스트 `tests/test_codex_client.py` 17건 — 격리 플래그, `--ephemeral` 상시 적용,
  중립 작업 디렉터리, 도구 매핑, **재청 거절**(프로세스를 띄우지 않는 것까지),
  실패·한도·타임아웃, 단계별 엔진 매핑

**스펙**

- `specs/05-pipeline.md` 「확정된 결정」의 LLM 줄을 엔진 분기로 고쳤다
- 같은 파일 「자원과 비용」에 **`ChatGPT 구독`** 행을 더하고 `Claude 구독` 행에서 대본 두
  단계를 뺐다
- `CLAUDE.md` 기술 스택의 LLM 줄을 같은 내용으로 고쳤다

**비용**

- 변동비 변화 **없음**. 두 경로 다 구독 정액이고 한계비용 0이다. 한도 풀이 둘로 갈린다
- 클립 수는 는다 — codex가 편당 1.3줄을 더 쓴다(실측 2). 로컬 라인이면 GPU 시간, 유료
  라인이면 편당 $0.4~0.65다
- 금지선: `.env`에 `OPENAI_API_KEY`를 넣지 않는다

**되돌릴 조건**

1. **codex 산출이 기계 검사를 claude보다 자주 깨면** — 9편에서 1건(총 글자 8자 초과)이
   나왔다. 재청 비용이 엔진을 옮긴 값을 상쇄하면 되돌린다. 관측 수단은 run 상태의
   `validation_errors`이고 엔진별로 센다
2. **`[2] factcheck`를 옮길 근거가 쌓이면** — 이 ADR은 그 단계를 claude에 뒀다. codex의 웹
   사다리를 실측해 근거 URL 품질이 같거나 나으면 그때 옮긴다 (실측 먼저, ADR 다음)
3. **codex가 맡은 단계에 재청이 필요해지면** — 지금은 `[1]`·`[2l]` 둘 다 한 번에 끝나
   `--ephemeral`이 공짜다. 이 단계들에 씬 단위 재청 같은 것이 생기면 `--ephemeral`을 끄고
   `codex exec resume <SESSION_ID> -`을 붙인다 — 그때는 세션 파일이 쌓이는 값을 낸다
4. **수미상관·마지막 줄이 반복해서 무너지면** — 기계가 못 보는 자리다(실측 2의
   `seokguram-humidity`). 편이 쌓여 사람 판독에서 계속 걸리면 `[1]` 프롬프트를 고치거나
   엔진을 되돌린다
5. **ChatGPT 플랜 한도도 병목이 되면** — 그때는 ADR-0008이 원래 지목한 API 종량제가 다시
   후보다. 두 구독을 다 채우고도 모자란 생산량이면 그 값을 낼 만하다
6. **엔진별 문체 차이가 채널 정체성을 흔들면** — ko는 codex, ja·en도 codex라 한 편 안에서는
   섞이지 않는다. 다만 이 결정 이전 편들과는 결이 갈린다
