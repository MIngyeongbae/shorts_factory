# ADR-0091: **썸네일은 씬 1 위에 막을 덮고 제목 훅을 그대로 얹는다** — 새 렌더 값이 하나도 없다

- 상태: **승인** (2026-09-02, 사람 — *"승인할게"*). 판(*"실사는 하지말고 제일 처음씬에"*),
  막의 방식(*"덧씌우기로하고"*), 제목 크기(*"지금 제목 크기랑 똑같이해"*)가 전부 사람 결정이고,
  막의 값 셋만 실측이 정했다
- 날짜: 2026-09-02
- 관련 스펙: `specs/03-visual-rules.md`(「제목 훅」), `specs/05-pipeline.md`(새 단계 `[9t]`,
  `[10] upload`), `specs/schema/subtitle-style.json`
- 관련 ADR: **유지** — ADR-0002(정확해야 하는 한국어는 번인이 진다), ADR-0020(그 언어의
  시각·제목을 읽는 곳은 `scenes.timed.{lang}.json` 하나), ADR-0064·0074·0080(제목 훅의
  크기·줄바꿈·폭 계산 — **이 결정은 그 값을 그대로 빌린다**), ADR-0065(제목 훅),
  ADR-0084(`[10]`이 드라이브로 올린다), ADR-0090(같은 대화에서 나온 앞 결정)

## 맥락

### 1. 채널 그리드가 밋밋하다 (사람 관찰, 2026-09-02)

사람이 잘 되는 쇼츠들의 채널 화면을 캡처해 왔다: *"썸네일에 저렇게 검은색으로 여백을 두고
글자를 크게해서 제목을 강조하더라고."* 우리 편들은 썸네일을 안 올려서 유튜브가 영상에서
프레임을 자동으로 하나 뽑고, 그 결과 그리드에 글자가 하나도 없다.

**기대치를 먼저 못박는다 — 이것은 노출을 늘리는 결정이 아니다.** 쇼츠 **피드는 썸네일을
보여주지 않는다**(스와이프로 바로 영상이 뜬다). 썸네일이 일하는 자리는 채널 그리드·검색·
홈의 쇼츠 선반이다. 그래서 지금의 1.2~1.5K 정체(ADR-0090 맥락 1)를 뚫는 축이 아니라
**한 편 보고 채널에 들어온 사람이 두 번째를 누르는 축**이다.

### 2. 씬 1은 구조적으로 자리를 비워 둔다 (실측 3편)

사람이 *"실사는 하지말고 제일 처음씬에 넣을까?"*로 판을 골랐다. 실제로 `clips/1.mp4`의 첫
프레임을 뽑아 보니 **세 편 다 위쪽 1/3이 비어 있다** — 고려청자는 어두운 전시실 벽,
고인돌은 하늘, 경도 상금은 밝은 배경이다. 우연이 아니라 **구도 어휘가 피사체를 가운데
두기 때문**이고(스펙 03), `studio`·`location` 둘 다 그렇다.

엔딩 실사를 쓰지 않는 것도 값이 맞는다 — 엔딩은 29편 중 28편이지만 **씬 1은 항상 있고**,
라이선스·크레딧·인물 축(ADR-0055)이 썸네일에 딸려오지 않는다.

### 3. 판은 `clips/1.mp4`에서 뽑아야 한다 — `timeline.{lang}.mp4`가 아니다

타임라인에는 이미 제목 훅(99px)과 자막이 구워져 있다. 거기서 뽑으면 **제목이 두 겹으로
얹히고 나레이션 자막까지 딸려온다.** 클립은 언어 중립이라 **판 하나로 3개 국어 썸네일**이
나온다는 값도 여기서 나온다.

### 4. 재료가 이미 다 있다 — 새 렌더 값이 **하나도 없다**

사람이 *"지금 제목 크기랑 똑같이해"*로 정했다. 그러면 빌려 쓰는 것이 이렇다:

| 필요한 것 | 어디 있는가 |
|---|---|
| 제목 문자열 | `scenes.timed.{lang}.json`의 `title` (ADR-0065) |
| 크기 99px | `subtitle-style.json` `title.font_scale` 1.5 × 66 (ADR-0080) |
| 줄당 상한·줄 수 | `title_max_line_chars_for`·`title.max_lines` (ADR-0062·0080) |
| 채워쓰기·일본어 금칙 | `fill_text`·`title.kinsoku` (ADR-0074) |
| 폰트·세로 메트릭 | `assets/fonts` + `normalize_font_metrics.py` (ADR-0064) |

**새로 정할 값은 막(scrim) 셋뿐이다.**

### 5. 막 실측 — **진하기보다 아래끝 처리가 문제였다**

하니스 `reports/thumbnail-probe/probe.py`(gitignore), 실편 3편 × 변종 6개.
먼저 딱딱한 띠의 알파만 0.00·0.35·0.55·0.75로 흔들었다.

| 판 | 딱딱한 띠에서 드러난 것 |
|---|---|
| 고려청자(어두움) | 알파 0에서도 읽힌다 — 막이 거의 할 일이 없다 |
| 고인돌(밝은 하늘) | 0.35부터 편해진다 |
| **경도 상금(밝고 복잡한 동전)** | **0.55는 되어야 읽힌다** — 여기가 바닥이다 |

**그런데 세 판 모두 막의 아래끝이 가로 줄로 남았다.** 반투명 띠라 letterbox처럼 읽히지
않고 **그림을 자른 자국**으로 보인다 — 동전 판에서 동전 더미가 중간에서 끊긴다.

그래서 그라데이션 변종을 다시 쟀다(위에서 일정 구간 유지 후 아래끝에서 0으로):

| 변종 | 결과 |
|---|---|
| 딱딱 0.55 · 0.75 | 대비는 되지만 **자른 자국이 남는다** |
| 그라데 0.75 | 자국이 사라진다. 동전 판은 아직 아슬하다 |
| **그라데 0.85** | **자국 없음 + 동전 판에서도 확실히 읽힌다** ← 채택 |

자국이 사라지자 어두워진 부분이 **조명처럼** 읽힌다 — 어두운 판(고려청자)에서도 손해가 없다.

## 결정

**`[9t] thumbnail`을 새 단계로 두고, 씬 1 클립의 첫 프레임 위에 그라데이션 막을 덮은 뒤
제목 훅을 그대로 얹어 언어당 한 장을 굽는다.** 영상에는 아무 변화가 없다.

1. **판은 `clips/1.mp4`의 첫 프레임**이고 세 언어가 **같은 판**을 쓴다. 크롭·스케일 없이
   1080×1920 그대로다.
2. **막은 덧씌우기다** (사람 결정 — *"덧씌우기로하고"*). 레터박스로 그림을 밀지 않는다.
   위에서 `alpha`로 시작해 `hold`까지 유지하고 아래끝에서 0으로 뺀다. **아래끝은 제목
   블록의 아래끝 + `pad`**이므로 줄 수를 따라 움직인다 — 2줄 제목에 절반을 덮지 않는다.
   값은 `subtitle-style.json`의 새 블록 `thumbnail.scrim`: `alpha: 0.85` · `hold: 0.55` ·
   `pad: 48`. **실측 3편이 정한 값이고 코드가 선언하지 않는다** (ADR-0034).
3. **제목은 제목 훅 그대로다** (사람 결정 — *"지금 제목 크기랑 똑같이해"*). 크기·줄당
   상한·줄 수·채워쓰기·금칙·폰트·외곽선을 전부 물려받고 **썸네일 전용 제목 값을 만들지
   않는다.** 없어도 되는 계약값은 안 만든다 (ADR-0065가 제목 길이 상한을 안 만든 태도).
   `[9]`가 굽는 것과 같은 ASS 스타일·같은 함수를 탄다.
4. **언어당 한 장** — `thumbnail.{lang}.png`. `title`이 없는 언어는 **굽지 않고 경고**한다.
   자막·엔딩과 달리 **제목 없는 썸네일은 만들 이유가 없다** — 이 산출물의 일 전부가 제목이다.
5. **새 단계는 기존 단계를 수정하지 않는다** (specs/05 D-4). `[9t]`의 입력은 `clips/1.mp4`와
   `scenes.timed.{lang}.json`뿐이고 `[9]`·`[8]`·`[7]`을 안 건드린다. **`[10] upload`만
   바뀐다** — `thumbnail.{lang}.png`가 있으면 그 언어의 영상과 같은 폴더에 같이 올리고,
   없으면 지금과 완전히 같이 돈다 (D-3).
6. **붙이는 것은 사람이다.** 파이프라인은 드라이브까지이고 유튜브 스튜디오에서 썸네일을
   지정하는 것은 사람 손이다 (ADR-0084의 경계 그대로).

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| **엔딩 실사를 판으로** | 실물 사진이라 신뢰가 선다 | 29편 중 28편에만 있다 | **사람이 뺐다** (*"실사는 하지말고"*). 라이선스·크레딧·인물 축(ADR-0055)이 썸네일까지 따라오고, 씬 1은 항상 있다 |
| **레터박스(진짜 검은 띠)** | 캡처의 룩에 제일 가깝고 가독성이 확실 | 그림이 밀리고 아래가 잘린다 | **사람이 덧씌우기로 정했다.** 실측에서 그라데 0.85가 레터박스 없이도 동전 판을 읽히게 했다 |
| **딱딱한 반투명 띠** | 구현이 `drawbox` 한 줄 | 아래끝이 그림을 자른 자국으로 남는다 | **실측이 죽였다** (맥락 5). 세 판 전부에서 가로 줄이 보였다 |
| **`timeline.{lang}.mp4`에서 프레임을 뽑는다** | 제목이 이미 구워져 있어 합성이 필요 없다 | 자막도 같이 딸려온다 | 제목 훅이 이미 있는 프레임에 또 얹으면 두 겹이고, 나레이션 자막은 썸네일에 있을 것이 아니다 |
| **썸네일 전용 제목 크기를 새로 둔다** | 그리드 셀에서 더 크게 보일 수 있다 | 계약값이 늘고 ADR-0080의 한 벌이 갈린다 | **사람이 "지금 제목 크기랑 똑같이"로 정했다.** 없어도 되는 계약값은 안 만든다 |
| **`[9] assemble`이 곁다리로 굽는다** | 새 단계가 없다 | `[9]`의 책임이 는다 | **D-4를 어긴다.** `[9t]`의 입력은 `[9]`의 산출물이 아니라 클립과 실측 계약이라 독립 단계로 완전히 선다 |
| **파이프라인 밖 도구(`tools/`)로 둔다** | 스펙 05를 안 건드린다 | run 기록에 안 남고 잊힌다 | 편마다 3장이 나오는 산출물이라 계약 자리가 있어야 한다. 재실행·건너뛰기(ADR-0020)도 공짜로 딸려온다 |

## 결과

### 바뀌는 것

| 자리 | 무엇 |
|---|---|
| `specs/05-pipeline.md` | **새 단계 `[9t] thumbnail`** + I/O 계약표에 `thumbnail.{lang}.png`. `[10]`이 있으면 같이 올린다 |
| `specs/03-visual-rules.md` | 「제목 훅」에 *"같은 값이 썸네일도 진다"* 한 줄 |
| `specs/schema/subtitle-style.json` | `thumbnail.scrim` 블록 (`alpha`·`hold`·`pad`) |
| `stages/thumbnail.py`(신설) · `video/thumbnail.py`(신설) · `cli.py` | 프레임 추출 + 막 + 제목 |
| `stages/upload.py` | 있으면 같이 올린다 (D-3) |
| **안 바뀌는 것** | **영상 · `[7]` · `[8]` · `[9]` · 자막 · 제목 훅 · 씬 계약 · 변동비** |

비용은 **0원**이다 — FFmpeg 호출 두 번(프레임 추출·합성)이고 GPU도 API도 안 쓴다.

### 되돌릴 조건

1. **제목이 5줄을 넘는 편이 잦으면 막의 크기를 다시 본다.** 아래끝이 제목 블록을 따라가므로
   6줄이면 269 + 712.8 + 48 = 1030px으로 **화면의 54%**가 어두워진다. 그라데라 아래쪽은
   거의 투명하지만 상한을 확인할 자리다 (제목 실측 19편은 2~4줄이었다 — ADR-0074)
2. **씬 1 첫 프레임이 판으로 못 쓸 편이 4편 중 1편을 넘으면** 프레임 고르는 규칙을 만든다.
   지금 실측 3/3은 위가 비어 있다 — 그때는 사람이 씬을 지정하는 인자가 답이다
3. **채널 그리드에서 두 번째 편 클릭이 안 늘면 뺀다.** 이 결정의 목표가 노출이 아니라
   유입자의 2편째라(맥락 1) 그 지표가 안 움직이면 유지할 이유가 없다
4. **막이 피사체를 가리는 편이 나오면 `hold`를 줄인다** — 알파가 아니라 유지 구간이 먼저다

### 관측할 값

- 제목 줄 수 분포(막의 크기가 그것을 따라간다)와 굽지 못한 편 수
- 채널 그리드에서의 두 번째 편 클릭 (사람이 스튜디오에서 읽는다 — 파이프라인이 못 재는 값이다)
