# ADR-0011: 1부 단계 산출물은 run 디렉터리 JSON 계약에 싣고, 헤드리스 세션에는 쓰기 권한을 주지 않는다

- 상태: 승인
- 날짜: 2026-08-07
- 관련 스펙: specs/05-pipeline.md, specs/06-topic-research.md
- 관계: ADR-0008(헤드리스 실행), ADR-0009(세션 독립성·인간 게이트)의 구현 계약을 확정

## 맥락

`[0a. topic]` ~ `[0b. research]`를 구현하면서 스펙이 정하지 않은 빈칸 네 개가 드러났다.

1. **[0a]의 출력 스키마가 없다.** specs/05-pipeline.md는 "각 단계는 독립 실행 가능한 모듈이며,
   **파일 기반 JSON으로 통신한다**"고 규정하지만, `[0a. topic]`의 출력은 "`topics/{slug}/` 폴더 생성"으로만
   적혀 있다. 폴더 생성은 JSON 계약이 아니다. `[0b]`가 소재명·슬러그·백로그 4조건을 넘겨받을 경로가 없다.
2. **`{slug}`의 정의가 없다.** specs/06은 `topics/{slug}/`를 쓰지만 한글 소재명에서 슬러그를 얻는 규칙이
   없다. 폴더 이름이므로 같은 소재명이 항상 같은 슬러그로 떨어져야 한다.
3. **실행 상태의 저장 위치가 없다.** specs/05 실패 정책은 "해당 run 디렉토리에 상태 기록 후 종료",
   "같은 run_id로 재실행 시 완료된 단계는 스킵"을 요구하지만 파일명과 형식이 없다.
4. **세션이 산출물을 직접 쓸지 정해지지 않았다.** ADR-0008은 `claude -p` 호출까지만 정한다.
   세션에 Write 도구를 주면 `[0b]`의 조사 세션이 임의 경로에 파일을 쓸 수 있게 된다.

빈칸을 코드가 암묵적으로 메우면 되돌리기 비싸진다. 특히 1번과 3번은 하류 단계(`[1. script]` 이후)가
전부 의존하게 될 데이터 계약이라, CLAUDE.md 원칙 4에 따라 ADR 없이 굳히면 안 된다.

## 결정

**1부 단계 간 계약은 `runs/{run_id}/` 아래 JSON으로 싣고, `topics/{slug}/`는 사람이 읽는 패키지로만 둔다.**
specs/06이 정의한 토픽 패키지 구조(01~06 + STATUS.md)는 사람의 검토 대상이므로 기계용 계약 파일을 섞지 않는다.

| 파일 | 생산자 | 내용 |
|---|---|---|
| `runs/{run_id}/topic.json` | `[0a]` | `run_id`, `topic`, `slug`, `topic_dir`, `backlog_conditions`, `sources_hint`, `created_at` |
| `runs/{run_id}/state.json` | 전 단계 | 단계별 `status`(pending/running/done/failed/blocked), 타임스탬프, 산출물 경로, 세션 메타 |
| `runs/{run_id}/research.json` | `[0b]` | 팩트시트 사본 (specs/06이 이미 규정) |
| `runs/{run_id}/logs/*.json` | LLM 어댑터 | 헤드리스 세션 응답 원본 (추적성) |

- **슬러그**: 음운 변화(자음동화 등)를 적용하지 않는 음절 단위 국어의 로마자 표기 →
  `[a-z0-9-]`, 최대 60자. "한양도성 각자성석" → `hanyangdoseong-gakjaseongseok`.
  백로그에 `slug` 컬럼이 있으면 그 값이 우선한다(짧은 이름 수동 지정용).
- **run_id**: `YYYYMMDD-{slug}` (specs/05의 예시 `20260807-baekak`을 규칙화)
- **세션 권한**: 헤드리스 세션에는 **읽기 도구만** 준다(`[0b]` 조사·검증·비판은 `WebSearch`/`WebFetch`,
  팩트시트 종합은 도구 없음). 산출물 파일은 전부 오케스트레이터(Python)가 쓴다.
- **세션 격리**: 세션마다 중립 임시 디렉터리를 작업 디렉터리로 준다. 프로젝트 `CLAUDE.md`와 로컬 설정이
  조사·검증·비판 세션에 유입되면 ADR-0009가 요구한 세션 독립성이 깨진다.

## 검토한 대안

| 대안 | 장점 | 단점 | 탈락 사유 |
|---|---|---|---|
| 계약 파일 없이 slug만 CLI 인자로 전달 | 파일 하나 안 늘어남 | 재시작 시 4조건·소재명 출처를 잃음, 감사 추적 불가 | specs/05 "파일 기반 JSON으로 통신" 정면 위반 |
| `topics/{slug}/00-topic.json`에 계약을 둠 | 패키지만 보면 다 보임 | 사람 검토용 폴더에 기계 파일이 섞여 specs/06 구조가 흐려짐 | 인간 게이트(ADR-0009)의 검토 대상이 불명확해짐 |
| 세션에 Write 도구 부여 → 세션이 직접 산출물 기록 | 오케스트레이터 코드 감소 | 출력 경로를 파이프라인이 통제 못 함, 조사 세션이 리포지토리를 수정할 수 있음 | 계약 강제 불가 (스키마 검증 전에 파일이 이미 쓰임) |
| 슬러그를 한글 그대로 폴더명 사용 | 변환 규칙 불필요 | Windows/Linux·git·URL 경로에서 인코딩 사고, run_id 가독성 저하 | 크로스 플랫폼 리스크 대비 이득 없음 |
| 음운 변화까지 반영한 정밀 로마자 표기 | 표기법상 정확 | 동일 입력의 결과가 구현·버전에 따라 흔들릴 수 있음 | 폴더 이름에는 정확성보다 **결정성**이 중요 |

## 결과

- `[1. script]` 이후 단계는 `runs/{run_id}/topic.json` + `research.json`만 읽으면 되고,
  `topics/{slug}/`의 마크다운을 파싱할 필요가 없다
- `state.json` 덕에 중간에 끊긴 run을 같은 `run_id`로 이어서 실행할 수 있다 (서브스텝 단위 스킵)
- 세션이 파일을 못 쓰므로, 스키마 검증을 통과하지 못한 팩트시트는 디스크에 남지 않는다
- **되돌릴 조건**: 하류 단계가 `topics/{slug}/`의 마크다운(01~03)을 기계적으로 파싱해야 할 일이 생기면,
  해당 산출물도 JSON 계약으로 승격하는 것을 재검토한다. 슬러그 충돌(다른 소재명이 같은 슬러그)이
  실제로 발생하면 run_id에 짧은 해시를 덧붙이는 방안을 재검토한다

## 반영한 스펙 수정 (승인 시 적용 완료)

`specs/05-pipeline.md`에 계약 파일을 명시한다.

`## 핵심 계약: scenes.json`과 `## 단계별 규칙` 사이에 절을 하나 넣는다.

```diff
+## 단계 간 계약 파일 (runs/{run_id}/)
+
+토픽 패키지(`topics/{slug}/`)는 사람이 읽는 산출물이고, 단계 간 기계 계약은 run 디렉터리에 둔다 (ADR-0011).
+
+| 파일 | 생산자 | 용도 |
+|---|---|---|
+| `topic.json` | [0a] | 소재명·슬러그·백로그 4조건. 하류 단계의 입력 |
+| `state.json` | 전 단계 | 단계 상태(pending/running/done/failed/blocked). 재시작 시 완료 단계 스킵 판단 |
+| `research.json` | [0b] | 팩트시트 사본 (스펙 06) |
+| `logs/*.json` | LLM 어댑터 | 헤드리스 세션 응답 원본 |
+
+- `slug`: 음운 변화 미적용 로마자 표기, `[a-z0-9-]` 최대 60자 (ADR-0011)
+- `run_id`: `YYYYMMDD-{slug}`
+- 헤드리스 세션에는 읽기 도구만 준다. 산출물 파일은 오케스트레이터가 쓴다 (ADR-0011)
+
 ## 단계별 규칙
```

`specs/06-topic-research.md`의 백로그 항목 정의에 슬러그 오버라이드를 추가한다.

```diff
-- `topics/backlog.md`에서 관리. 항목: 소재명, 4조건 체크, 출처 후보, 상태(후보/리서치중/제작완료/반려)
+- `topics/backlog.md`에서 관리. 항목: 소재명, 4조건 체크, 출처 후보, 상태(후보/리서치중/제작완료/반려)
+- 선택 항목: `slug` 컬럼. 있으면 자동 로마자 변환 대신 이 값을 폴더명으로 쓴다 (ADR-0011)
```
