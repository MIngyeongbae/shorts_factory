# 열린 결정: 대본 구조 자유화와 도메인 확장

- 작성: 2026-08-13
- 상태: **결정 전.** 이 문서는 무엇이 무너지는지의 조사이지 결정이 아니다
- 계기: "대본 틀조차도 자료를 만들고 그거에 맞춰서 만들어 쓰자" + "그렇게 간다면 건축
  관련도 다 정리해야 한다"

## 1. 지금 구조가 왜 한 덩어리인가

두 변경이 독립이 아니다. **하나의 사슬로 묶여 있고, 사슬의 끝이 2부 연출 룰이다.**

```
도메인 = 건축·토목·문화기술사        (ADR-0015 → 0016, 스펙 00·06)
   └→ 소재 4조건                     (스펙 06)
        · 2번 "실패한 대안의 기록"이 명시적으로 "템플릿 3~4단을 채울" 사료다
        · 제외 항목의 사유가 전부 "7단 구조를 채우지 못한다"이다
   └→ 7단 구조 + 시그니처            (스펙 01)
        └→ beat enum 12종            (스펙 02, "대응 템플릿 단계" 열이 7단에 1:1)
             └→ ★ beat = 파이프라인 전체의 유일한 분기 기준 (스펙 02 첫 줄, ADR-0001)
                  ├─ 구도 표 36칸     (스펙 03, beat × subject_scale)
                  ├─ 오버레이·카메라   (스펙 03, beat 12행)
                  ├─ 전환 규칙        (스펙 03, 하드컷 3비트)
                  ├─ 오디오 룰        (스펙 04, turning_point 차임)
                  └─ 대본 검증        (script_rules.py, STAGES_OF_BEAT·REQUIRED_STAGE_BEATS)
```

**7단을 풀면 `beat`의 정의 근거가 사라지고, `beat`이 흔들리면 2부 룰 테이블 전부가 근거를
잃는다.** 도메인을 넓히면 4조건이 흔들리고, 4조건이 7단을 지탱하고 있다.

그래서 "대본 파이프라인만 고치면 되는 일"이 아니다.

## 2. 다행히 층이 갈린다 — 셋 중 어디까지 갈 것인가

`beat`에는 두 가지가 섞여 있고, **분리하면 파급이 크게 달라진다.**

- **시퀀스 제약**: 순서 역행 금지, 단계별 필수 비트, `failed_solution` 2회 이상,
  `turning_point` 정확히 1회, 전환점 260~310자 → **전부 7단에서 온다**
- **어휘 12종**: `hook_fact`·`failure_reason`·`turning_point`… → 이건 **"문제 해결 서사"의
  기능 분류**다. 순서 제약 없이도 존재할 수 있다

| | 무엇을 푸는가 | 무너지는 것 | 사는 것 |
|---|---|---|---|
| **L1 시퀀스만 자유화** | 순서·개수·위치 제약. `[1a]`가 소재마다 단(act) 구성을 설계 | 스펙 01의 7단 표·검증 5항목, `script_rules.py`의 절반 | **2부 룰 테이블 전부.** 어휘가 남으므로 구도·오버레이·전환·오디오가 그대로 돈다 |
| **L2 어휘까지 도출** | 소재마다 beat을 새로 만든다 | 위 + **스펙 03·04 룰 테이블 전체**, ADR-0001·0018의 전제 | 씬 계약(`visual_goal`·`subject`·`subject_scale`)과 2부 배관 |
| **L3 서사 유형까지** | "문제 해결 서사"가 아닌 것도 허용 (연대기·비교·인물) | 위 + **소재 4조건**(스펙 06), `[0b]` 판정, 백로그 기준 | 팩트시트 스키마, 소스 등급, 그라운딩 |

> **L2는 룰 테이블을 되살릴 방법을 함께 설계해야 한다.** beat이 소재마다 달라지면
> "beat → 구도" 표를 못 만든다. 대안은 두 가지뿐이다 — (a) 자유 beat을 **고정 어휘로
> 매핑**하는 층을 둔다(사실상 L1에 이름만 자유), (b) 구도를 `[1s]`가 직접 고른다
> (**ADR-0001 폐기**: "비트가 연출을 결정한다"의 종료). (b)는 이 프로젝트의 1번 원칙을
> 뒤집는 일이라 별도 ADR이고, 되돌리기가 가장 비싸다.

### 3-3. 이미 쓴 ADR 중 손봐야 할 것

- **ADR-0029(방금 작성)** — `[1a] outline`을 "스펙 01의 7단 고정 순서다. 단계를 늘리거나
  줄이지 않는다"로 썼다. **이 결정과 정면으로 충돌한다.** L1 이상을 택하면 그 문장을 고쳐야

- ADR-0001 — "비트가 연출을 결정한다". L2(b)에서 폐기 대상

## 4. 무너지지 않는 것 — 건드릴 이유가 없다

**전부 실측에서 나온 값이고 도메인·구조와 무관하다.**

| 유지 | 근거 |
|---|---|
| 길이 90~102초, 545~575자, 23~28줄, 5.3~6.3자/초 | 레퍼런스 3편 실측. **쇼츠의 값이지 건축의 값이 아니다** |
| 씬 = 자막 한 줄 (ADR-0013) | 자막 리듬 실측 |
| 1부↔2부 경계 2파일 (ADR-0017) | 구조와 무관 |
| 2부 계약 전부 (ADR-0020·0024) | `scenes.timed.json`·`prompts.json`·클립 기하 |
| 팩트시트 그라운딩 (ADR-0007), 소스 등급·confidence (ADR-0016) | 사실 검증 축 |
| TTS·이미지·모션 경로 (ADR-0004·0025·0031) | 프로바이더 축 |
| 세션 격리·계약 (ADR-0009·0011) | 실행 축 |
| ADR-0029의 **3분할 자체** | 과부하 해소가 목적이고 구조 자유화와 독립이다 |

## 6. 권장 순서 (D1이 정해진 뒤)

1. **ADR-0033 "대본 구조를 자료에서 도출한다"** — D1·D2·D3를 한 번에 결정. ADR-0015 폐기와
   ADR-0029 개정을 이 ADR이 명시
2. `specs/01` 재작성 — 7단 표를 **구조 설계 지침**으로 바꾼다 (무엇을 만족해야 하는가만
   남기고 형태는 소재가 정한다)
3. `specs/06` 재작성 — 도메인·4조건
4. `schemas/script_rules.py` — 시퀀스 검증 제거, 분량·그라운딩 검증만 남긴다
5. ADR-0029 개정 + `[1a]`/`[1s]`/`[1w]` 구현 (프롬프트 3분할)
6. (L2를 택했을 때만) 스펙 03·04 룰 테이블 재설계 — **별도 ADR, 별도 세션**

## 7. 곁가지: 사분면 선택 기준 (ADR-0031)

"4장 중 대본의 자세한 내용과 잘 맞는 것을 고르게 한다" — **이미 판정 기준 ①②가 그것이고,
판정 세션에 씬의 `text`까지 준다는 점만 명시하면 된다.** 이 결정은 위 사슬과 무관하게
독립적이라 먼저 반영해도 안전하다.
